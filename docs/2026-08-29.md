## feature/quantization

### 1. 추론 지연 링 버퍼 + p50/p95/max 통계

**파일:** `src/detector_ort.c`, `include/yolo11.h`

`struct Detector`에 최근 256회 추론 시간을 저장하는 고정 크기 링 버퍼 추가. 매 `detector_run()` 후 추론 ms를 기록하고 insertion sort(n≤256)로 백분위를 계산해 `DetectorRunStats`에 저장한다.

```c
double inference_p50_ms;
double inference_p95_ms;
double inference_max_ms;
```

p95가 p50의 2배를 넘으면 서멀 스로틀링 의심. `--metrics` JSON으로 확인.

### 2. ORT 세션 최적화

- **Denormals-as-zero** (`session.set_denormals_as_zero=1`): Haswell FP32 denormal 수백 사이클 페널티 제거
- **웜업** (`--warmup N`): 시작 시 더미 추론 N회 → 첫 프레임 지연 스파이크 서비스 전에 소진
- **DirectML + INT8 경고**: 모델명에 `int8` 포함 + DirectML 조합 시 자동 경고 출력

### 3. `--threads` 상한 2→3

CLAUDE.md 방침 "2코어 4스레드 중 3스레드를 파이프라인에, 1스레드는 OS 예비" 반영.

### 4. metrics JSON 확장

`write_metrics()`에 `inference_p50_ms`, `inference_p95_ms`, `inference_max_ms` 추가.

### 5. `scripts/quantize.py` — static INT8 양자화

```sh
python scripts/quantize.py --model yolo11n-pose-416.onnx --calib-dir samples/
```

- `quant_pre_process()` → shape inference 선행 적용
- `YoloCalibReader`: C 코드의 `letterbox_to_nchw()`와 동일한 전처리 (114 패딩, 중앙 정렬, /255.0, NCHW)
- **Haswell 기대치: 1.5~2.5×** (VNNI 없음. 일부 문서 "2~4×"는 Cascade Lake+ 기준)

### 6. `scripts/bench.ps1` + `scripts/bench.sh`

같은 입력으로 FP32/INT8을 돌려 추론 시간·p95·CPU ms/frame 비교표 출력.

### 7. `docs/quantization.md`

변환 절차, 캘리브레이션 준비법, Haswell 기대치, DirectML 비호환, 지연 통계 해석.

## feature/anomaly-rules

`feature/pose-model`을 main에 머지한 뒤 분기.

### 1. 공유 그레이 버퍼 — `src/gray.c`

BT.601 luma `(77R+150G+29B+128)>>8`, 1/4 다운샘플. camera_health와 모션 게이트가 프레임당 한 번 계산한 버퍼를 재사용.

### 2. 구조화 이벤트 로그 — `src/log.c`

```
2026-08-29T14:03:11 WARN   rules        overstay track=7 dwell=4821s limit=3600s
2026-08-29T14:03:11 INFO   camera       whiteout recovered
```

ISO 8601 타임스탬프, INFO/WARN/ERROR, 모듈 태그, key=value 근거 필드.
`--event-log PATH` 미지정 시 stderr 출력.

### 3. 매장별 설정 파서 — `src/config.c`

외부 라이브러리 없는 `key = value` 파서. `#` 주석, 공백 트림 지원.

```ini
dwell_limit_seconds     = 3600
unordered_grace_seconds = 300
fall_hold_seconds       = 5.0
motion_ratio_threshold  = 0.004
idle_refresh_seconds    = 10.0
luma_white_threshold    = 240
luma_black_threshold    = 12
frozen_frames_threshold = 150
roi_kiosk               = 820,120,300,420
```

### 4. 카메라 장애 감지 — `src/camera_health.c`

그레이 버퍼만 입력, 모델 불필요.

| 증상 | 판정 | 이벤트 |
|------|------|--------|
| 백화 | 평균 luma > 240, 히스테리시스 5프레임 | `camera_whiteout` |
| 암전 | 평균 luma < 12, 히스테리시스 5프레임 | `camera_blackout` |
| 프리즈 | 변화 픽셀 비율 ≈ 0, 히스테리시스 150프레임 | `camera_frozen` |

상태 진입·복구 양쪽 모두 이벤트 로그 기록.

### 5. 안정적 트랙 ID — `src/tracks.c`

IoU 그리디 매칭(임계값 0.3)으로 프레임 간 같은 사람에게 같은 ID 유지. 기존 `LightTracker`는 박스 이동만 할 뿐 ID가 없어 체류 시간 누적이 불가능했다.

- 매칭 성공: `dwell_seconds` 누적, `last_seen` 갱신
- 매칭 실패: `misses++` → 임계 초과 시 트랙 제거
- 새 detection: 신규 트랙 (`next_id++`)
- `tracks_mark_ordered(id)`: 결제 이벤트 연동 예정 지점

### 6. 룰 엔진 — `src/rules.c`

각 이벤트는 트랙당 1회만 발화(latch), 조건 해소 시 해제.

| 룰 | 판정 | 이벤트 |
|-----|------|--------|
| 초과 체류 | `dwell > dwell_limit_seconds` | `overstay` |
| 미주문 착석 | UNORDERED + `dwell > unordered_grace_seconds` | `unordered_seated` |
| 쓰러짐 | bbox 가로 > 세로×1.2 + keypoint y 분산 ≤ bbox 높이×0.25, `fall_hold_seconds` 지속 | `person_fallen` |

keypoint 없으면 bbox 비율만으로 판단. score < 0.4 관절 제외.

### 7. `src/main.c` 통합

`process_frame()` 실행 순서:

```
1. gray_buf_update (prev ↔ curr swap)
2. camera_health_update → 이상 시 event_log_write
3. 모션 게이트:
   변화 픽셀 비율 < motion_ratio_threshold (0.004)
   && (now - last_detection_time) < idle_refresh_seconds (10s)
   → run_detector = 0, kind = "gated"
4. detect_every / tracker adaptive 로직 (기존)
5. 추론 프레임: tracks_update → rules_evaluate
```

신규 CLI: `--config PATH`, `--event-log PATH`, `--motion-gate 0|1`
metrics JSON에 `gated_frames`, `event_count`, `motion_gate` 추가.

### 8. `docs/anomaly-rules.md`

구현된 룰 목록, 설정 키 설명, 이벤트 로그 형식, 모션 게이트 원리, 결제 연동 지점 설명.

## 대시보드 UI 개선 (세션 2)

### 1. 실시간 FPS HUD — EMA 방식

**파일:** `src/main.c`

`AppContext`에 `realtime_inf_fps` (α=0.3), `realtime_cam_fps` (α=0.15) 추가. 기존 누적 평균 대신 지수 이동 평균으로 현재 시점의 처리 속도를 표시. HUD 텍스트 `INF FPS: 12.4` / `CAM FPS: 28.7` 형태.

- cam FPS: 프레임 시작마다 갱신 (α=0.15 ≈ 7~8프레임 반응)
- inf FPS: 추론 완료마다 갱신 (α=0.3 ≈ 3프레임 반응)

### 2. 문 감지 — 이중 기준 이미지 (열림/닫힘 각각)

**파일:** `include/door.h`, `src/door.c`

단일 기준에서 이중 기준으로 전환. `ref_closed_rgb`와 `ref_open_rgb` 두 장을 각각 저장해, 현재 프레임의 L1 픽셀 거리가 더 작은 쪽으로 상태를 결정. 조명 변화로 인한 오감지를 크게 줄임.

`door_load(monitor, closed_path, open_path)`: 파일 없으면 0 반환(에러 아님), 두 경로 모두 옵션.

### 3. 문 개방 지속 임계값 + latch 패턴

**파일:** `src/main.c`, `include/door.h`

`door_open` 이벤트를 개방 즉시가 아닌 `door_open_seconds`(기본 30초) 경과 후에만 발화. `open_since` 타임스탬프 + `open_event_fired` 플래그로 이중 발화 방지. `door_closed`는 `door_open`이 발화된 경우에만 기록.

```
door_open_seconds 슬라이더: 5~300초, 스텝 5
```

### 4. 설정 hot-reload

**파일:** `src/main.c`

`config_reload_path` + `config_mtime` + `config_check_time` 조합. `process_frame` 내에서 2초마다 파일 mtime을 체크해, 변경 시 `reload_config()` 호출. 재시작 없이 임계값 즉시 반영.

`reload_config()`이 바꾸는 항목:
- 모션 게이트 임계값
- 문 여닫이 설정 (enabled, diff_threshold, open_threshold_seconds, ROI)
- 카메라 장애 임계값
- 체류/쓰러짐 룰 임계값

### 5. 설정 로드 실패 버그 수정

**파일:** `dashboard/server.c`

Windows 텍스트 모드(`"r"`)에서 `\r\n → \n` 변환으로 `ftell` 크기 ≠ `fread` 바이트 → `Content-Length` 불일치 → 브라우저 JSON 파싱 실패. `"rb"` + `fread` 반환값을 Content-Length로 사용하도록 수정.

### 6. 문 현재 상태 실시간 표시

**파일:** `src/stream.c`, `include/stream.h`, `src/main.c`, `dashboard/index.html`

`/door/state` GET 엔드포인트 추가. `g_door_state` + `g_door_enabled` 두 글로벌 변수. 대시보드 JS가 3초마다 폴링해 사이드바 배지를 실시간 갱신.

```json
{"state":1,"enabled":1,"label":"open"}
```

상황별 배지:
- 감지기 미연결: `—`
- `door_enabled=0`: `비활성`
- `door_enabled=1` + 기준 없음: `기준 없음`
- 닫힘: `False (닫힘)` (초록)
- 열림: `True (열림)` (주황)

**버그 수정**: `stream_set_door_enabled`가 `process_frame` 내부에만 있어 카메라 연결 전에는 `g_door_enabled=0`으로 남던 문제. `stream_start()` 직후와 `reload_config()` 말미에도 호출하도록 수정.

### 8. PERSON_FALLEN 오감지 개선

**파일:** `src/rules.c`

기존 `is_horizontal_pose()` 기준의 세 가지 약점을 수정:

| 항목 | 기존 | 개선 |
|------|------|------|
| bbox 비율 (keypoint 있음) | `w > h × 1.2` | `w > h × 1.8` |
| bbox 비율 (keypoint 없음) | `w > h × 1.2` | `w > h × 2.2` |
| keypoint 최소 유효 수 | 2개 | 3개 |
| y 표준편차 비율 상한 | ≤ 0.25 | ≤ 0.20 |
| bbox 최소 세로 | 없음 | 30px 미만 무시 |
| detection score 하한 | 없음 | 0.30 미만 무시 |

오감지 시나리오:
- 앉아서 팔 벌린 자세 (bbox는 넓어도 1.8x 미달)
- 앞으로 몸 숙인 자세 (keypoint 부족 시 2.2x 기준 적용)
- 작은 노이즈 검출 (30px 이하 필터링)
- 저신뢰 검출 (score 0.30 미만 필터링)
