## feature/quantization

### 1. 추론 지연 링 버퍼 + p50/p95/max 통계

**파일:** `src/detector_ort.c`, `include/yolo11.h`

`struct Detector`에 최근 256회 추론 시간을 저장하는 고정 크기 링 버퍼를 추가했다. 매 `detector_run()` 후 추론 ms를 기록하고, insertion sort(n≤256)로 p50/p95/max를 계산해 `DetectorRunStats`에 저장한다.

```c
double inference_p50_ms;
double inference_p95_ms;
double inference_max_ms;
```

p95가 p50의 2배를 넘으면 서멀 스로틀링 의심. `--metrics` JSON으로 확인한다.

### 2. ORT 세션 최적화

**파일:** `src/detector_ort.c`

- **Denormals-as-zero**: `session.set_denormals_as_zero=1`. Haswell FP32 denormal 수백 사이클 페널티 제거.
- **웜업(`--warmup N`)**: 시작 시 더미 추론 N회 → JIT 초기화를 서비스 전에 소진, 첫 프레임 지연 스파이크 제거.
- **DirectML+INT8 경고**: 모델명에 `int8` 포함 + DirectML 조합 시 자동 경고 출력.

### 3. `--threads` 상한 2→3

CLAUDE.md 방침 "2코어 4스레드 중 3스레드를 파이프라인에 활용, 1스레드 OS 예비"에 맞춰 상한 조정.

### 4. metrics JSON 확장

```json

  "inference_p95_ms": 61.8,
  "inference_max_ms": 87.2

```

### 5. `scripts/quantize.py` — static INT8 양자화

```sh
python scripts/quantize.py --model yolo11n-pose-416.onnx --calib-dir samples/
```

- `quant_pre_process()` → shape inference 선행
- `YoloCalibReader`: C 코드의 `letterbox_to_nchw()`와 동일한 전처리(114 패딩, 중앙 정렬, /255.0, NCHW)
- **Haswell 기대치: 1.5~2.5×** (VNNI 없음. 일부 문서의 "2~4×"는 Cascade Lake+ 기준)

### 6. `scripts/bench.ps1` + `bench.sh`

FP32/INT8 모델을 같은 입력 영상으로 돌려 추론 시간·p95·CPU ms/frame 비교표 출력.

### 7. `docs/quantization.md`

## feature/anomaly-rules

`feature/pose-model`을 main에 머지한 뒤 분기.

### 1. 공유 그레이 버퍼 — `src/gray.c`

**파일:** `include/gray.h`, `src/gray.c`

BT.601 luma `(77R+150G+29B+128)>>8`, 1/4 다운샘플 포인트 샘플링. camera_health와 모션 게이트가 프레임당 한 번 계산한 같은 버퍼를 재사용한다.

```c
void gray_buf_update(GrayBuf *g, const uint8_t *rgb, int width, int height, int stride);
```

### 2. 구조화 이벤트 로그 — `src/log.c`

**파일:** `include/log.h`, `src/log.c`

```
2026-08-29T14:03:11 WARN   rules        overstay track=7 dwell=4821s limit=3600s
2026-08-29T14:03:11 INFO   camera       whiteout recovered
```

ISO 8601 타임스탬프, INFO/WARN/ERROR, 모듈 태그, key=value 근거 필드.
`--event-log PATH` 미지정 시 stderr 출력.

### 3. 매장별 설정 파서 — `src/config.c`

**파일:** `include/config.h`, `src/config.c`, `config/store.example.ini`

외부 라이브러리 없이 직접 구현한 `key = value` 파서. `#` 주석, 공백 트림 지원.

```ini
dwell_limit_seconds     = 3600
unordered_grace_seconds = 300
fall_hold_seconds       = 5.0
motion_ratio_threshold  = 0.004
idle_refresh_seconds    = 10.0
luma_white_threshold    = 240
luma_black_threshold    = 12
frozen_frames_threshold = 150
roi_kiosk               = 820,120,300,420
```

`config_long()` / `config_float()`: 범위 체크 실패 시 기본값 반환.

### 4. 카메라 장애 감지 — `src/camera_health.c`

**파일:** `include/camera_health.h`, `src/camera_health.c`

그레이 버퍼만 입력. 모델 불필요.

| 증상 | 판정 | 이벤트 |
|------|------|--------|
| 백화 | 평균 luma > 240 히스테리시스 5프레임 | `camera_whiteout` |
| 암전 | 평균 luma < 12 히스테리시스 5프레임 | `camera_blackout` |
| 프리즈 | 변화 픽셀 비율 ≈ 0 히스테리시스 150프레임 | `camera_frozen` |

상태 진입·복구 양쪽 모두 이벤트 로그 기록 (CLAUDE.md 요구 사항).

### 5. 안정적 트랙 ID — `src/tracks.c`

**파일:** `include/tracks.h`, `src/tracks.c`

IoU 그리디 매칭(IoU > 0.3)으로 프레임 간 같은 사람에게 같은 ID를 유지한다. 기존 `LightTracker`는 박스를 이동시키지만 ID가 없어 체류 시간 누적이 불가능했다.

- 매칭 성공: `dwell_seconds` 누적, `last_seen` 갱신
- 매칭 실패: `misses++` → `max_misses` 초과 시 트랙 제거
- 새 detection: 새 트랙 생성 (`next_id++`)
- `tracks_mark_ordered(track_id)`: 결제 이벤트 연동 예정 지점

### 6. 룰 엔진 — `src/rules.c`

**파일:** `include/rules.h`, `src/rules.c`

각 이벤트는 **트랙당 1회만 발화(latch)**, 조건 해소 시 해제.

| 룰 | 판정 | 이벤트 |
|-----|------|--------|
| 초과 체류 | `dwell > dwell_limit_seconds` | `overstay` |
| 미주문 착석 | UNORDERED + `dwell > unordered_grace_seconds` | `unordered_seated` |
| 쓰러짐 | bbox 가로>세로×1.2 + keypoint y 분산 ≤ bbox 높이×0.25, `fall_hold_seconds` 지속 | `person_fallen` |

쓰러짐 판정: keypoint가 없으면 bbox 비율만으로 판단. score < 0.4 관절은 제외하고 계산.

### 7. `src/main.c` 통합

`process_frame()` 실행 순서:

```
1. gray_buf_update (prev ↔ curr swap)
2. camera_health_update → 이상 시 event_log_write
3. 모션 게이트:
   변화 픽셀 비율 < motion_ratio_threshold (0.004)
   && (now - last_detection_time) < idle_refresh_seconds (10s)
   → run_detector = 0, kind = "gated"
4. detect_every / tracker adaptive 로직 (기존)
5. 추론 프레임: tracks_update → rules_evaluate
```

신규 CLI:
- `--config PATH` — 매장별 설정 파일
- `--event-log PATH` — 이벤트 로그 파일 (기본: stderr)
- `--motion-gate 0|1` — 모션 게이트 활성화 (기본: 1)

metrics JSON에 `gated_frames`, `event_count`, `motion_gate` 추가.

### 8. `docs/anomaly-rules.md`

구현된 룰 목록, 설정 키 설명, 이벤트 로그 형식, 모션 게이트 동작 원리, 향후 결제 연동 지점 문서.
