# 타 구현체 비교 분석

> 동일 목적(무인 카페 CV 관리)으로 개발된 타 팀 리포지토리와의 구조·기능 비교.
> 참고 목적이며, 이 프로젝트에 도입 여부는 별도 검토 필요.

---

## 타 프로젝트 개요

- **언어**: Python 3.x (운영) + 순수 C 포팅 (배포)
- **구조명**: "하이브리드 캐스케이드" — 전체 화면 경량 추적 + 소수 크롭 정밀 분석
- **영상 입력**: OpenCV (웹캠 / RTSP IP카메라 / 파일)
- **추론 엔진**: ultralytics (Python판), ONNX Runtime C API (C판)
- **배포 대상**: Intel i5-4200U급, GPU 없음, 24시간 연속 가동

---

## 핵심 구조 차이

### 1. 감지 모델 — 가장 큰 차이

| | 이 프로젝트 | 타 프로젝트 |
|---|---|---|
| 모델 | YOLO11n (detection) | **YOLO11n-pose** |
| 출력 | 바운딩 박스 + 신뢰도 | 바운딩 박스 + **17개 관절 좌표 (COCO keypoints)** |

포즈 모델 하나로 추가 모델 없이 아래가 가능해진다:

| 감지 항목 | 판단 방법 |
|---|---|
| 쓰러짐 | `aspect_ratio >= 1.4` OR 코-엉덩이 y좌표 차 / BBox 높이 `< 0.15` |
| 손 들기 | `wrist.y < shoulder.y` |
| 키오스크 근접 | `face_width / frame_width >= 0.13` |
| 상체 수평 | 어깨-엉덩이 y차 < x차 |

이 프로젝트는 동일한 기능을 위해 별도 포즈 추정 모델을 추가해야 한다.

---

### 2. 추적 방식

| | 이 프로젝트 | 타 프로젝트 |
|---|---|---|
| 알고리즘 | SAD 패치 추적 | **ByteTrack** |
| 목적 | YOLO 호출 사이 박스 위치 보정 | 고유 ID 부여 + 수 분간 동일인 식별 |
| Re-ID | 없음 | HSV 색상 + 신체 비율 시그니처 |
| 재입장 복원 | 없음 | 소실 갤러리 기반 복원 |
| 가려짐 대응 | 없음 | `track_max_misses=30` 프레임 유지 |

SAD 패치 추적은 CPU 절감 목적의 최적화이고, ByteTrack은 "이 사람이 누구인지"를 시간 축으로 추적하는 것으로 목적이 다르다. 체류 시간·미주문·인원 카운트 등 모든 행동 기반 룰은 ByteTrack 수준의 Re-ID가 전제 조건이다.

**ByteTrack Re-ID 구현 방식 (타 프로젝트)**
- 상의(BBox 20~50%) / 하의(50~80%) 구간 HSV 평균값 추출
- 어깨너비 / 상체길이, 다리 / 상체 비율 저장
- EMA(α=0.3)로 시그니처 갱신 → 조명 변화 완충
- Hue 순환 거리로 유사도 계산
- 딥러닝 불필요, 스칼라 6개만 저장

---

### 3. 파이프라인 구조

**이 프로젝트**
```
프레임 → YOLO 전체 추론 → NMS → 박스 그리기 → 저장
```

**타 프로젝트 (캐스케이드)**
```
프레임
  └─ Stage 1: YOLO11n-pose 전체 추론 + ByteTrack (416px)
       └─ Stage 2: 트리거 조건 선별 → 상위 3명 크롭 (zero-copy numpy 뷰)
            └─ Stage 3: MediaPipe 33pt 포즈 + 6pt 얼굴 정밀 분석 (256px 크롭만)
                 └─ Stage 4: 상태 머신(FSM) → 이벤트 큐 → WebSocket 전송
```

핵심 아이디어: **전체 화면은 빠르게, 정밀 분석은 소수 크롭에만** 투입한다.
`max_precision_targets=3`으로 상위 3명만 Stage 3에 진입시켜 CPU 부담을 고정한다.

---

### 4. 상태 관리 및 이벤트

타 프로젝트는 인물별 FSM(유한 상태 머신)과 이벤트 큐를 분리한다.

| 규칙 | 조건 | 이벤트 |
|---|---|---|
| 쓰러짐 | `torso_horizontal` 5프레임 연속 | `fall_alert` |
| 장기 체류 | 체류 >= 300초 AND 미결제 | `announce_dwell` |
| 키오스크 손 들기 | `kiosk_enter` AND `hand_raised` | `kiosk_assist` |

감지(Stage 1~3)와 판단(Stage 4)이 분리되어 있어 규칙이 늘어도 코드가 뒤엉기지 않는다.
이벤트는 `queue.Queue`를 통해 워커 스레드가 소비하며 WebSocket으로 JSON 전송.

---

### 5. 스레드 모델

| 스레드 | 역할 |
|---|---|
| Main | 캡처 + 추론 + 상태 업데이트 (순차) |
| EventWorker | 이벤트 큐 소비 |
| WebSocketSender | JSON 전송, 지수 백오프 재연결(1~30초) |
| ResourceMonitor | CPU/RAM 상시 감시, 피크 경고 |
| stdin watcher | 터미널 `q` 종료 수신 |

메인 추론 루프를 막지 않기 위해 I/O는 전부 별도 스레드로 분리한다.

## 이 프로젝트가 더 나은 부분

| 항목 | 근거 |
|---|---|
| **Python 없음** | 인터프리터 오버헤드 없음. 동일 하드웨어에서 순수 추론 성능 유리 |
| **FFmpeg 파이프라인** | OpenCV보다 포맷 호환성·인코딩 제어 정밀 |
| **메모리 제어** | GC·numpy 숨겨진 할당 없이 버퍼 완전 직접 관리 |
| **보안** | 외부 전송 구조 자체가 없음 (타 프로젝트는 WebSocket 전송 존재) |

## 참고·도입 검토 항목

### 즉시 반영 가능

- **쓰러짐 종횡비 임계값 1.4**: 타 프로젝트에서 실제 검증된 수치. 이 프로젝트 1단계 쓰러짐 감지에 그대로 적용 가능.

- **ByteTrack C 구현** (`c/src/tracker.c`): 체류·미주문 등 행동 기반 룰의 전제인 Re-ID 구현 시 참고. 칼만 필터 없는 경량 버전으로 i5-4200U에서 검증됨.

- **HSV Re-ID 방식**: 딥러닝 없이 스칼라 6개로 동일인을 식별하는 구조. 소규모 카페(10m 이내)에서 충분히 유효.

### 중기 도입 검토

- **YOLO11n → YOLO11n-pose 모델 교체**: 현재 `detector_ort.c`의 출력 파싱이 유연하게 설계되어 있어 포즈 출력 추가 파싱이 가능한 구조. 교체 시 추가 모델 없이 쓰러짐·제스처 감지 확보.

- **캐스케이드 구조 (전체 감지 → 크롭 정밀 분석)**: 정밀 기능(포즈, 얼굴)을 추가할 때 전체 프레임에 적용하면 CPU를 감당할 수 없음. 소수 크롭에만 투입하는 이 구조가 저사양 하드웨어의 유일한 현실적 방법.

- **FSM + 이벤트 큐 분리**: 행동 규칙이 10개 이상이 되면 감지 코드와 판단 코드를 섞는 현재 구조는 유지보수가 어려워짐. 상태 머신 도입 시점 검토 필요.

### 참고만 (구조 차이로 직접 적용 어려움)

- MediaPipe: Python 의존성 있음. C판에서는 동일 ONNX 모델 재추론으로 대체.
- WebSocket 전송: 이 프로젝트는 보안 정책상 외부 전송 불가. 전송이 필요하다면 별도 보안 검토 선행 필요.
