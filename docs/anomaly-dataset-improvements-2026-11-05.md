# AI-Hub 이상행동 데이터로 찾은 개선점과 측정 결과 (2026-11-05)

대상 데이터: AI-Hub 「실내(편의점, 매장) 사람 이상행동 데이터」(5,841클립, 1920x1080, 3fps, 60초). 이 문서는 데이터로 **무엇이 개선되었고 무엇이 안 되었는지**를, 측정하지 못한 것과 함께 적는다. 모든 수치는 `scripts/`의 도구로 재현된다.

## 결론

1. **전도(쓰러짐) 재현율을 설정과 룰 보강으로 약 2배로 올릴 수 있었다.** 현장 설정(`config.json`) 기준 21.0%(pool, 138장면) → 권고 프로파일 44.2%. 같은 평가에서 음성(전도가 없는 클립) 7시간에 오탐 0건. 지연 중앙값도 4.7초 → 2.7초.
2. **기존 문서의 원인 분석은 틀렸다.** 트랙 분리는 주원인이 아니라 두 번째 병목이다(아래 3절). 목표 "70% 이상"은 달성하지 못했고 근거도 없었다.
3. **새 룰 기능은 모두 기본 꺼짐이다.** 낮은 신뢰도 박스를 쓰러짐 근거로 쓰지 않는다는 기존 안전장치를 일부 푸는 변경이고, 이 데이터에는 의자에 앉은 사람이 거의 없어 **카페 환경의 오탐은 검증되지 않았다.** 켜기 전에 매장 영상으로 확인해야 한다.
4. **휠체어·보조기구 사용자에 대한 오탐은 박스 비율을 너무 낮추면(1.0) 생긴다.** 현장 비율(1.3)을 유지해야 한다.
5. **기물 파손은 단순 규칙으로 풀리지 않는다(no-go). 쓰레기 투기(유기)의 기존 룰은 이 데이터로 평가할 수 없다.** 폭행·흡연·방화·절도는 제품 감지 목록에 없어 구현하지 않았다.
6. 쓰러진 사람의 검출 점수 붕괴(중앙값 0.33)는 규칙으로 못 고친다. 그 부분은 모델(AI)의 몫이며 근거는 8절에 적었다.

## 1. 평가 프로토콜

- **분할**: 인덱스(`E:\hunik-anomaly\anomaly_index.csv`, `scripts/build_anomaly_index.py`)가 장면 키(상점·날짜·시:분)로 나눈다. 한 사건을 카메라 6대가 동시에 찍어서 클립 단위로 나누면 같은 사건이 양쪽에 들어간다. `dev` 1,306 / `pool` 3,858 / `test` 650(제공된 Validation) / 장면이 겹쳐 제외 27.
- **쓰임**: 진단·후보 선택은 `dev`만. `test`는 사전에 고정한 설정 3개를 **한 번** 측정. `pool`은 test를 본 뒤 후보를 새로 정해야 해서 따로 둔 **새 검증 세트**(설정 선택에 쓰이지 않았다). 진단·평가 스크립트는 test 분할을 거부하거나(진단) 명시 선택이 필요하다.
- **모델**: `models/yolo11n-pose-416x224.onnx`(16:9 카메라에서 현장이 자동 선택하는 모델), FP32 CPU. 기존 기준선은 정사각 `yolo11n-pose-416.onnx`였다.
- **정답**: 전도 구간 [start, end]. 구간 앞 1초~뒤 3초 안의 `person_fallen`이면 검출, 지연은 start로부터. 음성: 전도 외 클래스(08~14) 클립의 모든 `person_fallen`은 오탐.
- **영상 시간**: `--video-clock`으로 룰 시간을 프레임/fps로 계산, `--infer-cache`로 클립당 모델은 한 번만 실행.
- **한계**: 3fps 연출 촬영(배우 1~2명, 젊은 사람, 매장 7곳)이라 현장(약 15fps, 다양한 손님)과 다르다. 절대 수치를 현장 성능으로 옮기면 안 된다. 전체 클립 수가 많아 보여도 독립된 장면 수는 test 20, pool 138이다.

## 4. 시도한 후보와 결과

모두 config 키이며 기본값은 꺼짐(현재 동작). 구현은 `src/rules.c`의 `try_fall_handoff`, `fall_wide_step`, 설정은 `fall_handoff_seconds`, `fall_handoff_reach`, `fall_wide_ratio`, `fall_wide_min_score`. 단위 테스트 126개 통과(신규: 인계, 매칭 중 트랙 무시, 도달 배율, 넓은 박스 조건별 6가지).

**dev 격자 (전도 48장면 / 음성 210클립 3.5시간)**

| 설정 | 전도 | 음성 오탐 |
|---|---|---|
| 코드 기본값(1.8/2.2, 5초) | 11 (22.9%) | 0 |
| 설정만(비율 1.0, 3초) — `fall_hold_seconds`는 재현율을 바꾸지 않고 지연만 5.0→2.7초로 줄인다 | 13 (27.1%) | 0 |
| + 트랙 인계(3초) | 18 (37.5%) | 0 |
| + 넓은 박스 1.6 | 23 (47.9%) | 0 |
| + 넓은 박스 1.3 | 26 (54.2%) | 1 (0.29/h) |
| + 넓은 박스 1.15 | 27 (56.2%) | 2 (0.57/h) |

넓은 박스 비율을 낮출수록 재현율이 오르지만 쪼그려 앉기·물건 놓기 같은 웅크린 자세(박스 가로/세로 1.15~1.5)를 쓰러짐으로 오인했다. 1.6을 채택했다.

**test (사전에 고정한 3개 설정, 한 번)** — 전도 81클립(20장면), 음성 210클립(3.5시간)

| 설정 | 전도 | 장면 단위 | 지연 p50 | 음성 오탐 |
|---|---|---|---|---|
| A 코드 기본값 | 9/81 (11.1%) | 6/20 | 4.7초 | 0 |
| B 현장 설정(1.3/1.6, 5초) | 12/81 (14.8%) | 6/20 | 4.8초 | 0 |
| C dev 채택안(비율 1.0 + 인계 + 넓은 박스 1.6, 3초) | 35/81 (43.2%) | 11/20 | 2.7초 | **4 (1.14/h)** |

C의 오탐 4건: **교통약자(휠체어) 1건은 새 기능이 아니라 기존 경로**(`upright_to_horizontal`)로, 박스 비율 1.0 때문이다. 같은 클립이 B(1.3)에서는 오탐이 없었다. 파손(08) 3건은 넓은 박스 경로이고 한 매장(SMC)에서 났으며 그중 둘은 인계 거리가 493px로 **정상 발화 21건의 최대(378px)보다 멀었다.** dev에서 오탐 0이었던 설정이 test에서 4건 생긴 것은 dev 선택이 낙관적이었다는 신호다.

**pool (새 검증 세트)** — test를 본 뒤 후보 4개와 선택 규칙(음성 오탐 ≤0.3/h 중 재현율 최고)을 **결과를 보기 전에** 고정. 전도 138장면(장면당 1클립), 음성 420클립(7.0시간). 95% 구간은 Wilson.

| 후보 | 전도 | 95% 구간 | 지연 p50 | 음성 오탐 |
|---|---|---|---|---|
| P0 현장 설정(1.3/1.6, 5초) | 29/138 (21.0%) | 15.0~28.6% | 4.7초 | 0 |
| P1 비율 1.0 + 인계 + 넓은 박스 1.6 (= C) | 65/138 (47.1%) | 39.0~55.4% | 2.7초 | 1 (0.14/h) |
| P2 비율 1.3 + 인계 + 넓은 박스 1.6, 3초 | 60/138 (43.5%) | 35.5~51.8% | 2.7초 | 0 |
| P3 P2 + 인계 도달 배율 0.75 | 61/138 (44.2%) | 36.2~52.5% | 2.7초 | 0 |

- **사전 규칙대로면 P1이 선택된다. 그러나 권고는 P3이며 이것은 사전 규칙과 다른 선택이다.** 이유: test에서 P1(=C)이 휠체어 오탐을 냈다. test+pool 음성 10.5시간으로 합치면 P1은 5건(0.48/h), P2·P3은 pool 7시간 0건(95% 상한 약 0.43/h). P2·P3은 test를 측정하지 않았다(test는 소진).
- P2와 P3의 차이(1클립)는 구별되지 않는다. P3의 도달 배율은 test 오탐(먼 인계) 관찰에서 나온 것이고 pool에서는 막을 오탐이 없어 효과를 보이지 못했다. "재현율을 잃지 않았다"까지만 말할 수 있다.
- 한 번에 후보 4개를 보고 하나를 고르는 것이므로 P3의 pool 수치는 약간 낙관적이다.

**발화 경로(dev v4 + test C의 정상 발화 58건)**: 기존 경로 `upright_to_horizontal` 10건, 새 `upright_to_wide_box` 48건. 개선의 대부분은 넓은 박스 증거에서 왔다. 이는 곧 "낮은 신뢰도 박스를 근거로 쓰는" 부분이 개선의 핵심이자 카페에서 검증이 필요한 위험이라는 뜻이다.

## 5. 권고 프로파일 (켜기 전에 매장 영상 확인 필수)

```ini
fall_aspect_ratio_kp = 1.3        # 현장 값 유지. 1.0 은 휠체어를 쓰러짐으로 오인(test)
fall_aspect_ratio_nokp = 1.6
fall_hold_seconds = 3             # 재현율은 그대로, 지연 4.7초 → 2.7초
fall_handoff_seconds = 3          # 쓰러지며 끊긴 트랙의 직립 이력 승계
fall_handoff_reach = 0.75
fall_wide_ratio = 1.6             # 1.3 이하는 웅크림 오인(dev 오탐)
fall_wide_min_score = 0.25
```

- 기본값은 건드리지 않았다(`config.json`·코드 기본값 불변). 설명은 `config/store.example.ini`에 주석으로 있다.
- **3fps에서 `fall_hold_seconds`는 초 단위지만 샘플 수 조건(3샘플)이 같이 걸린다.** 현장 약 15fps에서의 동작은 측정하지 못했다.
- 쪼그려 앉기·바닥에 앉기·반려동물 곁에 앉기 같은 정상 행동의 오탐은 이 데이터로 검증할 수 없다. 켠 매장은 `person_fallen`의 `evidence=upright_to_wide_box` 이벤트를 따로 점검해야 한다.
- 인계가 일어나면 INFO `fall_handoff from=.. to=.. dist=.. gap=.. reach=..`가 남는다. dev 음성 3.5시간에서 92건(약 26건/시간, 인계 도달 배율 1.0·넓은 박스 1.15 설정 기준)이었으므로 로그가 늘 수 있다. 도달 배율을 줄이면 감소한다(미측정).

## 6. 하드 네거티브 (교통약자, 하드 네거티브 클래스)

- 교통약자(휠체어·목발·지팡이) dev 30클립, test 30클립에서 기존 룰·현장 설정은 오탐 0. 비율 1.0에서 test에 1건(위 4절).
- `person_unaccounted`(WARN)는 음성 210클립에서 77건(약 22건/시간)이고 **전부 `where=interior`**, 화면 가장자리 12% 이내 소실은 0건. 점수 중앙값 0.72, `door=unknown`(문 ROI 미설정). 사람이 화면 가운데에서 사라지는데 문으로 나간 건지 구분할 수 없는 설정 부족으로 보인다. 이 데이터에는 "진짜 소실"의 정답이 없어서 **튜닝 근거를 줄 수 없었고** 변경하지 않았다.

## 7. 새 이상행동 후보의 타당성

- **기물 파손(08): no-go.** dev에서 양성 42클립·음성 84클립으로, 손목 속도·프레임 차분 같은 단순 특징의 분리도를 쟀다(사전 기준: 정상 프레임 95% 스킵 시 클립 재현율 0.90 이상). 최고 특징(손목 속도)이 AUC 0.68, 클립 재현율 0.55로 기준에 크게 못 미친다. 단순 모션 규칙으로는 안 풀린다. (`scripts/measure_anomaly_filter_auc.py`)
- **쓰레기 투기(유기, 11): 기존 룰을 이 데이터로 평가할 수 없다.** 잔류물 룰은 "사람 없고 화면이 멈추면" 자동으로 기준 이미지를 잡는데, 유기 42클립에서 기준이 잡힌 클립이 **0개**, 음성 72클립에서 3개뿐이다. 클립에 빈 매장 구간이 없다. 기준을 대시보드에서 수동 캡처한 매장에서의 성능은 측정하지 못했다.
- **추론 호출 절감 근거: 미측정.** 이 데이터는 거의 모든 프레임에 사람이 있어 정적 장면에서의 모션 게이트 절감을 대표하지 못한다.
- 폭행·흡연·방화·절도: `CLAUDE.md`의 감지 대상 목록에 없어 구현하지 않았고 측정도 하지 않았다.

## 8. 규칙으로 안 되는 부분 (AI가 필요한 근거)

쓰러진 사람의 포즈 검출 점수가 무너진다(정답 구간 중앙값 0.33). 현재 포즈 모델은 서 있는 사람 위주로 학습돼 누운 자세에 약하다. 이 데이터는 전도 구간의 프레임별 17개 관절 정답을 제공하므로, 누운 자세에서 포즈 모델을 보강하는 것이 정석 해법이다. 프로젝트 원칙(AI 최소화)에 따라 이번에는 하지 않았고, 룰 보강이 이 한계의 일부(재현율 약 44%까지)만 우회한다는 점을 기록한다. 연출 배우 1~2명 데이터로 학습하면 과적합 위험이 크다.

## 9. 평가 도구에서 발견한 문제

- 데이터 디렉터리는 `--config` 파일이 있는 폴더라서 잔류물 기준·문 위치·보정 파일이 같은 설정을 쓰는 클립 간에 공유되어 **상태가 샌다.** 유기 평가에서 음성 클립이 이전 클립의 기준을 이어받아 `residue_unknown`이 클립당 20건 넘게 나왔고, 그 결과는 폐기했다. 전도 평가의 설정 폴더에는 `door_location.json`·`captures`·`config`만 있고 쓰러짐 판정은 이 파일들을 읽지 않으므로 전도 수치는 영향이 없다. 하네스는 이제 설정을 클립별 폴더로 복사해 상태를 격리한다(`--shared-config`로 끌 수 있다).
- exe가 비ASCII 경로(`원천데이터\...`)를 열지 못한다(`avformat_open_input: Invalid argument`). 이번에는 ASCII 디렉터리 정션으로 우회했다. 배포 환경에서도 같은 위험이 있으니 별도 수정이 필요하다.
- 평가 작업 폴더를 HDD(E:)에 두면 디스크가 포화해(231%) 처리량이 약 4분의 1이었다. NVMe로 옮기자 분당 약 75클립.
