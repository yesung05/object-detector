- **기준선 측정 완료 (Validation 162클립 전수)**:
  - `07.전도`: 재현율 **13.58% (11/81)**, 오탐 **0.00/h (0건)**, 지연 p50 **5.0초**.
  - `14.교통약자 (휠체어/목발/지팡이)`: `person_fallen` 오탐 **0.00/h (0건)**.

### 2) 전도 미감지 70건의 원인 규명
1. **3fps 저프레임 환경에서 트랙 끊김 (Track Fragmentation)**:
   - 사람이 쓰러질 때 1~2프레임 사이 큰 변위로 인해 트래커가 기존 트랙을 소실(`person_unaccounted`)시키고, 바닥의 쓰러진 사람을 신규 트랙으로 인식함.
   - 신규 트랙은 직립 이력(`upright_last=0`)이 없어 `rules.c:766`의 `fall_gate=4`에서 차단됨.
   - 실제로 미감지 70건 중 **42건에서 전도 시점에 `person_unaccounted (where=interior)`가 정확히 발화**되었음.
2. **2D 화각 종횡비 한계 (`is_horizontal_pose`)**:
   - 카메라 정면이나 뒤쪽(복도/통로 방향)으로 쓰러질 때 2D 화면상 박스는 세로가 더 김(`w < h`).
   - 현재 룰의 `w > h * ratio` (1.3~1.8) 조건에 걸려 수학적으로 통과 불가.
3. **상체 수평 판정 (`fall_torso_pose`)**:
   - 비스듬히 누웠을 때 어깨-골반 수평 거리 `dx > w * 0.15` 조건 미충족.

## 1단계: 순수 규칙 기반(Rule-based) 전도(쓰러짐) 재현율 개선

> **목표**: 새 AI 모델 학습 없이, 순수 C 코드 규칙 보정 및 파라미터 튜닝만으로 전도 재현율 **13.58% → 70% 이상** 달성 (오탐 0.00/h 유지).

### 1. 소실 트랙-바닥 트랙 연계 (Vanish-to-Floor Handoff)
- **위치**: `src/rules.c` (`rules_evaluate` 내 vanish 처리 및 fall 평가 부근)
- **원리**: 매장 내부(`where=interior`)에서 정상 직립하던 사람이 갑자기 사라지고(`person_unaccounted`), 해당 위치 반경 R(예: 100px) 내에 새로 발생한 트랙이 바닥에 머물러 있는 경우:
  - 기존 소실 트랙의 직립 이력(`upright_last`, `upright_samples`)을 신규 바닥 트랙의 `TrackRuleState`로 상속.
  - 신규 트랙의 `fall_gate=4` 차단을 해제하여 쓰러짐 카운트가 즉시 누적되도록 수정.

### 2. 카메라 시선 방향(원근) 전도 판정 보완
- **위치**: `src/rules.c:213` (`is_horizontal_pose`), `src/rules.c:500` (`fall_torso_pose`)
- **원리**: `w > h * ratio` 박스 종횡비 조건 외에 **키포인트 수직 압축율** 추가:
  - 서 있는 사람: 머리(Nose) y < 어깨(Shoulder) y < 골반(Hip) y < 발목(Ankle) y (확연한 계단식 수직 배열, `box_height`의 80% 이상 점유).
  - 카메라 정면으로 쓰러져 누운 사람: 머리와 골반의 y좌표 차이가 극도로 좁혀지거나 역전됨 (`abs(hip_y - nose_y) < box_height * 0.35`).
  - 이 경우 `w < h` (세로 박스)여도 수평 쓰러짐 상태(`horizontal = 1`)로 판정.

### 3. `dev` 세트 파라미터 그리드 서치
- **도구**: `scripts/eval_anomaly_dataset.py` (--config 옵션 사용)
- **조정 대상**:
  - `fall_aspect_ratio_kp`: 1.3 → 1.0 ~ 1.2
  - `fall_hold_seconds`: 5.0초 → 3.0초 ~ 4.0초 (3fps 영상에서는 5초가 15프레임이므로 현장 15fps 대비 너무 긴 hold를 요구함)
- **검증**: `test` 세트 162클립에서 재현율 상승폭 및 오탐 여부 최종 확인.

## 2단계: 1차 규칙 필터의 분리도(AUC) 측정 (폭행·흡연·유기 타당성 검증)

> **목표**: 2차 AI를 학습하기 전에, 가벼운 1차 규칙(모션/기하학)이 **평온한 정상 시간을 95% 이상 스킵**할 수 있는지 데이터로 증명 (Go/No-go 판정).

### 1. 폭행/싸움 (클래스 08/13, 721개 클립)
- **1차 룰 가설**:
  - 조건 1: 두 사람 트랙 간 중심 거리 < 80px 또는 BBox IoU > 0.
  - 조건 2: 두 사람 주변의 그레이스케일 프레임 차분(모션 에너지) 급증 (`diff_energy > threshold`).
  - 조건 3: 위 두 조건이 0.5초 이상 지속.
- **측정 방법**: 폭행 이벤트 구간(GT) vs 정상 보행 구간에서 클립별/프레임별 AUC 측정.
- **Go 기준**: 정상 프레임의 95% 이상을 스킵하면서 폭행 구간의 90% 이상을 트리거할 수 있는가?

### 2. 흡연 (클래스 10, 772개 클립)
- **1차 룰 가설**:
  - 조건 1: 손목(wrist) 키포인트와 코/입(nose) 키포인트의 2D 유클리드 거리 `< box_height * 0.15`.
  - 조건 2: 손이 입 근처에 머무는 지속 시간 `≥ 1.0초`.
- **측정 방법**: 흡연 772개 클립 vs 타 클래스 정상 보행 프레임의 AUC 측정.
- **한계 및 점검**: 하품, 전화 통화, 턱 괴기와의 겹침 비율 확인.

### 3. 유기/방치 (클래스 11, 722개 클립)
- **현 시스템 매핑**: 현재 `src/residue.c` (배경 차분 표면 감시) 룰.
- **문제점**: 현재 `residue_confirm_seconds` 기본값(60초)이 데이터셋의 유기 라벨 구간(중앙값 19프레임 = 6.3초)보다 훨씬 긺.
- **측정**: 확인 시간을 5~10초로 단축했을 때 정상 클립에서의 오탐 발생 빈도와 유기 감지 재현율 측정.

## 3단계: 의심 구간 핀포인트 2차 경량 AI 파이프라인 설계 및 학습

> **목표**: 1차 룰이 켜진 1~3초짜리 의심 윈도우에 대해서만 초경량 전용 AI를 호출하여 최종 판정 (저사양 CPU 상시 부하 0 유지).

```
[카메라 영상]
      │
      ▼
┌───────────────────────────────────────────────┐
│ 1단계: C 런타임 1차 규칙 필터 (비용 ~0ms)     │
│   - 폭행: 2인 초근접 + 모션 에너지 폭발      │
│   - 흡연: 손목-코/입 1초 이상 머무름         │
└───────────────────────────────────────────────┘
      │
      ├─ [정상 95% 이상] ──> AI 호출 없이 스킵 (CPU 절약)
      │
      ▼ [의심 구간 트리거]
┌───────────────────────────────────────────────┐
│ 2단계: 2차 전용 초경량 AI (< 15ms)           │
│   - 폭행: 키포인트 시계열 분류기 (1D-CNN/MLP) │
│   - 흡연: 손-얼굴 128x128 크롭 패치 분류기     │
└───────────────────────────────────────────────┘
      │
      ▼
[관리자 알림 및 Replay DB 저장]
```

### 1. 폭행 2차 AI (Keypoint-Sequence Classifier)
- **입력**: 트리거 전후 15프레임(약 5초) 동안 두 사람의 17개 관절 궤적 텐서 `[15, 2, 17, 2]`.
- **모델 크기**: 1D-CNN 또는 경량 GRU (가중치 파일 크기 < 100KB, ONNX Runtime CPU 추론 시간 < 2ms).
- **학습 데이터**: AI-Hub 폭행(721클립)의 이벤트 구간(양성) + 일반 대화/동행/물건 교환 구간(음성).

### 2. 흡연 2차 AI (Crop-patch 제스처/객체 분류기)
- **입력**: 손목이 코 근처로 올라간 시점의 손-얼굴 주변 128×128 RGB 크롭 패치.
- **모델 크기**: MobileNetV4-nano 또는 SqueezeNet (가중치 < 2MB, CPU 추론 시간 < 8ms).
- **출력**: 2-클래스 분류 `[smoking vs not_smoking(통화/하품/턱괴기)]`.
- **학습 데이터**: AI-Hub 흡연(772클립)의 손-얼굴 패치 크롭 + 타 클래스의 얼굴 손 터치 패치.

### 3. C 런타임 통합 구조
- `src/detector_ort.c`에 2차 분류용 경량 세션 로더 추가.
- 1차 규칙 상태 머신에서 플래그가 켜질 때만 프레임 큐의 크롭/키포인트를 전달하여 결과 수신.

## 정정 (2026-11-04)

이 계획서의 1단계 전제는 `docs/anomaly-dataset-benchmark-2026-10-25.md` 하단 "정정"에 적은 대로 수정이 필요하다.

- **목표 "재현율 70% 이상"은 근거가 없다.** dev 분할에서 설정만 바꿨을 때의 상한과 쓰러진 사람의 검출 점수 붕괴(점수 중앙값 0.33)를 볼 때 규칙만으로 그 수준에 도달한다고 볼 근거가 아직 없다. 목표는 실측 후 다시 정한다.
- **"1. 소실 트랙-바닥 트랙 연계"의 근거(트랙 분리가 주원인)는 데이터와 맞지 않는다.** 직립 이력 부재로 막힌 클립은 dev 48클립 중 3개다.
- **"3. 그리드 서치"는 현장 설정(비율 1.3/1.6, 16:9 현장 모델 416x224)을 기준선으로 삼아야 한다.** 기존 기준선은 코드 기본값과 정사각 모델로 측정됐다.
- 체크리스트 3번 "make test"는 이 환경에 `make`가 없어 CMake `test_core` 타깃으로 실행한다.
- **3단계(2차 AI)는 보류.** 폭행·흡연은 `CLAUDE.md`의 감지 대상 목록에 없고, 1차 규칙의 분리도(2단계) 측정 전에는 학습을 시작하지 않는다는 이 문서의 조건을 유지한다.
