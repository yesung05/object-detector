# 노트북 현장 로그 분석 (logs-3200u, 2026-11-06 ~ 11-09)

사용자의 노트북에서 약 80시간 실행한 로그(`logs\logs-3200u.zip`, 파일 이름 기준 3200U)를 읽기 전용으로 집계했다. 카메라는 USB 웹캠(`HD WEB CAMERA`, dshow, 1280x720@30), CPU provider, 스레드 3, `detect_every=5`, 입력 416x224.
이 로그에는 정답 라벨이 없고, 카페가 아닌 사무·가정 환경의 노트북 웹캠이라는 점을 감안해 읽어야 한다.

| 2 | 11-07 18:40 → 11-09 20:58 이후 | `Nov 7 18:32` = **0.1.0-alpha.8** (로깅 v2) | 로그를 복사할 때까지 실행 중(종료 요약 없음) |

## 로깅 v2의 현장 검증 (alpha.8 실행 51개 파일)
- 모든 파일에 `run_info` 1행(2.8KB)과 시간별 `summary` 이벤트가 있다. 파일 전환 훅이 현장에서 정상 동작했다(첫 파일 `segment=0` … 50번째까지).
- 설정 사본 71개 키, **PIN은 기록되지 않았다**(`access_pin` 없음 또는 `***`).
- 이벤트의 `mono`·`frame`은 프레임 안 이벤트 100%, 시작 이벤트만 NULL(첫 파일 83/100).
- 요약으로 한눈에 보이는 값: 비동기 추론 평균 36~46ms/회, 대기 프레임 시간당 295~3,434, 버린 결과 0, 처리 FPS 중앙값 15~20(저조도에서 웹캠이 15fps), 카메라 이상 비율 0~100%.
- 문제 두 가지를 찾아 고쳤다: 요약의 `cam_bad_pct` 가 100.1 까지 나옴(100 으로 제한), 그리고 아래 access 로그 폭주.

## 이 로그로 정한 새 기능
- **시스템 정보 기록**(사용자 요청): 시작 때 한 번 OS·CPU·코어·명령어 집합(AVX2 등)·메모리·전원/배터리·로그 드라이브 남은 공간을 `module=system` 이벤트와 `run_info.system` 에 남긴다. 이 로그에는 CPU 모델이 없어 "3200U"를 파일 이름으로만 알 수 있었던 것이 계기다. 호스트·사용자 이름은 수집하지 않는다.
- **대시보드 알림 관리를 켜짐/끔 2단계로**(사용자 요청): "켜짐(알림 X)"(그림자)·"출시 프로파일"·"알림 X 권장" 배지를 없애고, 그림자로 남은 알림도 켜짐으로 보고 점주 화면에 표시한다.

## 한계
- 한 대의 노트북, 연출 아닌 일상 사용, 정답 라벨 없음. "해소됨"은 오탐의 대용 지표다(사람이 다시 나타났다는 뜻이지 알림이 틀렸다는 확정이 아니다).
- 사람 소실 반복 억제의 효과(655→446)는 이 로그를 되돌려 본 시뮬레이션이며, 실제 동작은 단위 테스트로만 확인했다.
- i5-4200U와 직접 비교는 하지 못했다(이 기기의 CPU 모델 로그가 없다).
