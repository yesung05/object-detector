# 셀프 무인 카페 주문·체류 판정 시나리오

## 1. 문서 목적

이 문서는 키오스크 소프트웨어를 수정하지 않고 별도 실행하는 영상 분석 SW가 실제 **셀프 무인 카페**에서 주문·체류 상태를 어떻게 다뤄야 하는지 정리한다.

매장마다 너비, 테이블 위치, 기둥, 조명, 카메라 화각, 2층 유무가 다르다. 따라서 모든 매장에서 개인 단위의 주문 여부를 확정한다는 가정은 하지 않는다. 설치된 카메라가 실제로 제공하는 증거 수준에 따라 결과를 구분하고, 증거가 부족하면 점검 대상으로만 남긴다.

관련 데이터 모델과 주문·상품 증거 배정 규칙은 [order-group-verification-design.md](order-group-verification-design.md)를 따른다.

## 2. 공통 원칙

### 2.1 주문 상태는 세 단계로 표현한다

| 상태 | 의미 | 운영 동작 |
| --- | --- | --- |
| `CONFIRMED_ORDERED` | 인원·주문 수량·상품 증거가 충분히 일치 | 알림 제외 |
| `LIKELY_ORDERED` | 주문 또는 상품 증거는 있으나 연결이 불완전 | 알림 보류, 대시보드 표시 |
| `UNVERIFIED` | 해당 그룹/구역의 주문 근거가 부족 | 유예 시간 후 점검 후보 |

`UNVERIFIED`는 미주문 확정이 아니다. 카메라 사각지대, 테이크아웃, 상품 가림 등이 있는 매장에서 오탐을 줄이기 위한 상태다.

### 2.2 사람의 영구 ID를 전제하지 않는다

현재 사람 추적 ID는 같은 화각에서 연속적으로 보이는 동안만 유효하다. 사람이 기둥 뒤, 계단, 화장실, 다른 층 또는 화각 밖으로 나가면 재등장 때 새 ID가 될 수 있다.

따라서 다음 단위를 사용한다.

```text
person track     : 현재 화각에서의 짧은 관찰 단위
table/group      : 테이블 또는 가까이 머무는 익명 인원 집합
order credit     : 결제된 메뉴가 커버할 수 있는 인원 수
product evidence : 주문 뒤 새로 등장한 컵·트레이·용기 등의 관찰 증거
```

### 2.3 설치 범위 밖은 추정하지 않는다

2층에 카메라가 없으면 2층 인원과 주문을 정확히 연결할 수 없다. 1층 주문 정보가 있다는 이유만으로 2층 손님을 주문 완료 처리하지 않는다.

## 3. 설치 유형

### 유형 A: 키오스크·1층 좌석을 한 카메라가 함께 보는 소형 매장

```text
입구 ─ 키오스크 ─ 좌석/테이블
             └──── 단일 광각 카메라 ────┘
```

- 장점: 결제 전후, 그룹 이동, 테이블 착석, 컵/트레이 배치를 하나의 시간축에서 볼 수 있다.
- 가능: 테이블/그룹 단위의 높은 신뢰도 자동 배정.
- 한계: 기둥 뒤·화각 가장자리·군중 가림에서는 개인 ID가 바뀔 수 있다.

### 유형 B: 넓은 1층, 여러 카메라 또는 사각지대가 있는 매장

```text
카메라 1: 입구·키오스크       카메라 2: 좌석 A       카메라 3: 좌석 B
        [사각지대]                  [일부 중첩 또는 없음]
```

- 장점: 테이블별 인원과 상품 증거를 더 잘 볼 수 있다.
- 가능: 카메라별 테이블 점유·상품 증거, 전체 주문 수량과의 대조.
- 한계: 카메라 사이에 화각 중첩이 없으면 특정 결제자와 특정 테이블을 확정 연결할 수 없다.
- 운영: 카메라별 독립 그룹을 관리하고, 시간·수량·상품 증거가 충분할 때만 주문을 배정한다.

### 유형 C: 1층 키오스크 + 2층 좌석 매장

```text
1층: 입구, 키오스크, 일부 좌석
             ↓ 계단/엘리베이터 (사각지대 가능)
2층: 좌석
```

#### C-1. 2층에 카메라가 있는 경우

- 1층 주문 이벤트와 2층 테이블의 신규 컵/트레이·인원 변화를 시간 창으로 비교한다.
- 계단 구간을 보지 못하면 개인 연결은 불확실하지만, 그룹/테이블 단위의 주문 가능성은 계산할 수 있다.
- 동일 시간대에 여러 주문과 여러 2층 그룹이 생기면 자동 확정하지 않고 `LIKELY_ORDERED` 또는 `UNVERIFIED`로 둔다.

#### C-2. 2층에 카메라가 없는 경우

- 2층 사람의 주문 여부는 판정 범위에서 제외한다.
- 1층 카메라에서 사람이 계단으로 이동한 것은 `upper_floor_exit` 같은 통계 이벤트로만 기록한다.
- 1층의 주문 크레딧을 2층 손님에게 자동 배정하지 않는다.

### 유형 D: 카운터·키오스크만 보이고 좌석이 거의 보이지 않는 매장

- 가능: 키오스크 앞 대기 인원, 결제 시각 주변의 혼잡도, 주문 건수 통계.
- 불가능: 실제 착석 인원 및 주문된 사람이 어느 테이블에 있는지 판정.
- 운영: `unordered_seated` 기능을 끄고, 키오스크 운영/혼잡 분석만 사용한다.

## 4. 기본 시간 창

초기값은 설치 후 조정한다. 모든 시간은 카메라 장치와 주문 데이터 원본의 시간이 동기화되어 있다는 전제다.

| 항목 | 초기값 | 의미 |
| --- | ---: | --- |
| 그룹 형성 관찰 시간 | 15초 | 같은 테이블/근접 구역에 안정적으로 머물러야 그룹 생성 |
| 결제 후 상품 관찰 창 | 0~10분 | 컵·트레이·용기가 새로 나타나는지 확인 |
| 주문 크레딧 유효 시간 | 20분 | 미배정 주문을 다른 손님에게 뒤늦게 붙이지 않는 상한 |
| 일시 가림 유예 | 10초 | 같은 테이블에서 잠시 미검출된 사람/객체의 상태 유지 |
| 주문 확인 필요 유예 | 5~10분 | `UNVERIFIED`를 바로 알리지 않기 위한 대기 시간 |
| 테이블 비움 종료 시간 | 60초 | 테이블 그룹을 종료하고 다음 손님과 분리 |

## 5. 대표 시나리오

### S-01. 4명이 함께 방문하고 1명이 메뉴 4개를 결제

**환경**: 1층의 키오스크와 T-03 테이블이 화각에 보인다.

```text
14:00  T-03 또는 키오스크 주변에 4명 관찰
14:02  기존 주문 로그에서 menu_count=4, paid 이벤트 수신
14:04  T-03에 4명 착석, 신규 컵 4개 또는 트레이/용기 증거 관찰
```

**판정**

```text
T-03: observed_people=4, order_credits=4, new_product_evidence>=4
→ CONFIRMED_ORDERED
```

컵이 2개만 보이더라도 트레이 1개와 주문 수량·인원·시간 연결이 강하면 `LIKELY_ORDERED`로 둘 수 있다. 컵이 가려진 상황에서 무조건 미주문으로 바꾸면 안 된다.

### S-02. 1명 팀과 3명 팀이 있고, 3명 팀만 메뉴 3개를 결제

**환경**: T-01에 1명, T-03에 3명이 있다.

```text
14:00  T-01=1명, T-03=3명
14:02  menu_count=3 결제 이벤트 수신
14:05  T-03에서 신규 컵/용기 3개 관찰
14:05  T-01에는 신규 상품 증거 없음
```

**판정**

```text
T-03: cover=3 / people=3 / 신규 상품=3 → CONFIRMED_ORDERED
T-01: cover=0 / people=1 / 신규 상품=0 → UNVERIFIED
```

T-01은 주문 지연, 동행의 추가 구매, 화각 밖 수령 가능성이 있으므로 설정된 유예 시간이 지나기 전에는 알림을 보내지 않는다.

### S-03. 4명이 있지만 3명만 주문하고, 1명은 잠시 후 합류

```text
14:00  T-03=3명
14:02  menu_count=3 결제
14:04  T-03에 신규 상품 3개
14:10  네 번째 사람이 T-03에 합류
```

**판정**

- 최초 3명은 `CONFIRMED_ORDERED`다.
- 네 번째 사람이 합류한 시점부터 T-03의 인원은 4명, 주문 커버는 3명이다.
- 네 번째 사람을 기존 주문으로 소급 처리하지 않는다.
- 추가 상품·추가 주문이 없고 유예 시간이 지나면 T-03은 `REVIEW_REQUIRED` 또는 해당 추가 인원을 `UNVERIFIED`로 표시한다.

### S-04. 주문자가 혼자 키오스크에 가고, 일행은 테이블에 대기

```text
14:00  T-03=3명, 키오스크=1명
14:02  menu_count=4 결제
14:05  T-03에 신규 컵/트레이 4인분 증거
```

**판정**

키오스크의 결제자 track과 테이블의 사람을 직접 이어 붙일 수 없더라도, 시간·수량·상품 증거가 하나의 테이블에 명확하면 T-03을 `CONFIRMED_ORDERED`로 처리할 수 있다.

동시에 다른 테이블에도 같은 규모의 그룹이 있고 어느 쪽에도 상품 증거가 없다면 자동 배정하지 않는다.

### S-05. 여러 팀이 짧은 시간에 연속 결제

```text
14:00  T-01=2명, T-02=3명, T-03=1명
14:01  주문 A: menu_count=2
14:02  주문 B: menu_count=3
14:03  주문 C: menu_count=1
```

**판정 원칙**

- 주문 A/B/C를 결제 시간만으로 테이블에 배정하지 않는다.
- 각 테이블의 신규 상품 등장 시각·수량, 결제자 이동 관찰, 테이블 인원 일치를 점수화한다.
- `T-01=컵 2`, `T-02=컵 3`, `T-03=컵 1`처럼 근거가 명확하면 모두 확정한다.
- 근거가 뒤섞이면 각 주문은 미배정 크레딧으로 보관하고 대시보드 검토 대상으로 남긴다.

### S-06. 테이크아웃 주문

```text
14:02  menu_count=2 결제
14:04  결제자 또는 상품이 출입구 방향으로 이동
14:06  어떤 테이블에도 신규 상품/인원 변화 없음
```

주문 원본에 `takeout`, `dine_in` 필드가 있다면 이를 최우선으로 사용한다. 필드가 없다면 주문 크레딧을 테이블에 억지로 배정하지 않고 `unassigned_takeout_possible`로 종료한다.

### S-07. 컵이 보이지 않는 경우

**원인**: 트레이에 가려짐, 테이블이 화각 가장자리, 불투명 용기, 사람이 계속 들고 있음, 조명 반사.

**판정**

- 주문 수량과 테이블 인원이 일치해도 상품 증거가 없으면 기본 상태는 `LIKELY_ORDERED`다.
- 일정 시간 뒤에도 증거가 없다면 신뢰도를 낮추되, 카메라 가시성이 낮다고 판단된 테이블은 미주문 알림 대상에서 제외할 수 있어야 한다.
- 객체 검출 실패를 사람의 미주문으로 해석하지 않는다.

### S-08. 기존 컵 또는 쓰레기가 남아 있는 경우

```text
14:00  T-03 비어 있음, 컵 2개 남아 있음
14:05  새 2명 착석, menu_count=2 결제
14:08  컵 2개만 계속 보임
```

기존 컵 2개는 신규 주문의 증거가 아니다. 주문 직전 기준선과 객체의 위치·지속 시간을 비교해, 주문 이후 새로 등장하거나 이동·추가된 객체만 증거로 센다.

### S-09. 2층으로 이동하는 일행

```text
14:02  1층에서 menu_count=4 결제
14:04  네 명이 계단 방향으로 이동
14:06  2층 T-21에 네 명, 신규 상품 4개 관찰
```

- 계단과 2층 카메라가 있으면 높은 신뢰도로 T-21에 주문을 배정한다.
- 계단이 사각지대여도 같은 시간대에 유일한 4인 주문과 4인 테이블, 신규 상품 4개가 일치하면 `LIKELY_ORDERED` 또는 설치 정책상 `CONFIRMED_ORDERED`로 처리할 수 있다.
- 같은 시간대에 여러 팀이 계단을 이용하면 자동 확정하지 않는다.

### S-10. 2층 카메라가 없는 경우

```text
14:02  1층에서 4개 결제
14:04  여러 명이 2층 방향으로 이동
```

이후 2층은 관측 불가이므로 주문 크레딧을 2층의 특정 사람에게 배정하지 않는다. 1층 대시보드에는 “상층 이동, 확인 범위 밖”으로 표시한다.

## 6. 가시성 등급과 기능 제한

매장별로 설치 완료 시 카메라 범위를 평가해 등급을 지정한다.

| 등급 | 관측 범위 | 허용 기능 |
| --- | --- | --- |
| A | 키오스크, 모든 테이블, 상품 배치 지점이 충분히 보임 | 그룹별 자동 주문 확인·점검 후보 |
| B | 키오스크와 대부분의 테이블이 보이나 일부 사각지대 존재 | 높은 점수만 자동 확인, 나머지는 보류 |
| C | 키오스크 또는 일부 좌석만 보임 | 주문/혼잡 통계, 수동 검토 지원 |
| D | 좌석·상품 증거를 거의 볼 수 없음 | 미주문 체류 판정 비활성화 |

가시성 등급은 카메라 모델이 아니라 실제 설치 화면으로 평가한다. 화각을 바꾸거나 가구 배치를 변경하면 다시 평가한다.

## 7. 대시보드 운영 화면

대시보드는 단순 상태색만 보여서는 안 되며, 점주가 판정 근거를 확인할 수 있어야 한다.

- 매장 도면 또는 카메라별 화면에 테이블 ROI와 층을 표시한다.
- 테이블별 인원, 신규 컵/트레이 수, 주문 커버 수, 상태, 상태 유지 시간을 표시한다.
- 상태를 클릭하면 주문번호, 결제 시각, 근거 점수, 가시성 경고를 보여 준다.
- `UNVERIFIED`는 “주문 확인 필요”로 표시하고, 미주문 확정 표현은 사용하지 않는다.
- 점주는 주문을 특정 테이블에 수동 배정·해제할 수 있어야 한다.
- 카메라 화각 밖/2층 미설치 구역은 회색으로 표시해 판정 범위가 아님을 명확히 한다.

## 8. 현장 설치 체크리스트

### 필수 확인

- [ ] 키오스크 주문 데이터의 원본 위치와 읽기 권한을 확인했다.
- [ ] 주문 완료·취소·환불을 구분할 수 있다.
- [ ] 키오스크 장치와 카메라 장치의 시간이 동기화되어 있다.
- [ ] 테이블/좌석/계단/출입구 ROI를 설정했다.
- [ ] 카메라별 가시성 등급을 기록했다.
- [ ] 컵·트레이·용기가 실제 화면에서 충분한 크기와 빈도로 보인다.
- [ ] 2층 존재 여부와 카메라 설치 여부를 설정했다.
- [ ] 테이크아웃 주문의 처리 규칙을 정했다.

### 운영 전 검증

- [ ] 1인·2인·3인·4인 이상 방문 사례를 각각 재현했다.
- [ ] 서로 다른 팀이 같은 시간대에 연속 결제하는 사례를 검증했다.
- [ ] 주문자가 혼자 결제하고 일행은 테이블에 남는 사례를 검증했다.
- [ ] 기존 컵이 남은 테이블, 빈 트레이, 쓰레기통 인접 영역을 검증했다.
- [ ] 계단 이동과 2층/사각지대 이동을 검증했다.
- [ ] 오탐 알림이 발생했을 때 근거 화면과 로그로 원인을 확인할 수 있다.

## 9. 도입 순서

1. 카메라별 매장 구역과 가시성 등급을 대시보드에 등록한다.
2. 주문 데이터 어댑터를 읽기 전용으로 연결하고, 결제 시각·수량이 올바른지 로그로 검증한다.
3. 테이블 인원과 컵/트레이의 신규 등장만 기록한다. 이 단계에서는 자동 알림을 내지 않는다.
4. 실제 운영 영상과 주문 로그로 배정 점수를 검증한다.
5. `LIKELY_ORDERED`와 `UNVERIFIED`를 대시보드에만 표시한다.
6. 오탐률이 허용 범위 안일 때, 장기 `UNVERIFIED`를 점검 알림으로 전환한다.

## 10. 최종 운영 기준

이 SW가 말할 수 있는 것은 “주문과 상품 증거가 특정 테이블/그룹에 얼마나 잘 맞는가”다. 카메라가 보지 못한 구간에 대해 사람의 행동이나 주문 여부를 단정하지 않는다.

따라서 매장별 최종 정책은 아래 원칙을 지킨다.

```text
충분한 증거 → 주문 확인
일부 증거   → 주문 가능성 표시, 알림 보류
증거 부족   → 주문 확인 필요, 수동 점검 대상
관측 불가   → 판정하지 않음
```
