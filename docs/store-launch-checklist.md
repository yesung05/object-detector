# 매장 설치·출시 체크리스트

목적: 처음 설치하는 매장에서 **무엇을 켜고, 무엇을 확인하고, 어떻게 켤지 판단하는지**를 한 장에 정리한다.
출시 프로파일: `config/store-launch.ini`. 근거 수치: `docs/anomaly-dataset-improvements-2026-11-05.md`, `docs/detection-status.md`.

> 현장 정답 데이터가 없다. 정밀도는 그림자 운영 데이터와 표본 검토로, 재현율은 아래 **연출 시험**으로만 잴 수 있다.
> i5-4200U 실기기 CPU·스로틀링은 아직 실측하지 못했다(개발 PC 기준 추정만 있음). 설치 후 24시간 확인이 필요하다.

## 1. 설치 직후 (30분)

| 확인 | 방법 | 통과 기준 |
|---|---|---|
| 실행 모델이 FP32 | 기동 로그 `[model]`, `[tier2]` 경로 | 파일명에 `int8` 없음(`run-all.ps1`은 FP32 우선, `run.bat`도 동일) |
| 스레드 | 실행 인자 `--threads 2` | i5-4200U 물리 코어 2개. 기본 실행 스크립트는 3으로 되어 있으니 매장 PC에서 확인 |
| 설정 적용 | 이벤트 로그 `startup` 의 `alert_modes shadow=… off=…` | `config/store-launch.ini` 의 모드와 같음 |
| 카메라 | 대시보드 화면, 로그 `camera state=ok` | 끊김·암전 없음 |
| 보호 모드 | 대시보드 상단 배너 | 켜짐(영상 대신 박스·관절만) |

## 2. 위치 설정 (설정용 임시 해제 후)

1. **문**: ROI와 기준 이미지(닫힌 상태, 열린 상태)를 잡는다. 안 잡으면 문 알림이 동작하지 않고 `door=unknown`이 된다.
2. **키오스크**: `roi_kiosk`를 설정한다. 안 하면 미주문 착석은 판정하지 않는다(로그 `roi_kiosk 미설정`).
3. **테이블**: 자동 탐색을 켜 두고 로그를 본다.
   - `table_mapping progress elapsed=… seen=… max_score=… threshold=… candidates=… best_hits=…/5` (60초마다)
   - 등록되면 `stable Tier 2 table locations registered automatically`.
   - 30분 넘게 없으면 `table_mapping_stalled` 경고와 원인 힌트가 나온다: 검출 없음 / 최고 점수가 기준 미만 / 위치 불안정. 이때는 수동으로 지정한다.
   - **이미 `table_confidence`가 0.55로 저장된 매장은 0.28로 바꿔야 한다**(0.55는 현장 점수 최대 0.40이라 한 번도 등록되지 않았다).
   - 등록된 영역이 선반·의자를 테이블로 잡지 않았는지 대시보드에서 확인하고 수정·잠금한다.
4. **잔류물**: 사람이 없을 때 기준 이미지를 캡처한다(자동 캡처 대기 또는 수동). 이 알림은 그림자라 기록만 남는다.
5. 안정화(보정) 10분은 매장이 비어 있을 때 한다. 실패하면 30분 뒤 사람이 없을 때 자동 재시도한다.

## 3. 연출 시험 (30분, 직원 1~2명) — 재현율을 재는 유일한 방법

각 항목을 정해진 위치에서 수행하고 시각과 결과(알림이 떴는지)를 아래 표에 적는다. `scenario-recorder`(`scripts/serve_scenario_recorder.js`)로 기록해도 된다.

| # | 상황 | 기대 알림 | 방법 | 결과 |
|---|---|---|---|---|
| 1 | 매트 위에서 쓰러짐 | `person_fallen` | 서 있다가 쓰러져 10초 유지, 3회(카메라 정면·측면·뒤) | |
| 2 | 앉았다 일어서기·줍기 | 알림 없음(오탐 확인) | 의자 앉기, 바닥 물건 줍기, 쪼그려 앉기 각 3회 | |
| 3 | 문 열어 두기 | `door_open` | 설정 시간 이상 개방 | |
| 4 | 병 반입 | `external_drink`(그림자) | 병을 들고 착석 | |
| 5 | 컵 없이 착석 | `no_cup_seated`(그림자) | 2명이 컵 없이 착석 | |
| 6 | 키오스크 거치지 않고 착석 | `unordered_seated` | 유예 시간 초과 | |

- 2번에서 `person_fallen`이 뜨면 즉시 기록한다. 쓰러짐 오탐은 신뢰에 직결된다.
- 결과를 `docs/`에 날짜와 함께 남기면 설치 후 알림별 재현율 근거가 된다.

## 4. 그림자 운영 (1~2주)

shadow 알림은 점주 피드에 안 뜨고 `logs/*.db`에 `mode=shadow`로 남는다. 사람이 일일이 검토하지 않아도 되도록 **자동 지표**로 판단한다.

```
python -I scripts/analyze_field_logs.py <로그 폴더>
python -I scripts/sample_events_for_review.py <로그 폴더>   # 알림 종류별 표본(주 10건 내외)
```

**대시보드로 하는 법**: 메인 화면의 알림 줄에서 "오탐"/"맞아요"를 누르면 이벤트 DB(`alert_feedback`)에 저장되고, 설정 > **알림 관리**에서 알림 종류별 건수·그림자 건수·정밀도(최근 7일)를 보고 켜짐/그림자/끔을 직접 바꿉니다(PIN 필요, 쓰러짐을 끌 때는 확인 창). 표본이 10건 미만이면 "표본 부족"으로만 표시하고, 정밀도 60% 미만이면 "그림자 권장", 그림자에서 80% 이상이면 "켜도 됨"을 **제안**합니다(자동 변경 없음). 같은 집계는 `python -I scripts/analyze_alert_quality.py <로그 폴더>`의 "점주 판단"·"정밀도" 열로도 나옵니다.

켤지 판단하는 기준(사전 고정):
- 그림자 **7일 이상** 운영.
- **무인 시간대(활성 사람 0)에 발화 0건.** 사람이 없는데 울리면 오탐이 확정이다.
- 하루 WARN 알림 합계가 매장이 감당할 수준(권고 상한 10건).
- 표본 검토 정밀도 ≥ 80%(쓰러짐은 오탐 주 1건 이하). 표본은 대시보드 리플레이 화면에서 `정상 감지 / 오탐 의심 / 판단 불가`로 표시.
- 통과한 알림만 `alert_<이벤트> = on`으로 바꾼다. 미달이면 shadow 유지 또는 off.

## 5. 문제가 생기면 볼 로그

| 증상 | 로그 / 위치 |
|---|---|
| 알림이 안 보임 | `alert_modes` 시작 로그(shadow·off 목록), 이벤트에 ` mode=shadow` 가 붙었는지 |
| 테이블이 안 잡힘 | `table_mapping progress` / `table_mapping_stalled` |
| 같은 사람이 오래 체류로 표시 | `track_reid_dwell_reset`(오래 떠났다 돌아온 트랙의 체류를 초기화한 횟수) |
| 카메라 끊김 | `camera state=…`, `restarts.log` |
| 프레임 끊김 | 성능 DB `*_perf.db` (CPU·추론 fps·온도 `-1`은 Windows 미지원) |

## 6. 알려진 한계

- 쓰러짐 재현율은 현장 설정 기준 약 21%(AI-Hub, 연출 3fps)다. 보강 기능을 켜면 약 44%까지 오르지만 카페(앉은 사람)의 오탐은 미검증이라 기본 꺼짐이다.
- 매장 판매 음료와 외부 음료를 구분하지 못한다(클래스 구조상).
- 휠체어·보조기구 사용자에서 `person_unaccounted`(그림자)가 발생할 수 있다.
