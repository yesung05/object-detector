# 표면 감시 v1 사용 및 개발 가이드

## 구현 범위

동일 detector 프로세스 안에서 `SurfaceMonitor`가 바닥·벽·테이블의 규칙 기반 변화 감시를 수행한다. 기존 사람 추적 결과와 물체 모델을 공유한다. 새 기능은 기본 비활성이며 실제 매장 영역과 청결 기준을 등록한 후 켠다.

- 바닥·벽: 승인된 기준에서 달라진 연결 영역의 지속성을 확인한다.
- 테이블: 이용 구역에 사람이 있으면 일반 알림을 보류한다. 전원 부재 유예 후 잔류 확인을 거쳐 알린다.
- 동물: 후보 crop의 기존 cat/dog 모델 결과와 상판 위치 관계를 반복 확인한다. 이용 중에도 동작한다.
- 일반 물체: AI가 확인하지 못해도 규칙 근거가 유지되면 종류 미확인 잔류물로 알릴 수 있다.
- 위생 위험 세부 분류: **미지원**. 현재 모델로 배설물·토사물을 확정하지 않는다. 해당 외형 변화는 일반 변화 후보로 잡힐 수 있지만 이용 중 위생 예외의 완전한 구현을 의미하지 않는다.
- 자동 설정: 아직 생성기는 없다. 공통 JSON 형식, source, locked, revision과 검증·적용 경계가 준비되어 있다.

새 모드 활성화 시 기존 residue/slot 청소 경로와 Tier 2 전역 객체 룰 호출을 대신한다. Tier 2는 표면 후보 검사에 사용하므로, 기존 화면 전체의 컵 수/외부 음식 룰과 병행 실행되지 않는다. 새 모드를 비활성화하면 기존 경로로 돌아간다. 사람·쓰러짐·문·카메라 관련 기존 경로는 유지된다.

## 시작 순서

메인 대시보드의 ‘지금 청소가 필요한가요?’ 카드에서 장소별 상태를 확인하고 ‘깨끗한 모습 등록’을 실행할 수 있다. ROI 편집은 ‘감시할 곳 설정’에서 한다. 영상 포트는 메인 카메라 연결 설정과 공유한다.

- 이상 없음: 기준이 등록되고 관측이 유효하며 사람·변화 후보·알림이 없는 상태. 쓰레기가 절대로 없다는 보장은 아니다.
- 청소 확인 필요: 지속된 변화로 청소 확인 알림이 발생한 상태. 쓰레기 종류를 확정한 것은 아니다.
- 사람이 사용 중이에요 / 확인 중 / 가려져서 안 보여요: 아직 청결 여부를 확정하지 않는 상태.
- 처음 설정이 필요해요 / 깨끗한 모습 기억 중: 최초 등록 안내와 자동 수집 진행 상태.
- 연결 끊김·영상 갱신 중단: 현재 상태를 알 수 없다고 표시하며 정상 카드로 유지하지 않는다.

재등록 및 기준 사진 링크는 카드의 ‘등록한 모습 보기 · 다시 등록’을 펼쳐 사용한다. 메인 등록 버튼도 확인 대화상자를 표시하고 저장 설정과 감지기 적용 버전이 일치하는지 확인한다.

1. 기존 방식으로 detector와 대시보드를 실행한다. 동물 검사에는 기존 Tier 2 모델이 필요하다.
2. 대시보드 상단 **표면 감시 설정** 링크 또는 `/surfaces`를 연다.
3. ‘영상 새로고침’으로 배경 영상을 가져온다. 영상이 안 보이면 고급 설정의 영상 포트가 detector의 `--stream-port`와 일치하는지 확인한다.
4. 영상 위의 ‘+ 테이블’, ‘+ 바닥’, ‘+ 벽’을 누르고 기존 방식으로 꼭짓점을 3개 이상 클릭한 뒤 ‘영역 확정’을 누른다. ID는 자동 생성된다.
5. 테이블은 ‘사람이 앉는 곳 추가’를 눌러 좌석/이용 구역의 꼭짓점도 지정하고 확정한다. 사람의 몸이 있는 곳을 포함하되 통로를 넓게 포함하지 않는다. 선택 영역의 경계는 ‘경계 다시 그리기’로 수정한다.
6. 고정된 컵·휴지통 등 기본 비치물은 하나씩 그리거나 이름을 등록하지 않아도 된다. 평소 배치를 다음 단계에서 정상 모습으로 함께 등록한다. 이동 허용·제외 영역이 필요할 때만 고급 그리기를 사용한다.
7. 활성화를 선택하고 ‘검증하고 저장’을 누른다. detector가 약 2초 주기로 변경을 적용한다.
8. 영역을 선택하고 평소 비치물은 그대로 둔 채 쓰레기·오염만 치운 다음 ‘이 영역의 정상 모습 등록’을 누른다. 가림 없는 5회 분석을 모으므로 실시간 감시 상태에서 완료를 확인한다. 저장되지 않은 변경이나 감지기 설정 적용 대기 중에는 등록을 막는다.
9. 물건이 움직여도 허용해야 한다면 고급 그리기의 비치물 영역과 이동 허용 영역을 별도로 지정한다. 물건 아래까지 비교하려면 선택 사항에서 빈 표면을 등록하고 원래 배치로 되돌린다. 고정된 기본 비치물 등록에는 이 과정이 필요 없다.
10. 기준 영상 보기와 실시간 후보/이용 상태를 확인한다. 작은 시험 물체로 거리별 검출 한계를 확인한다.

정상 모습 등록은 물건의 정체를 학습하는 기능이 아니라 현재 배치와 이후 영상의 차이를 비교하는 기능이다. 물건의 위치·모양이 바뀌면 변화로 감지될 수 있다. 정상 배치를 바꿨을 때는 청결을 확인한 후 기준을 다시 등록한다. 쓰레기까지 남긴 채 등록하면 그것도 정상 기준에 포함되므로 주의한다.

기준 없음, 가림, 검출 정보 만료, 큰 조명 변화, 구도 변화는 정상과 다르게 표시한다. 캡처 실패는 detector 로그에서도 확인할 수 있다.

## 설정·저장 위치

중복 AI 재검사 억제는 기본으로 켜져 있다. 동일 위치·모습의 성공한 검사 결과를 최대 60초 재사용하며, 동물 의심 재확인과 퇴석 후 확인은 유지한다. 비교 실험에서는 최상위 `ai_reuse`를 false로 저장해 기존 주기 검사와 비교할 수 있다. 설계·테스트 수치·논문용 실험 계획은 [중복 AI 재검사 억제 기록](2026-09-11-ai-reinspection-reduction.md)을 참고한다.

기존 `--config` 파일이 들어 있는 디렉터리를 데이터 루트로 사용한다. 일반적인 루트의 `config.json` 실행 구성에서는 다음 위치에 저장한다.

```text
config/surfaces.json                      활성 설정
config/surfaces.json.revision-N           이전 설정 사본
config/surface-ID-HASH-normal.bin         정상 배치 기준
config/surface-ID-HASH-empty.bin          빈 표면 기준
config/surface-*.bin.history-*            이전 기준 캡처
config/surface-ID-evidence-TIME-SERIAL.bin 알림 시점 영상
logs/...                                 이벤트 이력
```

표면 기준/근거 영상은 96×96 RGB 분석 버퍼다. 원본 해상도 증거 영상이 아니다. 근거 영상에는 시각·일련번호를 붙이며 이벤트 로그에 파일명을 연결한다. 현재 자동 보관 기한/용량 삭제 정책은 없으므로 로컬 디스크 사용량을 관리해야 한다.

설정 변경은 증가하는 revision을 요구한다. 이전 설정으로 돌아갈 때도 JSON의 revision을 현재보다 크게 지정한다. 재시작/설정 변경 시 런타임 확인 시간은 새 관측으로 시작하고, 기존 이벤트는 로그 이력으로 남는다.

최소 설정 예시:

```json
{
  "schema_version": 1,
  "revision": 1,
  "enabled": true,
  "camera_id": "camera-1",
  "geometry_revision": 1,
  "width": 1280,
  "height": 720,
  "source": "manual",
  "surfaces": [{
    "id": "table-1",
    "type": "table",
    "locked": true,
    "polygon": [[0.2, 0.3], [0.7, 0.3], [0.7, 0.7], [0.2, 0.7]],
    "usage_zones": [[[0.1, 0.1], [0.8, 0.1], [0.8, 0.3], [0.1, 0.3]]],
    "exclusions": [],
    "fixtures": [],
    "enter_seconds": 3,
    "departure_seconds": 45,
    "confirm_seconds": 15,
    "clear_seconds": 10,
    "threshold": 24,
    "min_area": 0.003
  }]
}
```

좌표는 좌상단 `(0,0)`, 우하단 `(1,1)`인 영상 비율이다. 위 좌표는 예시이며 실제 영상에 맞게 그려야 한다. 표면 16개, 다각형 꼭짓점 16개, 표면별 이용/제외 구역 각각 8개, 비치물 8개가 상한이다. 표면끼리 겹치는 분석 픽셀은 거부된다.

`source: "auto"`인 초안은 기존 `locked: true` 표면이나 카메라 구도를 변경할 수 없다. v1의 잠금 단위는 개별 필드가 아닌 표면 전체다. 자동 표면 생성기를 추가할 때 동일 스키마를 출력하면 된다.

## 판단·성능 기본값

| 항목 | 구현 기본값 |
|---|---|
| 상판·바닥 규칙 검사 | 2Hz |
| 벽 규칙 검사 | 0.5Hz |
| 사람 관측 확보 | 새 감시 활성 시 마지막 성공 추론으로부터 약 1초마다 실행 기회 확보 |
| 사람 관측 유효 시간 | 2초 |
| 이용 진입 확인 | 3초 |
| 퇴석 부재 확인 | 45초 |
| 퇴석 후 잔류 확인 | 15초, 최소 5회 후보 관측 |
| 바닥/벽 확인 | 20초 / 60초 |
| 해소 확인 | 10초 |
| 후보 AI 호출 상한 | 전체 초당 최대 1회, 처리 루프 안에서 직렬 실행 |
| 일반 후보 재검사 | 5초 간격 |
| 동물 후보 재검사 | 1초 간격, 연속 근거 2회 |
| 변화 없는 표면의 AI 점검 | 작업 여유가 있을 때 표면별 60초 이상 간격 |

모델 실행 시간이 길면 이 주기를 달성하지 못할 수 있다. 규칙/AI는 캡처 스레드와 별개인 기존 처리 흐름에서 동작하므로 처리 지연 자체를 제거하는 구조는 아니다. 작은 crop도 모델 입력 크기가 같으면 연산량은 비슷하다.

96×96은 각 표면의 경계 상자 안에서 샘플링한 분석 해상도다. 작은 원거리 오염·투명한 액체·같은 색 얼룩은 놓칠 수 있다. 더 높은 해상도의 후보 정밀 분석은 후속 최적화 대상이다.

비치물 이동은 허용 구역 내 제한적인 평행 이동 템플릿 비교다. 큰 회전, 형태 변화, 가림, 유사 물체는 배치 확인으로 유보한다. 자동 청결 기준 갱신은 없다.

## 인터페이스

대시보드 서버:

- `GET /surfaces`: 설정 UI.
- `GET /api/surfaces`: 설정 조회. 미설정 시 비활성 초안.
- `POST /api/surfaces`: 구조·영역·revision·자동 잠금 검증 후 원자 저장.

detector 영상 서버:

- `GET /surface/status`: 적용 revision·관측 상태·후보·분류 지원 상태.
- `POST /surface/capture?id=table-1&empty=0`: 처리 스레드에 기준 캡처 요청.
- `POST /surface/ack?id=table-1&candidate=0&revision=1&version=1`: 알림 확인 요청. 청결 판정과 별개.
- `GET /surface/reference?file=...`: 로컬 기준 또는 최근 근거 버퍼를 JPEG로 변환해 조회.

공개 C API는 `include/surface_monitor.h`에 있다. JSON 설정 파서는 기존 SQLite JSON 기능을 사용하며 외부 모델·FFmpeg 없이 테스트할 수 있다. HTTP 스레드는 모니터 메모리에 직접 접근하지 않고 명령·상태 사본을 교환한다.

## 검증 명령

```powershell
cmake --build build-windows --config Release --target test_surface test_surface_stream hunik-dashboard yolo11-person
ctest --test-dir build-windows -C Release -L unit --output-on-failure
node scripts/test_surface_http.js
node scripts/test_surface_stream.js
```

HTTP 테스트는 OS 임시 폴더와 별도 포트의 서버를 사용해 실제 매장 설정을 변경하지 않는다. UI 테스트는 DOM 대역을 사용한 이벤트/저장 흐름 검사이며, 실제 브라우저의 시각적 렌더링 검증과는 다르다. 현장 영상 정확도와 i5-4200U 장시간 성능은 별도 검증이 필요하다.
