# 구현 현황 (2026-08-30 기준)

## 시스템 목적

무인 카페 카메라 영상을 실시간으로 분석해 비정상 상황을 감지합니다.
영상과 감지 결과는 기기 내부에서만 처리되며, 외부로 전송되지 않습니다.

---

## 감지 대상 상황

| 구분 | 감지 항목 |
|------|-----------|
| 행동 | 시럽 과다 복용 / 구토, 실신·쓰러짐, 기물 파손 |
| 체류 | 주문 없이 착석, 1인 1메뉴 미구입, 초과 장기 체류 |
| 반입 | 외부 음식 반입·취식, 쓰레기 투기 |
| 접근 | 출입 제한 대상 진입(노키즈존 등), 반려동물 의자 착석 |
| 시설 | 출입문 열림 감지, 카메라 장애(가림·정지) |

---

## 이번에 구현하거나 개선한 것들

### 1. 필요할 때만 AI 분석 실행

AI 분석(YOLO 추론)은 비용이 큽니다. i5-4200U 기준으로 한 번 실행하는 데 60~120ms가 걸립니다.
화면에 아무 변화가 없거나, 변화가 사람과 무관한 위치에서만 생긴 경우에는 분석을 건너뜁니다.

**건너뛰는 조건 (4단계, 순서대로 확인)**

| 단계 | 조건 | 설명 |
|------|------|------|
| L0 | 운영시간 외 | `active_hours`로 지정한 시간 바깥이면 분석 없음 |
| L1 | 변화 없음 | 직전 AI 분석 이후 화면이 전혀 바뀌지 않았으면 건너뜀 |
| L2 | 무시 구역 내 변화만 있음 | 설정한 무시 구역(`ignore_roi`) 안에서만 변화가 생겼으면 건너뜀 |
| L3 | 기존 박스 안 변화만 있음 | 이미 추적 중인 사람 위치 내부에서만 변화가 생겼으면 건너뜀 |

L0~L2는 "완전 건너뜀"입니다. 움직임이 감지되어도 AI를 깨우지 않습니다.
L3는 "약한 건너뜀"입니다. 박스 밖에서 새로운 움직임이 감지되면 즉시 AI를 실행합니다.

---

### 2. 화면 변화를 빠르게 감지

화면 전체를 분석하는 대신, 밝기 정보만 추출해서 어느 구역에서 변화가 생겼는지 파악합니다.

- **밝기 정보 직접 사용**: 카메라는 원래 밝기(Y)와 색(UV)을 분리해서 보냅니다. 이전에는 색 정보까지 합쳐서 별도로 계산했는데, 이제는 카메라가 보낸 밝기 데이터를 그대로 씁니다. 계산 한 단계가 줄었습니다.
- **블록 단위 위치 파악**: 화면을 8×8 픽셀 블록으로 나눠서 어느 블록에서 변화가 생겼는지 기록합니다. 이 정보로 무시 구역 안/밖을 빠르게 판단합니다.
- **두 가지 기준으로 비교**: "직전 프레임과의 차이"(카메라 멈춤 감지용)와 "마지막 AI 분석 시점과의 차이"(새 물체 등장 감지용)를 한 번의 스캔으로 동시에 계산합니다.

---

### 3. 출입문 열림 감지

문이 열렸는지 닫혔는지를 기준 이미지와 비교해서 판단합니다.

- 대시보드에서 문 영역 사진을 찍어 기준으로 등록합니다.
- 등록된 기준과 현재 화면을 지속적으로 비교해 상태 변화를 감지합니다.
- AI 분석 없이 픽셀 비교만으로 동작하므로 부담이 거의 없습니다.
- 이전에 그림(박스 오버레이)이 그려진 후에 기준과 비교하는 버그가 있었습니다. 이제는 그리기 전에 비교합니다.

---

### 4. 카메라 이상 감지

| 이상 유형 | 감지 방법 |
|-----------|-----------|
| 화면 정지(freeze) | 현재 프레임과 직전 프레임이 거의 동일하면 감지 |
| 화면 가림 | 화면 전체가 비정상적으로 어둡거나 밝으면 감지 |

---

### 5. 실시간 대시보드

브라우저에서 `http://localhost:8080`으로 접속합니다.

**대시보드에서 할 수 있는 것들**

- 실시간 카메라 화면 확인 (MJPEG 스트림, `http://localhost:8081/stream`)
- 감지 설정 변경 및 저장
- 출입문 기준 이미지 등록
- 각종 임계값 조정

**이번에 고친 문제**: 설정 저장 시 대시보드가 모르는 항목까지 삭제되던 문제를 수정했습니다. 이제는 저장 시 기존 파일을 먼저 읽고 항목을 합쳐서 저장합니다.

---

### 6. 중간 프레임 추적

AI 분석을 매 프레임 실행하지 않기 때문에, 분석을 건너뛴 프레임에서도 사람 위치를 계속 파악해야 합니다.

- 분석을 건너뛴 프레임에서는 이전 위치에서 박스를 추적(이동 보정)합니다.
- 추적하던 사람이 박스 밖으로 빠져나가거나 추적에 실패하면, 다음 프레임에서 즉시 AI를 실행합니다.
- 이제 밝기 데이터를 직접 써서 추적 속도도 개선됐습니다.

---

### 7. 운영시간 설정

`active_hours = 07:00-23:00` 형태로 설정하면, 해당 시간 외에는 AI 분석을 완전히 멈춥니다.
자정을 넘기는 범위(예: `22:00-06:00`)도 지원합니다.

---

### 8. 무시 구역 설정

화면 내 특정 구역(예: 키오스크 화면, 창문)을 무시 구역으로 등록하면, 해당 구역 내에서만 변화가 생길 경우 AI 분석을 건너뜁니다.

설정 예시:
```
ignore_roi_1 = 820,120,300,420
ignore_roi_2 = 0,0,160,90
```
`x좌표, y좌표, 너비, 높이` 순서입니다.

---

### 9. 성능 지표 기록

`--metrics m.json`으로 실행하면 아래 항목을 JSON으로 기록합니다.

| 항목 | 설명 |
|------|------|
| AI 분석 지연시간 (p50/p95/p99) | 분석 한 번에 걸리는 시간 |
| 게이트 적중 횟수 | 단계별로 건너뛴 프레임 수 (L0~L3) |
| 화면 그리기 건수 | 실제로 박스 등을 그린 프레임 수 |
| CPU 사용률 | 전체 및 추론 전용 |
| 처리 FPS | 초당 처리 프레임 수 |

---

### 10. 오탐(잘못된 감지) 개선

i5-4200U 배포 대상 기기의 차순위 기기(Celeron J1900)에서 프로그램이 시작하자마자 종료되는 문제를 수정했습니다. AVX2 명령어가 없는 CPU에서도 정상 실행됩니다.

## 주요 설정 항목

| 설정 키 | 기본값 | 설명 |
|---------|--------|------|
| `detect_every` | 3 | N 프레임마다 AI 분석 실행 |
| `block_gate` | 1 | 변화 위치 기반 필터 활성화 여부 |
| `block_min_changed` | 2 | AI를 실행하려면 최소 몇 블록이 변해야 하는지 |
| `block_margin` | 1 | 박스 경계 여유 블록 수 |
| `track_refresh_seconds` | 2.0 | 추적기를 이 간격으로 강제 갱신 |
| `active_hours` | (미설정) | 운영시간 (예: `07:00-23:00`) |
| `ignore_roi_1` ~ `_N` | (미설정) | 무시 구역 좌표 |
| `confidence` | 0.25 | 감지 신뢰도 최소 기준 |
| `door_*` | (미설정) | 출입문 감지 관련 설정 |

## 아직 구현 안 된 것들

| 항목 | 내용 |
|------|------|
| 경로 검증 (긴급) | `--output`에 외부 URL을 넣으면 영상이 외부로 전송될 수 있음. 로컬 경로 여부 검증이 필요함 |
| 대시보드 보안 | 설정 저장 API가 외부 요청에도 응답함. 접근 제한 필요 |
| 주문 상태 3단계 | "확인 안 됨 → 추정됨 → 확인됨" 전환 로직 미구현 |
| ID 교체 버그 | 두 사람이 교차할 때 추적 ID가 뒤바뀌는 현상 |
| 쓰러짐 감지 개선 | 현재 박스 비율 기준, 몸통 방향 기반으로 개선 필요 |
| 저해상도 입력 지원 | 640×360으로 낮추면 처리 부담이 크게 줄어드나, ROI 좌표 변환 작업 필요 |
| 대시보드에서 무시 구역 그리기 | 현재는 설정 파일 직접 편집 필요 |
