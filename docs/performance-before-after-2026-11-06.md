### 1.6 후처리: 클래스별 NMS (C 변경, `postprocess.c`)

원래 NMS는 다른 클래스의 겹친 박스(의자+식탁, 동물+가구)를 서로 지웠다. 앱 경로를 재현한 평가(A0, v3 val 3,315장)에서:

| 클래스 (conf 0.20) | 재현율 전 → 후 | 정밀도 전 → 후 |
|---|---|---|
| dining table | 0.496 → **0.536** | 0.631 → 0.624 |
| dog | 0.646 → 0.664 | 0.754 → 0.726 |
| cat | 0.789 → 0.804 | 0.813 → 0.788 |
| chair·bottle·cup·food | 변화 ≤ 0.007 | 변화 ≤ 0.005 |

단위 테스트: `test_core` 117 통과/2 실패 → 119 통과/0 실패. 효과는 식탁·동물에 한정되고 **작다.** 파이썬 재현이라 C와 절대 수치가 다를 수 있다.

### 1.7 HomeObjects 데이터 추가(A1)의 효과

| 지표 | A0 | A1 | 차이 |
|---|---|---|---|
| v3 val mAP50 | 0.5081 | 0.5046 | −0.0035 |
| v3 val mAP50-95 | 0.3434 | 0.3434 | 0 |
| chair AP50 | 0.336 | 0.337 | +0.001 |

회귀는 없지만 이득도 없다(단일 학습 한 번씩이라 ±0.01은 구별 불가). **채택 근거 없음.** 반면 해상도·재학습(R416)은 실제 이득이 있다.

### 1.8 이 비교의 한계

- v3 val은 학습 중 모델 선택에 쓰인 세트라 낙관적이다(A0·R416 모두 동일 한계).
- **R416은 해상도와 함께 batch(128 → 64)도 바뀌었다.** 배치가 가중치 감쇠 스케일에 영향을 줘 두 요인이 섞여 있다. 각 모델 1회 학습이라 시드 분산도 모른다.
- 지연은 개발 PC. 기존 추정(`i5-4200u-pose-tier2-load-estimate.md`)상 4200U에서 Pose와 Tier 2가 직렬로 돌 때 이미 스톨이 있어, ×1.65 지연은 그 위에 얹힌다. 환산은 하지 않았다.

## 2. 쓰러짐 감지 룰 (AI-Hub 이상행동 데이터)

평가 세트: 장면 키(상점·날짜·시:분)로 분할해 카메라 6대 동시 촬영 누수를 막았다. `dev` 1,306 / `pool` 3,858 / `test` 650. 모델은 `yolo11n-pose-416x224`, FP32. 정답 구간 앞 1초~뒤 3초 안의 `person_fallen`이 검출, 전도 외 클립의 `person_fallen`은 오탐.

### 2.2 pool(새 검증 세트) 결과 — 전도 138장면, 음성 420클립 7.0시간

| 후보 | 재현율 | 95% 구간 | 지연 p50 | 음성 오탐 |
|---|---|---|---|---|
| P0 현장 설정 (**전**) | 29/138 = 21.0% | 15.0~28.6% | 4.7초 | 0 |
| P1 비율 1.0 + 인계 + 넓은 박스 | 65/138 = 47.1% | 39.0~55.4% | 2.7초 | 1 (0.14/h) |

| **P3 권고 (후)** P2 + 인계 도달 0.75 | **61/138 = 44.2%** | 36.2~52.5% | 2.7초 | **0** |

- **약 2.1배**(21.0 → 44.2%), 신뢰구간이 겹치지 않는다(15.0~28.6% vs 36.2~52.5%). 지연은 4.7 → 2.7초.
- **P3 선택은 사전 규칙과 다르다.** 사전 규칙(오탐 ≤ 0.3/h 중 재현율 최고)대로면 P1이다. test에서 P1이 휠체어 오탐을 냈기 때문에 P3을 권고한다. P2/P3의 1클립 차이는 구별되지 않는다.
- test 결과(사전 고정 3개 설정, 1회): 코드 기본값 11.1%, 현장 설정 14.8%, dev 채택안 43.2%(음성 오탐 4건, 1.14/h). **dev에서 오탐 0이던 설정이 test에서 4건** — dev 선택은 낙관적이었다.

### 2.4 한계

- 연출 촬영(배우 1~2명, 3fps, 매장 7곳). 독립 장면은 test 20, pool 138. 현장(약 15fps, 다양한 손님·**의자에 앉은 사람**)과 다르다.
- 개선의 대부분(발화 58건 중 48건)이 "낮은 신뢰도 박스" 증거에서 나온다. **카페의 쪼그려 앉기·바닥 착석 오탐은 미검증**이라 신규 룰은 기본 꺼짐이다.

| 등록 횟수(현장) | **0회**(점수가 기준에 못 미쳐 한 번도 등록 안 됨) | 현장 재측정 전 |
| 진행 가시성 | 없음(원인 파악 불가) | 60초마다 `table_mapping progress elapsed seen max_score threshold candidates best_hits`, 30분 정체 시 원인 힌트(검출 없음 / 점수 미달 / 위치 불안정) |
| 대시보드 표시 | — | `0.40 / 0.28 · 후보 1 · 120s` 숫자 |

**원인은 점수 임계값이 현장 최대값보다 높았던 것**이며, 0.28로 낮춘 효과(실제 등록 성공률·선반·의자 오등록 여부)는 **현장에서 측정되지 않았다.** 기존 설치 매장은 `config.json`의 `table_confidence`를 직접 바꿔야 한다. 테이블 이동 감지는 미구현.

## 7. 측정하지 못한 것 (우선순위순)

1. **i5-4200U 실기기**: CPU 점유율·서멀 스로틀링·Tier 2 416의 지연. 개발 PC(i7-8700) 수치는 환산 불가. 프로젝트 목표(CPU 점유율 1/4 감축)에 대한 달성도는 이번에 판단하지 못했다.
2. **현장 알림 재측정**: 래치·유령 트랙·미주문 수정과 새 프로파일 이후의 실제 알림량. 새 로그 7일 이상 필요.
3. **카페 환경의 쓰러짐 오탐**: AI-Hub에는 의자에 앉은 사람이 거의 없다.
4. **현장 15fps에서의 쓰러짐 룰 동작** (평가는 3fps).
5. **테이블 자동 등록 성공률**(0.28 이후)과 오등록.
6. Tier 2 **현장 라벨 평가 세트**(카페 프레임 직접 라벨링) — 현재 지표는 모두 COCO 계열(v3)·거실(HomeObjects).
7. 학습 반복(시드 분산)과 batch 효과 분리.

## 8. 결론과 다음 단계

- **효과가 입증된 것**: 쓰러짐 룰 보강(재현율 약 2배, 오탐 증가 없음 — 단 연출 데이터), Tier 2의 416 재학습(병·컵 재현율 +7~8%p, 식탁 박스 회복), 클래스별 NMS 버그 수정, 학습 파이프라인 속도(4~5배).
- **효과를 아직 모르는 것**: 알림 폭주 해소 정도, 테이블 자동 등록 개선, 대시보드의 사용성. 모두 새 현장 로그가 필요하다.
- **효과가 없었던 것**: HomeObjects 데이터 추가(A1).
- 권장 순서: ① 4200U 실기기에서 R416 지연·24시간 CPU/온도 실측 → 교체 여부 결정, ② 출시 프로파일로 그림자 운영 1~2주 → `analyze_alert_quality.py` 재실행, ③ 30분 연출 시험(재현율), ④ 통과한 알림만 on 전환.
