# 보호 화면 모양(privacy_style) 성능 비교 (2026-11-06)

`stream_privacy_style=1`(엣지 그레이)의 CPU 비용을 단색·가림 없음과 비교하고, 엣지 설정을 바꿀 때(블러 세기, 선 번짐·농도)의 전후 차이를 잰 기록이다. **개발 PC(i7-8700)에서 잰 값이며 배포 대상 i5-4200U 실측은 아니다.**

## 비교한 설정

| 이름 | 설정 | 설명 |
|---|---|---|
| off | `stream_privacy_mode=0` | 가림 없음(기준선) |
| solid | `stream_privacy_style=0` | 단색 채움 |
| edge_v1 | 블러 1, 번짐 0, 농도 100 | 처음 구현(선명한 흰 선) |
| edge_v2 | 블러 3, 번짐 0, 농도 100 | "덜 선명하게" 변경 전 |
| **edge_v3** | 블러 8, 번짐 1, 농도 70 | 변경 후(현재 기본값) |

엣지 설정은 `privacy_style_fps`(보는 사람이 있을 때 엣지를 다시 그리는 최대 횟수/초) **30**(거의 매 프레임: 최악)과 **5**(기본)를 각각 측정했다. 보는 사람이 없으면 1초에 한 번만 렌더한다(코드 `apply_privacy_mask`, `main.c`).

## 1. 렌더러 단독 시간 (`test_core`의 `test_privacy_style_speed_report`, 1280×720, 6회 중 최소)

| 설정 | ms/프레임 |
|---|---:|
| 블러 1, 번짐 0, 농도 100 (edge_v1) | 17.3 |
| 블러 3, 번짐 0, 농도 100 (edge_v2) | 19.5 |
| 블러 3, 번짐 1, 농도 70 | 22.2 |
| 블러 8, 번짐 0, 농도 100 | 35.7 |
| **블러 8, 번짐 1, 농도 70 (edge_v3, 기본값)** | **38.4** |

- 비용의 대부분은 엣지 전 가우시안 횟수(블러)다. 5탭 가우시안 한 번이 가로·세로 두 패스라 블러 3 → 8로 올리면 약 +16ms.
- 선 번짐 1회와 농도(알파 합성)는 합쳐서 약 +2.7ms(35.7 → 38.4, 블러 8 기준).

## 2. 실제 실행 중 비용 (같은 매장 클립 180프레임, 1920×1080, `--video-clock`, 출력 파일 인코딩 포함)

설정마다 3회 실행해 중앙값을 쓴다. 출력 인코딩이 들어간 값이라 **설정 간 차이만 의미 있다.**

| 설정 | fps | 처리 시간 | 프레임당 CPU(ms) | off 대비 CPU 증가 |
|---|---:|---:|---:|---:|
| off (가림 없음) | — | 8.40 s | 58.7 | 기준 |
| solid (단색) | — | 8.10 s | 57.3 | +0 (측정 오차 이내) |
| edge_v1, `privacy_style_fps=5` | 5 | 9.63 s | 63.7 | +5.0 |
| edge_v2, 5 | 5 | 9.79 s | 65.4 | +6.7 |
| **edge_v3, 5 (기본)** | 5 | **11.26 s** | **72.8** | **+14.2** |
| edge_v1, `privacy_style_fps=30` | 30 | 15.47 s | 96.6 | +37.9 |
| edge_v2, 30 | 30 | 16.65 s | 103.7 | +45.0 |
| edge_v3, 30 | 30 | 21.58 s | 130.6 | +71.9 |

(solid는 아래 "측정 정정"의 이유로 세 번째 실행에서 따로 다시 쟀다. 처리 시간(초)은 같은 입력을 영상 시간 모드로 처리한 벽시계 시간이다.)

### 해석
- **단색은 비용이 사실상 0**이다. 엣지 스타일은 보는 사람이 있을 때 기본값(5회/초)에서 프레임당 CPU가 약 +14ms(1080p) 늘고, 거의 매 프레임 그리면(30) +72ms까지 오른다.
- **"덜 선명하게" 변경 전후(edge_v2 → edge_v3)**: 블러를 3 → 8로 올린 것이 대부분의 비용이다(5회/초에서 +7.4ms/프레임). 선 번짐·농도 자체는 렌더러 단독으로 약 +2.7ms(720p)다.
- 보는 사람이 없으면 1초에 한 번만 그리므로 평소 상시 비용은 위 `fps=5` 값의 약 1/5 이하다(스냅샷용으로 캐시를 복사). 이 값은 따로 측정하지 않았다.
- i5-4200U는 코어당 성능이 낮아 몇 배 느릴 수 있다(**미측정**). CPU가 모자라면 `privacy_style_fps`를 낮추거나 `privacy_edge_blur`를 줄인다.

## 측정 정정과 한계

- **solid 값 정정**: 첫 두 번의 측정에서 solid가 off보다 약 +3초(+17ms/프레임) 느리고 edge_v1(5회/초)보다도 느리게 나왔다. 원인은 측정 스크립트가 설정 템플릿에 `stream_privacy_style`을 한 번 더 넣어 **같은 키가 두 번** 생겼고, 설정 파서가 앞의 값(엣지)을 써서 solid 측정이 실제로는 엣지 기본 설정으로 돌았기 때문이다. 템플릿에서 키를 빼고 solid만 다시 쟀다(`ONLY=solid`, 로그에 `privacy_style` 렌더 줄이 없음을 확인). 위 표의 solid는 정정값이다. 같은 이유로 edge 행은 영향이 없었다(키가 한 번만 들어갔다).
- 측정 중 다른 프로세스(대시보드 여러 개, 때때로 사용자의 detector)가 같은 PC에서 돌고 있었다. 같은 설정의 3회 값 편차는 대체로 ±0.5초 이내였고, 첫 번째 전체 측정(`runs/privacy-bench`)과 두 번째(`runs/privacy-bench2`)의 edge 행은 서로 ±1초 안이었다. 그래도 **작은 차이(±1~2ms/프레임)는 구별하지 못한다.**
- 입력은 1080p 한 클립(매장 연출 영상)이다. 해상도가 다르면 비용은 대략 화소 수에 비례한다.
- 정확도·화질은 이 문서의 범위가 아니다. 비식별 수준은 `docs/system-overview.md`의 보호 화면 절과 앞선 시각 비교를 따른다.

## 재현
```
bash scripts/bench_privacy_style.sh <detector exe> <클립> <출력 폴더> [REPS=3]      # 전체
ONLY=solid bash scripts/bench_privacy_style.sh <exe> <클립> <출력 폴더> 3          # 한 설정만
```
원시 결과: `runs/privacy-bench/results.tsv`(첫 측정, solid 오염), `runs/privacy-bench2/results.tsv`(둘째), `runs/privacy-bench3/results.tsv`(solid 정정). 렌더러 단독 시간은 `build\...\test_core.exe`의 `[info] privacy_style` 출력.
