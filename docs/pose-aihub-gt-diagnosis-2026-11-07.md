# 포즈 모델의 누운 사람 진단 (AI-Hub 관절 정답 기준, 2026-11-07)

> **데이터 출처**: AI-Hub 「실내(편의점, 매장) 사람 이상행동 데이터」(과학기술정보통신부·한국지능정보사회진흥원 「지능정보산업 인프라 조성」 사업의 결과물). 이 문서는 그 2차적 저작물이다. 이 데이터의 프레임(가공본 포함)은 AI 도구로 열지 않았다 — 라벨 XML 과 실행 파일이 낸 CSV 수치만 봤다.

## 요약
- 지금까지 이 데이터에서 쓴 라벨은 이벤트 시작·끝 프레임뿐이었다. 라벨 XML 에는 이벤트 구간의 **17관절 정답(Azure Kinect 골격) 37.5만 인-프레임**, 유기물·절도품·파손 도구 박스, 행위자 나이대가 더 있다.
- 그 관절 정답으로 배포 포즈 모델(`yolo11n-pose-416x224`, FP32)을 직접 재 보니, **쓰러진 사람에서 관절 정확도(PCK@0.1)가 0.46으로, 서 있는 사람(0.89~0.90)의 절반**이었다. 사람 점수 0.5 이상 비율도 0.66 대 0.99.
- 관절 점수는 위치가 틀려도 0.4 이상이 99%다. **룰의 "보이는 관절"(점수 ≥ 0.4) 조건은 쓰러진 사람에서 사실상 걸러 내지 못한다** — 틀린 관절로 몸통 각도를 판정하고 있다는 뜻이다.
- 쓰러짐 재현율 병목(저신뢰 20%, 몸통 자세 판정 불가 15%, `anomaly-dataset-improvements-2026-11-05.md`)의 원인이 포즈 모델이라는 해석을 직접 확인했다 → 포즈 파인튜닝(사전등록 `prereg_pose_aihub.md`)으로 진행.
- 노키즈존 탐색: 관절 비율로 어린이를 가르는 AUC 최고 0.60 → **중단**(사전 기준 0.8).

## 방법 (`scripts/diag_pose_gt.py`)
- dev 분할(학습·선택에 쓰지 않은 장면), 전도(07) 169클립, 대조군 폭행(13) 179·파손(08) 166클립.
- 배포 실행 파일을 매 프레임 추론(`--detect-every 1`, 추적·게이트 끔, `--confidence 0.1`)으로 돌려 검출·관절 CSV 를 받고, 라벨의 관절과 비교.
- 골격 매핑: 어깨·팔꿈치·엉덩이·무릎은 같은 관절, 손→손목, 발→발목(근사). 머리는 COCO 코와 위치가 달라 제외(평가 12관절).
- 정답 사람 박스 = 관절 외곽 + 15% 여백. 검출과 IoU ≥ 0.3 이면 매칭. PCK 기준 = 정답 박스 대각선의 10%.
- 자세 구분: 정답 박스 가로 > 세로 = horizontal(누움), 아니면 vertical.
- 좌우 규약: 서 있는 사람에서 그대로 0.89, 뒤집으면 0.40~0.44 → 라벨 좌우는 COCO 와 같은 "사람 기준"이다.

- 서 있는 사람이 숙여서 박스가 가로가 된 경우(13·08 가로)는 PCK 0.76~0.78 로 크게 떨어지지 않는다 → **박스 모양이 아니라 "누운 자세"가 원인**이다.
- 전도의 넘어지는 중·웅크린 프레임(07 세로)이 가장 나쁘다(0.36).
- 07 에서 좌우를 뒤집은 PCK(0.44)가 그대로(0.46)와 거의 같다 → 누운 사람의 관절은 좌우를 구분하지 못할 만큼 흐트러진다.

## 노키즈존 탐색 (`scripts/explore_child_pose.py`)
- 같은 실행 결과에서 이벤트 행위자의 `age group` 을 관절 정답 사람과 잇고, 서 있는 프레임의 배포 모델 관절로 비율 특징을 만들었다(행위자-클립당 중앙값).
- 364 행위자-클립(어린이 79, 독립 장면 25 / 어른 장면 77).

| 특징 | AUC(좋은 방향) | 어린이 중앙값 | 어른 중앙값 |
|---|---|---|---|
| 머리 크기 / 몸 높이 | **0.602** | 0.082 | 0.074 |
| 다리 / 몸통 | 0.570 | 1.358 | 1.381 |
| 어깨 너비 / 몸 높이 | 0.510 | 0.166 | 0.166 |

- 최고 0.60 < 사전 기준 0.8 → **이 방향(관절 비율 규칙)은 중단**. 연출 데이터의 "child" 가 어떤 나이 범위인지 라벨에 정의가 없고 장면 수가 작다는 한계도 있다. 얼굴 기반 나이 추정은 민감 정보 처리라 별도 정책 결정이 필요하다.
