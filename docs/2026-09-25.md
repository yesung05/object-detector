## 1부. 카메라 끊김 자동 재연결 (`src/media_ffmpeg.c`, `src/reconnect.c`)

### 문제 (기존 G: 코드)

- USB 카메라를 뽑으면 캡처 스레드만 조용히 끝나고, 처리 루프는 오류 플래그 없이 새 프레임을
  **영원히 기다림**. 프로세스가 안 죽으니 `run-all.ps1` 감시 루프도 동작하지 않고 로그도 없음.
- 디코딩 오류는 루프를 빠져나와 **exit 0** 으로 끝남 → 감시 루프가 "운영자 정지"로 보고 멈춤.
- 캡처 스레드가 5초 안에 안 멈춰도 버퍼를 강제로 해제 → 스레드가 해제된 메모리를 쓸 위험.
- 차단 모드 dshow 는 패킷이 없으면 무한 대기하고 interrupt 콜백도 안 봄 → 프레임만 멈춘 카메라는
  감지 불가, Ctrl+C 도 안 먹음.

### 변경

- 열기 후 `AVFMT_FLAG_NONBLOCK` (find_stream_info 이후에만 — 탐색 중 EAGAIN 은 sleep 없이 돌아 코어를 먹음).
- 캡처 스레드가 끝날 때 원인(`read`/`eof`/`decode`)을 기록하고 신호. 처리 스레드는
  "새 프레임이 `camera_stall_seconds`(5초) 동안 없음"으로 멈춤을 판정(첫 프레임 전에는 10초 유예).
- 끊기면 입력만 닫고 **1→2→4…30초 백오프**로 다시 엶. 이전 해상도로 고정해 열고, 해상도가 바뀌면 포기.
- `camera_reconnect_giveup_seconds`(300초) 동안 못 붙으면 **exit 3** → 감시 루프가 새 프로세스로
  장치를 다시 탐지(카메라 교체·이름 변경 대응).
- 재연결 후: 게이트·카메라헬스 기준 프레임 리셋, **트랙·쓰러짐 타이머를 끊긴 시간만큼 뒤로 미룸**
  (`tracks_shift_time`, `rules_shift_time`) — 그대로 두면 자리에 있던 손님 전원이 "미확인 소실"로 뜸.
- 캡처 스레드가 5초 안에 안 멈추면 아무것도 해제하지 않고 exit 3.
- 끊긴 동안 `/snapshot`·기준 저장은 503, `/door/state` 에 `camera_connected: 0`.
- 로그: `camera` 태그 `state=disconnected cause=…` / `reconnecting attempt=N` / `reconnected down=Ns` /
  `still_disconnected`(60초마다) / `give_up`. 종료 사유는 `shutdown` 태그.

### 종료 코드 규약

| 코드 | 의미 | `run-all.ps1` |
|---|---|---|
| 0 | 운영자 정지(Ctrl+C) · 파일 입력 완료 | 정지 |
| 10 | 예약 재시작 | 즉시 재시작 |
| 3 | 카메라 입력 비정상 종료 | 재시작(장치 재탐지) |
| 그 외 | 크래시·초기화 실패 | 백오프 재시작 |

`run-all.ps1`: 30초 안에 5번 연속 실패하면 **영구 정지하던 것을 300초 간격 재시도로** 변경
(부팅 때 카메라가 빠져 있어도 꽂으면 복구). `logs\restarts.log` 기록, `logs\STOP` 파일로 원격 정지.

## 2부. 카메라 입력 변환 비용 절감 (`src/media_ffmpeg.c`)

캡처 스레드가 **모든** 프레임을 720p RGB 로 변환했지만, 처리 스레드는 최신 프레임만 가져가므로
추론이 밀리면 버려질 프레임까지 `sws_scale` 을 하고 있었습니다.

- 삼중 버퍼의 각 칸을 RGB 대신 **디코더 프레임 참조**(`AVFrame`)로 바꿈. 덮어써지는 칸은 `av_frame_unref` 뿐.
- 변환은 처리 스레드가 **가져간 프레임에만** 수행.
- 디코더가 8비트 평면 YUV(MJPEG → yuvj422p 등)면 **luma(Y) 평면을 그대로 전달** → main.c 의
  RGB→그레이 재계산(`gray` 폴백, `full_luma` 변환)이 사라짐. YUY2 같은 packed 형식은 기존 폴백 유지.
- 종료 로그에 `captured=`(카메라가 보낸 프레임) / `processed=`(처리·변환한 프레임) / `convert=`(변환 시간) 추가.
  captured 대비 processed 가 작을수록 추론이 카메라를 못 따라가고 있다는 뜻.

## 3부. 카메라 대비 저하 판정 (`src/gray.c`, `src/camera_health.c`)

김서림·초점 상실·반투명 가림은 평균 밝기가 정상이라 기존 백화·암흑 판정에 걸리지 않았습니다.

- `gray_analyze` 같은 순회에서 가로 이웃 차이 합(`grad_sum`)을 계산(픽셀당 뺄셈 1회).
- **선명도 비율 = 평균 기울기 / 평균 밝기** 가 `camera_low_contrast_ratio`(0.045) 미만이
  `camera_low_contrast_hold_frames`(300, 15fps 기준 약 20초) 이어지면 `state=low_contrast`.

비율을 쓰는 이유(실내 사진 3장, 다운샘플 8 실측):

| 상태 | 절대 기울기 | 비율 |
|---|---|---|
| 정상 | 9.9 ~ 19.3 | 0.089 ~ 0.28 |
| 조명만 30%로 낮춤 | 3.0 ~ 5.8 | 0.09 ~ 0.29 (정상과 같음) |
| 김서림(흰 안개 70%) | 3.0 ~ 5.8 | 0.014 ~ 0.030 |
| 강한 흐림(σ=20) | 2.6 ~ 3.1 | 0.023 ~ 0.041 |

절대 기울기는 어두운 매장과 김서림을 구분하지 못합니다. hold 를 길게 둔 이유는 손님이 렌즈 앞에
서서 무늬 없는 옷만 보이는 순간도 같은 값을 내기 때문입니다.

**함께 고친 버그**: `luma_black_threshold`·`luma_white_threshold`·`frozen_frames_threshold` 가
hot-reload 에서만 적용되고, 첫 프레임의 `camera_health_init(NULL)` 이 기본값으로 덮어써 시작 시에는
무시되었습니다. 시작·reload 가 같은 함수(`apply_camera_health_config`)를 쓰게 했고, 키가 없을 때의
기본값도 두 경로가 달랐던 것(40/45 vs 12/150)을 `camera_health` 기본값 하나로 통일했습니다.

## 4부. 추적 품질 — 2단계 매칭 · 이동 예측 · 발밑 기준점 (`src/tracks.c`, `src/rules.c`)

### 2단계 매칭 (ByteTrack 방식)

사람이 반쯤 가리거나 자세가 바뀌면 신뢰도가 0.1~0.2 로 떨어져 트랙이 끊기고, 다시 보일 때 새 ID 가
붙어 체류·주문 상태가 처음부터 시작되었습니다.

- 검출기 하한을 `track_low_score`(0.10)로 낮추고, `--confidence`(기존 값)를 기준(keep_score)으로 유지.
- 추론 직후 기준 미만 박스를 `low_detections` 로 분리 → 그리기·로그·규칙·잔류물 등은 **예전과 같은 박스만** 봄.
- 1차에서 못 이어진 활성 트랙만 낮은 박스로 이음. **새 트랙·Re-ID 에는 절대 안 씀.**
- 낮은 박스로 이을 때 위치만 갱신하고 **score 는 직전 값 유지** — 쓰러짐·소실 판정이 score 로
  "흐릿한 탐지"를 거르므로, 쓰러져 신뢰도가 떨어진 사람의 판정이 꺼지면 안 됨.
- Tier 2 물체 감지는 원래 기준을 그대로 씀. `track_low_score=0` 이면 비활성.

### 이동 예측

- 트랙에 박스 중심 속도(px/s, EMA α=0.5, 상한 2000)를 두고 **예상 위치에서 IoU** 를 잼.
- 외삽은 최대 1초. 새 트랙·Re-ID 부활은 속도 0 에서 시작.
- 테스트: 400px/s 로 걷는 사람 — 예측 없이 IoU 0.11(끊김) → 예측 시 0.67(같은 ID 유지).

### 발밑 기준점

- `roi_anchor = foot` 이면 키오스크 ROI 판정에 박스 아래 가운데를 씀(기본 `center` — 기존 ROI 호환).
- 발밑을 쓰려면 ROI 를 **손님이 서는 바닥**에 다시 그려야 함.

### 이미 있어서 가져오지 않은 것

| 팀원 기능 | G: 현황 |
|---|---|
| 리소스 모니터 | `perf_log`(1분마다 CPU·온도·메모리·FPS) + `throttle`(적응형 감속) |
| 외형 재식별 | 상체 H·S 히스토그램 + 30분 limbo 복원 |

## 5부. 설치 직후 흔들림 구역 자동 학습 (`src/calib.c`)

선풍기·흔들리는 달력이 게이트를 계속 통과시켜 YOLO 를 깨우던 문제.

- 첫 실행 시 `calibration_minutes`(10분) 동안 0.5초 간격으로 블록별 변화 빈도를 누적.
- 사람 박스 주변 블록은 집계 제외, 화면 절반 이상이 동시에 변한 표본(조명·노출)은 통째로 버림.
- 30% 이상 변한 블록이 씨앗, 이어진 10% 이상 블록까지 한 구역(가장자리 흔들림 포함).
- **문·키오스크·감지된 테이블/의자 슬롯**과 겹치면 거부, 화면 15% 초과 구역도 거부(조명·TV).
- 결과는 `calibration.json`(config.json 과 분리 — 대시보드와 동시 쓰기 충돌 방지). 해상도가 바뀌면 재학습.
- 영상 파일 입력은 영상 시간 기준으로 진행해 녹화본으로 재현 가능.
- 합성 영상 실측(흔들리는 박스 1개): 재시작 후 추론 357회 → 1회, CPU 11.3초 → 2.7초.

### 3. 끊김·재연결 (웹캠 없이 재현 — 로컬 UDP 스트림)

카메라 경로(캡처 스레드)를 그대로 타도록 `--camera-format mpegts` 로 로컬 UDP 를 입력으로 씁니다.
영상은 127.0.0.1 밖으로 나가지 않습니다.

```bash
# 송신 6초 → 끊김 → 17초 뒤 10초 재송신
send() { ffmpeg -loglevel error -re -f lavfi -i testsrc=s=640x360:r=15 -t "$1" \
  -c:v libx264 -tune zerolatency -g 15 -pix_fmt yuv420p -f mpegts "udp://127.0.0.1:23000?pkt_size=1316"; }
send 6 &  sleep 1
yolo11-person.exe --model models --camera --camera-format mpegts \
  --camera-device "udp://127.0.0.1:23000" --camera-size 640x360 --provider cpu \
```

### 4. 실기기 (USB 웹캠)

1. 대시보드·검출기를 모두 끄고 `run-all.bat` 실행.
2. 웹캠 USB 를 뽑음 → 1초 안에 `state=disconnected cause=device_lost`, 이어서 `reconnecting` 로그.
   대시보드 `/door/state` 의 `camera_connected` 가 0, 스냅샷은 503.
3. 다시 꽂음 → `state=reconnected down=Ns`, 대시보드 영상 복귀. **(2026-09-25 사용자 확인 완료)**
4. 뽑은 채 300초 → `give_up` → exit 3 → `run-all.ps1` 이 재시작(`logs\restarts.log` 에 `reason=camera_lost`).
5. 끊긴 상태에서 Ctrl+C → 0.5초 안에 종료(exit 0), 감시 루프도 멈춤.

### 5. 쓰러짐 캡처

COCO 서 있는 사람 사진(`000000223959.jpg`)으로 "3초 서 있다가 누움" 영상을 만들어 확인합니다.
pose 모델은 처음부터 누워 있는 사진은 감지하지 못하므로(감지 0건), 서 있다가 사라질 때 회전 재탐지가
붙잡는 실제 상황을 흉내 냅니다.

```bash
ffmpeg -loop 1 -i 000000223959.jpg -f lavfi -i "color=c=0x707070:s=1280x720:r=30" -filter_complex \
 "[0]scale=-2:560[up];[0]transpose=2,scale=-2:420[lay];[1][up]overlay=x=(W-w)/2:y=(H-h)/2:enable='lt(t,3)'[a];[a][lay]overlay=x=(W-w)/2:y=(H-h)/2:enable='gte(t,3)':shortest=1" \
 -t 300 -r 30 -c:v libx264 -pix_fmt yuv420p fall.mp4
yolo11-person.exe --model models --input fall.mp4 --config <임시폴더>\config.json --motion-gate 0 --event-log <임시폴더>\ev.db
```

기대: `person_fallen track=N hold=5.0s` → `capture kind=person_fallen … privacy=masked file=…\captures\person_fallen_*.jpg`
(보호 모드에서는 회색 배경에 박스·관절만). 쓰러짐 판정 유지 시간은 벽시계 기준이라 영상은 충분히 길게(300초) 만듭니다.

### 6. 흔들림 학습

overlay 로 **움직이는** 박스를 만든 영상을 씁니다(drawbox 의 x 식은 이 빌드에서 매 프레임 갱신되지 않아
정지 영상이 됨 — 실제로 한 번 헛돌았음).

```bash
ffmpeg -f lavfi -i "color=c=0x606060:s=1280x720:r=30:d=90" -f lavfi -i "color=c=white:s=120x160:r=30:d=90" \
 -filter_complex "[0][1]overlay=x='100+40*sin(t*5)':y=100" -c:v libx264 -pix_fmt yuv420p swing.mp4
# config: {"calibration_minutes": 0.25, "calib_sample_seconds": 0.1}
```

1회차 로그: `calib region accepted rect=0,64,256,192` → `calibration.json` 생성.
2회차: `calib loaded … auto_ignore_roi=1`, 메트릭 `gate_l2_hits` 증가·`inference_runs` 급감.
문 ROI 안에 둔 두 번째 흔들림은 무시 구역이 되지 않아야 함. 해상도를 바꾸면 `불일치 — 다시 안정화`.

### 7. 대비 저하

`camera_low_contrast_hold_frames` 를 60 정도로 줄이고, 흐리게 만든 영상(`-vf gblur=sigma=20`)을
입력으로 → `camera state=low_contrast`. 원본 영상은 `state=ok` 유지. 조명만 낮춘 영상
(`lutrgb=r=val*0.3:g=val*0.3:b=val*0.3`)도 `ok` 여야 함.

### 8. 입력 변환 절감

카메라(또는 3번의 UDP) 입력으로 실행 후 종료 로그를 봅니다.

```
INFO  gray     source=luma_plane 그레이스케일 RGB 재계산 생략     ← MJPEG/H.264 등 평면 YUV 이면
INFO  shutdown exit=0 … captured=450 processed=300 convert=1.20s
```

`captured − processed` 만큼 RGB 변환을 건너뛴 것입니다. i5-4200U 처럼 추론이 느린 기기일수록 차이가 큽니다.
