## 가장 중요한 라벨 정의

- 현재 모델: cat, dog, bottle, cup, food, chair, dining table의 7클래스.
- 기존 food는 COCO의 banana/apple/sandwich/orange/broccoli/carrot/hot dog/pizza/donut/cake를 병합한 것이다. 종이·휴지·빈 식품 포장지는 food가 아니다.
- **사람이 없는 장면 ≠ 빈 라벨 이미지.** 의자나 컵이 있으면 표시해야 한다.
- **사무용 책상 ≠ dining table로 자동 통일할 수 없음.** 모든 책상/테이블을 감지하려는 목적이라면 클래스 의미와 기존 데이터 처리 정책을 먼저 정하고 별도 버전으로 관리해야 한다.
- 현재 앱의 16클래스 해석 오류는 데이터 증강으로 고칠 수 없다. 모델 자체 평가와 앱 표시/규칙 평가는 분리한다.

## 공개 데이터 후보

### 1순위: 기존 COCO 자료 재활용

`datasets/tier2/annotations/instances_train2017.json`과 `instances_val2017.json`이 존재한다. 기존 7클래스 정의와 정합성이 높아 출처를 새로 혼합하기 전 비교 기준으로 유지한다. 추가 후보를 고를 때 기존 tier2_v3의 train/val/test 이미지 ID와 해시를 확인해 평가용 이미지가 학습에 섞이지 않게 한다. 데이터가 같은 사진의 중복일 경우 보강으로 세지 않는다. 대상 주석이 없다는 이유만으로 이미지 내용 확인 없이 빈 라벨로 쓰지 않는다.

### 2순위: Open Images V7의 필요한 클래스 부분집합

공식 배포 페이지에서 이미지와 박스 주석을 받을 수 있다. 전체가 아닌 컵·병 등 클래스 후보를 좁혀 소량 검토하는 방향을 권장한다. 최종 매핑은 [공식 boxable 클래스 목록](https://storage.googleapis.com/openimages/v7/oidv7-class-descriptions-boxable.csv)과 클래스 계층을 읽고 확정한다. broad Food/Table을 기존 food/dining table과 무조건 동일시하지 않는다. [공식 다운로드](https://storage.googleapis.com/openimages/web/download_v7.html)

이미지에 모든 클래스가 완전하게 라벨링됐다고 가정하면 안 된다. 미표기 대상을 배경으로 학습하지 않도록 7개 대상 전체를 검수한다. group-of, depiction, 중복 부모/자식 박스 처리 정책도 필요하다. 공식 설명상 주석은 CC BY 4.0이며 이미지는 CC BY 2.0으로 기재되지만 개별 이미지 권리 확인을 요구한다. 수집 시 이미지 ID, 원본 URL, 저작자, 라이선스를 함께 보존한다. [공식 설명·라이선스](https://storage.googleapis.com/openimages/web/factsfigures_v7.html)

### 보류: Objects365

다양한 물체 자료 후보지만 공식 페이지가 academic purpose only를 명시한다. 이미지 재배포 금지 등 조건도 있어 일반적인 배포용 보강 데이터로 바로 채택하지 않는다. 현재 목적과 조건을 확인한 뒤 검토한다. [공식 배포 조건](https://www.objects365.org/download.html)

## 권장 첫 실험: 검수 가능한 소량부터

1. 먼저 기존 촬영물의 평가 사용 이력을 확인한다. 이 프로젝트의 여러 기존 평가에 사용된 영상이므로 전부를 새로운 독립 테스트라고 부르지 않는다.
2. 기존 영상에서 컵 등장/이동/가림/조명 변화 전후를 중심으로 **총 300~500장 후보**를 추출한다. 이는 목표 수량이며 아직 생성하지 않았다. 영상 타임스탬프와 원본 경로를 보존하고 중복 장면을 줄인다. 부분 녹화는 우선 제외한다.
3. 영상/촬영 세션 단위로 분리한다. 날짜 2개만으로 train/val/test 독립성을 확보했다고 주장하지 않는다. 별도 영상 그룹으로 검증하고 최종 현장 테스트는 새 촬영 날짜·시점으로 마련하는 것이 바람직하다. 동일 배경의 상관성도 한계로 기록한다.
4. 모델 예측은 박스 초안으로만 사용한다. 빠진 객체와 잘못된 클래스를 수정하고 대상 7종을 전부 검수한다. 모델이 검출한 프레임만 고르지 말고 미검출과 무작위 프레임도 섞는다.
5. 학습 이미지에만 약한 밝기/색 변화·흐림·압축 열화·작은 크기 변화 등을 적용한다. 기하 변환은 박스도 함께 변환하며 작은 컵이 소실될 정도의 변형은 피한다. 과도한 가림과 합성은 첫 실험에서 제외한다. 검증/테스트는 원본으로 유지한다. [Ultralytics 증강 문서](https://docs.ultralytics.com/guides/yolo-data-augmentation)
6. 기존 COCO 유지 → 현장 검수 이미지 혼합 → 약한 증강 추가를 단계별로 비교한다. 같은 검증 세트에서 클래스별 정밀도/재현율, 크기별 성능을 보고, 라벨된 영상에서는 분당 오탐을 측정한다. 반복 프레임의 같은 오탐을 사건 단위로 세는 규칙도 고정한다.

증강으로 이미지 수가 늘어도 독립적인 장면 수가 늘어난 것은 아니다. 현재 부족한 실제 병·음식·동물 장면은 컵 영상 증강만으로 대체하지 않는다. 사용자 영상은 외부 서비스에 업로드하지 않았다.
