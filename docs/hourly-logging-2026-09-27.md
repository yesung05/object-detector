# unmanned_detector 0.1.0-alpha.2 — 시간별 로그 저장

기존에도 이벤트와 좌표는 실행 중 SQLite에 커밋되었습니다. 종료 시 WAL 보조 파일이 DB에 합쳐지는 동작과 실제 저장 시점은 다릅니다.

## 변경 사항

- 실행 후 1시간마다 이벤트·좌표 DB와 성능 DB를 함께 새 파일로 전환합니다. 카메라·추적 상태는 유지합니다.
- 최초 파일: `20260927_090000.db`, `20260927_090000_perf.db`
- 다음 파일: `20260927_090000_part000001.db`, `20260927_090000_part000001_perf.db`
- 새 파일을 열지 못하면 기존 파일에 계속 기록하고 60초 후 재시도합니다.
- WAL + synchronous=FULL로 성공한 커밋마다 디스크 동기화를 요청합니다. 저장 장치에 따라 기록 지연이 늘 수 있으며 물리적 전원 장애까지 시험한 것은 아닙니다.
- 대시보드 로그 목록의 400개 제한과 고정 응답 버퍼를 제거했습니다.

## 적용 및 주의 사항

새 Alpha 2 설치 파일로 업데이트한 뒤 앱을 다시 실행해야 적용됩니다. 이번 작업 중 실행 중인 기존 감시 프로그램은 교체하지 않았습니다.

분할 시점은 실행 시간을 기준으로 하며, 1시간이 지난 뒤 다음 카메라 프레임 처리 시 전환합니다. 카메라 입력이 멈춰 있으면 다음 프레임까지 전환을 기다립니다. 실행기 콘솔 로그와 재시작 진단 텍스트 로그는 시간별 분할 대상이 아닙니다.

좌표는 평상시 10초 간격, 이벤트 주변은 최대 5Hz로 저장합니다. 저장 대상이 아닌 메모리 링 버퍼 전체를 강제 종료 시 복구하지는 못합니다. 시간 경계의 이벤트 이후 구간은 다음 파일에도 걸칠 수 있으며, 이벤트별 뷰어는 두 파일을 자동 병합하지 않습니다.

실행 중 DB를 옮길 때 `.db`만 복사하면 WAL에 저장된 최신 기록이 빠질 수 있습니다. 좌표 내보내기 도구나 SQLite 백업을 사용하세요. 1GiB 제한은 파일별 좌표 데이터 기준이며, 전체 디스크 자동 정리는 하지 않습니다.

## 검증

- Full Release 빌드 및 CTest 7개 통과.
- 1시간 경계 전후 전환, 별도 DB 연결에서 실행 중 저장 확인.
- 정상 종료를 생략한 자식 프로세스 강제 종료 후 이벤트 복구 확인.
- 좌표 링 버퍼·영역 설정 이관과 새 파일 열기 실패 시 기존 파일 기록 확인.
- 테스트 대시보드에서 시간별 로그 450개 목록이 유효한 JSON으로 조회됨을 확인.

설치 파일: `dist/unmanned_detector-Setup-0.1.0-alpha.2-x64.exe`
