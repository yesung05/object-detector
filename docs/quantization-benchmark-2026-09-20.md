# FP32/INT8 모델 성능 및 CPU 부하 벤치마크

측정일: 2026-09-20

## 결론

현재 개발 PC의 ONNX Runtime CPU EP에서는 `yolo11n-pose-416-int8.onnx`가 FP32 모델보다 작지만 빠르지 않았다.

- 모델 파일 크기: **72.05% 감소** (`11.156 MiB` → `3.119 MiB`)
- 순수 ONNX 추론 평균: INT8이 **83.03% 느림** (`23.659 ms` → `43.304 ms`)
- 추론 1회당 CPU 시간: INT8이 **49.28% 증가** (`43.125 ms` → `64.375 ms`)
- 실제 C 실행 경로의 추론 p50: INT8이 **73.65% 느림** (`26.613 ms` → `46.212 ms`)
- 실제 C 실행 경로의 프레임당 CPU 시간: INT8이 **38.19% 증가** (`51.823 ms` → `71.615 ms`)

따라서 현재 측정 환경과 CPU 실행 경로에서는 **FP32 모델을 성능 기준 배포 후보로 유지**하는 것이 타당하다. INT8은 저장 공간 절감 효과가 있으므로, 실제 배포 대상 장비에서 별도 재측정한 뒤 채택해야 한다.

> 이 문서는 속도와 CPU 부하 측정 결과다. 정확도(mAP, precision, recall, pose AP)는 평가하지 않았으므로 INT8 모델의 검출 품질이 동일하다고 결론 내릴 수 없다.

## 비교 대상

| 구분 | 모델 | 입력 | 출력 | 파일 크기 |
|---|---|---|---|---:|
| FP32 | `yolo11n-pose-416.onnx` | `[1, 3, 416, 416]`, float32 | `[1, 56, 3549]` | 11.156 MiB |
| INT8 | `yolo11n-pose-416-int8.onnx` | `[1, 3, 416, 416]`, float32 | `[1, 56, 3549]` | 3.119 MiB |

INT8 모델도 외부 입력 형식은 float32지만, 모델 내부의 양자화 연산 및 가중치를 사용한다.

## 1. 순수 ONNX Runtime 추론 결과

카메라 디코딩, 전처리, 후처리, 렌더링, 네트워크 전송을 제외하고 모델 추론만 측정했다.

| 지표 | FP32 | INT8 | INT8 변화 |
|---|---:|---:|---:|
| 평균 지연시간 | 23.659 ms | 43.304 ms | **+83.03%** |
| 중앙값 | 24.091 ms | 43.248 ms | +79.52% |
| p95 | 27.169 ms | 46.820 ms | +72.33% |
| 최소~최대 | 20.802~29.200 ms | 38.598~51.137 ms | - |
| 이론 처리량 `1000 / 평균` | 42.27 FPS | 23.09 FPS | 0.546× |
| 측정 전체 벽시계 시간 | 2.3661 s | 4.3306 s | +83.00% |
| 측정 전체 CPU 시간 | 4.3125 s | 6.4375 s | +49.28% |
| 추론 1회당 CPU 시간 | 43.125 ms | 64.375 ms | **+49.28%** |

### CPU 점유율 해석

연속해서 추론을 실행하는 동안의 프로세스 CPU 사용량은 다음과 같다.

| 지표 | FP32 | INT8 |
|---|---:|---:|
| 1 논리 CPU를 100%로 본 프로세스 점유율 | 182.26% | 148.65% |
| 전체 12 논리 CPU 기준 점유율 | 15.19% | 12.39% |

이 값만 보면 INT8 점유율이 낮아 보이지만, INT8은 같은 100회를 더 오래 걸려 처리한다. 고정된 추론 횟수 또는 고정된 카메라 FPS에서 CPU 예산을 비교할 때는 **추론 1회당 CPU 시간**이 더 적절하다. 이 기준에서는 INT8이 `43.125 ms`에서 `64.375 ms`로 증가했다.

## 2. 실제 C 실행 경로 결과

기존 `build/Release/yolo11-person.exe`로 `test_pose_out.mp4`의 60프레임을 읽고, 모든 프레임에 추론을 실행했다. 파일 디코딩과 전처리·후처리 측정은 포함했지만 출력 파일·미리보기·네트워크 전송은 사용하지 않았다.

실행 조건:

- `--detect-every 1`
- `--detect-fps 0`
- `--motion-gate 0`
- `--threads 2`
- `--warmup 10`
- `--provider cpu`

| 지표 | FP32 | INT8 | INT8 변화 |
|---|---:|---:|---:|
| 처리 프레임 | 60 | 60 | - |
| 추론 횟수 | 60 | 60 | - |
| 추론 p50 | 26.613 ms | 46.212 ms | **+73.64%** |
| 추론 p95 | 31.915 ms | 60.168 ms | +88.53% |
| 추론 총 시간 | 1.6093 s | 2.8070 s | +74.43% |
| 전체 벽시계 시간 | 1.7849 s | 2.9758 s | +66.72% |
| 전체 CPU 시간 | 3.1094 s | 4.2969 s | +38.19% |
| 프레임당 CPU 시간 | 51.823 ms | 71.615 ms | **+38.19%** |
| 30 FPS 실시간 처리에 필요한 1코어 환산 부하 | 155.47% | 214.84% | +38.20% |

이 조건은 프레임마다 추론하는 최악 부하에 가깝다. 실제 애플리케이션의 `detect-every`, 모션 게이트, 추적 설정에 따라 평균 부하는 낮아질 수 있지만, 동일한 추론 횟수를 비교한 INT8의 상대적 불리함은 유지된다.

## 판정

| 항목 | 우세 모델 | 판단 |
|---|---|---|
| 저장 공간 | INT8 | 파일 크기 약 72% 감소 |
| 순수 추론 지연시간 | FP32 | INT8이 평균 1.83배 느림 |
| 추론 1회당 CPU 비용 | FP32 | INT8이 약 49% 큰 CPU 시간 사용 |
| 실제 C 파이프라인 지연시간 | FP32 | INT8 p50이 약 74% 증가 |
| 정확도 | 미측정 | 별도 데이터셋 평가 필요 |

## 재현 방법

CPU 사용량까지 포함한 모델 전용 벤치마크 스크립트:

```powershell
.\.venv-train\Scripts\python.exe scripts\benchmark_quantization.py `
  --fp32 .\yolo11n-pose-416.onnx `
  --int8 .\yolo11n-pose-416-int8.onnx `
  --threads 2 `
  --warmup 10 `
  --runs 100
```

실제 C 경로 측정 예시:

```powershell
$metrics = Join-Path $env:TEMP 'quant_fp32_metrics.json'
.\build\Release\yolo11-person.exe `
  --model .\yolo11n-pose-416.onnx `
  --input .\test_pose_out.mp4 `
  --max-frames 60 `
  --warmup 10 `
  --provider cpu `
  --detect-every 1 `
  --detect-fps 0 `
  --motion-gate 0 `
  --threads 2 `
  --metrics $metrics
```

INT8 측정은 위 명령의 모델 경로를 `yolo11n-pose-416-int8.onnx`로 바꾸면 된다.

## 한계 및 후속 시험

1. 이번 측정은 i7-8700에서 수행했으며, 실제 배포 대상인 i5-4200U의 성능을 직접 보장하지 않는다.
2. ONNX Runtime 버전, 스레드 수, CPU instruction set, 전원 관리와 발열 상태에 따라 결과가 달라질 수 있다.
3. INT8 정확도는 평가하지 않았다. 같은 테스트 이미지에 대해 FP32/INT8의 검출 수, confidence, IoU/mAP 또는 pose AP를 비교해야 한다.
4. 최종 배포 전에는 대상 장비에서 FP32와 INT8을 같은 입력 영상으로 최소 5~10분간 반복 측정하고, CPU 온도 및 thermal throttling도 함께 기록해야 한다.
