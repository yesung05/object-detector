# 표면 감시의 중복 AI 재검사 억제: 구현 및 논문 실험 기록

작성일: 2026-09-11

## 1. 기록의 성격과 주장 범위

이 문서는 현재 저장소에 구현한 알고리즘과 재현 가능한 합성 테스트를 기록한다. 논문 Methods 및 실험 계획의 초안으로 사용할 수 있으나, 실제 매장 영상에 대한 정확도·CPU·전력·FPS 개선을 검증한 논문 결과는 아니다. 관련 연구 조사, 외부 데이터셋 평가, 통계적 검증은 별도 수행해야 한다. 새로운 학술적 기여라는 주장은 아직 하지 않는다.

구현 대상은 기존 규칙 기반 표면 변화 감시 뒤에 연결된 Tier 2 AI의 중복 호출이다. 사람 검출 모델 자체와 청소 알림의 규칙 판정은 변경하지 않는다.

## 2. 기존 시스템과 문제 정의

- 바닥·테이블은 최소 0.5초 간격, 벽은 최소 2초 간격으로 관측한다.
- 표면별 96×96 RGB 표본에서 기준 영상과의 차이를 찾는다.
- 사람 사각형과 겹친 부분은 관측에서 제외한다.
- 후보는 연결 성분과 경계 상자 IoU로 연결하며, 최대 16개/표면이다.
- AI 호출은 전체 표면을 합쳐 최대 초당 1회다.
- 기존 후보 재검사 간격은 일반 후보 5초, 동물 확인 과정 1초다.
- 정상 상태의 전체 표면 감사 검사는 60초, 큰 화면 변화 상태는 5초 간격이다.

같은 위치에 같은 물체가 남아 있으면 이미 검사한 후보도 주기적으로 분류한다. 특히 테이블 이용 중의 일반 물체와 이미 알림이 발생한 잔류물에서 반복 비용이 생긴다. ROI crop은 모델의 고정 입력 크기로 전처리되므로 crop 면적 감소 자체가 모델 FLOPs 감소를 보장하지 않는다. 본 변경은 호출 횟수를 줄이는 접근이다.

## 3. 이번 구현 범위

구현 완료:

1. 위치·영상 특징에 기반한 성공한 AI 결과 재사용.
2. 테이블 이용 중 확인된 동일 후보의 반복 검사 억제 및 퇴석 후 1회 재확인.
3. 알림이 이미 발생한 동일 후보의 반복 분류 억제. 알림 해제는 기존 가시성·기준 비교 로직으로 유지.
4. 가림 상태에서는 캐시를 사용하지 않고, 다시 보이면 현재 특징을 재검증.
5. 동물 의심의 두 번째 확인, 새 후보의 최초 검사, 주기적인 안전 감사 유지.
6. 결과 일련번호 검증, 지연·실패 결과의 캐시 금지, 비교 실험용 설정, 스케줄러 계측 추가.

후속 작업으로 남긴 아이디어:

- 일반 후보의 안정화 대기 시간 추가.
- 가까운 후보 crop 병합.
- 규칙 검사 간격의 적응적 변경.
- AI 추론의 별도 작업자 분리.

위 항목은 이번 성능 결과에 포함되지 않는다. 여러 정책을 동시에 바꾸면 놓침·지연 증가 원인을 분리하기 어려우므로 현재는 동일 후보 재사용 계열을 먼저 검증한다.

## 4. 자료구조 및 구현 위치

| 파일 | 변경 내용 |
|---|---|
| `include/surface_monitor.h` | `SurfaceConfig.ai_reuse`, 요청의 8×8 RGB 특징·관측 당시 이용 상태 |
| `src/surface_config.c` | `ai_reuse` 파싱, 기본 활성화, 잘못된 값 거부 |
| `src/surface_monitor.c` | 특징 추출·캐시 판정·퇴석 재검사·감사 우선권·계측 |
| `tests/test_surface.c` | 동일 입력 A/B 및 상태 전이 회귀 검사 |
| `scripts/test_surface_http.js` | 잘못된 설정값 및 기존 HTTP/UI 저장 검증 |

후보마다 성공한 검사 당시 RGB 특징(192 bytes), 경계 상자, 검사 시간, 이용 상태, 유효 플래그를 유지한다. 추론 요청에도 그 순간의 특징을 복사하므로 결과가 늦게 돌아와 현재 모습에 잘못 연결되는 위험을 줄인다. 기존에 고정 할당된 후보 배열을 확장했으며 매 프레임 동적 할당은 추가하지 않았다. 정렬을 포함한 정확한 전체 메모리 증가는 아직 계측하지 않았다.

## 5. 재사용 조건

후보 c의 성공한 검사 시점을 t_c, 현재 시점을 t, 두 특징을 A와 B라고 한다.

```text
MAE(A, B) = sum(abs(A[k] - B[k])) / 192
large(A, B) = count(abs(A[k] - B[k]) > 24)
```

아래 조건이 모두 성립할 때만 기존 검사 결과를 재사용한다.

- 현재 후보가 관측되며 표면 quality가 0(유효)이다.
- 캐시 나이가 60초 미만이고 시간이 역행하지 않았다.
- 현재 경계와 캐시 경계의 IoU가 0.8 이상이다.
- 후보 사각형의 표면 표본 전체가 유효하고 가리지 않았다. 부분 가림에서는 재사용하지 않는다.
- 8×8 RGB 특징의 MAE가 8 이하이다.
- 차이가 24를 초과하는 채널 수가 19 이하이다(192의 10% 정수 절삭).
- 동물 의심의 두 번째 확인을 기다리는 후보가 아니다.
- 테이블에서 ‘이용 중 검사 → 퇴석 확정’ 전이가 아직 재검사되지 않은 상태가 아니다.

위치 또는 특징 불일치는 캐시를 무효화한다. 같은 표면 관측 사이에 스케줄러가 여러 번 호출되어도 성공한 재사용 판단은 다시 계산하지 않는다.

이 특징은 객체 ID, 임베딩, 의미 분류가 아니다. 비슷한 색의 다른 물체가 같은 자리를 차지하면 구분하지 못할 수 있다. 작은 변경도 96×96 표본과 8×8 특징에서 소실될 수 있다. TTL 및 감사 검사는 위험 완화 장치이지 무누락 보장이 아니다.

## 6. 스케줄링 절차

```text
전역 호출 간격 1초 확인
각 최신 후보:
    기존 재시도 간격 / pending / 관측 여부 확인
    재사용 가능하면 후보 검사 생략
    그 외에는 기존 우선순위로 후보 선택
주기가 지난 전체 표면 감사가 있으면 우선 요청
그 외에는 선택한 후보 요청
```

재사용 활성 모드에서는 주기가 지난 전체 표면 감사가 후보에 계속 밀리지 않게 우선권을 준다. 비활성 모드는 기존처럼 후보가 없을 때 감사한다. 따라서 현재 A/B는 **캐시 + 감사 우선권 정책 묶음**의 비교이며, 순수 캐시만의 효과를 주장하려면 감사 우선권도 별도 인자로 분리해야 한다.

검사 결과 처리:

1. 설정 revision, 후보 version, pending 여부와 요청 serial을 검증한다.
2. 실패·2초 초과 지연·시간 역행 결과는 캐시하지 않는다.
3. 성공했고 현재 모습과 요청 당시 특징이 일치하면 캐시를 갱신한다.
4. 동물 결과는 기존의 반복 확인 로직으로 처리한다. 의심 단계의 재사용은 금지하지만, 이미 확인된 동물의 동일 모습은 재사용할 수 있다.

실패 결과는 기존 5초 재시도 경로를 따른다. 모델이 없거나 오류가 발생한 상황을 ‘정상’으로 캐시하지 않는다.

## 7. 테이블 및 가림 정책

테이블 이용 중 모든 AI를 끄는 방식은 채택하지 않았다. 최초 미분류 후보가 동물일 수 있기 때문이다.

| 상황 | 동작 |
|---|---|
| 이용 중 새 후보 | 최초 AI 검사 허용 |
| 이용 중 성공적으로 검사된 동일 후보 | 재사용 조건 충족 시 반복 검사 생략 |
| 동물 의심 1회 | 기존 1초 간격의 추가 확인 허용 |
| 사람이 떠나 퇴석 확정 | 이용 중 생성한 캐시를 건너뛰고 1회 재검사 |
| 기존 알림 후보가 그대로 있음 | 결과 재사용, 규칙 알림 유지 |
| 후보가 사람에게 가림 | 현재 특징 재사용 금지, 알림을 자동 해제하지 않음 |
| 가림 해제 후 동일 모습 | 유효한 캐시가 남아 있으면 특징 비교 후 재사용 가능 |
| 가림 해제 후 변경된 모습 | 캐시 무효화 후 재검사 |
| TTL 경과 | 동일 물체여도 재검사 허용 |

청소 알림은 기존 규칙 근거로도 발생한다. AI가 ‘쓰레기’라는 세부 분류를 확인해야만 알림이 발생하는 시스템은 아니며, 본 변경도 그 의미를 바꾸지 않는다. 배설물·토사물 세부 분류는 여전히 미지원이다.

## 8. 설정과 비교 실행

`config/surfaces.json` 최상위 설정:

```json
"ai_reuse": true
```

생략 시 true이다. false는 기존 주기적 후보 스케줄러 비교 모드다. 대시보드 고급 JSON 초안에서 수정하고 저장하면 적용된다. 저장 시 revision이 증가하며 후보/캐시가 새로 시작된다. 고정 임계값은 현재 C 코드의 실험 상수이고 UI 조정 항목은 아니다.

공정한 비교에서는 동일 영상·모델·ROI·기준 이미지·스레드 수·실행 공급자를 사용하고 프로세스를 각각 새로 시작한다. 중간에 설정을 변경하여 전후 구간을 비교하면 초기 상태가 달라질 수 있다.

`/surface/status`의 `ai_scheduler`:

| 필드 | 의미 |
|---|---|
| `reuse_enabled` | 현재 정책 |
| `requests` | 반환한 AI 검사 요청 수, 후보와 감사 합계 |
| `audits` | 전체 표면 감사 요청 수 |
| `reuse_observations` | 후보·표면 관측별 재사용 판단 횟수 |
| `occupied_reuse` | 위 횟수 중 vacant가 아닌 상태의 재사용 |
| `alert_reuse` | 위 횟수 중 이미 일반/동물 알림이 있는 후보의 재사용 |

카운터는 모니터 객체 생명주기 동안 누적되며 설정 revision 변경만으로 초기화되지 않는다. `requests`는 실제 성공한 ONNX 실행 횟수가 아니다. 모델 미설정이나 실행 실패도 요청에는 포함될 수 있다. `reuse_observations`는 관측별 횟수이므로 ‘절감한 추론 횟수’로 직접 해석하면 안 된다. 실제 호출 절감은 동일 입력 A/B의 requests 차이와 실제 추론 계측을 함께 보고한다.

## 9. 실행한 합성 테스트 결과

환경: Windows, MSVC Release 빌드. 입력은 100×100 합성 RGB, 정상 배경 값 80, 4초부터 같은 위치에 값 180의 사각형을 추가한다. 표면은 96×96으로 처리하며 t=1..50초를 0.5초 간격으로 관측한다. AI는 즉시 성공하고 동물을 반환하지 않는 테스트 대역이다. 두 조건의 영상·알림 규칙은 동일하다.

| 조건 | 50초 후보 AI 요청 수 | 잔류물 알림 |
|---|---:|---|
| `ai_reuse=false` | 9 | 발생 |
| `ai_reuse=true` | 1 | 발생 |

이 구간은 감사 주기 60초보다 짧아 감사 요청이 없다. 후보 요청 감소율은 `(9-1)/9 × 100 = 88.9%`이다. **특정 정적 합성 장면의 스케줄링 결과이며, CPU 88.9% 절감이나 실환경 평균 효과를 의미하지 않는다.** 실제 ONNX 모델 실행·전력·정확도는 이 테스트에서 측정하지 않았다.

회귀 검증 항목:

- 동일 경계에서 RGB 모습이 달라지면 재검사한다.
- 실패 결과를 캐시하지 않고 기존 재시도 간격을 지킨다.
- 가려졌다고 기존 알림을 해제하지 않는다.
- 안전 감사가 정상적으로 실행된다.
- 캐시 60초 만료 후 같은 후보를 다시 검사한다.
- 이용 중 동일 후보의 반복 검사 억제 및 퇴석 확정 후 재검사.
- 기존 동물 2회 확인, 설정 revision 변경 후 오래된 결과 거부.
- HTTP 설정 검증, 캡처·기준 조회·알림 확인 및 메인 UI 동작 회귀 검사.

## 10. 재현 방법

표준 빌드가 가능한 경우:

```powershell
cmake --build build-windows --config Release --target hunik-dashboard yolo11-person test_surface test_surface_stream
.\build-windows\Release\test_surface.exe
node scripts/test_surface_http.js
node scripts/test_surface_stream.js
node scripts/test_surface_main_ui.js
```

이번 검증 시 실행 중 EXE의 잠금 때문에 `build-windows/surface-validation`에 별도 출력하여 빌드했다. 별도 바이너리로 HTTP 테스트할 때는 `SURFACE_TEST_DASHBOARD`, 스트림 테스트는 `SURFACE_TEST_STREAM` 환경 변수에 절대 EXE 경로를 지정한다. 테스트는 격리된 디렉터리와 포트를 사용한다. 실제 사용자 설정·카메라·대시보드를 종료하거나 덮어쓰지 않는다.

## 11. 논문용 추가 실험 설계

### 연구 질문

1. 검사 요청·실제 추론 시간·CPU/전력을 얼마나 줄이는가?
2. 새로운 잔류물·동물의 검출률과 알림 지연을 악화시키는가?
3. 가림·조명·동일 위치 물체 교체에서 캐시가 얼마나 자주 잘못 유지되는가?

### 필수 장면

정적 잔류물, 이용 중 컵 이동, 잠깐 이석과 실제 퇴석, 완전/부분 가림, 가림 중 새 물체 추가, 같은 위치에서 비슷한 색 물체로 교체, 그림자/조명 변화, 카메라 흔들림, 움직이는/정지한 동물, 다중 표면 동시 변화, 모델 실패 및 지연 결과를 포함한다.

### 비교군 및 절제 실험

- 기존 주기 검사.
- 캐시만 적용.
- 캐시 + 퇴석 후 재확인.
- 캐시 + 퇴석 + 안전 감사 우선권(현재 구현).
- TTL 15/30/60/120초, 특징 해상도 4/8/16, MAE 임계값 변화.

현재 설정은 on/off 묶음 비교만 지원한다. 세부 절제 실험은 해당 정책별 플래그 추가 후 진행한다. 학습·임계값 튜닝에 사용한 영상과 최종 평가 영상은 카메라/날짜 단위로 분리하여 누수를 막는다.

### 지표 및 보고

모델 호출 수/분, 모델 추론 누적 시간, 규칙·특징 비교 시간, 전체 CPU 평균/p95, RSS 최대값, FPS와 프레임 나이 p95, 에너지/분을 함께 측정한다. 정확도 측면에서는 사건별 precision/recall, 영상 시간당 오탐 수, 사건 시작부터 최초 알림까지 지연 p50/p95, 가림 해제 후 복구 지연, 캐시 오재사용률을 보고한다.

동일 녹화 영상을 같은 입력 속도로 반복 실행하고 초기 기준·캐시·카운터를 리셋한다. 실행 순서를 바꾸고 여러 번 반복하며 영상별 paired 비교와 불확실성 구간을 보고한다. 추론 속도가 프레임 누락을 바꾸는 실시간 실험과, 정확히 동일 프레임을 공급하는 결정적 재생 실험을 구분한다. 모델·해시·입력 크기·양자화·런타임·CPU/GPU·스레드·OS·코드 커밋을 기록한다.

## 12. 남은 한계

이 구현은 의미적 동일 물체 추적이 아니다. 부분 가림에서는 의도적으로 재사용을 제한하므로 사람 많은 장면의 절감률이 작을 수 있다. 전체 표면 감사도 전역 초당 1회 예산을 공유하므로 다중 표면에서 지연될 수 있다. AI는 여전히 영상 처리 경로에서 동기 실행된다. 사람이 검출되지 않으면 가림 처리 자체가 실패할 수 있다. 실험 결과는 이러한 제약과 함께 보고해야 한다.
