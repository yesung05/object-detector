## 1부. 대시보드 레이아웃 재설계 (커밋 `0887146`)

### 문제

- 간단·고급 모드 모두 `max-width: 960px` 고정폭이라 1920px 모니터에서 화면 절반을 버림
- **고급 모드에 카메라 뷰가 아예 없음** — 설정을 만지는 동안 매장을 볼 수 없음
- 감지 항목이 6개로 하드코딩되어 항목 추가 시 레이아웃이 깨짐
- 체류 한도를 초 단위 숫자 입력으로만 조절 — 실제 운영에서 쓰기 어려움

### 변경

**고급 모드 2열 구조**

```
┌──────────────────┬────────────────────────────┐
│  카메라 피드      │  [현황] [설정] [로그]        │
│  (300px 고정)     ├────────────────────────────┤
│                  │                            │
│  상태 칩 6개      │  탭 내용 (남은 높이 채움)    │
│  (auto-fill)     │                            │
└──────────────────┴────────────────────────────┘
```

카메라 `<img>`는 **단일 요소를 `setMode()`가 easy/adv 슬롯 사이로 DOM 이동**시킵니다.
요소를 복제하면 MJPEG 연결이 두 개가 되어 i5-4200U에서 인코딩 부하가 2배가 됩니다.

**간단 모드** — 900px 이상에서 `카메라 | 상태카드+알림` 2열. 알림 개수 5→12개
(2열 레이아웃에서 알림 열이 세로 공간을 모두 쓰는데 5개는 너무 적음).
900px 미만(태블릿·폰)은 기존 세로 스택 유지.

**감지 항목 확장 대비** — 상태 카드·칩 그리드를 `repeat(auto-fill, minmax(…, 1fr))`로 변경.
새 감지 항목을 추가해도 레이아웃이 자동으로 줄바꿈합니다.

**시간 슬라이더** (간단 설정)

| 항목 | 슬라이더 범위 | 눈금 | 직접 입력 |
|---|---|---|---|
| 장기 체류 한도 | 10분 ~ 8시간 | **10분** | 1 ~ 1440분 |
| 미주문 착석 유예 | 1분 ~ 30분 | 1분 | 1 ~ 60분 |

범위 밖 값은 직접 입력란으로 넣으며, 이때 슬라이더는 끝에 고정된 채 **썸과 숫자가 주황색**으로
바뀌어 "슬라이더가 실제 값을 나타내지 못함"을 표시합니다. 저장은 항상 `cfg-` 입력란을 거치므로
`saveSettings()`는 수정하지 않았습니다.

> 미주문 유예만 1분 눈금인 이유: 프리셋 값이 2·3·5·7.5·10분이라 10분 눈금이면 조절 자체가 불가능합니다.

**개발자 설정 분리** — `tier2_always`를 Tier 2 아코디언에서 빼내 별도 `🛠 개발자 설정`
아코디언으로 이동(주황색 강조 + 경고 문구). 이후 최적화 우회형 테스트 스위치를 모으는 자리입니다.

## 2부. 기준 이미지 자동 캡처

### 문제

문·잔류물·표면 감지가 전부 **설치 기사의 수동 캡처**를 요구했습니다.
문 하나만 해도 ROI 드래그 → 닫힘 캡처 → 문 열러 가기 → 돌아와 열림 캡처의 4단계이고,
조명이 바뀌거나 계절이 지나면 다시 해야 합니다. 이 반복 노동이 실질적 운영 부담이었습니다.

### 설계 원칙

셋 다 **"사람이 없고 화면이 멈춘 상태가 일정 시간 유지되면"** 을 공통 조건으로 삼았습니다.
룰 기반이라 추가 추론이 없고(CLAUDE.md "AI 최소화"), i5-4200U 부담도 없습니다.

### 문 설정 흐름: ① ROI 수동 → ② 기준 자동

ROI 드래그 도구는 이전부터 있었지만 **고급 설정 아코디언 깊숙이** 묻혀 있어 간단 설정만 쓰는
점주는 문 영역을 지정할 방법이 없었고, 수동 캡처 버튼이 자동 캡처와 구분 없이 나란히 있어
무엇을 눌러야 하는지 알 수 없었습니다. 흐름을 드러내도록 재구성했습니다:

```
🚪 출입문 감지
  감지 활성화                          [토글]
  ① 문 영역 지정   〔직접〕            [화면 불러오기] [초기화]
                                      💡 유리문이면 문틀·손잡이만 포함하세요
  ② 열림·닫힘 기준 〔자동〕            닫힘 ✓ · 열림 수집 중 ███░░ 12s
  개방 허용 시간                       [슬라이더] 30초
```

- ROI 도구는 **단일 블록(`#roi-tool`)이 간단/고급 슬롯 사이를 DOM 이동**합니다.
  복제하면 canvas·요약 요소 ID가 중복되고 드래그 상태를 두 벌 관리해야 합니다(카메라 패널과 같은 패턴)
- 수동 캡처 버튼은 **"자동으로 안 잡힐 때 — 기준 사진 직접 찍기"** 접이식으로 강등했습니다.
  지우지는 않았습니다 — 유리문처럼 자동 조건이 성립하기 어려운 매장에서 필요합니다
- 깨져 있던 단계 번호(1 → 3, 2 없음)를 정리했습니다

### 문 (`src/door.c`, +199줄)

```c
DOOR_AUTO_OFF(0) → NO_ROI(1) → WAIT_CLOSED(2) → WAIT_OPEN(3) → DONE(4)
```

| 단계 | 조건 |
|---|---|
| 닫힘 기준 | ROI 정지(샘플 루마 평균차 < 3.0) + ROI를 사방 25% 넓힌 영역에 사람 없음 + 카메라 정상, **20초 유지** |
| 열림 기준 | 닫힘 기준 존재 + ROI 평균 L1 ≥ 25 + **전체 프레임 L1 < ROI L1 × 0.5** + 정지, **1초 유지** |

- **조명 변화 가드**: 문만 열리면 ROI는 크게, 화면 전체는 거의 안 변합니다. 조명이 바뀌면 둘이
  함께 움직여 비율이 1에 가까워지므로 걸러집니다. (ROI가 화면 절반 이상이면 이 가드가 항상
  걸리므로 ROI는 문짝·문틀만 포함해야 합니다 — 대시보드 안내 문구와 동일한 전제)
- **전제**: "아무도 없을 때의 문 = 닫힘". 무인 카페 문은 자동 닫힘이라 성립하지만,
  **문을 열어 두는 매장에서는 `door_auto_capture=0`으로 꺼야 합니다.**
- ROI 정지 판정은 8픽셀 간격 격자 샘플입니다. 전체 픽셀을 매 프레임 비교하면 `door_check`와
  합쳐 부담이 두 배가 됩니다. 버퍼는 ROI 크기가 바뀔 때만 재할당합니다.
- 저장 성공 시 `install_reference()`가 메모리에 곧바로 설치하므로 파일을 다시 읽지 않습니다
  (호출자는 mtime 캐시만 맞춰 2초 뒤 `reload_door_references`가 중복 로드하지 않게 합니다).

신규 공개 함수: `raw_rgb_save()` — `[int32 w][int32 h][w*h*3 RGB]`, 기존 수동 캡처와 동일 형식.

**정체 감지 (`auto_stalled`)** — 유리문 대응

닫힘 단계에서 `quiet`의 6배가 지나도록 누적 대기가 절반도 못 차면 "조건이 계속 깨지는 중"으로
보고 플래그를 세웁니다. 열림 단계는 손님이 문을 열 때까지 자연히 오래 걸리므로 제외했습니다.

```
WARN door  door_auto_capture stalled — 120초 동안 닫힘 기준을 잡지 못했습니다.
           ROI 안에 계속 움직임이나 사람이 잡히는 중입니다
           (유리문이면 유리 대신 문틀·손잡이만 포함하도록 ROI를 좁히세요)
```

로그 1회 + `/status`의 `door.auto_stalled` + 대시보드 주황색 경고로 드러냅니다.
**조용히 대기만 하면 "감지가 켜져 있는데 아무 일도 안 일어나는" 상태로 남습니다.**

> **유리문의 구조적 한계**: ① 유리 너머 바깥 움직임 때문에 ROI 정지 조건이 충족되지 않음
> ② 닫혀 있어도 이미 바깥이 보이므로 열렸을 때 L1 차이가 작아 기본 임계 25에 못 미칠 수 있음
> ③ 야간 실내 조명 반사는 ROI만 변화시켜 조명 가드를 통과, 열림 오판 가능.
> **대응은 ROI를 유리가 아닌 문틀·손잡이에 잡는 것**이 가장 효과적이며, 그래도 안 되면
> `door_auto_open_l1`을 10~15로 낮추거나 자동 캡처를 끄고 수동 2장을 씁니다.

### 잔류물 (`src/residue.c`)

`residue_auto_init(r, gray, person_count, camera_ok, motion_ratio, now)`

- 기준 없음 + 사람 0명 + 카메라 정상 + `motion_ratio < 0.002` 가 **15초 유지** → 현재 gray를 기준으로

  같은 raw 형식으로 저장해 재시작 후에도 남고 대시보드 미리보기에도 보이게 합니다.

### 표면 (`src/surface_monitor.c`)

`surface_monitor_set_auto_capture(monitor, enabled, quiet_seconds)` — 기본 on / 10초

  10초 유지되면 기존 수동 캡처와 **같은 5프레임 누적 경로**를 시작합니다
- `quality=3`(기준 없음)은 그대로 둬 대시보드가 "처음 설정 필요"를 계속 보이게 합니다

## 3부. 네트워크 보안 계층

### 문제

두 서버(`dashboard/server.c` 8080, `src/stream.c` 8081)의 헤더 주석은 **"127.0.0.1 전용"** 이라고
적혀 있는데 코드는 `INADDR_ANY`였습니다. 같은 망의 누구나 영상을 보고 설정을 바꿀 수 있었고,
그 사실이 아무 데도 기록되지 않았습니다.

### `include/netaccess.h` · `src/netaccess.c` (신규 258줄)

판정 로직을 **한 모듈로 묶은 이유**: 두 서버에 따로 두면 한쪽만 고쳐 다른 포트가 열린 채
남기 쉽습니다.

| 계층 | 범위 | 권한 |
|---|---|---|
| `LOCALHOST` | `127.0.0.0/8` — 키오스크 자체(개발 환경) | PIN 없이 모든 조작 |
| `LAN` | 연결이 들어온 인터페이스와 **같은 서브넷** | 읽기 허용, 변경은 PIN |
| `DENIED` | 그 밖 전부 | 403 |

**"같은 망"의 정의를 사설 대역(`192.168.x`)이 아니라 넷마스크 기준으로 잡은 이유**:
게스트 Wi-Fi가 다른 서브넷(`192.168.50.x`)이면 사설 대역 검사는 통과시키고 서브넷 검사는 막습니다.
무인 매장은 **손님이 매장 Wi-Fi에 붙어 있을 수 있어** 이 차이가 실제 방어선입니다.
넷마스크는 `GetIpAddrTable`(iphlpapi)로 OS 인터페이스 테이블에서 읽습니다.
마스크 조회에 실패하면 **거부** 쪽으로 기웁니다 — 허용으로 기울면 방어선이 조용히 사라집니다.

**PIN**
- 헤더 `X-Hunik-Pin`, 줄 시작에서만 인식(본문에 같은 문자열이 있어도 오인 안 함), 인쇄 가능 ASCII만
- IP당 5회 불일치 → 10분 잠금 (슬롯 16개, LRU 교체)
- **"미제출"은 실패로 세지 않습니다** — 브라우저 첫 요청은 항상 PIN 없이 오고, 그걸 세면 정상 사용자가 잠깁니다

### 개인정보 보호 뷰 (privacy)

**가리는 위치가 핵심입니다.** 대시보드 JS로 `<img>`를 숨기는 방식은 8081 포트가 여전히 원본을
내보내므로 보안이 아닙니다. `main.c`가 **모든 분석이 끝난 뒤, 그리기 직전에** 프레임 버퍼를
단색(`0x24`)으로 채웁니다.

```
detector_run / tracker / door_check / residue / surface   ← 원본 픽셀 (변경 없음)
  ↓
[privacy] 프레임을 단색으로 채움                            ← 이 아래로는 실제 픽셀 없음
  ↓
draw_tracks / draw_skeleton / draw_hud
  ↓
stream_push · preview · 출력 파일
```

- Tier 1이 pose 모델이라 **스켈레톤**이 함께 그려집니다 — 신원은 안 드러나면서
  "쓰러졌다 / 앉아 있다"가 박스만 볼 때보다 잘 보입니다
- 관찰자가 없어도 지웁니다 — `stream_push`가 `/snapshot`용으로 1fps로 계속 복사하기 때문
- 버퍼는 다음 프레임에 디코더가 새로 채우므로 이후 분석에 영향이 없습니다
- **배포 기본값 ON** (`stream_privacy_mode=1`)

**설정 작업용 시간 제한 해제**

privacy가 켜지면 ROI 드래그·기준 캡처가 전부 검은 화면 위에서 이뤄져 쓸 수 없게 됩니다.
그래서 잠금 해제 개념이 필요했습니다:

```
[ROI 불러오기] 클릭 → "설정을 위해 5분간 실제 화면을 표시할까요?" 확인
  → POST /privacy/unlock?seconds=300
  → 이벤트 로그: "privacy unlocked by 192.168.0.23 (lan) for 300s"
  → 시간 종료 시 서버가 스스로 재잠금 (브라우저가 닫혀도 복귀)
```

| 대상 | privacy 중 동작 |
|---|---|
| `/door/preview`, `/surface/reference` (저장된 매장 사진) | **403** |
| `POST /door/save`, `/residue/save` | **409** — 가려진 프레임을 기준으로 저장하면 검은 사진이 되어 감지가 조용히 망가짐 |
| `/snapshot`, `/stream` | 200 (이미 가려진 프레임이라 새는 것 없음) |

### 접근 로깅

8081은 클라이언트 스레드가 SQLite를 건드릴 수 없으므로(준비문은 main 스레드 전용)
**mailbox 링(32칸) → main 스레드 회수** 구조입니다. 넘치면 버린 개수를 한 줄로 보고합니다.
8080은 최신 `logs\*.db`에 직접 INSERT합니다. 둘 다 `module=access`라 **대시보드 로그 탭에
추가 UI 없이 그대로 나타납니다**.

```

INFO  access  config changed by 192.168.0.23 (lan): dwell_limit_seconds 3600→7200, door_enabled 0→1
INFO  access  privacy unlocked by 127.0.0.1 (localhost) for 20s
INFO  access  stream opened by 192.168.0.23 (lan) privacy=1

WARN  access  DENIED 192.168.0.88 POST /api/config — pin_wrong
```

- **설정 변경은 `key old→new`로 기록** — "누가 문 감지를 꺼놨지?"를 로그 한 줄로 답하기 위함.
  `access_pin` 값은 `***`로 마스킹합니다
- **MJPEG·SSE 주의**: 프레임마다 로그를 남기면 초당 15줄이 쌓여 로그가 쓸 수 없게 됩니다.
  스트림은 **연결 열림/닫힘 시 한 줄씩**, heartbeat는 기록하지 않습니다
- 거부 로그는 같은 IP가 10초 안에 반복하면 묶어서 남깁니다(`+N suppressed`) — 스캐너 한 대가
  로그를 덮어 실제 이벤트를 밀어내지 못하게

## 함께 고친 버그

### 1. 잔류물 감지가 실제 설치에서 동작하지 않고 있었음 ★

```c
/* 기존 */
if (r->baseline_w != bw || r->baseline_h != bh) return 0;
```

파일에서 읽은 기준은 **원본 해상도(1280×720)** 인데 `gray`는 **다운샘플(160×90)** 입니다.
크기가 달라 매 프레임 조용히 `0`을 반환했고, **파일 기준이 있는 모든 설치에서 잔류물 감지가
한 번도 동작하지 않았습니다.** 로그도 남지 않아 알 방법이 없었습니다.

수정: 정확히 `downsample` 배수이면 gray와 **같은 방식(블록 중앙 점 샘플)** 으로 한 번 축소해 이어 쓰고,
`residue_baseline_downsampled` INFO를 남깁니다. 배수가 아니면 기준을 폐기하고 WARN을 남겨
자동 캡처가 다시 잡게 합니다(래치로 한 번만).

### 2. `door/save` · `residue/save`가 GET으로도 열려 있었음

PIN 검사는 POST에만 걸리므로 GET을 열어 두면 **검사를 그대로 우회**합니다. POST 전용으로 변경.

### 3. `log.c` — 두 프로세스 동시 쓰기 시 이벤트 유실

대시보드가 같은 DB에 접근 로그를 쓰기 시작하면서 드러난 문제입니다.
WAL은 쓰기를 직렬화하므로 겹치는 순간 한쪽이 `SQLITE_BUSY`를 받는데, 대기 없이 실패하면
**detector 이벤트가 조용히 사라집니다.**

- `sqlite3_busy_timeout(250)` — 프레임 처리를 눈에 띄게 막지 않으면서 상대 쓰기(수 ms)를 넘기는 값
- `sqlite3_step` 반환값을 확인해 실패 시 stderr 출력 (로그 실패는 로그로 남길 수 없으므로 최후 수단)

### 4. 접근 로그 인과 순서 역전

`privacy view inactive`(main 스레드)가 `privacy unlocked by X`(mailbox)보다 먼저 찍혀
**원인과 결과가 뒤집혀** 보였습니다. mailbox 회수를 전환 로그보다 앞으로 옮겼습니다.
`stream_privacy_active()`가 타임아웃 재잠금을 큐에 넣는 경우도 같은 이유로 이 순서여야 합니다.

### 5. stream.c 헤더 수신이 1회 `recv`

PIN 헤더가 붙은 브라우저 요청은 1KB를 넘기도 합니다. `\r\n\r\n`까지 이어 받되 상한(4096)과
시간(5초)을 둬 반쪽 요청이 스레드를 붙잡지 못하게 했습니다.

## 폐기한 대안

**출입구 히트맵으로 문 ROI 자동 탐색** — 사람 트랙의 출현·소멸 좌표를 며칠간 누적해 피크를 문으로
추정하는 안을 검토했다가 제외했습니다:

- **콜드 스타트**: 며칠치 데이터가 쌓여야 동작하는데 설치 기사는 그날 떠납니다. 첫날엔 결국
  손으로 그려야 하므로 설치 부담을 전혀 줄이지 못합니다
- **소멸 지점이 문만이 아님**: 앉을 때(bbox 비율 급변으로 트랙 끊김), 기둥·키오스크에 가려질 때도
  찍혀 피크가 여러 개 생기고 그중 어느 게 문인지 다시 사람이 골라야 합니다
- **프레임 가장자리**: 7~10평 매장은 문이 화면 끝에 걸리는 경우가 많아 "프레임 밖으로 걸어나감"과
  "문으로 나감"이 구분되지 않습니다

대신 **설치 워크스루**(드래그 1회 + 문 통과 1회로 기준 2장 자동 추출)를 후보로 남겼습니다.
오늘 구현한 문 자동 캡처가 그 절반(기준 추출)을 이미 담당합니다.

**Tier 2 테이블 bbox → 표면 ROI 자동 확정** — bbox에 다리·바닥·의자가 섞여 상판만 잘라내려면
카메라 각도별 경험적 규칙이 필요하고, 의자를 살짝 밀어도 오탐이 납니다.
"자동 확정"이 아니라 **"후보 제안 + 점주 확인"** 으로 격하해 후순위로 남겼습니다.

## 4부. 사람 가림 대응 — ROI 상단 밴드

### 문제

판정 단계(`door_check`)에 **사람 가림 대책이 아예 없었습니다.** 시그니처에 사람 bbox가 들어가지
않았습니다. 좁은 문 ROI를 사람이 채우면:

```
dist_c = |(닫힌문 + 사람) − 닫힘기준| ≈ 사람 픽셀
dist_o = |(닫힌문 + 사람) − 열림기준| ≈ 사람 픽셀 + 문 차이   ← 그 문 차이를 사람이 가림
```

두 거리가 비슷해져 판정이 사실상 무작위가 됩니다. **문 앞에서 통화하는 손님 하나로
`door_open` 오탐이 나는 경로**였습니다.

### 해결 — 가려졌을 때만 상단 밴드

문 위쪽은 머리 위라 통행에 가려지지 않는다는 관찰에 기댑니다. 평소에는 픽셀이 많은 전체 ROI가
더 정확하므로 **밴드는 가려졌을 때만** 씁니다.

```c
if (사람이 ROI 와 겹침) {
    if (band_ratio > 0 && band_valid == 1) 상단 band_ratio 만큼만 비교;
    else                                    return -1;   /* 판정 보류 */
} else 전체 ROI 비교;
```

### 핵심 안전장치 — 밴드 유효성 자동 측정

ROI를 문틀 위(**상인방**)까지 넉넉히 잡으면 밴드가 "열려도 닫혀도 똑같은" 구역에 걸려
감지가 조용히 죽습니다. 이걸 막기 위해 기준 두 장이 모이면 **두 기준의 밴드 영역끼리 직접
비교**해 한 번 측정합니다:

```c
band_valid = (band_signal >= full_signal * 0.4 && band_signal >= 8.0);
```

**절대 임계가 아니라 전체 ROI 신호 대비 비율**을 쓰는 이유: 대비가 낮은 문은 전체 신호 자체가
작아서 절대값으로 자르면 멀쩡한 밴드까지 버립니다. 바닥값 8.0은 두 기준이 사실상 같은 사진인
경우(같은 상태에서 두 번 캡처한 실수)를 걸러냅니다.

무효면 WARN 1회 + `/status`의 `band_valid` + 대시보드 표시로 드러냅니다:

```
WARN door  door_band_no_signal signal=0.0 — ROI 상단 30%가 열림·닫힘 간에 거의 같습니다
           (문틀 위 상인방을 포함했을 가능성). 사람이 가리는 동안 문 판정을 보류합니다
```

CPU 추가 부담은 **음수**입니다 — 가려졌을 때 전체 ROI 대신 더 작은 밴드만 훑습니다.

신규 설정: `door_band_ratio` (기본 0.3, 0=밴드 비활성)

## 5부. 기본 모델을 FP32로

### 측정 (i7-8700, ORT CPU EP, 동일 영상·게이트 off·detect-every 1)

| 모델 | 입력 | 추론 p50 | p95 | peak RSS |
|---|---|---:|---:|---:|
| FP32 | 416×416 | **26.7 ms** | 34.8 | 99.5 MB |
| INT8 | 416×416 | **46.1 ms** | 58.5 | 92.9 MB |
| FP32 | 416×224 | 14.0 ms | 18.7 | 84.4 MB |
| 증류 | 416×224 | 6.9 ms | 12.1 | 67.1 MB |

**INT8이 같은 해상도에서 1.7배 느립니다.** `docs/quantization-benchmark-2026-09-20.md`의
독립 측정(FP32 26.6 / INT8 46.2 ms)과 일치합니다.

원인: ORT의 CPU INT8 커널은 **VNNI** 명령이 있어야 이득인데, 개발기(i7-8700 Coffee Lake)와
배포 대상(i5-4200U Haswell) **둘 다 VNNI가 없어** 연산마다 붙는 양자화/역양자화 오버헤드가
이득을 잡아먹습니다. 메모리 절감은 **7 MB**에 불과합니다.

### 변경

- `run-all.ps1` Tier 1·2 모두 **FP32 우선**, INT8은 FP32가 없을 때만 쓰는 폴백
- `models\` 디렉터리를 먼저 쓰는 이유는 **종횡비 자동 선택**이 정밀도보다 이득이 크기 때문입니다
  (416×416 26.7 ms → 416×224 14.0 ms)

### 함께 고친 것 — 동점 시 승자가 디렉터리 열거 순서로 결정되던 문제

`models\`에는 원본 FP32와 증류본이 **같은 입력 크기로** 들어 있어 letterbox 낭비율이 완전히
동일합니다(`yolo11n-pose-416x224` vs `yolo11n-pose-distilled-416x224`, 둘 다 4.3%).
기존 `if (w < best_waste)`는 **먼저 열거된 파일이 이기는** 구조라, 폴더에 파일을 하나 넣는
것만으로 조용히 다른 모델이 실행될 수 있었습니다.

동점 시 **파일이 큰 쪽**을 고르도록 바꿨습니다. 이름 규칙에 기대지 않으면서 "원본 FP32 우선"을
뜻합니다(증류·양자화 모델은 언제나 더 작음). 로그에 파일 크기도 함께 남깁니다:

```
model-select: 후보 yolo11n-pose-416x224.onnx (416x224) — letterbox 4.3%, 11.1 MB
model-select: 후보 yolo11n-pose-distilled-416x224.onnx (416x224) — letterbox 4.3%, 2.7 MB
model-select: 카메라 1280x720 → yolo11n-pose-416x224.onnx (416x224, letterbox 4.3%, 11.1 MB) 선택
```

### 왜 시작 시 자동 벤치마크로 고르지 않는가

"빠른 쪽을 자동으로" 는 매력적이지만 채택하지 않았습니다:

- **같은 기기에서 답이 바뀌지 않습니다.** 매 기동마다 상수를 다시 유도하려고 시작 시간(모델 2개
  로드 + 워밍업 ≈ 1.5초)과 복잡도를 영구히 지불하게 됩니다
- **이 측정은 속도만 봅니다.** 양자화 모델의 검출 정확도(mAP)는 평가된 적이 없습니다.
  몇 % 빠르다는 이유로 자동 전환하는 것은 감시 시스템에서 나쁜 거래입니다

대신 `scripts/bench-models.ps1`을 추가했습니다. 배포 기기에서 **한 번** 돌려 같은 입력 크기끼리
비교한 표와 권고를 출력하고, 결과가 다르면 `run-all.ps1`의 모델 목록 순서만 바꾸면 됩니다.

> **PowerShell 5.1 인코딩 함정**: BOM 없는 `.ps1`은 시스템 ANSI 코드페이지로 읽혀 한글이
> 깨집니다(`run-all.bat`의 `chcp 65001`은 콘솔 출력 코드페이지일 뿐 스크립트 디코딩과 무관).
> `bench-models.ps1`은 UTF-8 **BOM 포함**으로 저장했습니다.

## 알려진 한계

- **전부 평문 HTTP** — PIN이 LAN 위를 그대로 지납니다. 같은 LAN 안의 스니핑까지 막으려면 HTTPS가
  필요하지만 키오스크에 자체 서명 인증서를 배포·갱신하는 운영 부담이 커서 이 위협 모델에서는
  제외했습니다. **매장 Wi-Fi를 손님용과 분리하는 것이 가장 효과적인 방어**입니다
- **PIN 잠금 표가 프로세스 로컬** — 두 서버가 각자 셉니다(공격자는 두 포트에서 각 5회).
  은행이 아니라 키오스크라 이 정도로 충분하다고 판단했습니다
- **문 자동 캡처는 "아무도 없을 때 = 닫힘" 전제** — 문을 열어 두는 매장에서는 꺼야 합니다
- **`surfaces.json`이 활성이면 residue 모듈 전체가 건너뛰어지는 기존 게이팅은 그대로**입니다.
  위 버그 수정은 surface 비활성 설치에 적용됩니다
- **다음 `run-all` 실행 시 카메라 화면이 회색 + 박스로 보입니다.** localhost라 배너의 임시 해제는
  PIN 없이 한 클릭이고, 영구로 끄려면 간단 설정 → 🔒 토글 → 저장

## 손대지 않은 기존 경고

- `main.c`: `draw_residue_roi` 프로토타입 누락 (C4013), `WIN32_LEAN_AND_MEAN` 재정의 (C4005)
- `surface_config.c`: double→float 변환 (C4244 ×2)
- `log.c`: `event_log_count`의 미사용 지역 변수 `lv` (C4189)
