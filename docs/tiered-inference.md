# 계층형 추론 아키텍처 (Tiered Inference)

> 핵심 원칙: i5-4200U에서 YOLO를 항상 돌리지 않는다.
> 가벼운 분석이 먼저 이상 신호를 포착하고, 비싼 연산은 꼭 필요한 순간에만 실행한다.

---

## 전체 구조

```
카메라 입력 (30fps)
        │
        ▼
┌───────────────────────────────────┐
│  Tier 0 — 항상 실행 (CPU ~1-2%)  │
│  배경 차분 / 밝기 / 카메라 상태   │
└──────────────┬────────────────────┘
               │ 움직임 감지
               ▼
┌───────────────────────────────────┐
│  Tier 1 — 주기적 실행             │
│  YOLO + 트래커 + ROI + 체류 카운터│
│  개인별 주문 상태 머신 업데이트   │
└──────────────┬────────────────────┘
               │ 이상 Signal 감지
               ▼
┌───────────────────────────────────┐
│  Tier 2 — Signal 기반 실행        │
│  Pose 추정 / 커스텀 모델          │
└───────────────────────────────────┘
```

움직임이 없으면 Tier 0에서 끝난다. 대부분의 시간 동안 YOLO는 실행되지 않는다.

---

## Tier 0 — 항상 실행

**목적:** 아무것도 없는 유휴 상태를 최소 비용으로 감시한다.

**실행 조건:** 매 프레임 (30fps)

**수행 작업:**

| 작업 | 방법 | 출력 |
|---|---|---|
| 모션 감지 | 배경 차분 (frame difference) | 움직임 있음/없음 |
| 카메라 백화 | 프레임 평균 밝기 > 임계값 | 하드웨어 이상 알람 |
| 카메라 암전 | 프레임 평균 밝기 < 임계값 | 하드웨어 이상 알람 |
| 렌즈 가림 | N프레임 동안 변화량 = 0 | 하드웨어 이상 알람 |
| 출입문 열림 | 문 ROI 배경 차분 | Tier 1 트리거 |
| 충격음 감지 | 마이크 dB 임계값 초과 | Tier 2 직접 트리거 |

**Tier 1 전환 조건:** 모션 감지 픽셀 수가 임계값 초과

---

## Tier 1 — 움직임 감지 시 주기적 실행

**목적:** 사람을 추적하고 룰 기반 이상 여부를 판단한다.

**실행 조건:** Tier 0에서 움직임이 감지된 동안, `detect_every N` 프레임마다

**수행 작업:**

### 1) YOLO 감지 + 트래킹
- 사람·동물·사물 클래스 감지
- Tracker ID 부여 및 유지
- 입장 시각 기록, 퇴장 감지

### 2) ROI 교차 판정

```
설치 시 점주가 설정한 ROI 목록:
  - 키오스크 영역
  - 시럽 펌프 영역
  - 의자·테이블 영역
  - 출입문 영역
  - 쓰레기통 영역
  - 카운터 영역

매 Tier 1 실행마다:
  각 Tracker ID의 bbox가 어떤 ROI와 교차하는지 확인
```

### 3) 개인별 주문 상태 머신

```
사람 입장 → Tracker ID 생성, 상태 = UNORDERED
     │
     ├─ 키오스크 ROI 진입 + 결제 이벤트 수신
     │    → 상태 = ORDERED, 음료 수 N 기록
     │
     └─ 퇴장 → Tracker ID 소멸
```

**상태별 룰 판정:**

| Tracker 상태 | 행동 | 판정 | 액션 |
|---|---|---|---|
| UNORDERED | N분 이상 착석 | 미주문 착석 | 알람 |
| UNORDERED | 시럽 펌프 ROI 진입 | 미주문 펌프 사용 | 알람 |
| ORDERED | 시럽 펌핑 횟수 > N × 음료 수 | 과다 사용 | 알람 |
| ORDERED | 체류 시간 > N분 × 음료 수 | 초과 체류 | 알람 |
| 전체 | 입장 인원 > 결제 음료 수 × 허용 비율 | 무임승차 의심 | 로그 |

**결제 이벤트 연결:**
- 결제 발생 시 키오스크 ROI 안의 Tracker ID를 ORDERED로 전환
- 동시에 2명이 ROI 안에 있을 경우: 가장 가까운 ID를 선택하거나 둘 다 의심 유보

### 4) Tier 2 Signal 생성

Tier 1이 아래 조건을 감지하면 Tier 2를 요청한다:

| Signal | 조건 |
|---|---|
| `PERSON_FALLEN` | 사람 bbox 가로/세로 비율이 임계값 초과로 역전 |
| `PUMP_CONTACT` | UNORDERED Tracker가 시럽 펌프 ROI 진입 |
| `PUMP_EXCESS` | ORDERED Tracker 손목 keypoint 펌핑 횟수 초과 |
| `ANIMAL_ON_FURNITURE` | dog/cat bbox 중심이 의자 ROI 안에 위치 |
| `OBJECT_LEFT` | 사람 퇴장 후 테이블 ROI에 새 물체 잔류 |
| `STRANGER_ENTERING` | bbox 높이가 어린이 추정 기준 미만 |
| `IMPACT_SOUND` | Tier 0 마이크 dB 초과 (직접 Tier 2 트리거) |

---

## Tier 2 — Signal 기반 실행

**목적:** Tier 1이 포착한 이상 신호를 정밀 분석해 최종 판정한다.

**실행 조건:** Signal 수신 시에만 (초당 수회 이하)

**Signal별 수행 작업:**

### `PERSON_FALLEN`
```
Pose 추정 실행
→ 머리·어깨·엉덩이 y좌표 수평 여부 확인
→ N초 이상 지속 시 "쓰러짐" 알람
→ 지속되지 않으면 단순 자세로 분류
```

### `PUMP_CONTACT` (미주문자 접근)
```
즉시 알람 (Tier 2 추론 없이 규칙만으로 처리)
+ 해당 순간 프레임 저장 (증거 로그)
```

### `PUMP_EXCESS` (주문자 과다 사용)
```
손목 keypoint 추적 집중 실행
→ 펌핑 횟수 정밀 카운팅
→ 허용치의 N배 초과 시 알람
```

### `ANIMAL_ON_FURNITURE`
```
dog/cat bbox와 의자 ROI의 교차 면적 정밀 계산
→ 교차 면적이 bbox의 N% 이상 → "의자 착석" 알람
```

### `STRANGER_ENTERING`
```
(1단계) bbox 높이 비율로 키 추정 → 어린이 판정
(2단계, 선택) 얼굴 bbox crop → 경량 나이 추정 모델
→ N세 이하 추정 시 알람
```

### `OBJECT_LEFT`
```
테이블 ROI 배경 차분
→ 사람 없는 상태에서 새 물체 윤곽 감지
→ 일정 크기 이상이면 "쓰레기 투기 의심" 알람
```

### `IMPACT_SOUND`
```
해당 시점 전후 N프레임에서:
→ bbox 급격한 이동 또는 새 물체 바닥 출현 감지
→ 둘 다 해당 시 "기물 파손 의심" 알람
→ 시각 신호 없으면 "충격음 감지" 로그만
```

## 커스텀 모델 (COCO 외)

범용 YOLO로 판단하기 어려운 도메인 특화 상황은 소형 커스텀 모델로 처리한다.
노량진 파일럿 매장에서 데이터 수집 후 학습한다.

| 목적 | 입력 | 방식 | 크기 |
|---|---|---|---|
| 매장 컵 vs 외부 컵 | 컵 bbox crop | 이진 분류기 (MobileNet 백본) | ~수 MB |
| 시럽 잔량 레벨 | 용기 ROI | HSV 색상 분석 (ML 불필요) | - |
| 쓰러짐·이상 자세 | keypoint 51개 숫자 | 소형 MLP (수백 KB) | ~수백 KB |
| 얼굴 나이 추정 | 얼굴 bbox crop | 경량 분류기 | ~수 MB |

**keypoint 기반 MLP의 장점:**
- 입력이 이미지가 아닌 숫자 51개 (17 keypoints × x,y,confidence)
- 연산 비용이 사실상 0에 가까움
- 쓰러짐·구토 자세·이상 행동을 Tier 2에서 거의 무료로 판정 가능

---

## 리소스 분배 (i5-4200U 기준)

```
스레드 배분 (2코어 4스레드, 1스레드 시스템 예비):

Thread 0: FFmpeg 디코딩 + Tier 0 (상시)
Thread 1: Tier 1 YOLO 추론 (모션 감지 시)
Thread 2: Tier 2 + 상태 머신 + 알람 처리 (Signal 발생 시)
```

유휴 상태(매장 비어있을 때)에는 Thread 1, 2가 거의 잠들어 있고
Thread 0만 Tier 0을 돌리므로 전체 CPU 사용률이 최소 수준으로 유지된다.
