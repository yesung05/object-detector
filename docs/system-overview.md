## 한 줄 요약

**매장 천장의 카메라 한 대로, 사람이 지켜보지 않아도 "지금 이상한 일이 벌어지고 있는지"를 판단해 알려주는 프로그램입니다.**

영상은 **기기 밖으로 나가지 않습니다.** 판단도 저장도 전부 매장 안 컴퓨터에서 끝납니다.

## 1. 전체 흐름

```
 📹 카메라
     │
     ▼
 ┌───────────────────────────────────────────────┐
 │  ① 화면이 변했나?                              │  ← 안 변했으면 여기서 끝
 │     (아무도 없는 새벽엔 대부분 여기서 멈춤)      │     = 전기·CPU 절약
 └───────────────────────────────────────────────┘
     │ 변했다
     ▼
 ┌───────────────────────────────────────────────┐
 │  ② 사람 찾기        — 항상                     │
 │     몸의 뼈대(관절 17개)까지 찾아냄             │
 │     → 서 있나? 앉아 있나? 누워 있나?            │
 ├───────────────────────────────────────────────┤
 │  ③ 물건 찾기        — 가끔 (기본 6초에 한 번)   │
 │     고양이·강아지·음식·병·컵·의자·테이블        │
 └───────────────────────────────────────────────┘
     │
     ▼
 ┌───────────────────────────────────────────────┐
 │  ④ 규칙으로 판단                               │
 │     "1시간 넘게 앉아 있다" 같은 조건문           │
 │     → AI가 아니라 단순 계산. 그래서 빠르고 싸다  │
 └───────────────────────────────────────────────┘
     │
     ▼
 📋 기록 + 🖥 대시보드 알림
```

### 왜 ①번 단계가 있나요

CCTV 화면 대부분은 **아무 일도 일어나지 않습니다.** 새벽 4시 빈 매장을 1초에 15번씩 AI로 분석하는 건 낭비입니다.

그래서 먼저 **"직전과 화면이 달라졌나"** 만 봅니다. 이건 사진 두 장 빼기라서 거의 공짜입니다. 달라진 게 없으면 AI를 아예 부르지 않습니다.

## 2. 무엇을 감지하나

### 🧍 사람 관련

| 상황 | 어떻게 아는가 | 언제 알리나 |
|---|---|---|
| **장기 체류** | 같은 사람을 계속 추적하며 머문 시간을 잽니다 | 설정한 한도 초과 (기본 1시간) |
| **미주문 착석** | 키오스크 앞에 한 번도 간 적 없는 사람 | 유예 시간 초과 (기본 5분) |
| **쓰러짐 · 실신** | ① 머리가 갑자기 뚝 떨어지거나<br>② 몸이 가로로 길어진(누운) 자세가 지속 | ①은 **즉시**, ②는 5초 유지 시 |
| **미확인 소실** | 확실히 추적되던 사람이 **나갈 수 없는 자리에서** 사라짐 | 5초 이상 안 보일 때 |
| **소실 지점 잔류** | 위 + 사라진 자리에 **움직이지 않는 것**이 남음 | 잔류가 확인될 때 |
| **1인 1메뉴 미구입** | 앉아 있는 사람 수와 컵 개수를 비교 | 사람이 컵보다 많을 때 |

> **쓰러짐이 가장 중요합니다.** 그래서 여러 방법을 겹쳐 씁니다.
> 몸이 의자나 테이블에 가려져 안 보여도, **머리 하나만 추적되면** 급강하를 잡아낼 수 있습니다.

### 왜 "미확인 소실"을 따로 두었나

**사람 인식 모델은 바닥에 누운 사람을 못 잡는 경우가 있습니다.** CCTV처럼 비스듬히 내려다보는
각도에서는 누운 몸이 앞뒤로 눌려 보여서, 서 있는 사람만 잔뜩 학습한 모델이 사람으로 인식하지
못합니다. 네모 상자가 아예 안 생기니 "누운 자세"를 재는 방법 자체가 무용해집니다.

그래서 **"사라졌다"는 사실 자체**를 신호로 씁니다. 다만 사람은 정상적으로도 사라집니다 —
그냥 나가거나, 카메라가 안 비추는 쪽으로 걸어가거나, 칸막이 뒤로 가거나.

**그래서 "어디에서" 사라졌는지를 먼저 봅니다.** 같은 "사라짐"이라도 위치에 따라 뜻이 완전히
다르기 때문입니다.

| 사라진 곳 | 판단 |
|---|---|
| **출입문 앞** | 문이 열렸으면 → 나간 것 (무시)<br>문이 **닫힌 채**였으면 → 나갈 수 없었다는 뜻 (경고) |
| **화면 가장자리** | 카메라가 안 비추는 쪽으로 걸어갔을 수 있음<br>→ **그 자리에 뭔가 남았을 때만** 경고 |
| **화면 한가운데** | 나갈 곳이 없는데 사라짐 → 가장 강한 신호 (경고) |

> **출입문과 화면 가장자리는 다릅니다.** 이 둘을 같이 취급하면 반드시 한쪽이 깨집니다.
> 가장자리를 전부 무시하면 **문 앞에서 쓰러진 경우** — 가장 위험한 위치 — 를 놓치고,
> 반대로 문이 닫혔다는 이유로 가장자리를 전부 의심하면 **화각 밖으로 걸어 나간 정상 상황이
> 모두 경고**가 됩니다. 카메라가 매장 전체를 덮지 못하는 배치에서 특히 그렇습니다.

그리고 마지막으로 **그 자리에 뭔가 남아 있는지**를 봅니다. 쓰러진 사람은 그대로 있고,
걸어간 사람은 바닥이 원래대로 돌아옵니다. 이것이 확인되어야만 **응급**으로 올립니다.

칸막이나 기둥이 많아 사람이 자주 가려지는 매장이라면, 설정에서 **"항상 잔류 확인을 요구"**
를 켜서 경고 기준을 더 높일 수 있습니다.

> **이름을 "쓰러짐"이라고 붙이지 않았습니다.** 칸막이 뒤로 간 것일 수도 있는데 응급이라고
> 단정하면, 진짜 응급 알림까지 못 믿게 됩니다. 확실한 것만 말하고 판단은 사람에게 넘깁니다.

### 🐾 물건 · 동물 관련

| 상황 | 어떻게 아는가 |
|---|---|
| **반려동물이 의자에** | 동물 위치와 의자 위치가 겹치는지 |
| **반려동물이 테이블에** | 위와 같되, 테이블은 더 엄격히 (2회 확인) |
| **외부 음식 반입** | 매장에서 팔지 않는 음식류가 보일 때 |
| **외부 음료 반입** | 페트병·캔 등이 보일 때 |

### 🧹 청결 · 잔류물

| 상황 | 어떻게 아는가 |
|---|---|
| **바닥 흘림 · 토사물** | 깨끗할 때 사진과 비교해 **달라진 채 없어지지 않는** 부분 |
| **테이블 위 쓰레기** | 손님이 떠난 뒤에도 테이블이 원래 모습으로 안 돌아올 때 |
| **벽면 변화** | 위와 같은 방식 |

> **발상의 전환**: 보통 영상 감시는 *움직임*을 이상 신호로 봅니다.
> 여기서는 반대로 **"변한 채 그대로 있는 것"** 이 이상 신호입니다.
>
> 토사물이나 쓰레기는 **AI로 학습시킬 수 없습니다.** 공개 데이터셋에 그런 항목이 없고,
> 실제 장면을 촬영해 모으는 것도 현실적·윤리적으로 어렵습니다. 모양도 제각각이고요.
> 그래서 **"무엇인지"는 판단하지 않고 "남아 있다"는 사실만** 봅니다.

### 🚪 출입문

| 상황 | 어떻게 아는가 |
|---|---|
| **문 장시간 개방** | 문 영역이 "닫힘 사진"과 "열림 사진" 중 어느 쪽에 가까운지 |

손님이 드나드는 몇 초짜리 개폐는 **기록하지 않습니다.** 감지하려는 건 "문이 열린 것"이 아니라 **"문이 닫히지 않은 것"** 이니까요 (기본 30초 초과 시 알림).

### 📷 카메라 자체

| 상황 | 어떻게 아는가 |
|---|---|
| **화면 깜깜함** | 평균 밝기가 너무 낮음 (전원·케이블 문제) |
| **화면 새하얌** | 평균 밝기가 너무 높음 (렌즈 가려짐·역광) |
| **화면 멈춤** | 픽셀이 전혀 안 변함 (연결 끊김) |

> 감지 기능이 아무리 좋아도 **카메라가 죽으면 전부 무의미**합니다.
> 그래서 카메라 상태 자체를 항상 감시합니다.

## 3. 설치가 얼마나 간단한가

예전에는 설치 기사가 매장마다 **기준 사진을 손으로 찍어야** 했습니다. 조명이 바뀌거나 계절이 지나면 또 찍어야 했고요. 지금은 대부분 자동입니다.

| 항목 | 사람이 할 일 | 자동으로 되는 일 |
|---|---|---|
| **출입문** | 화면에서 문 영역을 **한 번 드래그** | 닫힘 사진 → 열림 사진 순서로 스스로 촬영 |
| **바닥 잔류물** | 없음 | 사람 없고 화면 멈추면 스스로 기준 촬영 |
| **테이블 · 벽** | 감시할 영역 지정 | 비어 있고 다 보일 때 스스로 기준 촬영 |

```
① 문 영역 지정  〔사람이 직접〕  [화면 불러오기] → 드래그 → 저장
                                   💡 유리문이면 유리가 아니라 문틀·손잡이를 포함

② 기준 사진     〔자동〕         닫힘 ✓ · 열림 수집 중 ███░░░ 12초
```

### 잘 안 될 때도 알려줍니다

자동 촬영이 **조용히 실패하는 것이 가장 나쁩니다.** 켜져 있는데 아무 일도 안 일어나는 상태가 되니까요. 그래서:

> ⚠ **기준이 잡히지 않습니다** — 문 영역 안에서 계속 움직임이 감지됩니다.
> 유리문이면 유리 대신 문틀·손잡이만 들어가도록 영역을 좁혀보세요.

**유리문이 대표적인 어려운 경우입니다.** 유리 너머로 바깥이 보이니 "화면이 멈춘 상태"가 오지 않고, 문이 닫혀 있어도 이미 바깥이 보이니 열렸을 때 차이도 작습니다. → **유리가 아닌 문틀을 잡으면** 대부분 해결됩니다.

## 4. 사람이 문을 가려도 판단합니다

**문제**: 손님이 문 앞에 서 있으면 문이 사람 몸에 가려집니다. 이때 "닫힘 사진"과 "열림 사진" 어느 쪽과 비교해도 결국 **사람 옷 색깔을 재는 꼴**이 되어 판단이 동전 던지기가 됩니다. 문 앞에서 통화하는 손님 하나로 오탐이 날 수 있었습니다.

**해결**: 문의 **위쪽은 머리 위라 가려지지 않습니다.**

```
 ┌─────────┐
 │▒▒▒▒▒▒▒▒▒│ ← 이 띠만 보고 판단 (사람이 가려도 보임)
 │─────────│
 │   🧍    │ ← 사람이 가리는 구간
 │         │
 └─────────┘
```

**단, 함정이 있습니다.** 영역을 너무 위로 잡으면 문틀 위쪽(고정된 벽)이 들어갑니다. 거기는 문이 열리든 닫히든 똑같아서, 믿고 판단하면 계속 틀립니다.

그래서 **그 띠가 실제로 열림/닫힘을 구분할 수 있는지 자동으로 검사**합니다. 못 한다고 나오면 그 사실을 알리고, 가려진 동안에는 **억지로 답하지 않고 판단을 보류**합니다.

> 이 시스템의 일관된 원칙입니다 — **틀린 답보다 "모르겠다"가 낫습니다.**

## 5. 개인정보 보호

### 영상은 기기 밖으로 나가지 않습니다

분석·판단·저장 전부 매장 컴퓨터 안에서 끝납니다. 외부 서버로 보내지 않습니다.

### 기본은 "화면 숨김" 모드

대시보드에서도 **실제 영상 대신 감지 결과만** 보입니다.

```
 실제 영상 대신 →  ┌──────────────┐
                   │ ▓▓▓▓▓▓▓▓▓▓▓▓ │  회색 배경
                   │   ┌───┐      │  + 사람 위치 네모
                   │   │ ╿ │      │  + 뼈대 선
                   │   └───┘      │
                   └──────────────┘
```

뼈대를 그리면 **누구인지는 알 수 없지만** "쓰러졌다 / 앉아 있다"는 오히려 더 잘 보입니다.

설정 작업이 필요할 땐 **"설정용 임시 해제"** 버튼으로 잠깐만 실제 화면을 봅니다. 시간이 지나면 **서버가 알아서 다시 잠급니다** (창을 닫아도 복귀).

### 아무나 못 건드립니다

| 접속 위치 | 볼 수 있나 | 설정 바꿀 수 있나 |
|---|---|---|
| 매장 컴퓨터 자체 | ✅ | ✅ |
| 같은 매장 네트워크 (점주 폰 등) | ✅ | 🔑 PIN 필요 |
| 그 외 전부 | ❌ 차단 | ❌ 차단 |

**모든 접속·변경·차단이 기록**됩니다. "누가 언제 문 감지를 꺼놨지?" 같은 질문에 로그 한 줄로 답할 수 있습니다.

```
설정 변경됨  192.168.0.23 : 체류한도 3600초 → 7200초, 문감지 꺼짐 → 켜짐
차단됨      203.0.113.7  : 매장 네트워크 밖에서 접근 시도
```

> **한계도 알려드립니다**: 통신이 암호화되어 있지 않아, 매장 네트워크 안에서 작정하고
> 엿보는 사람까지는 막지 못합니다. **손님용 Wi-Fi와 분리**하는 것이 가장 효과적입니다.

## 6. 성능 — 얼마나 가벼운가

배포 대상은 **10년 된 저사양 미니 PC**(Intel i5-4200U, 2코어 4스레드)입니다. 최신 PC가 아니어도 돌아가야 합니다.

### 키오스크를 방해하지 않는 것이 최우선입니다

이 프로그램은 키오스크의 **보조** 프로그램입니다. 우리 때문에 결제 화면이 버벅이면
매장이 멈춥니다. 그래서 두 겹으로 막습니다.

**1층 — 운영체제에 "우리는 뒷전"이라고 알려두기**

프로그램 시작할 때 자기 우선순위를 낮춥니다. 이러면 **키오스크가 일할 게 있으면 운영체제가
무조건 키오스크를 먼저** 돌립니다. 우리 코드에 어떤 문제가 생겨도 이건 유지됩니다.

**2층 — 남들이 바쁘면 스스로 물러나기**

2초마다 "우리를 제외한 나머지가 CPU를 얼마나 쓰는지"를 봅니다.

| 남들이 쓰는 양 | 우리가 하는 일 |
|---|---|
| 50% 미만 | 평소대로 |
| 50% 이상 | 사람 찾기 **2배 덜 자주**, 물건 찾기도 2배 덜 자주 |
| 70% 이상 | 사람 찾기 **4배 덜 자주**, 물건 찾기 정지, 화면 전송 절반 |
| 85% 이상 | **AI 정지** — 카메라가 살아 있는지만 확인 |

> **"우리가 얼마나 쓰는지"가 아니라 "남들이 얼마나 쓰는지"를 보는 이유**:
> 한가한 새벽에 우리가 CPU를 많이 쓰는 건 아무 문제가 아닙니다.
> 정작 중요한 건 손님이 결제하는 순간입니다.

단계가 바뀔 때마다 **기록을 남깁니다.** 안 그러면 "왜 갑자기 감지가 느려졌지?"에 답할 수
없습니다. 그리고 한 번 내려간 단계는 부하가 **충분히** 떨어져야 풀립니다 — 경계선에서
왔다 갔다 하면 오히려 더 불안정해지기 때문입니다.

### 정해진 시각에 다시 시작하기

오래 켜 두면 프로그램이 조금씩 무거워질 수 있습니다. **요일과 시각을 골라두면** 그때
스스로 껐다 켭니다. 기본은 꺼져 있습니다.

```
🔄 예약 재시작        사용 [켬]
   요일   [일][월][화][수][목][금][토]
   시각   04:00
```

**손님이 있으면 재시작하지 않습니다.** 재시작하면 추적 중이던 체류 시간과 경고가 전부
사라지기 때문입니다. 사람이 없어질 때까지 기다리고, **1시간 안에 비지 않으면 그날은
건너뜁니다** — 미뤄 두었다가 영업이 한창인 낮에 갑자기 재시작되는 것이 한 번 거르는 것보다
훨씬 나쁘기 때문입니다.

> 재시작한 날짜를 파일에 적어 둡니다. 이게 없으면 다시 켜진 프로그램이 "아직 재시작 안 했네"
> 하고 곧바로 또 꺼져서, 한 시간 내내 껐다 켜기를 반복하게 됩니다.

### 그 밖에 아끼는 방법

| 방법 | 효과 |
|---|---|
| **화면이 안 변하면 건너뛰기** | 빈 매장에서 AI를 거의 안 부름 |
| **변화가 기존 사람 안에서만 일어났으면** | 무거운 AI 대신 가벼운 추적으로 대체 |
| **감시 제외 구역 지정** | 창밖 도로·간판 조명 같은 건 무시 |
| **영업시간 밖에는 감시만** | 카메라 상태만 보고 분석은 쉼 |
| **보는 사람이 없으면 화면에 안 그림** | 아무도 대시보드를 안 볼 때 그리기 생략 |
| **물건 찾기는 가끔만** | 사람은 항상, 물건은 기본 6초에 한 번 |

### 측정값 (참고)

같은 영상·같은 조건에서 잰 **AI 분석 1회 소요 시간**입니다.

| 설정 | 시간 | 메모리 |
|---|---:|---:|
| 정사각형 입력 (416×416) | 26.7 ms | 99 MB |
| **화면 비율에 맞춘 입력 (416×224)** | **14.0 ms** | 84 MB |
| 압축(양자화) 모델, 정사각형 | 46.1 ms | 93 MB |

**두 가지가 드러납니다.**

1. **화면 비율을 맞추는 것만으로 2배 가까이 빨라집니다.** 16:9 화면을 정사각형 모델에 넣으면 위아래가 빈 공간으로 낭비되기 때문입니다. → 카메라 해상도에 맞는 모델을 **자동으로 고릅니다.**

2. **모델을 압축하면 오히려 느려집니다.** 파일 크기는 1/4로 줄지만 속도는 1.7배 느려집니다. 이 계산을 빠르게 처리하는 특수 명령어가 배포 대상 CPU에 없기 때문입니다. → **압축하지 않은 모델을 기본**으로 씁니다. 메모리 차이는 7 MB뿐이라 문제가 되지 않습니다.

> 새 하드웨어에 배포한다면 `scripts/bench-models.ps1`을 **한 번** 돌려 다시 재보면 됩니다.
> 매번 자동으로 재지 않는 이유는, 같은 기기에서는 답이 바뀌지 않는데 시작할 때마다
> 1.5초씩 낭비하게 되고, 이 측정은 **속도만 볼 뿐 정확도는 안 보기** 때문입니다.

사람 추적 · 장기 체류 · 미주문 착석 · 쓰러짐 · **미확인 소실** · 1인 1메뉴 · 반려동물(의자/테이블) · 외부 음식 · 외부 음료 · 바닥 잔류물 · 테이블/벽 청결 · 출입문 개방 · 카메라 장애 · 기준 사진 자동 촬영 · 개인정보 보호 · 접근 제어 및 로깅 · **키오스크 보호(우선순위 + 적응형 감속)** · **예약 재시작** · 웹 대시보드

**자동 검증 87개 전부 통과** 상태입니다.

### 🚧 아직 안 된 것

| 항목 | 이유 |
|---|---|
| **시럽 과다 복용** | 손 움직임을 세밀하게 봐야 해서 현재 방식으로는 어려움 |
| **노키즈존 등 출입 제한** | 나이 추정이 필요 — 정확도와 윤리 문제를 먼저 정리해야 함 |
| **기물 파손** | "부서짐"을 정의하기 어려움. 잔류물 감지가 일부 대신함 |
| **단골 손님 오탐** | 10시간 있었지만 20번 주문한 손님도 "장기 체류"로 잡힘 → 다음 작업 예정 |
| **메모리 누수 점검** | 예약 재시작으로 덮을 수는 있지만, 며칠 켜 두고 실제로 느는지 확인해 원인을 찾는 편이 낫습니다 |

### ⚠️ 알아두실 점

- **문 자동 촬영은 "아무도 없을 때 = 문이 닫혀 있다"를 전제**합니다. 문을 열어두고 영업하는 매장에서는 꺼야 합니다.
- **카메라가 흔들리거나 각도가 바뀌면** 기준 사진이 무효가 됩니다. 다시 촬영해야 합니다.
- **미주문 착석 감지는 키오스크 위치를 지정해야** 동작합니다. 안 하면 "주문했는지"를 알 방법이 없습니다.

## 8. 설계 원칙 세 가지

### ① 규칙이 먼저, AI는 최소한

"1시간 넘게 앉아 있다"는 **시계만 보면 알 수 있습니다.** AI를 부를 이유가 없습니다.
AI는 사람과 물건을 *찾는 데*만 쓰고, *판단*은 조건문으로 합니다. 그래서 저사양 PC에서도 돌아갑니다.

### ② 조용히 실패하지 않기

기능이 멈췄는데 아무도 모르는 상황이 가장 위험합니다.
그래서 **정상일 때도, 안 될 때도 이유와 함께 기록**합니다.
"기준 사진이 없습니다", "영역 안에 움직임이 계속됩니다" 처럼 **무엇을 해야 하는지까지** 적습니다.

### ③ 매장마다 다르게

5평 매장과 20평 매장이 같은 기준일 수 없습니다.
체류 허용 시간, 감지 민감도, 켜고 끌 기능을 **전부 대시보드에서 조절**할 수 있고, 프로그램을 다시 시작할 필요가 없습니다 (2초 안에 반영).
