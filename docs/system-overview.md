## 1. 한 줄 요약

**매장 천장의 카메라 한 대로, 사람이 지켜보지 않아도 "지금 이상한 일이 벌어지고 있는지"를 판단해 알려주는 프로그램입니다.**

영상은 **기기 밖으로 나가지 않습니다.** 판단도 저장도 전부 매장 안 컴퓨터에서 끝납니다.

### 상태 표기 범례

| 표기 | 뜻 |
|---|---|
| **켜짐** | 코드 기본값에서 동작합니다 |
| **출시 프로파일** | `config/store-launch.ini`를 적용하면 정해진 모드로 동작합니다(아래 3절) |
| **설정으로 켬** | 기본은 꺼져 있고 설정 키를 켜야 동작합니다 |
| **그림자** | 기록은 하되 점주 알림 화면에는 보이지 않습니다 |
| **평가만 완료** | 오프라인 평가는 했지만 배포(기본값)에는 반영하지 않았습니다 |
| **미구현 / no-go** | 구현하지 않았거나, 측정 결과 규칙으로 풀리지 않았습니다 |

### 아직 없는 것

시럽 과다 복용(손동작을 세밀히 봐야 함), 노키즈존 등 출입 제한(나이 추정의 정확도·윤리 문제), 단골 손님의 장기 체류 오탐 구분(다음 작업).

> **쓰러짐이 가장 중요합니다.** 오탐으로 신뢰를 잃지 않도록 보수적으로 판정합니다.
> 관측 품질 조건을 통과한 상태로 직립 이력 뒤 수평 자세가 유지될 때만 알립니다.
> 모델이 누운 사람을 아예 놓치는 경우는 "미확인 소실"이 맡습니다.

## 3. 알림 운영: 켜짐·그림자·끔

모든 알림은 `alert_<이름> = on | shadow | off`로 하나씩 정합니다(`config.json` 또는 대시보드에서 쓰는 설정 파일). 기본은 전부 `on`입니다.

| 모드 | 이벤트 기록 | 점주 알림 화면 |
|---|---|---|
| `on` | 기록 | 표시 |
| `shadow`(그림자, 대시보드 표시 **켜짐 (알림 X)**) | 기록하되 메시지 끝에 ` mode=shadow`를 붙임 | **표시 안 함**(대시보드 피드가 걸러냄). 리플레이에는 기록 |
| `off` | 기록하지 않음 | 표시 안 함 |

**왜 그림자가 필요한가**: 현장 정답 데이터가 없어서 새 매장에서는 어떤 알림이 오탐이 많은지 모릅니다. 처음에는 확신이 없는 알림을 그림자로 두고 1~2주 기록만 쌓은 뒤, 자동 지표(`scripts/analyze_alert_quality.py`)로 켤지 결정합니다.

### 출시 프로파일 (`config/store-launch.ini`)

| 모드 | 알림 |
|---|---|
| **on** | `person_fallen`, `overstay`, `unordered_seated`, `door_open` |
| **shadow** | `person_unaccounted`, `person_unaccounted_residue`, `external_drink`, `external_food`, `no_cup_seated`, `animal_on_chair`, `animal_on_table`, `residue_trash`, `residue_spill`, `residue_unknown`, `slot_item_urgent` |
| **off** | `occupancy_exceeded`, `person_motionless` |

그 밖에 `table_confidence = 0.28`, `reid_dwell_keep_seconds = 300`, `calib_retry_minutes = 30`, `stream_privacy_mode = 1`, `log_max_total_mb = 5120`이 들어 있습니다. 시작 로그에 `alert_modes shadow=… off=…`가 남습니다. 설치·연출 시험·켤지 판단하는 기준은 [설치 체크리스트](store-launch-checklist.md)에 있습니다.

**과거 로그에 소급한 참고값**: 6일(143.5시간) 현장 로그에서 점주에게 보이는 알림은 하루 평균 2,270건이었고, 출시 프로파일의 켜진 4종만 세면 1,137건입니다. 이 로그는 재알림·유령 트랙 수정 이전 코드로 쌓인 것이라 수정의 효과는 **새 로그가 쌓여야 알 수 있습니다**(미측정). 자세한 내용은 [성능 전후 비교](performance-before-after-2026-11-06.md) 3절.

## 4. 동작 원리 (개발자)

### 4.1 프레임 처리 순서

```
카메라/영상(FFmpeg 디코드)
   │
   ▼ process_frame (src/main.c)
 ① 로그 회전·설정 핫리로드(2초)·예약 재시작 확인 → 적응형 감속(throttle)
 ② 회색 평면 + 카메라 건강(암전/백화/멈춤) 갱신
 ③ 모션 게이트: 화면이 안 변했으면 AI 생략 (L0 영업시간 밖 ~ L3, idle_refresh 주기로 강제 갱신)
 ④ Tier 1: 사람 + 관절 17개 (yolo11n-pose, 화면 비율에 맞는 모델 자동 선택, 쓰러짐용 회전 프레임 재검출)
 ⑤ tracks: IoU + 색 히스토그램 Re-ID(limbo 보관) → 트랙 상태
 ⑥ rules_evaluate: 체류·미주문·쓰러짐·소실·인원·무동작
 ⑦ Tier 2: 물건·동물(yolo11n, 기본 90프레임마다. 표면 감시가 켜져 있으면 생략) → rules_evaluate_objects
 ⑧ 문(door_check, 자동 캡처) → 소실 판정 → 표면 → 잔류물·슬롯
 ⑨ perf 로그·리플레이 기록
 ⑩ 보호 모드면 프레임을 가림(apply_privacy_mask) ← 이 아래로는 실제 픽셀이 없음
 ⑪ 박스·스켈레톤·HUD 그리기(draw.c) → 스트림 전송(stream_push)
```

`코드 위치`: `process_frame`은 `src/main.c:2008`, 알림 모드 표 `ALERT_TOKENS`는 `src/main.c:1615`.

**원칙**
- **룰 우선, AI는 최소**: AI(Tier 1·2)는 사람과 물건을 *찾는 데*만 쓰고 *판단*은 조건문으로 합니다.
- **모든 버퍼는 시작 시 한 번만 할당**하고 프레임마다 재사용합니다(메모리가 프레임 수와 무관하게 고정).
- **조용히 실패하지 않기**: 정상일 때도 안 될 때도 이유와 함께 기록합니다.

### 4.2 추적과 Re-ID

- `TrackList`가 박스 IoU로 이어 붙이고, 사라진 트랙은 일정 시간 `limbo`에 보관해 색 히스토그램이 비슷하면 같은 사람으로 되살립니다.
- 되살릴 때 **부재가 `reid_dwell_keep_seconds`(기본 300초)를 넘었으면 체류 시간·최초 관측 시각·미주문 상태를 초기화**합니다. 색만 비슷한 다른 사람에게 ID가 넘어가 체류가 몇 시간씩 쌓이던 문제(유령 체류)를 막기 위한 것입니다. 초기화 횟수는 `track_reid_dwell_reset`으로 로그에 남습니다.
- 새 트랙은 `max(person_confidence, new_person_confidence)` 이상일 때만 만듭니다(`new_person_confidence` 코드 기본 0.30).
- 박스가 낮은 점수(`track_low_score` 0.10 이상)여도 **기존 트랙을 이어 주는 데**는 씁니다(새 트랙은 만들지 않음).

### 4.3 쓰러짐 판정

1. 품질 게이트(박스·매칭 점수), 직립 이력(최근 30초 안에 서 있던 샘플), 수평 자세 판정(`fall_aspect_ratio_kp` 1.8 / `nokp` 2.2, 몸통 벡터), 유지 시간(`fall_hold_seconds`, 기본 5초 + 샘플 수 조건)을 모두 통과해야 `person_fallen`을 발화합니다.
2. **쓰러짐 보강(기본 꺼짐)**: `fall_handoff_seconds/reach`(쓰러지며 끊긴 트랙의 직립 이력 인계), `fall_wide_ratio/min_score`(낮은 점수의 넓은 박스를 근거로 인정)를 켜면 AI-Hub pool 기준 재현율이 21.0% → 44.2%였습니다(음성 7시간 오탐 0건). 카페 환경(의자에 앉은 사람, 쪼그려 앉기) 오탐은 **검증하지 못했고**, 비율을 1.0으로 낮추면 휠체어를 쓰러짐으로 오인합니다(test).
3. 쓰러진 사람의 검출 점수 중앙값이 0.33으로 붕괴해 룰의 재현율은 약 44%가 상한입니다. 그 위는 모델의 몫입니다.
4. 발화 근거는 이벤트 메시지의 `evidence=`(`upright_to_horizontal`, `upright_to_wide_box`)로 남습니다.

### 4.4 사라진 사람(미확인 소실)

사람은 정상적으로도 사라집니다. 그래서 **어디에서 사라졌는지**를 먼저 봅니다.

| 사라진 곳 | 판단 |
|---|---|
| 출입문 앞 | 문이 열렸으면 나간 것(무시), **닫힌 채**였으면 경고 |
| 화면 가장자리 | 화각 밖으로 걸어갔을 수 있음 → **그 자리에 뭔가 남았을 때만** 경고 |
| 화면 한가운데 | 나갈 곳이 없는데 사라짐 → 가장 강한 신호 |

문과 가장자리를 같이 취급하면 한쪽이 깨집니다(가장자리를 전부 무시하면 문 앞에서 쓰러진 경우를 놓치고, 문이 닫혔다고 가장자리를 전부 의심하면 정상 퇴장이 모두 경고가 됩니다). 이름을 "쓰러짐"이 아니라 "소실"이라 붙인 것은 칸막이 뒤로 간 것을 응급이라고 단정하지 않기 위해서입니다. 출시 프로파일에서 그림자인 이유: 현장 로그 613건이 전부 문 위치 미설정(`door=unknown`)에서 나왔습니다.

### 4.5 문 판정

- 문 ROI의 닫힘 사진·열림 사진 중 어느 쪽에 가까운지로 열림/닫힘을 판단하고, **개폐 순간은 기록하지 않고 "기준 시간(기본 30초) 이상 열려 있음"만** 알립니다.
- 손님이 문을 가리면 **문 위쪽 띠(머리 위라 가려지지 않음)**만 봅니다. 그 띠가 열림/닫힘을 구분할 수 있는지 자동 검사하고(`band_valid`), 못 하면 그 사실을 알리고 **판단을 보류**합니다(틀린 답보다 "모르겠다").
- 기준 사진·문 ROI는 자동으로 잡습니다(사람이 문으로 드나드는 위치를 학습하고, 통과 전후 변화로 닫힘/열림 기준을 수집). 진행 상태는 `/status`와 대시보드에 숫자·배지로 표시되고, 정체하면 원인과 함께 경고합니다.
- **문 자동 캡처는 "아무도 없을 때 문 = 닫힘"을 전제**하므로 문을 열어 두는 매장에서는 꺼야 합니다.

### 4.6 테이블 자동 등록

Tier 2의 식탁 검출이 **5회 이상·10초 이상·겹침 없이** 같은 위치에 안정적으로 모이면 테이블 위치로 등록합니다. 현장(필드 6일)에서 식탁 검출 점수 중앙값 0.28·최대 0.40이라 기존 기준 0.55로는 **한 번도 등록되지 않았습니다.** 지금 기본값은 `table_confidence=0.28`이며, 60초마다 `table_mapping progress elapsed/seen/max_score/threshold/candidates/best_hits`를 로그에 남기고 30분 넘게 등록되지 않으면 원인(검출 없음 / 점수 미달 / 위치 불안정)을 알립니다. 실제 등록 성공률은 현장에서 재측정하지 못했습니다. 주의: 실제 적용 기준은 `max(table_confidence, object_confidence)`입니다.

### 4.7 잔류물·표면

"변한 채 그대로 있는 것"을 이상 신호로 봅니다. 쓰레기 종류를 분류하지 않고 "남아 있다"는 사실만 봅니다. 사람이 없고 화면이 멈추면 스스로 기준을 잡고(`*_auto_capture`), 표면 감시가 켜져 있으면 기존 잔류물 경로는 건너뜁니다.

### 4.8 모델

| 용도 | 파일 | 입력 | 상태 |
|---|---|---|---|
| 사람+관절(Tier 1) | `models/yolo11n-pose-416x224.onnx` 등(화면 비율별 자동 선택) | 416×224 | 배포 |
| 물건·동물(Tier 2) | `models/yolo11n_tier2_fp32.onnx` | 320 | 배포 |
| Tier 2 후보 R416 | 416으로 재학습 | 416 | **평가만 완료**(교체 안 함) |

- **FP32를 씁니다.** 이 CPU(Haswell)에서 INT8은 FP32보다 느렸고 일부 경우 점수가 무음으로 0이 되는 현상이 있습니다.
- **R416**: v3 val mAP50 0.508 → 0.558, 병·컵 재현율 +7~8%p, 식탁 박스 정확도 회복. 지연은 개발 PC 기준 10.5 → 17.3ms(×1.65)이고 **i5-4200U 실측은 없어** 교체하지 않았습니다. 자세한 표는 [성능 전후 비교](performance-before-after-2026-11-06.md).
- **클래스별 NMS**: 서로 다른 클래스의 겹친 박스(의자+식탁, 동물+가구)를 서로 지우지 않도록 같은 클래스끼리만 억제합니다(`postprocess.c`). Tier 1은 클래스가 하나라 동작이 같습니다.
- HomeObjects-3K 추가 학습은 이득이 없어 채택하지 않았습니다([상세](tier2-homeobjects-before-after-2026-10-25.md)).

## 5. 개인정보 보호

### 영상은 기기 밖으로 나가지 않습니다

분석·판단·저장 전부 매장 컴퓨터 안에서 끝납니다. 외부 서버로 보내지 않습니다. 대시보드 폰트도 로컬에서 서빙해 외부 요청이 0입니다.

### 보호 모드와 가림 화면 모양

`stream_privacy_mode=1`(매장 기본)이면 처리가 끝난 뒤 **그리기 직전에 프레임을 가리고** 박스·스켈레톤만 그립니다. 스트림·스냅샷·출력 파일·쓰러짐 증거 사진이 모두 이 가려진 프레임을 소비하므로 **원본 픽셀은 프로세스 밖으로 나가지 않습니다.** 분석은 가리기 전에 끝나므로 감지 정확도에는 영향이 없습니다.

가림 화면 모양은 `stream_privacy_style`로 고릅니다.

| 값 | 모양 | 특징 |
|---|---|---|
| **0 단색(기본)** | 어두운 회색 + 박스·뼈대 | 가장 안전. 어디서 무슨 일이 있는지 알아보기 어렵습니다 |
| **1 엣지 그레이** | 그레이스케일 + 강한 모자이크·가우시안 배경 위에 **엣지(윤곽선)** + 박스·뼈대 | 방 구조·가구·문의 윤곽이 보입니다 |
| **2 열화상** | 1과 같은 배경·엣지에서 **배경 밝기를 색**(어두움=검정·보라, 밝음=주황·노랑)으로 바꾸고 박스·뼈대 | 밝은 곳과 어두운 곳이 색으로 구분되어 한눈에 보입니다. 색은 흐려진 밝기에서만 나오므로 원본 색상 정보는 없고 비식별 수준은 1과 같습니다 |

**엣지 그레이의 처리 순서** (`src/privacy_style.c`, 정수 연산, 외부 라이브러리 없음)
1. 그레이스케일 → 2) 배경: 칸 단위 박스 평균(모자이크, 기본 24px) → 축소 이미지에서 가우시안 → 쌍선형 확대
3. 엣지: 원본을 가우시안으로 `privacy_edge_blur`번(기본 8) 흐린 뒤 → Sobel → 기울기 방향 비최대 억제 → 이력 임계(`privacy_edge_low/high` 40/110)
4. 선을 `privacy_edge_soft`번(기본 1) 번지게 하고 `privacy_edge_opacity`(기본 70%) 농도로 배경 위에 흰색을 섞음. 모든 픽셀이 R=G=B라 색 정보가 남지 않습니다.
5. 렌더가 실패하면 단색으로 덮어 원본이 남지 않습니다.

**CPU 비용 관리**: 엣지 렌더는 프레임 전체를 계산하므로 보는 사람이 없으면 1초에 한 번만, 있으면 `privacy_style_fps`(기본 5)회/초까지 렌더하고 나머지 프레임은 캐시를 복사합니다. 개발 PC(1280×720)에서 한 장 38ms(기본값), 1080p 실행에서 프레임당 CPU +14ms(5회/초)였습니다. 단색은 +0입니다. **i5-4200U는 미측정**입니다([성능 비교](privacy-style-performance-2026-11-06.md)).

**한계(꼭 알아 두세요)**: 엣지는 약하게 흐린 원본에서 뽑으므로 **얼굴 윤곽선과 간판 글자 일부가 읽힙니다.** 앞선 실험에서 pose 모델이 엣지 이미지에서 얼굴 키포인트를 일부 검출했습니다. 그래서 코드 기본값은 단색이며, 이 스타일이 비식별로 충분한지는 매장 정책과 법적 판단으로 정해야 합니다.

### 임시 해제

설정 작업(문 영역, 기준 사진)이 필요하면 **"설정용 임시 해제"**로 잠깐만 실제 화면을 봅니다(`POST /privacy/unlock?seconds=N`). 시간이 지나면 **서버가 알아서 다시 잠급니다**. 보호 모드 중에는 저장된 기준 사진(`/door/preview`, `/surface/reference`)이 403으로 막히고 `door/save`·`residue/save`는 409입니다.

### 접근 제어

| 접속 위치 | 볼 수 있나 | 설정 바꿀 수 있나 |
|---|---|---|
| 매장 컴퓨터 자체(localhost) | 가능 | 가능 |
| 같은 매장 네트워크(점주 폰 등, 같은 서브넷) | 가능 | PIN 필요(미설정이면 가능) |
| 그 외 | 차단(403) | 차단 |

PIN은 IP당 5회 실패 시 10분 잠금입니다. 모든 접속·변경·차단이 이벤트 로그(`module=access`)에 남습니다. **통신은 평문 HTTP**라 같은 네트워크 안의 도청은 막지 못합니다. 손님용 Wi-Fi와 분리하는 것이 실질적 방어선입니다. 코드: `src/netaccess.c`.

### 알아두실 점

- 문 자동 촬영은 "아무도 없을 때 = 문이 닫혀 있다"를 전제합니다. 문을 열어두고 영업하는 매장에서는 꺼야 합니다.
- 카메라가 흔들리거나 각도가 바뀌면 기준 사진이 무효가 됩니다. 다시 촬영하세요.
- 미주문 착석 감지는 키오스크 위치를 지정해야 동작합니다.
- 기존에 `table_confidence`가 0.55로 저장된 매장은 0.28로 바꿔야 합니다.
- 휠체어·보조기구 사용자에서 `person_unaccounted`(그림자)가 발생할 수 있습니다.
- `run.bat`은 아직 INT8 우선 선택일 수 있으니 실행 경로의 모델 파일명에 `int8`이 없는지 확인하세요(`run-all.ps1`은 FP32 우선).

## 9. 설계 원칙과 성능

### 설계 원칙

1. **규칙이 먼저, AI는 최소한.** "1시간 넘게 앉아 있다"는 시계만 보면 압니다. AI는 찾는 데만 씁니다. 이상행동 확장에서도 같은 원칙을 지켜, 1차 룰로 분리가 안 되는 항목만 2차 AI 후보로 올립니다.
2. **조용히 실패하지 않기.** 기능이 멈췄는데 아무도 모르는 상황이 가장 위험합니다. 정상일 때도 안 될 때도 이유와 함께 기록하고, "기준 사진이 없습니다", "영역 안에 움직임이 계속됩니다"처럼 무엇을 해야 하는지까지 적습니다.
3. **매장마다 다르게.** 체류 허용 시간, 민감도, 켜고 끌 기능, 알림 모드를 전부 설정으로 바꿉니다(대시보드, 재시작 불필요).
4. **틀린 답보다 "모르겠다"가 낫습니다.** 문이 가려지면 판단을 보류하고, 소실은 "쓰러짐"이라 단정하지 않습니다.

### 키오스크를 방해하지 않기

이 프로그램은 키오스크의 **보조**입니다. 두 겹으로 막습니다.
1. 시작할 때 운영체제 우선순위를 낮춥니다(키오스크가 일하면 우리가 양보).
2. 2초마다 **"우리를 뺀 나머지"**의 CPU 사용률을 보고, 50%↑이면 추론을 2배 덜 자주, 70%↑이면 4배 덜 자주(Tier 2 정지·화면 전송 절반), 85%↑이면 AI를 멈추고 카메라 감시만 합니다. 단계가 바뀔 때마다 기록하고, 한 번 내려간 단계는 부하가 충분히 떨어져야 풀립니다.

예약 재시작(기본 꺼짐)은 요일·시각을 정해 두면 손님이 없을 때만 껐다 켭니다(1시간 안에 비지 않으면 그날은 건너뜀). 그 밖의 절감: 화면이 안 변하면 건너뛰기, 감시 제외 구역, 영업시간 밖에는 감시만, 보는 사람이 없으면 그리기 생략, 물건 찾기는 가끔만.

### 측정값 (개발 PC i7-8700, 배포 대상 아님)

| 설정 | AI 1회 시간 |
|---|---:|
| 정사각형 입력(416×416) | 26.7 ms |
| **화면 비율에 맞춘 입력(416×224)** | **14.0 ms** |
| INT8 양자화, 정사각형 | 46.1 ms (FP32보다 느림) |

화면 비율에 맞추는 것만으로 거의 2배 빨라지고, 이 CPU에서는 INT8이 오히려 느려 FP32를 씁니다. 새 하드웨어에 배포한다면 `scripts/bench-models.ps1`을 한 번 돌려 다시 재세요.
