## 작업 내역

### 1. 신뢰도 히스테리시스 도입 (`include/tracks.h`, `src/tracks.c`, `src/main.c`)

- `TrackList`에 `new_track_min_score` 필드 추가
- 감지기 threshold 0.20, 신규 트랙 생성 threshold 0.30으로 분리
  - 이미 추적 중인 트랙: 0.20 이상이면 유지 (안정적 추적)
  - 신규 트랙 생성: 0.30 이상만 허용 (오탐 억제)
- `fall_sudden` 트리거 조건 강화: velocity > 0.5/s AND 위치 임계값 초과 (AND 조건)

### 2. MISS 박스 표시 제한 (`src/draw.c`)

- 프레임 밖 트랙(MISS)은 내부적으로 150프레임(10초) 유지하되 화면에는 15프레임(~1초)만 표시
- 주황 MISS 박스가 10초간 쌓이던 시각적 혼잡 제거
- fall detection에는 MISS 상태를 계속 활용

### 3. DirectShow 버퍼 오버플로우 수정 (`src/media_ffmpeg.c`)

- dshow 연결 시 MJPEG 우선 시도 → 실패하면 YUY2 재시도
  - MJPEG: USB 대역폭 1~3MB/s (YUY2 대비 10배 절감)
  - rtbufsize 30M → 60M (MJPEG 기준 약 20~60초 버퍼)
- `avformat_flush` / `avcodec_flush_buffers` 제거 — dshow에서 no-op이며 스톨 유발

### 4. 캡처 스레드 분리 (트리플 버퍼) (`src/media_ffmpeg.c`)

- `LiveCapture` 구조체 + 전용 캡처 스레드 구현
  - Windows: `CRITICAL_SECTION` + `CONDITION_VARIABLE`
  - POSIX: `pthread_mutex_t` + `pthread_cond_t`
- 트리플 버퍼(`write/fresh/read` 인덱스) — 처리 스레드가 항상 최신 프레임 획득
- YOLO 추론이 400ms 걸려도 영상 타임스탬프 드리프트 없음
- 카메라 입력만 별도 스레드; 파일 입력은 기존 단일 스레드 루프 유지

### 5. Tier 2 실행 조건 버그 수정 (`src/main.c`)

Codex 검토 문서(2026-09-10-feasibility-review.md)에서 발견된 버그:

```c
// 수정 전 (항상 false — Tier 2 단 한 번도 실행 안 됨)
(frame_index + 45) % 90 == 0 && frame_index % 5 != 0
// 45, 135, 225... 는 모두 5의 배수 → 두 번째 조건 항상 실패

// 수정 후
frame_index % detect_every_obj == 0
```

→ 이제 90프레임(약 3초)마다 Tier 2 실제 실행

### 6. Tier 2 바운딩 박스 카테고리별 표시 제어 (`include/yolo11.h`, `src/draw.c`, `src/main.c`, `dashboard/`)

- `OBJ_VIS_ANIMAL / FOOD / DRINK / FURNITURE` 비트마스크 상수 추가
- `draw_obj_detections()` 시그니처에 `uint32_t obj_vis_mask` 파라미터 추가
- CHAIR / DININGTABLE 하드코딩 skip 제거 → mask 비트로 제어
- `AppContext.obj_vis_mask` 필드 추가, 기본값 `OBJ_VIS_ALL`
- config.json `show_animal / show_food / show_drink / show_furniture` 키로 hot-reload
- 대시보드 설정 탭에 "Tier 2 바운딩 박스 표시" 섹션 추가 (토글 4개)
- `dashboard/server.c` DEFAULT_CONFIG에 4개 키 기본값(1) 추가

### 7. SlotMonitor 통합 (`src/slot_monitor.c`, `src/main.c`)

- 슬롯 기반 테이블·의자 청결 감지 모듈 완성
  - Tier 2 가구 bbox → 슬롯 생성 (ID: class×10000 + gx×100 + gy, 32px 그리드)
  - RGB crop → 8×8 블록 luma diff → dirty 판정
  - 자동 baseline 캡처 (사람 IoU < 0.10인 경우)
  - 자동 재학습 (clean_since + auto_relearn_seconds 경과)
  - 이벤트: `slot_no_baseline`, `slot_item_warning`, `slot_item_urgent`, `slot_cleared`
- `main.c`에서 Tier 2 실행 후 `slot_monitor_update()` 호출

### 8. Tier 2 데이터셋 레이블 오매핑 발견 및 분석

정적 추론 테스트(`test_tier2.py`)로 인스턴스 수를 집계한 결과,
레이블 파일 전체가 COCO category_id 리매핑 오류로 잘못된 클래스를 가리킴:

| 데이터셋 레이블 | 학습한 실제 물체 |
|---|---|
| bottle (3,276개) | 야구 방망이 (COCO baseball bat) |
| apple (20,650개) | 컵 (COCO cup) |
| cat (9,838개) | 벤치 (COCO bench) |
| chair (7,308개) | 브로콜리 (COCO broccoli) |

→ mAP50 29.8% + 실제 bottle/chair/table 감지 불가의 근본 원인
→ `docs/2026-09-10-tier2-dataset-labeling-issue.md` 작성

### 9. 런타임 스크립트 조정 (`run.bat`, `run-all.ps1`)

- `--confidence 0.20` (감지기 threshold)
- `--detect-every 5` (lag 감소)
- `--threads 3` (i5-4200U 3스레드 예산)
- Tier 2 INT8 모델 우선 탐색 추가

## 기술 결정 사항

| 항목 | 결정 | 이유 |
|---|---|---|
| 신뢰도 분리 | 감지 0.20 / 신규 트랙 0.30 | 추적 안정성 유지하면서 오탐 신규 추가 억제 |
| MISS 표시 시간 | 15프레임(~1초) | 10초간 주황 박스 누적 → 시각적 혼잡 |

| Slot ID | `class × 10000 + gx × 100 + gy` | 32px 그리드로 YOLO 지터 흡수, 인접 의자 구분 |
