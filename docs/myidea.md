# 기능별 구현 아이디어

> 원칙: 룰 기반으로 처리 가능한 건 YOLO 추론 없이 처리. AI는 룰로 판단 불가한 예외에만 위임.

---

## 출입문 열림 감지

**원안 평가: ✅ 현실적이고 정확한 방향**

문은 카메라가 고정되어 있으므로 배경 비교가 가장 가볍고 효과적이다.

**구현:**
- 설치 시 문이 닫힌 상태 기준 이미지(배경) 저장
- 매 프레임에서 문 ROI 픽셀과 기준 이미지 차분 → 변화량이 임계값 초과 시 "열림" 판정
- 이후 N초 이상 열린 상태 지속 → 알람 (에어컨 가동 중일 때만 알람하는 조건 추가 가능)

**YOLO 불필요.** OpenCV frame difference 수준으로 충분.

---

## 시럽 펌프 과다

**원안 평가:**
- 아이디어 1 (시럽 잔량 측정): ⚠️ 용기 내부를 카메라로 정량화하기 어려움. 조명·각도에 따라 부정확. 현실적으로 어려움.
- 아이디어 2 (손 keypoint 펌핑 횟수): ✅ 가장 현실적. 채택 권장.
- 아이디어 3 (다른 용기 감지): ⚠️ YOLO는 cup/bottle을 감지하지만 "매장 컵이냐 아니냐"를 구분할 방법이 없음. 방향은 맞으나 오탐 많을 것.

**구현 A — 잔량 레벨 측정 (조건부 가능):**
- 전제: 시럽 용기가 투명하고 카메라 측면에서 용기가 보일 것
- 시럽 용기 ROI 고정 → HSV 색상 범위로 시럽 픽셀 추출
- 색상 픽셀 최상단 y좌표 = 현재 잔량 레벨로 환산
- 사람이 가릴 때는 건너뛰고(배경 차분으로 가림 여부 판단), 사람이 떠난 직후 측정
- 기준 레벨 대비 급감 감지 → "과다 사용" 또는 "잔량 부족" 알람

**구현 B — 손 keypoint 펌핑 횟수 측정:**
- 시럽 펌프 ROI에 손목 keypoint가 진입하면 추적 시작
- 손목 Y좌표 오르내림 횟수 카운팅 → N회 초과 시 알람

두 방법을 조합하면 정확도가 높아진다 (횟수로 1차 감지, 잔량으로 크로스체크).

## 사람 쓰러짐

**원안 평가: ✅ 가장 현실적이고 검증된 방법. 그대로 진행.**

**구현:**
- YOLO11n-pose keypoint 사용
- 머리·어깨·엉덩이 y좌표가 거의 같은 수평선상에 위치 → 쓰러진 자세
- 보조 조건: bbox 가로/세로 비율 (서있으면 세로 > 가로, 누우면 가로 > 세로)
- 위 조건이 N초 이상 지속될 때만 알람 (잠깐 엎드린 것과 구분)

---

## 동물 의자·책상 착석

**원안 평가: 아이디어 없음 → 아래 제안**

YOLO가 이미 dog/cat class를 감지하므로 추가 모델 불필요.

**구현:**
- 설치 시 의자·테이블 ROI 영역 지정 (다각형 또는 사각형)
- YOLO가 dog/cat bbox 감지 → 해당 bbox 중심이 의자/테이블 ROI 안에 있으면 알람
- "바닥이 아닌 가구 위에 있는 동물" 조건이므로 bbox 하단 y좌표가 바닥 기준선보다 위에 있는지 추가 확인 가능

---

## 노키즈존

**원안 평가: 아이디어 없음 → 아래 제안**

얼굴 나이 추정 모델을 추가하는 것은 i5-4200U에서 부담이 크다. 경량 룰 기반을 먼저 적용한다.

**구현 (단계적):**

1단계 (룰 기반, 추가 모델 없음):
- 서있는 사람의 bbox 높이를 기준물(테이블, 의자 ROI)과 비교해 키 추정
- 키가 일정 비율 이하 → 어린이로 분류
- 오탐 가능성 있으나 알람 트리거용으로는 충분

2단계 (모델 추가 시):
- MiVOLO 또는 InsightFace Age Estimation (경량 버전) 추가
- 얼굴 bbox에만 부분 추론 → 전체 추론보다 부하 낮음
- 나이 추정 결과가 N세 이하일 때 알람

---

## 구토

**원안 평가: 아이디어 없음 → 아래 제안**

가장 구현이 어려운 항목이다. 완벽 감지는 어렵고 오탐 가능성이 높아 "주의 상황" 플래그로 처리하는 것이 현실적이다.

**구현 (간접 신호 조합):**
- keypoint: 머리 y좌표가 무릎 y좌표와 급격히 가까워지고 N초 지속 (앞으로 급격히 구부러진 자세)
- 보조: bbox 폭이 갑자기 넓어지고(구부릴 때 몸이 퍼짐) 세로가 짧아짐
- 위 조건 충족 → "이상 자세 감지" 로그 + 담당자 알람 (구토라고 단정 짓지 말고 확인 요청)
- 바닥에 새 얼룩이 생기는 것(배경 차분)은 카메라 각도에 따라 보조 가능

---

## 쓰레기 투기

**원안 평가: 아이디어 없음 → 아래 제안**

쓰레기를 "던지는 동작" 자체를 감지하기보다, "쓰레기통이 아닌 위치에 쓰레기가 생겼는지"를 보는 것이 더 현실적이다.

**구현:**
- 쓰레기통 ROI 설정
- 테이블·바닥 배경 이미지 저장
- 사람이 떠난 후 해당 영역 배경 차분 → 새 물체(쓰레기)가 남아있으면 알람
- 보조: 쓰레기통 ROI 방향이 아닌 곳으로 팔을 뻗는 동작 (손목 keypoint 이동 방향) 감지 가능하나 복잡도 높음

---

## 기물 파손

**원안 평가: 소리 활용 → ✅ 좋은 아이디어. 시각과 조합 권장.**

**구현:**
- 청각: 마이크 입력에서 급격한 충격음(dB 임계값 초과) 감지 → 해당 순간 전후 시각 프레임 저장 및 확인 트리거
- 시각: 급격한 팔 동작(손목 keypoint 속도가 임계값 초과) + 직후 바닥에 새 물체 출현(배경 차분)
- 두 신호가 동시에 나타날 때만 알람 → 오탐 감소

---

## 미주문 착석 (원안에 없음)

**구현:**
- 결제 DB와 연동: 입장(트래커 ID 최초 감지 시각) 기록 → N분 내 결제 이벤트 없으면 "미결제 착석" 알람
- 결제 DB 연동이 어려운 경우: 키오스크 ROI에 사람이 N초 이상 서있는 이벤트가 없으면 미결제로 추정 (보조)
- 1인당 1메뉴 미구입: 입장 인원수(트래커 카운트) vs 결제 수량 비교

---

## 초과 체류 (원안에 없음)

**구현 (완전 룰 기반, 가장 구현하기 쉬운 항목):**
- Tracker ID별 입장 시각 기록
- 결제 횟수 × 점주 설정 허용 시간 = 체류 허용 한도
- 한도 초과 시 알람 (점주가 UI에서 1잔 = 몇 분으로 설정)
- YOLO 추론 없이 트래커만으로 처리 가능

---

## 외부 음식 반입 (원안에 없음)

**구현:**
- 입장 시 손에 들고 오는 물체 감지 (YOLO: bottle, cup, bag, backpack 등)
- **매장 컵은 항상 카운터에서 나온다는 전제를 이용**
- 카운터 ROI 설정 → 카운터 ROI를 거치지 않고 테이블에 처음 등장한 cup/bottle = 외부 음식 의심
- 입장 직후 손에 이미 들고 온 cup/bottle도 동일하게 처리
- COCO cup 클래스가 매장 컵/외부 컵을 구분하지 못하므로, 위치 기반 룰로 처리하는 게 현실적
- (선택) 매장 컵 커스텀 학습 → 이진 분류기 추가. 단 매장마다 컵이 달라 배포 시 번거로움

---

## 카메라 장애 (원안에 없음)

**구현 (YOLO 불필요, 프레임 분석만으로 처리):**
- 백화 현상: 프레임 평균 밝기가 임계값 초과 시 → "렌즈 백화 의심" 알람
- 암전: 평균 밝기가 임계값 미만 시 → "카메라 차단 또는 전원 이상" 알람
- 렌즈 가림: 연속 N프레임 동안 픽셀 변화량이 거의 없고(정지 화면) 사람 감지도 없는 경우 → "카메라 가림 의심"
- 연결 끊김: 프레임이 아예 들어오지 않으면 → "카메라 연결 끊김" 알람
