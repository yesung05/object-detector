## 2. 오늘 작업의 배경과 목표

학교와 집에서 동일 프로젝트를 번갈아 사용하면서 문 위치, 테이블 영역, 기준 이미지, 안정화 결과가 이전 장소의 상태로 남는 문제가 있었다. 설정 화면도 여러 페이지로 흩어져 있었고, 자동 영역 매핑 결과와 초기화 상태를 확인하기 어려웠다.

추가로 실제 기기에 약 2주간 설치해 성능과 오탐을 검토할 계획이 있으나, 원본 카메라를 직접 볼 수 없다는 제약이 있었다. 이에 좌표·스켈레톤 기반 사건 재생과 성능 기록을 추가하고, 동일 환경을 쉽게 설치할 수 있도록 설치본을 만들었다.

## 3. 설정 화면과 장소 초기화

### 3.1 설정 구성 정리

대시보드 설정을 다음 범주로 정리했다.

| 범주 | 주요 내용 |
|---|---|
| 감시 장소 | 문 설정·자동 위치 판정·테이블 영역·배경 안정화·장소 초기화 |
| 알림 조건 | 사람/물체 감지 임계값, 새 사람 추적 시작 조건, 테이블 확정 조건 등 |
| 영상·개인정보 | 영상 표시와 개인정보 관련 기존 설정 |
| 자동 관리 | 운영 및 현장 시험 기록 진입 |

- 설정 그룹을 이동할 때 아직 저장하지 않은 입력을 불필요하게 다시 읽어 덮어쓰지 않도록 정리했다.
- 기존 설정을 다시 불러오는 동작은 사용자가 이해할 수 있도록 ‘변경 취소’로 표현했다.
- 저장할 때 서버의 현재 전체 설정을 읽고 UI 변경값을 합쳐 전송하도록 했다. 기존 서버의 부분 병합 과정에서 문자열 값이 손상될 수 있던 경로를 피한다.
- 초기 이미지 이벤트에서 아직 정의되지 않은 핸들러를 호출하는 브라우저 오류를 방어했다.
- 모바일 설정 화면의 가로 넘침과 주요 입력 동작을 확인했다.

### 3.2 기존 영역 에디터와 통합

- `/surfaces`의 테마를 대시보드와 일관되게 정리했다.
- 설정의 감시 장소 화면으로 돌아가는 경로를 제공한다.
- 수동 영역 입력은 필요한 경우 펼쳐 사용할 수 있게 했다.
- `/surfaces?view=1`에서 현재 영역을 확인하는 읽기용 흐름을 제공한다.
- 자동 테이블 결과와 수동 설정이 서로 덮어쓰지 않도록 소스와 영역 revision을 구분한다.
- 새 장소에서 자동 매핑할 대상은 테이블이다. 벽 자동 매핑은 이번 요구 범위에서 제외했다.
- 설치본에는 개발 환경의 ‘테이블 1 / 벽 1 / 벽 2’ 같은 기존 영역 데이터를 넣지 않는다.

### 3.3 초기화와 보존을 구분

| 동작 | 의도 |
|---|---|
| 장소 초기화 | 이전 장소의 문·테이블·기준/안정화 정보를 새 장소에 맞게 다시 시작 |
| 문 위치 초기화 | 자동 위치 후보 및 저장된 위치/연관 기준을 다시 학습 |
| 테이블 자동 초기화 | 기존 테이블을 비운 뒤 자동 매핑을 다시 시작 |
| 테이블 수동 초기화 | 영역을 비우고 수동 설정 상태로 시작 |
| 프로그램 재설치/업데이트 | 사용자 설정·기록을 유지하고 프로그램 파일 교체 |
| 프로그램 제거 | 프로그램 파일 제거, 사용자 데이터 보존 |

장소 초기화는 현장 인식 상태를 다시 학습하는 기능이다. 설치/제거 시 기록까지 지우는 정책과는 별개이다. 재설치는 장소 초기화를 대신하지 않는다.

## 4. 문 위치 및 기준 이미지 자동 학습

### 4.1 기본 상태와 표시

- 문 감지는 기본 ON이다.
- 문 위치가 없는 상태와 위치를 확보했지만 기준 이미지를 학습하는 상태를 구분했다.
- 위치가 잡혔는데 계속 ‘초기화 중’만 표시되던 혼동을 줄이기 위해 현재 학습 단계를 보여준다.
- AI가 문 후보로 선택한 위치와 위쪽 비교 영역을 확인할 수 있다.
- 자동 판단 외에 수동 위치 지정 경로도 유지한다.

### 4.2 사람 통행으로 문 위치 추정

사람의 출현·이탈 위치를 추적해 같은 구역에서 통행이 반복되는지 판단한다.

- 동일 후보에 통행 관측이 최소 6회 필요하다.
- 진입과 이탈이 각각 최소 2회 필요하다.
- 시작 직후 관측, 충분히 이동하지 않은 사람, 정지한 사람을 문 근거로 바로 사용하지 않는다.
- 오래 갱신되지 않은 후보는 만료한다.
- 확정한 위치는 `door_location.json`으로 저장한다.
- 사람의 머리보다 위쪽까지 후보 영역을 확장해 문의 상단을 비교할 공간을 확보한다.

이 기능은 통행 위치로 문을 추정한다. 통행이 거의 없거나 추적이 자주 끊기는 환경에서는 확정이 늦어질 수 있다.

### 4.3 통과 시점의 기준 이미지 학습

사용자가 제안한 ‘사람이 문을 통과할 때 문 위쪽을 비교’하는 흐름을 구현했다.

1. 사람이 없는 안정된 장면을 약 20초 확보한다.
2. 사람이 통과하면서 문의 상단 비교 영역에 변화가 있는지 확인한다.
3. 머리나 몸이 비교 영역을 가리는 구간은 학습 근거에서 제외한다.
4. 사람이 지나간 뒤 장면이 다시 안정되는지 확인한다.
5. 일치하는 왕복 변화가 2회 확인되면 기준 쌍을 함께 확정한다.

구현상 비교 영역 기본 비율은 문 ROI 상단의 약 20%이다. 장면 전체의 조명 변화와 문 부분의 변화를 구분하는 검사, 프레임 간격/시간 초과 시 사이클 초기화도 포함했다.

변화한 문 상단을 빈 장면의 기준에 합성하는 방식을 사용해 통과한 사람을 열린 문 기준에 그대로 남기지 않도록 했다.

### 4.4 문 기능 검증과 한계

- 정상 학습, 가림, 정지, 조명 변화 등 관련 단위 시나리오를 검증했다.
- 같은 위치를 다시 읽을 때 불필요하게 기존 기준을 지우지 않도록 했다.
- 위치가 달라지면 오래된 기준을 재사용하지 않는다.
- 최초 안정 장면을 닫힘 쪽 기준으로 해석하는 휴리스틱이 남아 있다. 실제 문의 의미상 열림/닫힘을 모든 환경에서 보장하는 분류기는 아니다.
- 이번 작업 중 실제 현장의 통행을 충분히 수집해 자동 기준 학습 완료까지 확인한 것은 아니다.

## 5. 테이블 자동 매핑과 10분 안정화

### 5.1 테이블 자동 매핑

- Tier 2의 dining table 결과를 사용한다.
- 기본 테이블 확정 임계값은 0.55이다.
- 후보가 최소 5회 관측되고 약 10초 이상 안정적으로 유지되는지 확인한다.
- 반복 관측의 위치 겹침을 검사하고 오래된 후보는 만료한다.
- 자동 모드에서 영역이 비어 있으면 일반 모션 게이트와 별도로 약 2초마다 전체 프레임의 테이블 탐색을 수행한다.
- 확정한 테이블은 영역 설정과 revision으로 저장한다.
- 첫 영역 집합을 확정한 뒤 자동 탐색은 계속 영역을 재배치하는 방식으로 동작하지 않는다. 다시 잡으려면 초기화한다.
- 자동으로 잡힌 위치는 영역 확인 화면과 좌표 재생의 테이블 윤곽으로 확인할 수 있다.

수동 영역이 있으면 자동 모드 전환 시 명시적으로 비우는 흐름을 거친다. 위치 revision이 달라지면 오래된 표면 기준을 재사용하지 않는다.

### 5.2 최초 실행 시 안정화의 역할

- 배경 안정화 기본 시간은 10분이다.
- 유효한 `calibration.json`이 있으면 매번 처음부터 다시 학습하지 않고 재사용한다.
- 장소 초기화 후에는 새 환경에 맞게 다시 학습한다.
- 진행 시간·전체 시간·결과 구역 수를 상태에 노출한다.

이 안정화의 목적은 반복적인 배경 움직임 등 자동 무시 영역을 학습하는 것이다. 다음 기능을 대신하지 않는다.

| 구분 | 안정화가 수행하는가? |
|---|---|
| 배경의 반복 움직임을 감지에서 제외할 근거 수집 | 수행 |
| 테이블이라는 물체의 의미 인식 | 별도 Tier 2 자동 매핑 |
| 문 열림/닫힘 기준 학습 | 별도 문 통과 학습 |
| 현재 테이블이 깨끗한 상태인지 확정 | 보장하지 않음 |
| 침대를 사람으로 인식하는 문제를 자동 해결 | 보장하지 않음 |

## 6. 사람·물체 임계값과 주문 추정

### 6.1 감지 임계값 설정 추가

| 설정 | 기본 운영값 | 의미 |
|---|---:|---|
| 사람 감지 임계값 | 0.20 | 사람 감지 결과의 기준 |
| 물체 감지 임계값 | 0.20 | Tier 2 물체 감지 기준 |
| 새 사람 추적 시작 임계값 | 0.30 | 낮은 점수 후보가 바로 새 사람 트랙이 되는 것을 제한 |
| 테이블 위치 확정 임계값 | 0.55 | 테이블 자동 매핑 확정 기준 |

- 실제 새 트랙 기준은 사람 감지 기준과 새 트랙 기준 중 더 높은 값이다.
- 테이블 확정 기준도 물체 감지 기준과 테이블 기준 중 더 높은 값을 적용한다.
- 실행 중 설정을 바꾸면 감지기와 추적기의 관련 기준을 갱신한다.
- 당시 적용값은 상태 및 좌표 기록에도 남긴다.
- 검증 중 임시로 다른 값들을 적용한 뒤 원래 운영값으로 복구했다.

낮은 점수로 기존 사람의 추적을 유지하는 조건과 새 사람을 생성하는 조건은 다르다. 재생 기록에서도 유지 점수와 최근 실제 매칭 점수를 따로 확인할 수 있다.

### 6.2 약한 ‘아마 주문’ 상태

커피머신/결제 API가 연결되지 않은 상태에서, 카메라 가까이 오래 서 있는 사람을 확정 주문으로 처리하지 않도록 별도 상태를 추가했다.

현재 구현의 주요 조건은 다음과 같다.

- 사람 박스 높이가 프레임 높이의 65% 이상.
- 사람 박스 면적이 프레임 면적의 20% 이상.
- 사람 점수 0.60 이상.
- 상체가 서 있는 자세로 판단되는 관절 근거.
- 약 30초 연속 유지. 긴 관측 공백은 누적을 끊는다.

결과는 `TRACK_PROBABLY_ORDERED`로 기록하고, 이벤트에 `payment=unconfirmed`를 남긴다. 실제 주문 완료 상태와 구분하며 확정 결제 이력이 생긴 것으로 취급하지 않는다.

이 근접 조건은 현재 카메라 구도를 전제로 한 휴리스틱이다. 설치 높이·렌즈·거리 변화에 대한 현장 확인이 필요하다.

## 7. 쓰러짐 오탐 원인 수정

첫 점검에서 침대가 사람으로 감지된 사례와 `sudden_head_drop`이 신뢰도·유지시간을 우회하는 경로를 발견했으나 수정이 남아 있었다. 후속 지적을 반영해 이번 알파 빌드에서 공통 판정 조건을 적용했다.

| 이전 경로 | 수정 |
|---|---|
| 머리 템플릿 급강하로 즉시 발화 | 즉시 발화 제거, 공통 사람·관절·시간 근거 필요 |
| 넓은 박스만으로 쓰러짐 후보 | 양어깨·양엉덩이의 유효 위치와 몸통 방향 확인 |
| 유지된 높은 점수로 현재 낮은 점수 가림 | 검출 및 최근 매칭 점수 모두 0.5 이상 요구 |
| 오래된 관측으로 시간 누적 | 서로 다른 새 관측만 사용, 미매칭/공백 시 후보 초기화 |
| 처음부터 수평인 정지 형상 | 이전 서 있는 자세 이력을 요구 |

- 양어깨/양엉덩이 점수 0.5 이상, 박스 내 타당한 위치, 퇴화하지 않은 몸통 축이 필요하다.
- 동일 트랙에서 최소 1초/3회 서 있는 자세를 확인해야 한다.
- 그 이력 이후 30초 안에 수평 자세를 기본 5초/3회 이상 새로 확인해야 발화한다.
- 2초 초과 관측 공백과 카메라 단절은 유지시간을 다시 시작한다.
- 계속 수평이면 한 번만 발화하고, 신뢰할 수 있는 서 있는 자세로 회복하면 래치를 해제한다.
- 좌표의 `fall_gate`: 0 대기, 1 신뢰도 부족, 2 새 관측 부족, 3 관절 근거 부족, 4 서 있는 이력 미확인, 5 수평 유지 중, 6 확정. 재생 화면에도 표시한다.

낮은 점수 급강하, 처음부터 수평, 관절 없는 박스, 엉덩이 누락, 유지/현재 점수 불일치, 오래된 좌표 재사용, 미매칭, 박스 밖 관절, 중간 관측 단절의 9개 회귀 시나리오와 정상 전환/유지/중복 억제를 검증했다.

이 변경은 모델 재학습으로 침대→사람 박스 자체를 없앤 것이 아니다. **처음부터 누워 있는 사람, 관절이 가려지거나 낮은 점수로 검출되는 실제 사람은 확정하지 못할 수 있다.** 현장 오탐률/미탐률의 개선 수치는 아직 측정하지 않았다.

### 8.3 SQLite 구조

기존 이벤트 DB에 다음 테이블을 추가한다.

| 테이블 | 용도 |
|---|---|
| `replay_sessions` | 실행별 모델/빌드/환경 정보 |
| `replay_frames` | 시간별 좌표 및 상태 JSON |
| `replay_events` | 이벤트와 재생 시간 연결, 검토 상태/메모 |
| `replay_geometry` | 영역 revision별 당시 위치 |

기존 이벤트 INSERT가 성공한 뒤 기록기를 알리는 경로를 추가했다. 좌표와 사건을 기존 로그 파일 단위로 함께 분석할 수 있다.

### 8.4 재생 화면과 API

진입 경로는 `/replay`이다. 설정의 자동 관리 및 로그 화면에서 이동할 수 있다.

- 빈 배경에 박스·스켈레톤·문·테이블 윤곽을 그린다.
- 원본 이미지, MJPEG 스트림, 스냅샷을 요청하지 않는 재생 흐름이다.
- 실제 관측 시간 간격에 따라 재생하며 중간 위치를 보간하지 않는다.
- 오래된 추론 결과나 관측 공백을 표시한다.
- 이벤트 목록은 페이지로 이동할 수 있다.
- 최근 좌표 또는 선택한 사건 전후를 조회한다.
- 검토 상태는 미검토 / 정상 감지로 판단 / 오탐 의심 / 판단 불가이다.
- 한글 메모를 저장하고 선택 기록을 JSON으로 내보낼 수 있다.

| API | 용도 |
|---|---|
| `GET /api/replay/events?file=...&before=...` | DB의 사건 목록 및 세션 정보 |
| `GET /api/replay/frames?file=...&event=...` | 사건 전후 좌표와 영역 |
| `GET /api/replay/frames?file=...&session=...` | 해당 세션 최근 좌표 |
| `POST /api/replay/review?file=...&event=...&label=...` | 검토 분류와 메모 저장 |

파일명과 이벤트 ID 검증, 경로 이탈 방어, 준비된 SQL을 통한 메모 저장을 적용했다. 기존 대시보드 네트워크/PIN 접근 규칙을 따른다.

### 8.5 용량 제한과 개인정보 범위

- **이벤트 DB 파일 하나당 좌표 JSON 누적 1 GiB**를 상한으로 둔다.
- 전체 SQLite 파일 크기, 다른 로그, 여러 DB 합계의 상한이 아니다.
- 한도에 도달하면 좌표 저장을 중단하고 상태에 표시한다.
- 기존 기록 자동 삭제나 순환 보관은 구현하지 않았다.
- 사건 빈도가 높으면 2주 이전에 한도에 도달할 수 있다.
- 새 좌표 기록 기능 자체는 원본 이미지·영상 파일을 생성하지 않는다.
- 좌표 기록기가 활성화된 동안 기존 쓰러짐 JPEG 캡처는 생략한다.
- 문/표면 감지용 기준 이미지는 별도 기존 기능으로 유지된다. 프로그램 전체가 어떤 이미지도 저장하지 않는다는 의미는 아니다.
- 설정 전체나 접근 PIN은 좌표 기록에 넣지 않는다.
- 모델의 FNV-1a 식별값은 분석용 식별자이며 보안 해시가 아니다. 설치본 무결성 확인에는 별도의 SHA256을 사용한다.

좌표만 보고 실제 침대/사람 여부를 항상 확정할 수는 없다. 사용자 검토 라벨은 검증된 정답 데이터와 다르다. 실제 상황을 따로 확인할 근거가 없으면 미탐률도 계산할 수 없다.

## 9. 카메라 RAW 접근 관련 확인

이번 작업에서는 기존 접근 제한 코드를 확인했다. 새 외부 인증 체계를 구축한 것은 아니다.

- 기존 서버는 실제 소켓 상대 주소를 기준으로 loopback/같은 IPv4 서브넷을 허용하고 그 밖의 접근을 제한한다.
- LAN의 변경 요청에는 설정된 PIN 정책이 적용되며 localhost는 예외가 있다.
- 개인정보 잠금 상태에서는 화면/스냅샷과 원본 기준 이미지 접근에 기존 보호 로직이 적용된다.
- 일반적인 외부 직접 접속이 차단된다는 코드 근거와, 모든 네트워크 구성에서 RAW 접근이 절대 불가능하다는 보장은 다르다.
- 프록시/터널이 외부 요청을 localhost 요청처럼 전달하는 구성을 별도로 식별하는 강화는 하지 않았다.
- 개인정보 해제 상태도 사용자별 독립 세션이라고 볼 수 없다.
- 실제 외부망에서의 침투/접근 시험을 수행한 것은 아니다.

## 10. 트레이 실행과 로그 경로

- `unmanned_detector-launcher.exe`가 네이티브 Windows 트레이 아이콘과 실행 창을 제공한다.
- 창의 X/최소화는 트레이로 숨기며 감시를 유지한다. 브라우저를 닫는 것도 감지기를 종료하지 않는다.
- 트레이에서 대시보드, 실행 창, 설정·기록 폴더를 열 수 있다.
- **완전 종료**는 감지기에 named event 종료를 요청한다. 최대 10초 후에도 남으면 해당 런처 Job Object의 하위 프로세스만 정리한다.
- 중복 실행은 기존 창을 보여준다. 다른 운영 프로세스를 이름만 보고 일괄 종료하지 않는다.
- 카메라 1개는 자동 선택, 여러 개면 GUI에서 선택한다. 0개일 때는 기존 기본 카메라/재연결 경로를 사용한다.
- `start-installed.ps1`은 호환용 진입점이며 새 런처를 실행한다.
- 부팅/로그인 자동 시작과 Windows 서비스 등록은 포함하지 않았다.

| 경로 | 내용 |
|---|---|
| `%LOCALAPPDATA%\Programs\unmanned_detector` | 기본 프로그램 설치 폴더 |
| `%LOCALAPPDATA%\unmanned_detector` | 신규 설치 사용자 데이터 |
| 위 데이터 폴더의 `logs/날짜_시간.db` | 이벤트 및 좌표/관절/검토 |
| `logs/날짜_시간_perf.db` | 기본 60초마다 성능 기록 |
| `logs/launcher-날짜-시간.log` | 실행 출력·시작 오류 |
| `logs/restarts.log` | 감지기 재시작 이력 |
| `config.json`, `surfaces.json`, `door_location.json`, `calibration.json` 등 | 기능별 설정/학습 결과 |

`--data-dir`로 다른 경로를 지정하면 그 폴더 아래 logs에 기록한다. 이 PC에서 시험 후 재개한 감시는 기존 `G:\DMU\Contest\hunik\object-detector` 데이터를 사용한다. 이전 HUNIK 데이터 폴더는 삭제하지 않으며 필요하면 --data-dir로 지정할 수 있다.

업데이트 전에는 X로 숨기는 대신 완전 종료한다. 프로그램 제거는 사용자 데이터 폴더를 삭제하지 않는다. 설치본에 개발 설정/PIN/기존 촬영 자료/로그를 포함하지 않았다.

운영 모델은 FP32 포즈 416×224/416×288/416×416와 Tier 2 320×320 네 개이다. INT8/증류 실험 모델, 테스트 EXE, 이전 바이너리 백업은 제외했다. FFmpeg·ORT·CRT DLL을 앱 폴더에 포함한다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-installer.ps1
# 다음 알파 빌드 예
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-installer.ps1 -Version 0.1.0-alpha.2
# 이미 빌드한 바이너리로 패키징만, CTest는 수행
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-installer.ps1 -SkipBuild
Get-FileHash dist/unmanned_detector-Setup-0.1.0-alpha.1-x64.exe -Algorithm SHA256
```

필요하면 `-BuildDir`, `-FfmpegRoot`, `-OrtRoot`, `-VcRuntimeDir`, `-Iscc`를 지정한다. 기본 빌드는 x64/baseline 구성→clean-first Release 전체 빌드→CTest→선정 파일 스테이징→기동 확인→파일 SHA256 명세→설치 EXE→EXE 해시 순서다. `-SkipBuild`는 수정 소스를 자동 빌드하지 않으므로 일반 릴리스에서는 기본 명령을 사용한다.

기본 실행은 CPU 3스레드, 사람 감지 간격 5프레임, warmup 2, confidence 0.20, 스트림 8081, 대시보드 8080이다. 카메라 1280×720/30은 요청 모드이며 실제 처리 FPS와 다르다. baseline은 앱 빌드 설정으로, 모든 구형 CPU에 대한 외부 DLL 호환성 보증은 아니다.
