# 모델 구성 선택과 쓰러짐 오탐 개선 방안

작성일: 2026-09-10

## 핵심 권고

**사람·컵·병·동물 같은 객체 감지는 한 모델로 통합하고, 사람 자세를 분석하는 Pose 모델은 별도로 두는 방향을 권장한다.**

다만 당장은 모델 구성 변경보다 쓰러짐 판정 로직 수정이 우선이다. 현재 코드에는 정상 행동이나 추적 실패가 쓰러짐 알림으로 이어질 수 있는 경로가 있다. 모델 개수를 바꾸는 것만으로 이 문제가 해결되지는 않는다.

이 문서는 코드 검토에 따른 설계 제안이다. 실제 오탐 영상을 대조해 주원인을 확정하거나, 대상 i5-4200U에서 구성별 성능을 실측한 결과는 아니다. 구현 코드는 변경하지 않았다.

관련 선행 검토: [구현 현실성 및 개선 사항](2026-09-10-feasibility-review.md)

## 1. 모델 한 개와 두 개의 차이

사람의 위치를 찾는 객체 감지와 사람의 관절을 찾는 자세 추정은 서로 다른 작업이다. 일반 객체 감지 모델로 사람과 물체를 함께 찾을 수 있지만, 그 결과만으로 관절 위치까지 얻을 수는 없다. 현재 사용하는 COCO 기반 Pose 모델은 사람 관절을 추정하는 모델이다. [Ultralytics Pose 문서](https://docs.ultralytics.com/tasks/pose/)

| 구성 | 장점 | 단점 | 판단 |
|---|---|---|---|
| 객체 감지 1개: 사람+물체 | 한 번에 검출하며 구조가 단순함 | 관절 정보가 없음 | 쓰러짐이 중요하지 않으면 적합 |
| 현재 구조: 사람 Pose+물체 감지 | 사람 자세를 주기적으로 확보 | 두 모델의 영상 특징 추출 비용 발생 | 단기적으로 유지 가능 |
| 객체 감지+필요할 때 Pose | 일반 감지 통합, 자세 분석 빈도 조절 가능 | 의심 대상 선정과 스케줄 설계 필요 | 권장 방향 |
| 객체+관절을 모두 출력하는 커스텀 모델 1개 | 특징 추출 공유 가능 | 학습 데이터·출력 해석·검증 부담이 큼 | 현재 단계에서는 후순위 |

### 권장 구조

```text
영상 → 통합 객체 감지: 사람·컵·병·동물·가구
              │
              ├─ 인원·체류·물체 관련 규칙
              │
              └─ 사람 추적
                    ├─ 낮은 빈도의 자세 확인
                    └─ 이상 징후 시 Pose 집중 분석 → 쓰러짐 의심 판단
```

Pose를 이상 징후가 있을 때만 실행하면 첫 단계가 징후를 놓쳤을 때 자세 분석 자체가 실행되지 않을 수 있다. 따라서 **낮은 빈도의 정기 확인과 의심 시 집중 분석을 함께 사용**하는 편이 좋다.

### 사람 영역을 잘라서 Pose에 넣을 때의 주의점

사람 영역을 잘라 넣으면 사람이 크게 보여 관절 검출에 유리할 수 있다. 그러나 고정 입력 크기 모델은 작은 영역을 잘라도 추론 연산량이 그대로일 수 있다.

또한 사람마다 모델을 호출하면 인원이 늘수록 비용이 증가한다. 여러 명이 있을 때는 전체 영상에 Pose를 한 번 실행하는 방식과 비교해야 한다. 영역 자르기만으로 연산량 절감을 보장할 수는 없다.

### 현실적인 전환 순서

1. 현재 두 모델을 유지하면서 쓰러짐 로직과 Tier 2 실행 조건을 수정한다.
2. 사람을 포함한 통합 객체 모델과 현재 구성을 같은 영상으로 비교한다.
3. 실제 i5-4200U에서 CPU 사용량·알림 지연·미탐을 측정한 뒤 최종 구성을 결정한다.

검토 시점에는 Tier 2가 실행되지 않는 조건 문제가 있다. 따라서 현재 CPU 사용량을 정상적인 두 모델 구성의 비용으로 해석하면 안 된다. 상세 조건은 [선행 검토 문서](2026-09-10-feasibility-review.md)를 참고한다.

## 2. 현재 쓰러짐 오탐의 의심 원인

오탐 영상을 대조하지 않아 주원인을 확정할 수는 없지만, 코드에서 우선 확인해야 할 경로는 다음과 같다.

| 현재 코드의 동작 | 오탐으로 이어질 수 있는 이유 |
|---|---|
| `fall_sudden`이면 즉시 알림 | 머리 패치가 다른 위치에 잘못 붙어도 유지 시간 없이 발화 |
| `head_drop OR horizontal_pose` | 머리가 낮아진 것만으로도 쓰러짐 후보가 됨 |
| 추적 실패해도 기존 `head_valid` 유지 | 오래된 머리 위치를 현재 관측처럼 사용 |
| 관절이 부족하면 박스 비율로 대체 | 관측 품질이 나쁜 상황에서 박스 모양으로 판정을 계속함 |
| 과거 박스로 유지 시간 계산 | 새 영상으로 자세를 확인하지 못해도 쓰러짐 상태가 지속된 것으로 해석 가능 |

관련 코드:

- [src/rules.c](../src/rules.c): 검토 시점 372행 부근의 머리 하강·수평 자세·즉시 알림 분기
- [src/tracks.c](../src/tracks.c): 검토 시점 447행 부근의 머리 패치 추적과 실패 처리

줄 번호는 이후 코드 수정에 따라 달라질 수 있다.

### 임계값만 조정해서는 해결되지 않는 이유

현재 설정의 `fall_hold_seconds=5`를 10으로 올려도 `sudden_head_drop` 경로는 이 시간을 우회한다. 따라서 즉시 알림 경로의 오탐은 그대로 남는다.

박스 가로·세로 비율 임계값을 높이는 것도 머리 하강 경로에는 효과가 없다. 먼저 어떤 경로가 알림을 발생시키는지 구분해야 한다.

## 3. 오탐 개선 순서

### 3.1. 머리 하강을 확정 알림에서 재검사 요청으로 변경

머리 패치 추적은 사람의 머리라는 의미를 이해하지 않고 비슷한 픽셀 무늬를 찾는다. 빠르게 앉거나 물건을 줍는 행동도 머리가 내려가므로, 머리 속도 하나로 쓰러짐을 확정하면 안 된다.

```text
머리가 급격히 내려감
  → 쓰러짐 후보 등록
  → 새 프레임에서 Pose 재확인
  → 자세·위치·지속성이 함께 확인되면 알림
```

`sudden_head_drop`은 집중 검사의 트리거로 사용하고, 즉시 최종 알림을 내는 경로에서는 제외하는 방향을 권장한다.

### 3.2. 관측 불충분 상태 추가

관절이 안 보이거나 추적이 실패하면 정상도 쓰러짐도 아닌 `UNKNOWN`으로 처리해야 한다.

- 머리 추적 실패 시 유효 상태를 해제하거나 짧은 유효 시간을 적용한다.
- 관절이 부족하면 박스 비율만으로 최종 알림을 내지 않는다.
- 오래된 관측으로 쓰러짐 확인 시간을 채우지 않는다.
- 장시간 가림은 별도의 확인 불가 상태로 관리한다.

단, 관측이 끊길 때 후보를 바로 삭제하면 실제 쓰러짐도 놓칠 수 있다. **후보는 잠시 보존하되, 확인 근거는 누적하지 않는 방식**이 적절하다.

### 3.3. 한 장의 모양 대신 행동 변화로 판단

권장 상태 흐름:

```text
정상 → 쓰러짐 후보 → 재확인 중 → 쓰러짐 의심 알림 → 회복
                       │
                       └─ 관측 불충분 → 확인 유보
```

재확인에는 다음 근거를 조합한다.

- 어깨–엉덩이 축이 이전보다 크게 기울었는가?
- 몸통·엉덩이가 이전 위치보다 내려갔는가?
- 바닥에 가까운 자세인가?
- 새로 관측한 여러 시점에서 낮은 자세가 유지되는가?
- 다시 일어서거나 앉은 자세로 회복했는가?

모든 조건을 무조건 AND로 묶으면 천천히 주저앉는 상황을 놓칠 수 있다. 다음 두 경로를 별도로 설계하는 것이 좋다.

| 경로 | 판단 방향 |
|---|---|
| 급격한 낙하를 관측한 경우 | 낙하 후 자세와 지속성을 재확인 |
| 낙하 장면을 관측하지 못한 경우 | 낮은 자세의 지속과 바닥·신체 위치 관계를 확인 |

카메라 화면 아래쪽에 있다고 바닥에 누운 것은 아니다. 바닥·좌석 영역과 카메라 원근을 함께 고려해야 한다. 반대로 좌석 영역 전체를 제외하면 의자에서 쓰러지는 상황을 놓칠 수 있다.

### 3.4. 의심 상태에서 추론 생략 정책 조정

현재는 움직임이 적으면 추론을 건너뛴다. 쓰러진 뒤 움직이지 않는 상황에서는 재확인이 늦어질 수 있다.

쓰러짐 후보가 생기면 일정 시간 동안 재검사 빈도를 높여 최신 관측을 확보해야 한다. 빈도는 대상 기기의 처리 시간을 기준으로 정한다. 다른 사람과 기능의 처리가 계속되도록 시간 예산도 제한해야 한다.

### 3.5. 실제 오탐 영상으로 기준 결정

학습 모델을 추가하기 전에 현재 오탐을 다음 유형으로 분류한다.

- 의자에 앉기
- 허리 숙이기·물건 줍기
- 바닥 청소
- 사람끼리 겹치기
- 테이블에 몸이 가려짐
- 화면 밖으로 나가기
- 머리 패치가 배경으로 이동

알림마다 다음 정보를 기록하면 원인 경로를 확인할 수 있다.

| 기록 항목 | 목적 |
|---|---|
| `sudden_head_drop` | 급격한 머리 하강 분기 확인 |
| `head_drop` | 머리 위치만으로 후보가 되었는지 확인 |
| `horizontal_pose` | 수평 자세 분기 확인 |
| 관절 신뢰도 | 관측 품질 확인 |
| 마지막 유효 관측 이후 시간 | 오래된 상태 사용 여부 확인 |
| 트랙 ID | 사람 ID 변경과 오탐의 관계 확인 |

현재 `hold=...` 로그만으로는 머리 하강과 수평 자세 중 무엇이 원인인지 구분하기 어렵다.

그다음 실제 쓰러짐 사례와 함께 이벤트 단위 오탐 수·미탐률·알림 지연을 비교해야 한다. 단순히 알림을 줄이는 것만으로 개선 여부를 판단하면 안 된다.

## 4. 우선 구현할 변경

1. `sudden_head_drop` 즉시 알림을 제거하고 재검사 요청으로 전환한다.
2. 오래된 머리·관절·박스 관측을 무효화하거나 판단에서 유보한다.
3. 최신 Pose 관측을 이용한 재확인 상태를 추가한다.
4. 알림 원인과 관측 품질을 로그에 기록한다.
5. 정상 행동과 실제 쓰러짐 영상으로 오탐·미탐·지연을 비교한다.

이 변경 후에도 정상 행동과 쓰러짐이 잘 구분되지 않으면, 관절의 시간 흐름을 입력으로 사용하는 작은 행동 분류기를 검토한다. 그 경우에도 해당 매장의 촬영 각도와 정상 행동을 포함한 데이터 및 별도 평가가 필요하다.

## 5. 판단 시 유지할 원칙

- 모델 개수보다 실제 호출 빈도·입력 크기·대상 인원에 따른 총비용을 비교한다.
- Pose 검출 성공을 쓰러짐 판단 성공과 동일하게 보지 않는다.
- 관측 실패를 쓰러짐의 증거로 취급하지 않는다.
- 오탐 감소와 함께 미탐 증가 여부를 확인한다.
- 처리 성능과 감지 신뢰도는 실제 대상 장치와 매장 영상에서 검증한다.
