# 바닥·테이블·벽의 규칙 기반 오염 감지 설계

작성일: 2026-09-11
상태: 설계 제안. 구현 변경 및 현장 성능 검증 전.

## 1. 목표와 판단 범위

고정 카메라에서 보이는 바닥, 테이블 상판, 벽을 지정하고 각 표면에 새로 생겨 지속되는 변화를 찾아 관리 알림을 만든다. 표면 분리·변화 검출·지속성·기본 비치물 처리는 규칙 기반으로 수행한다. AI는 사람·동물 검출에 제한적으로 사용한다.

| 표면 | 감시 대상 | 기본 출력 |
|---|---|---|
| 바닥 | 토사물·쓰레기·동물 배설물·흘림 등으로 나타날 수 있는 새 잔류 변화 | 바닥 오염/잔류물 의심 |
| 테이블 상판 | 기본 비치물 외 새 물체·얼룩·흘림, 동물 | 청소 필요 의심, 동물의 상판 점유 의심 |
| 벽 | 새 얼룩·부착물·표면 변화 | 벽 오염/변경 의심 |

규칙만으로 토사물·배설물·음료·쓰레기를 신뢰성 있게 구분하지 않는다. 종류를 모르더라도 청소 필요 후보를 찾는 것이 1차 목표다. 평평한 얼룩처럼 보이는지, 물체 같은 경계가 생겼는지는 보조 속성으로만 기록한다.

단안 영상의 다각형 영역은 실제 표면 깊이를 측정하지 않는다. 바닥 앞에 선 사람, 벽 앞의 가방 등은 영상에서 같은 위치에 겹칠 수 있다. 가림을 제거하고 표면이 다시 보일 때 판단한다. 보이지 않는 바닥이나 비치물 아래쪽은 감지 불가 영역이다.

## 2. 설치 시 표면 등록

매 프레임 AI로 표면을 분할하지 않고 설치자가 대시보드에서 다각형을 그린다.

- 바닥: 실제로 보이는 바닥만 등록한다. 테이블·가구가 가리는 부분은 구멍 마스크로 제외한다.
- 테이블: 테이블 전체 박스가 아닌 상판 경계만 등록한다. 테이블마다 고유 ID를 부여한다.
- 벽: 문·창문·화면·거울 등을 제외하고 고정된 벽면만 등록한다.
- 표면 경계에는 작은 여유 영역을 두어 경계 흔들림을 완화한다. 제외 범위는 화면에 표시한다.
- 겹친 다각형의 픽셀은 중복 집계하지 않는다. 설치 시 소유 표면을 확정하거나 겹침을 수정한다.
- 카메라 해상도·구도·렌즈 설정과 함께 설정 버전을 저장한다. 좌표 정규화만으로 구도 변경을 허용하지 않는다.

설치 단계:

1. 카메라 고정 및 표면 가시성 확인.
2. 표면별 다각형·제외 구역·테이블 이용 구역 등록.
3. 기본 비치물 등록.
4. 청결 상태 확인 후 가림 없는 여러 프레임을 모아 중앙값 기준 이미지 생성.
5. 야간 조명 등 필요한 정상 조명 상태도 별도로 확인·등록.
6. 작은 시험 물체와 얼룩 대체물을 놓고 거리별 검출 가능한 크기 확인.

선택적으로 상판·벽·바닥 평면마다 원근 보정을 적용할 수 있다. 실제 치수를 등록한 경우에만 면적을 cm²로 해석한다. 보정으로 가려진 표면이나 원본에 없는 세부 정보를 복원할 수는 없다. 평면 호모그래피의 적용 범위는 [OpenCV 공식 설명](https://docs.opencv.org/4.12.0/d9/dab/tutorial_homography.html)을 참고한다. 이 설계가 OpenCV 의존성 추가를 요구하는 것은 아니다.

## 3. 전체 처리 구조

```text
카메라 최신 프레임
  ├─ 카메라 상태·구도 변화 검사
  ├─ 사람·동물 검출/추적 (공유 결과, 유효 시각 포함)
  └─ 표면 관리자: 고정 다각형 마스크
       ├─ 바닥 마스크
       ├─ 테이블별 상판 마스크 + 기본 비치물 + 이용 상태
       └─ 벽 마스크
            ↓
       관측 가능 영역 계산 / 조명 보정
            ↓
       승인된 정상 기준과 비교
            ↓
       변화 연결 영역 추출 / 위치·면적·지속성 추적
            ↓
       표면별 규칙 + 비치물 규칙 + 동물 점유 규칙
            ↓
       후보 → 확인 → 알림 → 해소 재확인
```

표면 분석은 사람/물체 모델이 실행된 프레임 안에 종속시키지 않는다. 마지막 분석 시각으로 독립 예약한다. 대신 AI 결과가 오래되면 가림 판단의 신뢰도를 낮추고 필요한 재검사를 요청한다.

## 4. 기준 이미지와 기본 비치물

### 4.1. 기준은 두 역할로 분리

| 데이터 | 역할 | 변경 정책 |
|---|---|---|
| 승인된 정상 기준 | 청결한 표면과 정상 비치물 배치 | 설치·청소·배치 변경 확인 후 버전 갱신 |
| 조명 보정 파라미터 | 노출·밝기 변화 보정 | 변화·가림 없는 기준 패치에서 제한적으로 추정 |
| 직전 관측/단기 이력 | 움직임·가림·새 변화 확인 | 관측마다 갱신하되 정상 기준으로 승격하지 않음 |

사람이 없거나 오염이 오래 움직이지 않는다는 이유로 정상 기준을 갱신하지 않는다. 화면 전체가 크게 바뀌어도 기준을 덮어쓰지 않는다. 승인된 기준의 복수 조명 버전을 선택할 때는 후보 오염 영역이 아닌 안정된 패치를 사용하며, 선택 불확실 시 판단을 유보한다.

### 4.2. 비치물 정책

| 비치물 유형 | 예시 | 처리 |
|---|---|---|
| 고정 비치물 | 안내판·고정 꽃병 | 정상 기준에 포함. 이동·사라짐은 배치 변경 의심 |
| 제한적으로 이동 가능한 비치물 | 휴지통이 아닌 테이블 위 휴지 케이스·메뉴판 | 물체 템플릿과 허용 이동 영역을 등록. 기존/새 위치를 대응 |
| 소모·형태 변화가 있는 비치물 | 휴지·설탕 봉지·빨대통 | 실제로 가려진 좁은 영역을 관리 예외로 표시. 주변 표면은 계속 감시 |
| 손님이 놓은 물체 | 컵·휴대전화·가방 | 이용 중 임시 물체, 이용 종료 후 잔류 확인 |

고정 비치물은 함께 찍은 정상 기준에 존재하므로 계속 놓여 있어도 변화로 잡히지 않는다. 넓은 사각형 전체를 무시하면 그 안의 새 쓰레기를 놓치므로, 비치물이 실제 가리는 영역과 좁은 경계만 처리한다. 비치물 아래의 표면은 '정상'이 아니라 '관측 불가'다.

### 4.3. 비치물 이동 처리

예: 메뉴판이 왼쪽에서 오른쪽으로 이동한 경우.

1. 기존 위치의 변화와 새 위치의 변화를 각각 후보로 만든다.
2. 등록 템플릿의 윤곽·색상·크기와 허용 이동 범위로 대응을 시도한다.
3. 대응이 충분하면 `fixture_moved`로 분리한다. 새 위치에서 실제 비치물이 가리는 부분만 제외한다.
4. 기존 위치에서 새로 드러난 표면은 빈 상판 기준이 있으면 비교한다. 없다면 기준 미확보 상태로 두고 확인을 요청한다.
5. 대응이 모호하면 쓰레기나 정상으로 확정하지 않고 `layout_change_suspected`를 남긴다.

물체 회전·가림·유사한 새 물체는 규칙 매칭을 어렵게 한다. 이동 영역 전체를 면제하거나 새 배치를 자동 승인하지 않는다. 빈 상판 기준과 비치물이 놓인 정상 배치 기준을 둘 다 확보하면 이동 후 검사가 쉬워진다.

## 5. 규칙 기반 변화 검출

### 5.1. 관측 유효성

분석 마스크는 표면에서 사람·동물·기타 가림·관측 불가 부분을 뺀 영역이다. 사람 검출 박스는 가림의 보수적 근사로 쓸 수 있으나, 표면 전체를 제외하지 않고 겹친 부분만 제외한다.

- 검출/추적 정보에는 `observed_at`과 신뢰도를 둔다.
- 추적 실패 또는 오래된 검출이면 해당 영역을 즉시 청결로 취급하지 않는다.
- 동물이 가리는 픽셀은 오염 비교에서 제외하되, 동물 점유 분기는 계속 실행한다.
- 가림이 해제된 후 안정된 새 관측을 확보한다.
- 프레임 단절·구도 변경·심한 노출 변화 시 확인 시간과 해소 시간을 누적하지 않는다.

### 5.2. 저비용 1차 비교와 후보 정밀 비교

1. 표면별 저해상도 버퍼에서 밝기 차·색상 차·간단한 경계 차를 계산한다.
2. 큰 변화가 있는 타일뿐 아니라 작은 고대비 변화도 후보가 되도록 평균 차와 변화 픽셀 비율을 함께 사용한다.
3. 잡음 제거 후 연결 영역을 만든다.
4. 후보 영역만 더 높은 해상도로 재확인한다.
5. 위치·겹침·면적으로 동일 후보를 시간에 걸쳐 연결한다.

밝기 변화 하나만으로 오염을 확정하지 않는다. 밝기만 달라지고 색상·경계가 유지되면 그림자 가능성을 기록한다. 그러나 무색 액체나 같은 색 오염도 있으므로 이를 영구 제외하지 않고 가시성이 회복될 때 재검사한다. 배경 차분에서 그림자가 전경으로 검출되는 문제는 [OpenCV 공식 배경 차분 설명](https://docs.opencv.org/3.3.0/db/d5c/tutorial_py_bg_subtraction.html)에도 소개되어 있다.

### 5.3. 큰 변화의 처리

- 여러 안정 패치가 같은 방향으로 밝아짐: 조명 변화 후보. 제한된 보정 후 재평가.
- 많은 고정 경계가 함께 이동: 카메라 이동 후보. 분석 중지 및 재설정 요청.
- 한 표면에 국소적으로 넓은 변화: 대형 흘림 가능성. 크다는 이유로 조명 변화로 제거하지 않음.
- 테이블 위치가 변경됨: 상판 마스크 무효화 및 재등록 요청.

## 6. 표면별 판단 규칙

### 6.1. 바닥

새 변화가 바닥 마스크 안에 있고, 가림이 해제된 유효 관측에서 일정 면적 이상 지속되면 `floor_contamination_suspected`를 발생시킨다.

사람·동물이 지나간 뒤 새 변화가 생겼다는 시간적 관계는 근거로 기록할 수 있다. 다만 동물 근처에서 생겼다는 이유로 배설물이라고 단정하지 않는다. 컵·가방처럼 물체일 가능성이 높아도 통행 방해나 잔류물로 별도 관리할 수 있다.

### 6.2. 테이블 오염·잔류물

테이블 이용 상태와 오염 상태를 별도로 관리한다.

```text
이용 상태: 비어 있음 → 이용 중 → 이용 종료 확인 중 → 비어 있음
관측 상태: 유효 / 부분 가림 / 관측 불가
오염 상태: 정상 → 후보 → 확인됨 → 해소 확인 중 → 정상
```

- 이용 중 컵·가방은 즉시 청소 알림으로 보내지 않는다.
- 이용 상태는 상판과 사람 박스의 겹침만으로 결정하지 않는다. 좌석/접근 구역과 최근 이용 이력을 함께 사용한다.
- 한 프레임에서 사람이 사라져도 이용 종료로 전환하지 않는다. 새 관측을 통한 부재 확인과 유예가 필요하다.
- 이용 종료 후 비치물로 설명되지 않는 새 변화가 지속되면 `table_cleanup_suspected`를 발생시킨다.
- 남은 물체가 개인 소지품인지 쓰레기인지 확실하지 않으면 '잔류물 확인 필요'로 표시한다.
- 이용 중 넓게 퍼지는 변화는 '흘림 후보'로 기록하고 보이는 부분을 재확인할 수 있다. 손·그림자만으로 즉시 확정하지 않는다.

### 6.3. 테이블 위 동물

동물 여부는 규칙만으로 신뢰성 있게 알아내기 어려우므로 공유 객체 모델의 cat/dog 결과를 사용한다. 상판 점유 판단은 규칙으로 수행한다.

- 최신 동물 검출과 상판 다각형의 관계를 확인한다.
- 가능하면 동물의 접촉 지점이 보이는지 확인한다. 일반 객체 모델에는 발 관절이 없으므로 박스 하단은 근사일 뿐이다.
- 동물 박스와 상판의 겹침, 상판 안 하단 위치, 연속된 관측을 조합한다.
- 바닥에서 테이블 앞을 지나가는 경우와 구분이 어려우면 `animal_near_table` 또는 확인 유보로 낮춘다.
- 여러 유효 관측에서 상판 점유 근거가 유지되면 `animal_on_table_suspected`를 발생시킨다.
- 이 분기는 손님 이용 중에도 활성이다. 동물이 떠난 뒤 오염·잔류물 검사를 다시 수행한다.

단안 겹침만으로 높이·접촉을 확정할 수 없다. 상판이 잘 보이는 카메라 각도를 설치 조건으로 두고 실제 바닥 통과/상판 점유 사례로 구분 능력을 검증한다.

### 6.4. 벽

사람·가구 등 가림을 제외한 벽 다각형에서 새 색상·무늬·경계 변화가 지속되면 `wall_change_suspected`를 발생시킨다. 얼룩과 새 포스터·부착물은 자동으로 확정 구분하지 않는다. 매장 관리자가 승인한 포스터 교체는 기준 버전 변경으로 반영한다.

## 7. 후보의 시간과 상태 관리

후보마다 다음 정보를 저장한다.

```text
candidate_id, surface_id, bbox/mask
first_seen_at, last_valid_seen_at
valid_evidence_seconds, valid_observation_count
visible_fraction, change_area, appearance_features
state, reason_flags, baseline_version
```

일반적인 흐름:

```text
정상 → 변화 후보 → 유효 관측으로 지속 확인 → 알림
                     │                     │
                     └─ 가림: 누적 유보     └─ 깨끗한 새 관측 반복 → 해소
```

두 관측 사이가 너무 길면 전체 경과 시간을 증거 시간에 더하지 않는다. 최대 허용 간격 이내의 유효 관측 사이에서만 시간을 누적하고, 최소 관측 횟수도 요구한다. 단일 영상이나 오래된 박스로 확인을 완료하지 않는다.

가림은 청소 완료가 아니다. 기존 알림을 보존하면서 관측 불가 상태를 표시한다. 해소는 가림이 없는 새 영상이 정상 기준과 일치할 때만 확인한다. 같은 후보는 한 번 알리고 지속 시간/면적 변화는 갱신한다.

아래 값은 성능 보장이나 확정 기본값이 아닌 현장 시험 시작 범위다.

| 대상 | 분석 주기 시작안 | 확인 시간 시작안 | 주의점 |
|---|---|---|---|
| 바닥 변화 | 초당 1~2회 | 유효 관측 10~30초 | 작은 오염의 면적 기준은 거리별 검증 |
| 테이블 변화 | 초당 1~2회 | 이용 종료 유예 후 15~30초 | 이용 종료 유예는 별도 30~60초 시험 |
| 벽 변화 | 2~5초마다 | 유효 관측 30~120초 | 그림자·조명 전환 검증 |
| 테이블 동물 | 객체 감지 예산 내 별도 예약 | 유효 관측 1~3초 및 복수 검출 | 처리 속도가 부족하면 보장 불가를 표시 |

## 8. 코드 구조 제안

| 모듈 | 역할 |
|---|---|
| `surface_config` | 표면 다각형·고유 ID·좌석 구역·정책 로드 및 검증 |
| `surface_mask` | 다각형 래스터화·제외/가림 마스크, 선택적 좌표 보정 |
| `surface_baseline` | 승인 기준·조명 버전·카메라 설정 해시·기준 이력 |
| `surface_change` | 밝기/색상/경계 차·연결 영역·후보 추적 |
| `fixture_monitor` | 기본 비치물 존재·이동·미확인 배치 처리 |
| `surface_rules` | 바닥/테이블/벽 정책·이용 상태·동물 관계 |
| `surface_events` | 중복 억제·근거 기록·확인/해소 이벤트 |

공통 입력에는 프레임 시각, 최신 검출 시각, 표면 가시성, 기준 버전을 포함한다. 작업 버퍼와 표면 마스크는 재사용한다. 느린 벽 검사를 매 프레임 수행하지 않는다. 정밀 비교는 후보 영역에 한정하되 저해상도에서 작은 오염이 사라지지 않는지 검증한다.

### 기존 코드에서 재사용할 부분

- `gray.c`: 저해상도 분석과 변화 계산 도구.
- `residue.c`: 연결 영역·지속성 처리 아이디어.
- `slot_monitor.c`: 테이블별 상태·알림 단계 구조.
- `log.c`, `config.c`, 대시보드: 설정과 로깅 기반.

### 대체하거나 수정할 부분

- YOLO 가구 박스로 표면을 생성하는 방식 → 설치 시 고정 표면 ID와 다각형.
- 가구 안이면 쓰레기, 밖이면 흘림인 분류 → 표면 종류와 관측 근거에 따른 의심 이벤트.
- 사람이 없으면 현재 모습을 자동 기준으로 채택 → 청결 확인 후 기준 승인.
- 큰 변화가 생기면 기준 강제 갱신 → 조명/카메라/대형 오염을 구분하고 유보.
- `GrayRect`만 전달해 가구 종류가 사라지는 구조 → `surface_id`와 명시적 표면 종류.
- 반복 crop 할당 → 표면별 재사용 버퍼.

기존 residue/slot 경로와 새 경로를 처음에는 비교 모드로 실행할 수 있다. 사용자 알림을 보내는 주 경로는 하나만 정해 중복 알림을 피한다. 검증 후 같은 영역의 기존 판정은 해제한다.

## 9. 저장 및 대시보드

저장 구조 예시(향후 구현 대상):

```text
config/surfaces.json
baselines/<camera_id>/<surface_id>/<version>/
  manifest.json
  clean_reference.*
  fixture_templates.*
logs/...
```

대시보드는 표면별로 감시 가능/부분 가림/기준 없음/구도 변경/정상/확인 필요를 구분한다. '감지 안 됨'을 무조건 정상으로 보여주지 않는다. 설정에서 표면 다각형, 기본 비치물, 승인된 기준과 현재 변화 영역을 겹쳐 확인할 수 있게 한다.

알림에는 표면 ID, 최초 발생 시각, 유효 관측 시간, 변화 면적, 이유, 기준 버전과 로컬 근거 이미지를 연결한다. 기준 변경은 조작 이력을 남기고 이전 버전을 보존한다. 영상과 근거 자료는 로컬 저장 원칙을 따른다.

## 10. 구현 단계와 검증

1. 고정 표면 다각형·명시적 기준 등록·가시성 상태 구현.
2. 바닥/벽 변화와 테이블 이용 종료 후 잔류물 규칙 구현.
3. 비치물 이동/기준 미확보 상태 및 동물 점유 의심 구현.
4. 조명 보정·후보 정밀 비교·CPU 예산 조정.

필수 검증 사례:

| 상황 | 기대 결과 |
|---|---|
| 메뉴판·휴지 케이스가 계속 놓여 있음 | 정상 기준과 일치, 오염 알림 없음 |
| 메뉴판 옆에 새 쓰레기 | 비치물 예외 영역 밖에서 후보 검출 |
| 메뉴판 이동 | 배치 변경 처리, 드러난 면의 기준 없으면 확인 유보 |
| 시작할 때 이미 오염 | 자동 정상 등록 금지, 기준 확인 요구 |
| 손님이 컵을 놓고 이용 중 | 이용 중 임시 변화 |
| 손님 퇴장 후 컵/가방 잔류 | 유예·재확인 후 잔류물 확인 필요 |
| 청소 중 사람이 오염을 가림 | 해소로 처리하지 않음 |
| 사람 퇴장 후 깨끗한 표면 확인 | 복수 관측 후 해소 |
| 조명 켜짐·햇빛·그림자 | 기준 덮어쓰기 없음, 보정 또는 유보 |
| 넓은 액체 흘림 | 큰 변화라는 이유로 기준 흡수하지 않음 |
| 동물이 테이블 앞 바닥 통과 | 상판 점유로 확정하지 않음 |
| 동물이 상판에 머무름 | 유효 검출과 공간 관계로 의심 알림 |
| 카메라 또는 테이블 이동 | 표면 설정 불일치, 재설정 요청 |
| 원거리 작은 배설물/같은 색 얼룩/투명 액체 | 거리·크기·대비별 미탐 한계 기록 |

평가 지표는 표면별 하루 오탐 수, 사례별 미탐률, 알림 지연, 관측 불가 시간 비율, 기본 비치물 이동 오탐, CPU/메모리 및 장시간 변화다. ROI 면적이 같아도 원근에 따라 물체의 픽셀 크기가 다르므로 거리별 성능을 구분한다.

## 11. 한계

가림·반사·무색 액체·표면과 같은 색 오염·원거리 작은 물체는 놓칠 수 있다. 규칙 기반 변화 검출은 오염의 의미나 화학적 성질을 판별하지 않는다. 동물의 실제 높이와 표면 접촉도 단안 영상만으로 항상 구분할 수 없다.

따라서 제품 출력은 '청소/확인 필요 의심'을 기본으로 하며, 실제 보이는 범위와 관측 불가 상태를 명시한다. 먼저 고정 표면·승인 기준·비치물 정책으로 오탐을 줄인 뒤, 현장 자료에서 남는 문제에 한해 추가 AI 도입을 검토한다.
