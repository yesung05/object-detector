# 자동 화면 기록과 영상 기반 평가

## 가장 간단한 사용법

1. 기존 대시보드와 감지기를 실행한다. 테이블 기준 모습이 등록되어 있어야 한다.
2. 저장소의 `run-surface-experiment.bat`를 더블클릭한다.
3. 컵이나 종이를 놓고, 이용하고, 떠나고, 치우는 행동을 한다. 키 입력은 선택 사항이다.
4. 치운 뒤 알림이 해제되는 것까지 기다리고 `q` + Enter로 종료한다. 최대 10분이면 자동 종료한다.
5. 콘솔 마지막 `Saved:` 폴더의 **review.html**을 더블클릭하면 시간순 사진 보고서가 열린다.

기본 대상은 `table-1`, 포트는 `8081`이다. 다른 대상은 다음처럼 실행한다.

```powershell
node scripts/record_surface_trial.js --url http://localhost:8081 --surface table-1 --seconds 600 --evidence on
```

이 기능은 별도 읽기 전용 기록기다. 대시보드 버튼이나 감지기 내부 녹화 기능을 추가한 것은 아니며, 실행 중인 감지기를 교체하거나 재시작하지 않는다. 기존 CLI는 `--evidence off`가 기본이므로 명시적으로 켜야 사진이 저장된다.

## 자동 저장 조건

사람 이용 상태, 가림·화면 품질, 기준 등록, 설정 버전, 영상 정체 여부, 변화 후보 유무, 청소 알림, 동물 후보가 바뀌면 `events.jsonl`에 기록한다. 최초 상태도 저장한다. 후보 좌표의 매번 작은 변화나 후보별 ID 변동은 화면 저장 조건에 포함하지 않는다.

사진 요청은 최대 2초에 한 번으로 제한한다. 제한 중에도 상태 전이 로그는 남지만 사진은 생략된다. 변화가 없으면 약 5초마다 정기 사진을 저장한다. 별도의 앞뒤 영상 버퍼는 없다. 사진은 전체 `/snapshot` JPEG이며 얼굴·상호·다른 탐지 오버레이가 포함될 수 있다. 자동 익명화는 하지 않는다. 동의된 통제 환경에서만 실행하고 논문 공개 전 가림 처리한다.

사진 저장 오류는 사건 로그에 남고 다음 관측을 계속한다. 상태 조회와 사진 요청은 순차 실행되므로 사진 응답이 느리면 원래 0.5초 상태 조회 간격도 길어진다. 사진 요청 제한 시간은 1.5초다. 따라서 효율 비교에서는 양쪽 조건에 같은 기록 설정을 사용하거나 사진 수집을 끄고 별도 계측해야 한다. 이 기록기 자체의 부하를 감지기 최적화 성능으로 혼동하지 않는다.

결과물은 `images/*.jpg`, `events.jsonl`, `review.html`, 기존 `samples.jsonl` 및 `summary.json`이다. 화면 요청·수신 시각과 상태 수신 시각을 별도로 남긴다. 정확히 같은 프레임에 대응하는 자료는 아니다. 실험 자료는 Git 제외 경로에 저장하며 자동 삭제하지 않는다. 장기 운영용 저장 용량 제한·보존 기간 정책은 아직 없다.

## 사진과 연속 영상의 차이

자동 사진은 설정 문제나 오탐 원인을 빠르게 검토하는 데 적합하다. 하지만 감지기가 반응하지 않은 짧은 사건은 5초 정기 사진 사이에서 누락될 수 있다. **논문의 미탐·정확도·지연 평가는 연속 원본 영상과 사람이 만든 정답 라벨이 더 적합하다.** 알림 시점만 저장해서는 미탐을 충분히 검증할 수 없다.

권장 평가 절차:

1. 동일한 카메라의 연속 원본 영상과 상태 로그를 함께 수집한다. 얼굴이 필요하지 않은 구도로 촬영한다.
2. 영상에서 실제 배치, 퇴석, 가림 해제, 제거 시각과 정답 물체 위치를 사람이 확인한다. 감지기 알림을 정답으로 복사하지 않는다.
3. 동일 영상을 재사용 OFF/ON으로 각각 처리한다. 모델, ROI, 비치물, 기준 이미지, 입력 해상도를 고정한다.
4. 사건별 검출 여부, 오탐, 알림 지연과 별도 측정한 추론 요청·실제 실행·CPU를 비교한다.

현재 CLI에는 `--input in.mp4` 파일 입력과 `--output out.mp4` 주석 영상 출력 옵션이 있다(`src/main.c`의 사용법). 다만 주석 출력은 탐지 박스가 포함되므로 **그대로 다시 넣으면 입력 영상이 달라진다.** 원본 영상을 평가 입력으로 보존해야 한다. 영상 파일 지원만으로 표면 모듈의 재현 가능한 오프라인 평가가 완성되는 것도 아니다. 시간 기반 유예가 영상 PTS인지 처리 시계인지 확인하고, 기준 이미지·ROI 복원과 사건별 평가기를 검증해야 한다. 이번 변경은 연속 원본 녹화나 재생 평가기를 구현하지 않았다.

## 제공된 첫 실험에서 읽을 수 있는 것

`trial-V1olbg`의 수동 배치 시각 87.670초와 최초 알림 관측 135.306초의 차이는 47.636초다. 수동 퇴석 표시 112.845초부터는 22.461초다. 이 값은 영상으로 대응 관계를 확인하기 전에는 탐지 정확도나 확정된 지연이 아니다.

수동 가림 해제 표시는 알림보다 늦은 171.520초다. 알림이 다른 후보인지, 부분적으로 보였는지, 수동 표시가 늦었는지 확인해야 한다. 제거 후 종료까지는 2.820초밖에 없어 기본 10초 해제 정책의 성공 여부를 판단하기 어렵다. 다음 시험은 알림 해제까지 계속 기록한다. AI 계측이 미지원이므로 이 시험으로 최적화 절감률을 주장할 수 없다.

## 검증 범위

합성 HTTP 응답으로 최초·변화·정기 저장, 2초 사진 제한, 사진 오류 기록, HTML 이스케이프를 테스트했다. 기존 상태 기록기 회귀 테스트도 통과했다. 실제 카메라 사진 저장 및 실물 감지 정확도는 이번 자동 테스트에서 검증한 것이 아니다.
