# 실제 물건을 놓고 수치를 기록하는 절차

**간편 실행:** `run-surface-experiment.bat`를 실행하면 상태 변화와 약 5초 간격 화면을 자동 저장한다. 종료 후 저장 폴더의 `review.html`을 연다. [자동 화면 기록 안내](automatic-evidence-guide.md)를 참고한다. 연속 동영상 녹화는 아니다. 아래 기본 CLI 설명은 사진을 켜지 않은 모드다.

## 무엇을 해야 하는가

실제로 컵·종이 조각을 놓고, 사람이 떠나고, 물건을 치우는 **독립 사건**을 촬영해야 한다. 합성 사각형 테스트나 논문 인용만으로 실제 위생 감지 정확도를 주장할 수 없다. 공개 데이터는 보조 평가이고 자체 촬영이 주 평가다.

### 공개 데이터의 역할

- [TACO](https://arxiv.org/abs/2003.06975): 실제 환경의 쓰레기 이미지·인스턴스 주석. 쓰레기 외형 평가나 별도 학습/검증용으로 고려할 수 있다. 시간적 퇴석·가림·알림 지연을 평가하는 동영상이 아니며, 현재 모델이 해당 클래스를 지원하는지 먼저 확인한다.
- [CDnet 2014](https://openaccess.thecvf.com/content_cvpr_workshops_2014/W12/html/Wang_CDnet_2014_An_2014_CVPR_paper.html): 변화·전경 검출의 다양한 영상 조건 평가용이다. 정답 전경 마스크가 곧 청소 필요 사건 라벨은 아니다. 모듈 출력과 맞는 평가 연결이 별도 필요하다.
- 방치 수하물 연구 [1, 2]의 데이터는 잔류·사람 연관성의 보조 실험에 참고할 수 있으나, 컵·오염의 매장 감시를 대체하지 않는다.

이번에는 논문 PDF만 다운로드했다. 대용량 데이터셋을 자동으로 내려받거나 학습시키지는 않았다. 원본 이미지별 라이선스·데이터 버전·분할을 확인한 후 별도로 수집한다.

## 실물 실험 전 준비

1. 감지기에서 테이블 ROI와 사람이 앉는 곳을 설정하고 정상 모습을 등록한다.
2. 기존 알림이 없는지 확인한다. 시험 물체를 남겨둔 채 정상 기준을 등록하지 않는다.
3. 흰 종이컵 또는 종이 조각을 준비한다. 실제 토사물·배설물은 사용하지 않는다.
4. 화면에 얼굴·상호가 나오지 않는 동의된 통제 환경을 사용한다.
5. 가능하면 영상을 녹화하고 사건 시간을 라벨링한다. 아래 기록기는 영상을 녹화하지 않는다.
6. 재사용 OFF/ON 비교에는 최신 감지기가 필요하다. 상태에 `ai_scheduler`가 없으면 효율 수치를 측정할 준비가 안 된 것이다.

## 기록기 실행

저장소 루트 터미널에서:

```powershell
node scripts/record_surface_trial.js --surface table-1 --scenario table_residue --seconds 240
```

`node`를 찾지 못하면 다음처럼 설치 경로를 지정한다.

```powershell
& 'C:\Program Files\nodejs\node.exe' scripts/record_surface_trial.js --surface table-1 --scenario table_residue --seconds 240
```

기본적으로 0.5초마다 읽기 전용 상태 조회를 한다. 포트가 다르면 `--url http://localhost:8082`를 지정한다. 새 모니터를 실행하거나 설정·기준 이미지를 바꾸지 않는다. 입력창에서 아래 문자와 Enter로 실제 행동을 표시한다.

| 입력 | 실제 행동 시점 |
|---|---|
| `n` | 표면이 깨끗함을 사람이 확인 |
| `p` | 물건을 놓음 |
| `l` | 사람이 떠남 |
| `v` | 가림이 해제됨 |
| `r` | 물건을 치움 |
| `q` | 기록 종료 |

키 입력은 실제 사건보다 늦을 수 있다. 직접 눌러야 하므로 가능하면 배치 담당자와 기록 담당자를 나눈다. 최종 논문 지연 값은 동기화된 영상으로 사건 시각을 다시 확인한다.

## 한 번의 시험 예시

1. 기록 시작 후 10초 정도 깨끗한 상태를 유지하고 `n`을 입력한다.
2. 테이블에 컵을 놓고 `p`를 입력한다. 잠시 이용한 후 떠나며 `l`을 입력한다.
3. 운영 기본값이라면 45초 퇴석 유예와 15초 잔류 확인을 포함하도록 충분히 기다린다. ‘정확히 60초 후’라고 가정하지 않는다.
4. 알림이 발생해도 기준을 다시 등록하지 않는다. 상태와 발생 시점을 기록한다.
5. 컵을 치우고 `r`을 입력한다. 알림 해제까지 기다린 후 `q`로 종료한다.
6. 독립 사건을 반복하고, 물건 위치·크기·색·가림 여부를 기록한다. 한 시험에 동시에 여러 물체를 추가하면 간단한 표면 단위 이벤트 기록으로 구분하기 어려우므로 초기 실험은 한 사건씩 진행한다.

## 생성 파일

`runs/surface-experiments/trial-.../` 아래에:

- `manifest.json`: 시나리오, 기록 시작 시각, 조회 설정.
- `samples.jsonl`: 매 조회의 상태, 후보, 요청·수신 시각, 왕복 지연, 계측값.
- `labels.jsonl`: 사람이 키로 표시한 행동. 표시하지 않았다면 파일이 생성되지 않을 수 있다.
- `summary.json`: 조회 성공·실패 수, 처음 관측한 알림 전이, 지원되는 AI 카운터 차이와 경고.

파일은 로컬 실험 자료로 Git에서 제외한다. 원자료에는 ROI 식별자 등이 포함될 수 있으므로 외부 공개 전 비식별 처리를 한다. `source=test-fixture`인 자동 테스트 출력은 실제 카메라 결과로 사용하지 않는다.

## 자동 요약의 한계

기록기는 **정확도·정밀도·재현율을 자동 확정하지 않는다.** 알림이 잘못된 것인지 사람이 GT와 비교해야 한다. 표면에 알림이 계속 켜져 있는 동안 생긴 두 번째 사건은 단순 상승 전이로 구분되지 않는다. 이미 첫 관측에 있던 알림은 새 사건으로 세지 않는다.

`first_seen_s`는 HTTP 응답으로 알림을 처음 본 시각이다. 바로 전 관측과의 간격은 발생 시각의 참고 범위일 뿐이며 네트워크 지연, 상태 갱신 주기, 누락, 수동 키 입력 지연을 포함한다. 내부 이벤트 로그와 영상 시각을 정렬해야 정확한 지연을 산출할 수 있다.

AI 카운터가 없거나 재시작·설정 변경으로 비교가 깨지면 차이를 null로 남긴다. 실제 모델 실행 수·CPU·전력은 이 기록기에서 측정하지 않는다. 해당 값은 별도 계측 후 결과 표에 넣는다. `reuse_observations` 차이를 ‘절감한 추론 수’로 쓰지 않는다.

실제 성능 결과는 [추천 실험 및 평가](recommended-tests.md)의 사건 매칭 규칙으로 GT와 로그를 비교한 뒤 초안의 Results에 추가한다. 통신 확인만 한 기록을 ‘쓰레기 검출 실험’으로 보고하지 않는다.

## 기록기 검증 이력

2026-09-11: 합성 HTTP 응답으로 입력 검증·조회 실패 기록·카운터 미지원 처리·상승 전이 기록을 검증했다. 실제 실행 중인 감지기에 대해서는 `connectivity_only`로 5초간 상태 10건을 오류 없이 수신했다. 수동 행동 라벨은 없으며 실물 배치 실험을 수행한 것이 아니다. 당시 `ai_scheduler`가 없어 효율 카운터 차이는 null로 남겼다. 실제 감지 정확도·CPU·추론 성능 결과는 아직 없다.
