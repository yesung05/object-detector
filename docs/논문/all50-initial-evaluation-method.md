# 50개 시나리오 초기 설정 재생 평가 방법

## 대상과 버전 고정

이번 실행 폴더: `runs/all50-initial-RQ5cAO/`.

9월 11일 세션 20개와 9월 14일 세션 30개를 합쳐 시나리오당 완료 영상 1개씩, 총 50개(약 205.11분)를 평가한다. 각 시나리오는 최신 세션의 완료본을 우선하며, 같은 세션의 중단본 대신 완료본을 선택한다. S05·S07·S43의 부분 영상은 중복 산입하지 않는다. 50개 모두 원본을 처음부터 끝까지 모델에 입력하며 예전 추론 결과를 재사용하지 않는다.

모델과 실행 파일은 현재 models 폴더가 아니라 `runs/surface-search/baseline-EQYvBO/`의 보존본을 사용한다. 초기 평가 config.json을 그대로 복사하여 table-1을 평가한다. 변화 임계값 24, 최소 면적 0.003, 확인 시간 15초이며, Grid Search 추천 임계값 32를 적용하지 않는다. ROI·이용 구역·퇴석 유예도 변경하지 않는다. 모델 재학습은 없다.

50개 기본 실행에는 초기 비치물 미등록 설정을 동일하게 사용한다. S36에 한해 등록한 컵 polygon을 추가한 설정으로 한 번 더 실행한다. 이 51번째 실행은 별도 비교이며 50개 총점의 분모에 중복 포함하지 않는다. 이렇게 해야 컵 등록과 파라미터 튜닝을 혼동하지 않는다.

## 재생과 정답

- FFmpeg로 원본을 2 Hz RGB로 리샘플링. ONNX CPU, 추론 스레드 1, 순차 실행, 영상 사이 10초 휴식.
- 각 영상은 새 상태/기준 폴더에서 시작. 원본 15초부터 가림 없는 5회 관측으로 정상 기준 생성.
- 기존 세션 20개는 앞선 평가와 같은 관찰 후반 정답 시각을 유지한다.
- 신규 세션 30개는 메타데이터의 observe 카운트다운 시작 +75초를 정답 검토 시점으로 정한다. 녹화 음성 건너뛰기 때문에 모든 영상에 동일한 고정 초를 사용하지 않는다.
- 해당 시점에서 ±0.25초 이내의 가장 가까운 2 Hz 예측을 사용한다.
- 새 영상의 초기·검토 시점·마지막 화면 총 90장을 추출하여 어시스턴트가 시각적으로 비교했다. 이는 전체 행동의 연속 검수나 독립적인 사람 검수 완료가 아니다. 제출 전 사용자/별도 검수자가 정답을 확인하는 것이 필요하다.
- 기존 세션의 앞선 검토 라벨과 신규 화면 검토 라벨을 labels.json에 명시적으로 저장한다. 시나리오 이름만으로 자동 정답을 만들지 않는다. 정답 불명확 시 강제로 음성으로 처리하지 않는다.

평가 대상은 **해당 시점에 청소 알림이 필요한가**다. 물체가 존재하는지만 평가하는 이진 분류와 다르다. S36의 기본 비치 컵 및 S39의 사용 중 컵은 물체가 있어도 기대 알림이 없다. 전체 정답은 알림 필요 23개, 불필요 27개다.

## 촬영 조건 차이

| 항목 | 이번 평가에서의 처리 |
|---|---|
| S33 | 원본 시작부터 컵이 있음. 제거 후 관찰 시점의 무알림만 채점. 최초 알림 형성·가림 중 유지·제거 후 해제 시험 성공으로 해석하지 않음. S33 제외 합계도 제공 |
| S35 | 지정된 컵/종이 대신 작은 색상 물체가 남음. 일반 잔류 물체 알림으로 채점하며 쓰레기 종류 분류 검증으로 사용하지 않음 |
| S36 | 비치물 미등록 초기값과 등록 설정을 별도 비교. 등록 영역은 초기 화면으로 지정했으며 후반 점수에 맞춰 조정하지 않음 |
| S37 | 기존 검토의 무알림 정답을 유지. 실제 등록·들기 행동 충족 여부는 별도 확인 필요 |
| S38 | 새 컵이 남아 있는 시점은 양성. 비치물 등록에 의한 구분 능력 검증이라는 주장은 하지 않음 |
| S39 | 평가 시점에 사람이 앉아 사용 중. 컵이 있어도 청소 알림을 억제해야 하는 음성 조건 |
| S43 | 평가 시점과 마지막에 컵이 남음. 양성 검출만 평가하며 제거 후 해제 성능은 평가하지 않음 |
| S46 | 잔류물 없는 시점은 음성. 실제 그림자 행동 수행은 정지 화면만으로 확인하지 않음 |
| S50 | 두 위치의 잔류물에 대해 표면 알림 하나의 성공 여부만 평가. 두 박스 모두 검출했다는 뜻이 아님 |

원본 뒤의 깨끗한 프레임을 앞에 붙이거나 미래의 빈 테이블로 초기 기준을 만들지 않았다. 실시간 운영 설정도 수정하지 않았다.

## 보고 범위

TP/FP/TN/FN, 정밀도·재현율·F1·정확도는 영상마다 **관찰 후반 한 시점**에 대한 값이다. 50개 전체 영상에 모델을 실행했더라도 이 값이 전체 시간축의 사건 단위 성능이 되는 것은 아니다. 품질 무효인 시점도 알림 전달 평가 분모에 포함하되 유효 비율과 해당 ID를 병기한다.

양성 시점에는 table-1의 후보 중 하나라도 알림 상태이면 TP로 센다. 실제 잔류물 위치와 알림 박스를 매칭하지 않으므로, 잔류물이 있지만 다른 경계 부위에서 발생한 알림도 이 정의에서는 TP가 될 수 있다. 따라서 TP 수를 올바른 물체 위치 검출 수로 보고하지 않는다. 박스 정답을 추가해 위치까지 검증하는 것은 별도 평가다.

이 자료는 기존 개발 데이터와 검토 후 재촬영을 포함한다. 독립 테스트가 아니며 다른 매장·카메라에 대한 일반화 성능을 의미하지 않는다. 9월 11일 21개 점수와 이번 50개 점수의 차이를 알고리즘 개선 효과로 해석하지 않는다. 데이터 구성이 바뀌었기 때문이다.

평가 어댑터는 운영 추적기를 사용하지 않고 매 표본 사람 추론을 수행한다. 카메라 품질은 정상으로 가정하며 물체 AI는 동기식이다. 사람/물체 추론 호출 수와 호출 소요 시간은 로그에 있지만 CPU 사용률·실시간 FPS·운영 비동기 지연 측정은 아니다. 시간당 오탐, 정확한 퇴석 후 지연, 전체 사건 F1, 박스 mAP, 효율 ON/OFF 비교도 이번 평가 범위가 아니다.

## 실행 및 결과 파일

```powershell
# 새 입력 목록 및 초기 아티팩트 고정 (새 폴더 생성)
node scripts/evaluate_all50_initial.js --prepare
# 위 명령이 출력한 실제 폴더 사용
node scripts/evaluate_all50_initial.js --stills runs/all50-initial-RQ5cAO
node scripts/evaluate_all50_initial.js --run runs/all50-initial-RQ5cAO
# labels.json의 명시적 시점 정답을 검토한 뒤, 전체 실행 완료 시 집계
node scripts/summarize_all50_initial.js runs/all50-initial-RQ5cAO
node scripts/test_all50_metrics.js
```

단순 결과 확인을 위해 재실행할 필요는 없다. `progress.json`은 처리 진행 상황, `completed.json`은 50+1개 실행 종료를 표시한다. 미완료 case 폴더를 발견하면 프로그램은 자동 덮어쓰기 대신 중단한다. 여러 평가 프로세스를 동시에 시작하지 않는다.

`manifest.json`에 선택 영상·원본 SHA-256·모델/실행 파일 해시·시점을 기록했다. `labels.json`은 기대 알림과 사유, 각 Sxx 폴더는 프레임별 예측·실행 로그·체크포인트 결과를 포함한다. `summary.json`, `results.csv`, `report.md`는 완료 후 집계물이다. `review/`는 새 영상의 정답 검토용 화면이다. 원본 영상과 결과 폴더도 함께 보존해야 문서의 수치를 재현할 수 있다.
