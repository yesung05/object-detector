# 초기값 보존 및 Grid Search

## 현재 보존한 초기 버전

`runs/surface-search/baseline-EQYvBO/`에 다음을 복사·보존했다.

- `initial-evaluation/`: 앞선 21개 평가 설정·결과·프레임별 예측·평가용 기준 이미지.
- `operational-config/`: 보존 시점의 운영 `surfaces.json`과 정상 기준 `.bin` 파일. 운영 설정 자체를 수정하지 않았다.
- `models/`: 평가에 사용한 실제 사람·물체 ONNX 모델 복사본.
- `evaluator/`: 독립 평가 EXE와 일치하는 ONNX Runtime DLL.
- `source/`: 주요 평가·감지 소스 복사본.
- `baseline.json`: 영상별 정답 체크포인트·원본 해시·보존 파일 해시·초기 수치.

원본 영상은 큰 파일을 중복 복사하지 않고 절대 경로와 SHA-256을 보존한다. 원본을 이동하면 실행 경로를 다시 구성해야 하며, 내용을 바꾸면 검증에서 중지한다. 따라서 이 스냅샷만 다른 컴퓨터로 옮긴다고 영상까지 포함되는 것은 아니다. 운영 설정은 참고용 보존이고, 비교 기준은 기존 평가 당시의 `initial-evaluation/config.json`이다. 두 시점의 설정을 혼동하지 않는다.

초기 결과: TP 5 / FP 2 / TN 9 / FN 5, 정밀도 71.4%, 재현율 50.0%, F1 58.8%, 정확도 66.7%. 기존 체크포인트 정의를 변경하지 않는다. S06 포함, S17·S38 제외도 고정한다.

## 실행 방법

`run-surface-grid-search.bat`를 더블클릭하고 표시되는 조합 수와 주의사항을 확인한 뒤 시작 여부를 선택한다. 고정된 초기 폴더 `baseline-EQYvBO`를 사용한다. 이전 평가가 없는 다른 환경에서는 초기 폴더를 먼저 준비해야 한다.

직접 실행:

```powershell
# 탐색할 범위만 확인 (추론하지 않음)
node scripts/surface_grid_search.js --plan runs/surface-search/baseline-EQYvBO

# 전체 탐색 시작
node scripts/surface_grid_search.js --run runs/surface-search/baseline-EQYvBO

# 중단한 실행 재개: 실제 생성된 search-... 경로 사용
node scripts/surface_grid_search.js --resume runs/surface-search/search-실제폴더명

# 초기 설정 한 영상 재현 검증 (최적화 결과가 아님)
node scripts/surface_grid_search.js --smoke runs/surface-search/baseline-EQYvBO
```

`node`가 PATH에 없으면 `& 'C:\Program Files\nodejs\node.exe'`로 대체한다. 새 초기 스냅샷을 별도로 만들 때는 `--init`을 사용한다. 기존 스냅샷을 덮어쓰지 않는다.

## 탐색 공간과 선택 기준

| 파라미터 | 후보 | 초기값 | 의미 |
|---|---|---:|---|
| threshold | 16, 24, 32 | 24 | 픽셀 변화 민감도; 작을수록 작은 변화도 후보가 될 가능성 |
| min_area | 0.001, 0.003 | 0.003 | 최소 변화 영역 비율; 작을수록 작은 후보 허용 |
| confirm_seconds | 5, 10, 15 | 15초 | 테이블 잔류 확인 시간 |

총 3×2×3 = **18개 조합**이다. 기준 조합을 첫 항목으로 두고, 해시로 보존된 기존 초기 결과를 재사용한다. 나머지 17개는 21개 영상에 실제 모델·표면 모듈을 다시 실행하여 **추가 357회 영상 평가**를 한다. 기존 기준까지 새로 돌린다면 총 378회다.

1. 같은 21개가 모두 처리된 조합만 순위에 포함한다. 실패한 영상을 빼고 점수를 내지 않는다.
2. FP가 기존 2건을 넘으면 추천하지 않는다.
3. 품질 유효 비율이 95% 미만이면 추천하지 않는다. 초기값은 20/21이다.
4. 위 조건을 통과한 조합 중 F1이 가장 높은 것을 선택한다.
5. 동점이면 FP가 적은 순, 유효 비율이 높은 순, 고정 후보 ID 순으로 정한다.

이 기준은 현재 코드에 명시되어 있고 변경하면 새 탐색을 시작해야 한다. ‘18개 제한된 후보 중 조건을 만족한 최고점’이지 연속적인 모든 파라미터 공간의 전역 최적값은 아니다. ROI·이용 구역·모델·증거 초기화 로직·퇴석 유예는 이번 탐색에서 변경하지 않는다.

## 출력과 중단 처리

`runs/surface-search/search-.../` 아래에:

- `search.json`: 초기 버전·프로그램/탐색 정의를 반영한 서명.
- `candidate-XX/config.json`: 각 조합의 평가용 설정.
- `candidate-XX/Sxx/`: 영상별 실제 예측·과정 로그·완료 결과.
- `candidate-XX/summary.json`: 조합별 수치.
- `leaderboard.json`: 처리 완료 조합 목록과 점수.
- `best.json`, `best-config.json`: **현재까지의** 조건부 최고 조합. 전체 종료 전에는 잠정값이다.
- `completed.json`: 전체 탐색 완료 표시. 이것이 없으면 탐색이 끝난 것으로 해석하지 않는다.

완료된 영상의 예측 해시를 확인하고 재개 시 재사용한다. 중간 실패한 영상은 새 임시 기준 폴더에서 처음부터 다시 처리하여 이전 기준·후보 상태를 이어받지 않는다. Ctrl+C는 자식 추론/디코더도 중지시키며, 재개는 완료한 영상 이후부터 진행한다. 디스크 부족·입력 변경·모델 변경·실행 정의 변경을 정상 완료로 처리하지 않는다.

**운영 설정에 자동 적용하지 않는다.** `best-config.json`은 table-1만 포함하는 평가용 설정이므로 이것으로 운영 설정 파일 전체를 덮어쓰면 안 된다. 실제 적용은 결과 검토 후 필요한 파라미터만 운영 설정에 반영해야 한다. 기존 파일·모델·기준·원본 영상은 삭제하지 않는다.

## 시간과 성능 측정 범위

현재 실행은 영상 사이에 10초, 실제 계산한 조합 사이에 60초 쉬도록 설정했다. 항상 영상 하나씩 처리하고 로컬 포트 8093 잠금으로 CLI의 중복 실행을 막는다. 해당 포트를 다른 프로그램이 사용해도 시작하지 않는다. 이는 휴식 간격이지 CPU 사용률 상한 제어가 아니다. ONNX 스레드는 1개지만 FFmpeg·운영체제·다른 작업의 부하는 별개다. 진행 상황과 다음 재개 예정 시각은 결과 폴더의 `progress.json`에 기록한다. 17개 신규 조합 전체에 추가되는 휴식은 약 73분이다. 실행 정의가 바뀌기 전 생성한 예전 smoke 실행은 현재 코드로 resume하지 않고 새 smoke로 검증한다.

현재는 순차 평가다. 파라미터에 따라 후보와 잘라낸 AI 입력이 달라지므로 예전 후보 AI 결과를 무조건 재사용하지 않는다. 각 조합은 원본 디코딩과 실제 추론을 다시 수행한다. 전체 탐색은 수 시간이 걸릴 수 있으며 실시간 감시나 다른 학습 작업과 동시에 실행하면 서로 영향을 줄 수 있다. 자동으로 사용자 작업을 중지하지 않는다.

프로그램 제작 시 단위 테스트 및 초기 설정 1건의 재현 확인으로 실행 경로를 검증했다. 이후 2026-09-11 21:59:13 KST에 `search-KqZcln`의 전체 18개 탐색을 완료했다. 제약을 만족한 최종 추천은 candidate-17(threshold=32, min_area=0.003, confirm_seconds=15), 개발 체크포인트 F1=66.7%다. 운영 설정에는 적용하지 않았다. 전체 점수·한계·다음 작업은 [최종 결과·인수인계 문서](grid-search-final-results-2026-09-11.md)를 참고한다.

## 논문에 보고할 때

이 21개는 이미 결과와 화면을 보고 선택한 **개발 데이터**다. 모든 조합을 비교해 얻는 최고 F1은 튜닝 점수이며 독립 테스트 성능이 아니다. 같은 영상의 최고점을 기존 성능 대비 일반화 개선이라고 주장하지 않는다. 전체 촬영 세션이 하나이므로 임의 프레임 분할을 독립 검증처럼 쓰지도 않는다.

또한 평가 기준은 관찰 후반 한 시점의 알림 유무다. 그 지점의 점수가 높아져도 사용 중 오탐·후반 추가 오탐·퇴석 지연이 악화될 수 있다. 기존 S15의 뒤늦은 오탐처럼 체크포인트 외 사건은 별도 시간축 검토가 필요하다. 따라서 최종 채택 전에 실제 행동 시점 라벨과 전체 영상 검토가 필요하며, 추후 다른 촬영 자료로 검증하는 것이 적절하다.
