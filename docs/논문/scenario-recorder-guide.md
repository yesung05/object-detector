# 시나리오 랜덤 자동 녹화 웹

음성 안내는 **브라우저 기본 한국어 TTS**를 사용한다. CLOVA 인증 정보·사전 음성 생성은 필요 없다. 한국어 음성이 있으면 우선 선택하고 없으면 브라우저의 한국어 언어 요청 처리를 따른다. 실제 목소리와 네트워크 사용 여부는 브라우저·운영체제 음성 엔진에 따라 달라진다. ‘음성 미리듣기’로 확인한다. 안내 재생이 끝난 뒤 각 단계 타이머가 시작되므로 아래 기본 녹화 시간은 음성 길이를 제외한 값이다. 미지원·재생 오류는 안내하며 음성을 끄면 무음 촬영이 가능하다. 환경은 사진에 보이는 앞쪽 큰 흰색 테이블로 고정하며 모니터·칸막이는 움직이지 않는다.

## 실행

1. `run-scenario-recorder.bat`를 더블클릭한다. Node.js가 필요하며 서버 콘솔은 열어 둔다.
2. Chrome 또는 Edge에서 `http://127.0.0.1:8092`를 연다. 기본 브라우저가 다르면 주소를 직접 붙여 넣는다.
3. **카메라 연결**을 누르고 권한을 허용한다. 원하는 카메라를 목록에서 바꿀 수 있다.
4. **저장 폴더 선택**으로 전용 실험 폴더의 쓰기 권한을 허용한다.
5. 처음에는 시나리오 하나와 촬영 수 1을 선택해 예행연습한다. 정상 저장·영상 재생을 확인한 뒤 50개를 촬영한다.
6. **랜덤 촬영 시작**을 누른다. 매 영상 전 준비 카운트다운이 지나면 녹화가 자동 시작되고 단계별 타이머가 끝나면 자동 저장된다.

같은 테이블·한 사람·고정 카메라를 전제로 한다. 감지기와 카메라를 동시에 사용할 수 없는 장치라면 사용자가 감지기를 중지하거나 별도 카메라를 선택해야 한다. 이 웹은 감지기를 자동으로 종료하지 않는다. 촬영 원본은 카메라 스트림이며 탐지 박스가 없다. 마이크를 요청하거나 녹음하지 않는다. 안내 음성은 PC 스피커로만 출력한다.

## 촬영 진행

선택한 시나리오를 중복 없이 무작위로 섞고 지정 개수만 사용한다. 실행 순서를 `session.json`에 보존한다. 준비물 목록·구체적 행동 안내·현재 단계·남은 시간을 표시하며 선택적으로 읽어준다. 무작위 순서는 저장되지만 난수 시드를 지정하는 기능은 없다.

기본 단계는 준비 15초(미녹화), 초기 장면 15초, 행동 45초, 관찰 90초, 정리 20초, 정리 후 20초다. 영상당 기본 약 190초이며 S33은 사전 배치·관찰로 105초가 더 필요하다. 실제 시간은 브라우저 지연에 따라 달라진다. 50개 자동 촬영은 준비 구간까지 약 173분을 예상하고 추가 휴식·재촬영 시간을 확보한다. ‘저장 후 다음 시나리오 자동 진행’을 끄면 영상 하나마다 대기한다.

한 명이므로 시작 버튼을 누른 뒤 테이블로 이동할 수 있게 준비 시간을 조절한다. 행동 안내는 반드시 미리 읽는다. S39는 사람이 관찰 내내 앉아 있는 예외이며 S33은 사전 잔류 장면이 필요하다. 초기 장면 촬영이 감지기의 기준 등록 완료를 보장하지 않는다.

**중단**은 현재 영상의 부분 저장을 시도하고 멈춘다. 다시 시작하면 같은 시나리오를 새 파일로 촬영한다. **건너뛰기**는 대기 중에만 가능하며 사유 대신 건너뛴 사실을 기록한다. 완료한 항목의 재촬영은 새 세션에서 해당 항목만 선택한다. 새 세션은 이전 파일을 삭제하지 않는다. 페이지를 다시 열면 기존 세션 이어받기는 지원하지 않는다.

## 저장 파일

선택한 폴더 아래에 시간과 임의 ID가 붙은 `session-...` 하위 폴더를 만든다.

- `S17_take003_임의ID.webm`: 시나리오별 개별 영상. take 번호는 세션 내 녹화 시도 순번이다.
- 같은 이름의 `.webm.json`: 시나리오·준비물·행동 지침·카메라 설정·녹화 상태·단계 안내 시각.
- `session.json`: 순서·시간 설정·완료/부분/실패/건너뜀 기록.

WebM은 현재 지원 형식이고 MP4 자동 변환은 없다. 원본은 브라우저에서 사용자가 허용한 폴더로 직접 저장한다. 서버는 파일 수신·업로드·임의 경로 쓰기 API가 없는 로컬 읽기 전용 서버다. 회사명·로고는 UI에 없지만 실제 카메라 영상의 얼굴·상표는 자동으로 가리지 않는다.

브라우저 메모리에 영상 전체를 모으지 않고 약 1초마다 전달되는 조각을 파일 쓰기 큐에 넘긴다. 대기량이 16MiB를 넘거나 쓰기가 실패하면 자동 진행을 멈춘다. 이 값은 브라우저 내부 메모리 전체의 상한을 보장하지는 않는다. 다음 영상은 현재 파일 및 메타데이터 저장 완료 후 시작한다.

탭 숨김·카메라 종료는 부분 저장 후 중지한다. PC 절전·강제 종료·디스크 오류·페이지 강제 닫기 때 복구는 보장되지 않는다. 녹화 중에는 탭을 전면에 두고 충분한 디스크 공간을 확보한다. 완료한 영상을 실제 플레이어로 열어 확인한다.

## 평가와 구분

이 웹은 원본 수집 도구다. 쓰레기 박스 표시·검출기 상태 수집·정답 자동 작성·OFF/ON 재생 평가는 포함하지 않는다. 안내 시각은 `scheduled_prompt_not_ground_truth`로 기록하며 실제 배치·퇴석·제거 시각이나 영상 PTS로 간주하지 않는다. 성공 상태 `completed`는 녹화 일정·저장 완료만 뜻한다. 행동을 제대로 했는지는 사후 검토해야 한다.

같은 테이블·한 참여자 자료이므로 타 장소·타인·다중 이용자·바닥·벽 성능을 주장하지 않는다. 개발용과 평가용은 촬영 세션을 나누고 동일 원본의 시간적으로 인접한 클립을 양쪽에 섞지 않는다.

## 검증 범위

`scripts/test_scenario_recorder.js`로 50개 1인 행동 안내, S33/S39 예외 단계, 중복 없는 섞기, HTTP 허용 경로, 마지막 영상 조각 저장, 탭 숨김 부분 저장, 디스크 오류 시 자동 진행 중단을 검증했다. `scripts/test_scenario_recorder_browser.js`로 실제 Chrome의 가상 카메라와 MediaRecorder가 WebM 헤더 및 영상 데이터를 생성하고 메타데이터 완료 상태에 도달하는 것을 확인했다. 이 브라우저 테스트는 폴더 쓰기를 메모리 대역으로 검증하며 실제 카메라·폴더 권한 대화상자·물리 저장 장치까지 검증한 것은 아니다.

## 구현 근거 자료

브라우저 녹화는 [MediaRecorder API](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder)를 사용한다. 마지막 데이터는 stop 이벤트 전에 전달되므로 데이터 쓰기를 완료한 후 파일을 닫는다. 조각 발생 간격은 정확한 시계가 아니므로 단계 시각은 별도로 기록한다. 폴더 쓰기는 [File System Access API](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)를 사용하며 지원 브라우저와 명시적인 사용자 권한이 필요하다.
