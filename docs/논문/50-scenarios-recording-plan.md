# 일반 실내 공간의 50개 영상 시나리오와 촬영·평가 계획

최신 촬영 방식은 [시나리오 랜덤 자동 녹화 웹](scenario-recorder-guide.md)이다. 같은 테이블에서 한 명이 50개 행동을 수행하며, 준비 카운트다운 후 시나리오별 영상이 자동으로 시작·종료·개별 저장된다. 아래 연속 촬영 후 분할 절차는 웹을 쓰지 않을 때의 대안이다. 구체적인 행동은 [50개 행동 프롬프트](50-action-prompts.md)를 참고한다.

## 1. 실험 환경과 주장 범위

촬영 장소를 카페로 가정하지 않는다. **고정 카메라·동일 테이블·참여자 한 명**으로 모든 시나리오를 진행한다. 테이블 옆 지정 수거함은 정상 폐기 동작에만 사용하며 바닥·벽·다른 테이블로 감시 대상을 바꾸지 않는다. 실제 공간의 종류·크기·조명·카메라 설치 조건은 촬영자가 기록한다. 논문에는 실제 무인 매장 실증이 아니라 **동일 테이블·단일 참여자의 일반 실내 모의 환경에서 수행한 예비 평가**라고 명시한다.

음료 구매나 카페 서비스를 재현할 필요는 없다. 컵·휴지·종이·포장지·개인 물건을 이용한 착석, 접촉, 반출, 잔류, 정리 행동을 평가한다. 먹거나 마시는 행동은 빈 용기를 이용한 모의 행동으로 대체할 수 있으며 실제/모의를 기록한다. 액체를 전자제품 주변에 흘리거나 실제 배설물·토사물을 사용할 필요는 없다.

이 문서는 촬영 계획이다. 50개 영상이 이미 확보되었거나 정확도가 측정되었다는 의미가 아니다. 50종을 한 번씩 촬영한 결과는 상황 범위 평가이지 각 상황의 반복 안정성 검증은 아니다.

## 2. 쓰레기 의심 영역을 박스로 강조하기

가능하다. 현재 표면 상태에는 후보별 `bbox`, `alert`, `visible` 등이 있으므로 그 좌표로 강조할 수 있다. 다만 변화 후보는 쓰레기의 정답 영역이나 정밀한 물체 검출 박스가 아니다. 비치물 이동·그림자도 후보가 될 수 있으므로 **‘쓰레기 확정’ 대신 ‘잔류물 의심’ 또는 ‘청소 확인’**으로 표기한다.

권장 표시 설계:

| 상태 | 화면 표시 | 의미 |
|---|---|---|
| 변화 후보, 아직 알림 아님 | 노란 얇은 사각형 + ‘변화 확인 중’ | 확인 시간 또는 AI 판단 대기 |
| 청소 알림 | 빨간 굵은 사각형 + ‘청소 확인’ | 관리자가 확인해야 하는 후보 |
| 이전 알림 영역이 현재 가려짐 | 회색 점선 사각형 + ‘이전 위치 · 가림’ | 현재 물체 위치를 관측한 것으로 오해하지 않도록 표시 |
| 동물 후보 | 별도 색 사각형 + ‘동물 의심’ | 쓰레기와 구분 |

색뿐 아니라 글자로도 구분한다. 논문용으로 모서리 반경은 0으로 하고, 장식 테두리는 제외하되 **대상 표시 사각형은 유지**한다. 여러 후보에는 영역 ID와 후보 ID를 붙여 오탐 위치를 대조한다. ROI 전체에 빨간 테두리를 치는 것과 실제 후보 박스는 구분한다.

정규화 좌표 `[x1,y1,x2,y2]`는 영상의 실제 표시 영역 너비·높이로 환산하고, 여백이 있는 경우 그 오프셋을 반영한다. 상태와 JPEG를 별도 HTTP로 받는 현재 사진 기록은 시간차가 있으므로 ‘관측 근접 화면’으로 표시한다. 프레임 단위 평가용 박스는 해당 프레임과 동기화된 후보 결과로 그려야 한다.

**원본 영상은 박스 없이 보존하고, 박스는 검토 화면·별도 결과 영상에만 그린다.** 박스가 그려진 영상을 다시 모델에 입력하면 평가 입력이 달라진다. 현재 자동 사진 보고서에 이러한 후보 박스를 추가하는 작업은 이 문서의 표시 설계이며 이번 문서 작성에서 구현한 기능은 아니다.

## 3. 촬영을 편하게 하는 방법

### 대안: 같은 설치에서 5개씩 연속 촬영 후 분할

50번 카메라를 켜고 끄는 대신 같은 배치·조명 조건의 시나리오를 5개씩 묶어 약 10개 촬영 세션으로 진행한다. 아래 표의 분류와 촬영 세션은 반드시 같을 필요가 없다. 실제 준비물이 비슷한 순서로 촬영한다. 세션을 나중에 사건별로 분할하여 최종 영상 50개를 만든다.

각 사건 시작 전에 `S01`처럼 시나리오 번호를 소리 내어 읽거나 카메라에 번호 카드를 잠깐 보여준다. 번호 카드는 감시 ROI 밖에서 보여주고, 평가 시작 전에 치운다. 음성 수집 동의가 없으면 카드만 사용한다. 이 방식이면 촬영 중 행동별 단축키를 누르지 않아도 사후에 사건을 찾기 쉽다.

1. 카메라를 고정하고 모든 세션의 해상도·화각·프레임률을 유지한다.
2. 표면 ROI, 이용 구역, 정상 비치물 위치를 정하고 사진·설정으로 남긴다.
3. 원본 녹화 시작 후 시나리오 번호를 표시한다.
4. 카드를 치우고 깨끗한 초기 장면을 최소 10~15초 확보한다. 기준 등록 완료도 확인한다.
5. 시나리오 행동을 자연스럽게 수행한다.
6. 떠난 뒤에는 물건을 즉시 치우지 말고 확인 구간을 유지한다.
7. 정리 시점과 알림 해제까지 기록한다. 다음 사건 전 초기 상태를 복원한다.

초기 촬영 예산으로 사건당 약 2~4분, 순수 녹화 100~200분을 잡는다. 이는 편성을 위한 제안값이며 준비·재촬영 시간은 별도다. 운영 기본값의 퇴석 유예 45초와 테이블 잔류 확인 15초를 고려해, 실제 사람이 떠나고 가림이 풀린 뒤 대략 75~90초의 관찰 구간부터 시작한다. 정확히 60초에 알림이 뜬다고 가정하지 않는다. 제거 후에는 기본 해제 시간 10초보다 긴 15~20초 이상을 확보하고 실제 해제 여부를 본다. 벽 등 더 긴 확인 정책은 별도로 반영한다.

정상 시나리오도 같은 관찰 구간을 확보해야 늦게 발생한 오탐을 확인할 수 있다. 무조건 알림이 뜰 때까지 기다리는 방식 대신 최대 관찰 시간을 사전에 정하고, 미검출도 그대로 남긴다.

### 녹화 장치 선택

- 가장 좋은 평가 입력은 실제 감지기에 공급할 카메라의 **박스 없는 원본 영상**이다. 같은 카메라를 두 프로그램이 동시에 열 수 있다고 가정하지 않는다.
- 원본 수집을 먼저 하고 이후 파일 재생 평가를 수행하면 실시간 감지와 녹화의 카메라 점유 충돌을 줄일 수 있다. 다만 재생 평가 모듈 검증이 선행되어야 한다.
- 별도 고정 휴대전화 영상은 사람 행동과 가림을 확인하는 보조 자료로 사용할 수 있다. 화각이 다른 보조 영상의 좌표를 감지기 영상 좌표로 그대로 사용하지 않는다. 시작·끝의 공통 신호로 시간차와 드리프트를 확인한다.
- `run-surface-experiment.bat`는 상태 로그와 주기적 JPEG를 저장하는 도구이며 **연속 원본 영상 녹화 버튼이 아니다.** 별도의 `run-scenario-recorder.bat`는 시나리오별 원본 영상을 개별 녹화한다. 연속 영상 사후 분할 UI는 아직 없다.

## 4. 50개 독립 시나리오 체크리스트

‘알림 없음’은 지정 정상 구간에서 청소 알림이 없어야 한다는 뜻이다. ‘잔류 알림’은 퇴석·가림 해제·확인 시간 등 정책 조건 충족 후의 기대값이다. 사람 사용 중 경고를 억제하는 테이블 정책과 바닥·벽 정책을 혼동하지 않는다.

| ID | 행동 | 기대 결과·관찰 포인트 |
|---|---|---|
| S01 | 테이블 옆을 지나가기만 함 | 알림 없음 |
| S02 | 빈손으로 앉았다가 바로 떠남 | 알림 없음 |
| S03 | 빈손으로 일정 시간 앉아 있다가 떠남 | 사용 중/퇴석 상태 전이, 알림 없음 |
| S04 | 잠시 일어났다가 유예 시간 안에 돌아옴 | 일시 부재로 불필요한 청소 알림 없음 |
| S05 | 의자를 움직이고 떠남 | 의자 이동과 감시 표면 잔류물 구분 |
| S06 | 테이블을 손으로 짚고 떠남 | 접촉·손 그림자에 알림 없음 |
| S07 | 휴대전화를 놓았다가 가져감 | 정상 반출, 알림 없음 |
| S08 | 가방을 놓았다가 가져감 | 가림 복구 후 알림 없음 |
| S09 | 노트북을 사용하고 가져감 | 큰 가림 후 정상 복구 |
| S10 | 여러 개인 물건을 펼쳤다가 모두 가져감 | 후보가 많아도 최종 잔류 알림 없음 |
| S11 | 컵을 잠깐 놓고 바로 가져감 | 일시 변화에 알림 없음 |
| S12 | 마시는 동작 후 컵을 들고 떠남 | 이용 물체와 방치 구분 |
| S13 | 컵을 여러 위치로 옮기다가 가져감 | 이전 위치에 유령 후보·알림 없음 |
| S14 | 컵을 둔 채 잠깐 비웠다가 유예 안에 돌아와 가져감 | 일시 부재에 알림 없음 |
| S15 | 컵 두 개를 사용하고 모두 가져감 | 모두 제거된 뒤 알림 없음 |
| S16 | 컵 하나를 놓고 떠남 | 정책 조건 충족 후 잔류 알림 |
| S17 | 마시는 동작 후 컵을 남기고 떠남 | 사용 중 억제, 퇴석 후 알림 |
| S18 | 컵과 휴대전화 중 휴대전화만 가져감 | 남은 컵 위치 강조 |
| S19 | 컵 두 개 중 하나만 가져감 | 남은 컵 검출, 가져간 컵 위치 오탐 확인 |
| S20 | ROI 안쪽의 테이블 가장자리에 컵을 남김 | 경계 근처 검출 확인; ROI 밖은 평가 대상 아님 |
| S21 | 먹는 동작 후 포장지를 남김 | 퇴석 후 잔류 알림 |
| S22 | 마시는 동작 후 컵과 포장지를 남김 | 표면 사건 검출 및 여러 잔류물 위치 별도 확인 |
| S23 | 사용한 모양으로 구긴 휴지를 남김 | 작은 비정형 잔류물 검출 |
| S24 | 용기는 가져가고 작은 종이 조각만 남김 | 작은 잔류물 미탐 여부 |
| S25 | 쓰레기를 한곳에 모아두고 떠남 | 모아두었어도 미수거 상태 알림 |
| S26 | 모의 식사 후 모든 물건을 가져감 | 알림 없음 |
| S27 | 컵을 지정 쓰레기통 안에 버림 | 정상 폐기; 통 내부는 평가 제외/정상 정책 명시 |
| S28 | 포장지를 지정 쓰레기통 안에 버림 | 정상 폐기와 주변 투기 구분 |
| S29 | 깨끗한 테이블을 천으로 닦고 천도 가져감 | 손·천 이동에 잔류 알림 없음 |
| S30 | 잔류 알림 이후 돌아와 쓰레기를 치움 | 알림 발생 및 제거 후 해제 |
| S31 | 몸으로 테이블을 가린 뒤 아무것도 남기지 않고 떠남 | 가림만으로 잔류 알림 없음 |
| S32 | 몸으로 가린 동안 컵을 놓고 떠남 | 다시 보인 뒤 잔류 검출 |
| S33 | 이미 알림 중인 쓰레기를 가린 동안 치움 | 가림 중 섣부른 해제 방지, 재관측 후 해제 |
| S34 | 가방 뒤에 종이를 남기고 가방만 가져감 | 새로 드러난 잔류물 검출 |
| S35 | 자신의 한쪽 팔로 가린 동안 반대 손으로 물건을 남김 | 팔 가림 해제 이후 검출 |
| S36 | 비치 컵을 만지고 제자리에 둠 | 정상 비치물로 인한 잔류 알림 없음 |
| S37 | 등록된 비치물을 들었다가 같은 자리에 돌려놓음 | 비치물 복구 확인 |
| S38 | 비치물 옆에 개인 컵을 남김 | 비치물과 새 잔류물 구분 |
| S39 | 혼자 관찰 시간 내내 앉아서 컵을 계속 사용 | 사용 중인 테이블의 청소 알림 억제 |
| S40 | 잠깐 떠났다 돌아온 뒤 컵·종이를 남기고 완전히 떠남 | 일시 부재와 최종 퇴석 구분 |
| S41 | 테이블 위에 작은 종이를 떨어뜨리고 떠남 | 테이블의 작은 잔류물 검출 |
| S42 | 테이블 위에 떨어뜨린 종이를 바로 주움 | 일시 변화에 청소 알림 없음 |
| S43 | 컵 안에 포장지를 모아 넣고 컵째 테이블에 남김 | 쓰레기를 모았어도 미수거 상태 알림 |
| S44 | 테이블에 평평한 마른 얼룩 모형을 남김 | 평평한 표면 변화 검출; 실제 액체 분류 아님 |
| S45 | 포장지를 작게 접거나 구겨 테이블에 남김 | 외형·부피가 변한 잔류물 검출 |
| S46 | 물건 없이 그림자만 테이블을 지나감 | 조명·그림자 오탐 확인 |
| S47 | 물건을 남기지 않고 조명을 변경함 | 품질 경고와 청소 오탐을 구분 |
| S48 | 투명 컵을 남기고 떠남 | 배경과 유사한 물체 검출 |
| S49 | 테이블과 비슷한 색의 종이를 남김 | 낮은 대비에서 검출 |
| S50 | 작은 종이를 떨어진 두 위치에 남김 | 표면 알림 성공과 두 위치 검출 성공을 별도 평가 |

S33처럼 이전 알림이 필요한 사건은 영상 안에서 사전 배치·관찰 과정까지 포함한다. 쓰레기가 있는 장면을 깨끗한 기준으로 등록하지 않는다. 비치물은 촬영 전에 등록하고, 이동 허용 정책을 기록한다. 이 50개에는 동물·배설물·바닥·벽·다중 이용자 평가가 없으므로 해당 성능을 주장하지 않는다. 한 테이블과 한 사람의 반복 자료이므로 다른 사람·매장으로의 일반화도 주장하지 않는다.

## 5. 촬영 전 예행연습

50개 전체를 찍기 전에 S03, S17, S31, S30을 먼저 시험한다. 사람이 실제로 앉았을 때 상태가 `occupied`로 바뀌는지, 가림 때 품질 상태가 달라지는지, 떠난 뒤 유예와 알림이 이어지는지 확인한다. 이용 상태가 계속 `vacant`이면 이용 구역·사람 좌표·화각을 먼저 점검한다. 이것을 해결하지 않고 전체를 촬영하면 ‘퇴석 정책’ 검증에 쓸 수 없는 자료가 쌓일 수 있다.

촬영 중 정책을 바꾸면 설정 버전을 분리한다. 실패한 영상도 이유와 함께 남기고 성공 영상만 골라 성능을 계산하지 않는다. 촬영 사고, 파일 손상 등 분석 제외 기준은 결과를 보기 전에 정한다.

## 6. 파일과 정답 기록

권장 폴더 구조(향후 평가 도구의 입출력 제안):

```text
experiment-YYYYMMDD/
  environment.md          # 공간·카메라·조명·동의·비치물 설명
  config/                 # ROI, 기준 이미지, 모델/설정 버전
  raw/session-01.mp4       # 박스 없는 연속 원본
  clips/S01_take01.mp4     # 사건별 클립; 원본과의 시간 대응 보존
  labels/events.csv        # 사람이 확인한 정답 시점
  results/reuse-off/       # 기준 방식의 예측·계측
  results/reuse-on/        # 개선 방식의 예측·계측
  review/                 # 박스 강조 결과; 입력용이 아님
```

최소 메타데이터는 `scenario_id, take_id, session_id, actor_id, split, source_video, clip_start_s, clip_end_s, config_revision, notes`다. 배우 ID는 실명 대신 익명 번호를 쓴다.

정답 사건에는 `placed_s, person_left_s, visible_again_s, removed_s, expected_alert, target_surface, target_object`를 기록한다. 없는 사건의 시각은 빈 값으로 두며 0으로 채우지 않는다. 여러 물체는 물체 ID별로 나눈다. 시각의 기준은 클립 시작 0초 또는 원본 PTS 중 하나로 통일하고 원본 대응을 보존한다. 박스 위치 평가를 하려면 별도로 사람이 표시한 정답 박스·마스크가 필요하다.

## 7. 평가와 논문 결과

- 사건별 정밀도·재현율·F1: 예측 알림을 수동 정답 사건과 시간·표면·위치 기준으로 대응시킨다. 표면 전체 알림 하나로 잔류물 두 개를 모두 찾았다고 세지 않는다.
- 정상 구간 시간당 오탐: 정상 영상 길이를 분모로 사용한다. 0.5초마다 같은 알림이 반복 수신되어도 새 오탐 여러 건으로 세지 않는다.
- 지연: 배치 이후 지연, 실제 퇴석 이후 지연, 가림 해제 이후 지연을 구분한다. 정책 유예와 확인 시간을 문서화한다. 미검출을 지연 0초로 처리하지 않는다.
- 해제: 실제 제거 후 알림이 해제될 때까지 측정한다. 녹화 종료까지 해제되지 않으면 관찰 중단으로 보고한다.
- 성능: 동일 클립·모델·기준·ROI로 재사용 OFF/ON을 비교한다. AI 요청과 실제 실행 수를 구분하고 FPS·CPU·메모리는 별도 측정한다. 사진 기록 부하는 동일하게 맞춘다.

영상 파일 재생은 프레임 처리 속도가 달라도 **영상 시간 기준**으로 정책이 동작하도록 검증해야 한다. 현재 파일 입력 지원만으로 결정적인 재현 평가가 보장되지는 않는다. 기준 복원, 프레임 시각, AI 비동기 결과 시각, 상태 초기화, 종료 후 후보 처리를 함께 검증한다. 같은 영상의 반복 실행으로 재현성도 확인한다.

촬영 세션 또는 배우·배치 단위로 개발용과 최종 평가용을 분리한다. 같은 연속 촬영의 인접 클립을 양쪽에 나누지 않는다. 모든 유형의 일반화 성능을 별도로 주장하려면 해당 유형의 독립 반복 촬영이 추가로 필요하다. OFF/ON 2회 실행은 영상 100건이 아니라 동일한 50건의 쌍 비교다.

## 8. 구현 범위 정리

| 항목 | 현재 상태 |
|---|---|
| 상태 로그·변화/정기 JPEG·시간순 HTML 보고서 | 기존 자동 기록기로 지원 |
| 50개 시나리오·촬영 지침 | 본 문서로 제공 |
| 후보 사각형·가림 상태 강조 | 본 문서에서 설계, 별도 구현 필요 |
| 시나리오별 자동 시작·종료 및 원본 개별 저장 UI | `run-scenario-recorder.bat`로 지원; 연속 원본 사후 분할은 미지원 |
| 영상 정답 시점 편집 UI | 별도 구현 필요 |
| 영상 시간 기반 일괄 재생·OFF/ON 자동 비교 | 별도 구현·검증 필요 |

시나리오별 개별 녹화는 [랜덤 자동 녹화 웹](scenario-recorder-guide.md)으로 구현했다. 다음 구현 순서는 **동기화된 후보 박스 검토 → 정답 편집 → 일괄 평가**로 제안한다. 평가 숫자부터 자동 생성하지 않고 먼저 영상·상태 대응이 정확한지 확인한다.
