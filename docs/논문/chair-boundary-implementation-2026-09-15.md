# 의자 경계 가림 처리 구현 및 CPU 병렬 탐색

2026-09-15. 논문에 별도 장을 추가하는 기능이 아니라 기존 ‘가림 처리·오탐 억제’ 설명에 포함하기 위한 경량 보완이다. 운영 설정에는 자동 적용하지 않는다.

## 구현 범위

- `occluders`에 테이블 외부까지 포함하는 의자 탐색 영역을 등록한다. 테이블 위 정상 물체인 `fixtures`와 별도다.
- 의자 탐색 영역을 96×96 격자로 샘플링한다. 등록 영역 안에서 RGB 각 채널이 80 이하인 어두운 픽셀 중 표면 ROI 밖과 연결된 성분을 구한다. 사람이 가린 픽셀을 의자 연결의 근거로 사용하지 않는다.
- 실제 후보 검사에서 보류하는 것은 그 성분과 테이블 ROI의 **8격자 이내 경계 부분**의 교집합뿐이다. 큰 직사각형 영역을 상시 제외하지 않는다.
- 초기 기준에 있던 어두운 경계 성분은 빈 표면 기준이 없으므로 보류 상태를 유지한다. 의자가 이동했다고 자동으로 깨끗한 표면을 학습하지 않는다. 이 부분은 실제 컵/쓰레기가 나중에 놓여도 관측이 제한될 수 있음을 명시한다.
- 현재 가림이 해제되고 초기 기준이 이미 알려진 부분은 5회 비가림 관측을 거쳐 검사에 복귀한다. 기존 알림이 가려졌다는 이유만으로 해제하지 않는다.
- 전체 ROI의 10%를 초과해 보류하려는 결과는 거부하고 의자 마스킹 없이 처리한다(오탐이 나더라도 전체 영역을 가리는 방식으로 숨기지 않음).
- `occluder_fraction`, `occluder_rejected`를 상태 JSON에 출력한다. 평가 결과에는 시점·최대·평균 보류 비율과 거부 표본 수도 기록한다.
- 격자/버퍼 크기는 고정이며 별도의 AI 모델을 추가하지 않았다. 추가 CPU 시간은 아직 별도 측정하지 않았다.

**검은 의자·밝은 테이블에 대한 규칙 기반 기능이지 일반 의자 인식/추적기가 아니다.** 밝은 의자, 강한 조명 변화, 의자와 붙은 검은 물체, 등록 범위를 벗어난 움직임은 한계다. 보류 영역을 깨끗함/TN으로 설명하지 않는다. 표면 품질 유효 비율뿐 아니라 실제 보류 면적도 함께 보고한다.

## 설정

`config/video-evaluation/all50-chair-boundary.json`은 기존 초기 table-1 ROI를 유지하고 다음만 추가했다. 컵 fixture는 기존 A와 동일하게 미등록으로 유지한다.

```json
{
  "occluder_dark_threshold": 80,
  "occluder_max_fraction": 0.10,
  "occluders": [{
    "id": "chair-left",
    "polygon": [[0.10,0.40],[0.33,0.40],[0.33,0.95],[0.10,0.95]]
  }]
}
```

영역과 의자 처리 상수는 이번 Grid Search에서 탐색하지 않는다. threshold/min_area/confirm_seconds만 탐색한다. 영역 설정은 기존 오류 검토를 바탕으로 한 개발 설정이며 독립 테스트 성능으로 주장하지 않는다. 웹의 의자 전용 등록 UI는 이번 작업에 포함하지 않았고 평가용 JSON으로 등록했다.

## 검증 및 비교

- C 단위 테스트: 기존 표면/동물/AI 재사용 회귀 테스트, 의자 경계 보류, 등록 구역 안의 분리된 작은 검은 물체 유지, 중앙 잔류물 유지, 초기 가림 영역의 unknown 유지, 과도한 마스킹 거부를 확인했다.
- A는 `runs/all50-initial-RQ5cAO/`의 기존 50개 결과다. A 초기 설정으로 새 EXE를 실행하는 OFF 재현 검사도 수행한다.
- B는 새 의자 코드 + 기존 초기 파라미터(24/0.003/15초), 기존 초기 모델을 사용한다. 새 EXE·DLL·모델·소스를 별도 복사·해시 보존하고 50개를 실제로 다시 실행한다. A 결과를 B 초기값으로 재사용하지 않는다.
- B 실행 폴더: `runs/chair-B-i5fWGi/`. 완료 여부는 해당 폴더의 `completed.json`으로 확인한다. `comparison.json`은 A/B, `grid-ready.json`은 B 기반 새 탐색 기준 폴더를 기록한다.
- CPU 병렬도는 4개다. 원본 50개, 정답, 평가 시점, S33 제외 49개 주 지표 및 전체 50개 보조 지표를 유지한다.

## Grid Search 안전장치 및 선정 조건

기존 all50 도구를 수정해 탐색 서명에 실제 baseline 내용과 실행 스크립트 해시를 포함했다. 실행 전 영상 및 모델/DLL 해시도 재검사한다. 따라서 예전 스크립트로 만든 완료 탐색을 새 코드에서 강제로 resume하지 않는다.

새 탐색은 B 결과를 기준으로 초기 후보를 재사용한다. 영상 해시·체크포인트·EXE·설정을 비교하고 B 초기 프레임 로그 해시도 확인한다.

49개라는 **동일 분모**에서 A/B 기본값을 확인한 뒤, Grid 후보 점수를 보기 전에 다음을 고정한다.

- FP 상한: A/B 중 더 적은 FP.
- 품질 유효 비율 하한: A/B 중 더 높은 비율.
- 재현율 하한: A/B 중 더 높은 재현율.
- 통과 후보 중 F1 최대, 동점이면 FP 적은 순 등 기존 고정 규칙.

조건을 만족하는 후보가 없으면 추천 없음으로 끝낸다. 과거 48/50=0.96과 47/49를 잘못 비교했던 문제를 반복하지 않는다. Grid 결과를 본 뒤 조건을 완화해서 추천을 만들지 않는다.

## 논문 분량을 늘리지 않는 반영 예시

기존 가림 처리 설명을 아래처럼 **교체**하고, 결과 표의 기존 행에 의자 처리 전/후 조건을 추가 또는 대체한다. 별도 의자 인식 장을 만들지 않는다.

> 등록된 의자 영역에서 표면 외부와 연결된 어두운 경계 성분을 가림으로 처리하여 변화 후보의 오탐을 억제한다. 빈 표면 기준이 없는 초기 가림 영역은 불확실 상태로 유지하고, 알려진 표면은 재노출 후 유효 관측을 거쳐 검사한다.

성능 수치는 B 및 Grid 완료 후 확인된 결과만 반영한다. 의자 처리로 오탐이 줄어도 보류 면적 증가 또는 재현율 저하가 있다면 함께 기술한다. 기존 단일 체크포인트 평가가 전체 시간축의 사건 성능이 아니라는 한계도 유지한다.

## 실제 비교 결과 및 실행 인계

2026-09-15 B의 50개 영상 재평가를 완료했다. 아래 주 지표는 프로토콜이 다른 S33을 제외한 동일한 49개 체크포인트다.

| 조건 | TP | FP | TN | FN | 정밀도 | 재현율 | F1 | 정확도 | 품질 유효 비율 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| A: 기존 초기 설정 | 15 | 11 | 15 | 8 | 57.69% | 65.22% | 61.22% | 61.22% | 47/49 |
| B: 의자 처리, 동일 초기 파라미터 | 7 | 2 | 24 | 16 | 77.78% | 30.43% | 43.75% | 63.27% | 47/49 |

**오탐 감소만으로 개선 성공이라고 할 수 없다.** B는 재현율과 F1이 하락했다. 운영 적용을 보류하며, Grid Search에서도 재현율을 회복하지 못하면 추천하지 않는다. S33을 포함한 50개 보조 지표는 A: TP15/FP12/TN15/FN8, F1 60.00%; B: TP7/FP3/TN24/FN16, F1 42.42%다.

- 새로 미탐이 된 체크포인트: S17, S21, S22, S23, S24, S25, S41, S48. 새 오탐은 S09다. 상세 변경 목록은 `runs/chair-B-i5fWGi/comparison.json`에 있다.
- 기존 평가는 양성 영상에서 테이블의 어떤 위치든 알림이 있으면 TP로 계산한다. A의 의자 오탐이 양성 영상의 TP로 잡혔을 가능성과, B의 마스크가 실제 물체를 놓쳤을 가능성을 구별하려면 해당 프레임의 알림 위치와 물체 위치를 추가 확인해야 한다. 현재 수치만으로 어느 원인인지 확정하지 않는다.
- S36의 최종 체크포인트는 FP→TN이지만 B의 최초 알림은 75초다. 영상 전체에서 오탐이 사라졌다는 의미가 아니다.
- B의 적용 보류 면적은 최대 ROI의 9.686%; 영상별 평균의 단순 평균은 5.021%였다(프레임 수 가중 평균 아님). 면적 상한 거부는 S04에서 1개, S47에서 3개 표본이다. 품질 유효 비율이 같아도 검사 가능한 면적이 완전히 같지는 않다.
- C 단위 테스트와 all50 Grid Search JS 테스트 통과. 의자 설정을 끈 새 EXE로 S08을 재평가하여 기존 알림/품질/최초 알림 시점이 재현됨을 확인했다(`runs/chair-off-smoke-3WSRJS/`). OFF 전 영상 동등성 검사는 아니다. 평가기·실행 프로그램·대시보드 Release 빌드도 성공했다.

### CPU 병렬 Grid Search: 실행 중

- B 고정 기준: `runs/surface-search-all50/baseline-qbqiFW/`
- 새 탐색 결과: `runs/surface-search-all50/search-Zfde8w/`
- 시작 로그 및 PID: `runs/chair-grid-launch-WYNbpF/launch.json`, `stdout.log`, `stderr.log`
- CPU 작업자 4개, 후보 18개 × 영상 50개. 초기 후보 50개는 검증된 B 결과를 재사용하고 나머지 850개 조합은 실제 재추론한다. GPU 탐색이 아니다.
- 기준: threshold={16,24,32}, min_area={0.001,0.003}, confirm_seconds={5,10,15}. 의자 영역과 마스크 상수는 고정한다.
- 사전 고정 추천 조건: FP≤2, 재현율≥15/23, 품질 유효 비율≥47/49. 통과 후보가 없을 수 있으며, 결과를 본 뒤 조건을 완화하지 않는다.
- 백그라운드로 시작했고 실제 평가 프로세스 4개가 실행되는 것을 확인했다. **이 기록 시점에는 탐색이 끝나지 않았으며 최적값을 확정하지 않았다.** PC를 종료하거나 절전하면 실행이 중단될 수 있다.
- 탐색 완료는 `completed.json`, 최종 표는 `report.md`, 추천 여부는 `completed.json`의 `best`로 확인한다. `best.json`이 도중에 생겨도 개발 데이터에서의 임시 최선이며 운영 설정에 자동 적용되지 않는다.

진행 로그 확인(PowerShell):

```powershell
Get-Content runs/chair-grid-launch-WYNbpF/stdout.log -Tail 15
Get-Content runs/surface-search-all50/search-Zfde8w/progress.json
```

중단된 경우 기존 프로세스가 종료됐는지 확인하고 이어서 실행한다. 코드·영상·설정을 바꾸면 동일 탐색으로 재개하지 않는다.

```powershell
& 'C:\Program Files\nodejs\node.exe' scripts/surface_grid_search_all50.js --resume runs/surface-search-all50/search-Zfde8w --parallel 4 --no-rest
```

논문 본문은 아직 수정하지 않았다. 위의 짧은 방법 설명으로 기존 문장을 교체하고, 최종 검증된 결과로 기존 표를 대체하면 분량 증가 없이 반영할 수 있다. 이번 50개는 개발·튜닝에 사용했으므로 최종 독립 테스트 성능으로 표기하지 않는다.
