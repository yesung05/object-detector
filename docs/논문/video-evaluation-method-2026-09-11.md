# 촬영 영상 기반 표면 모듈 평가 방법

## 이번 평가의 단위

S17·S38은 정답/초기 기준이 불명확하여 실행 전에 제외했다. S06은 종료 전 정상 관찰 장면을 포함하므로 사용하며 제거 후 해제 지연에는 사용하지 않는다. 나머지 21개는 결과가 나쁘더라도 제외하거나 영상 내용을 편집하지 않는다.

**평가 단위는 영상당 관찰 후반의 표면 상태 한 지점**이다. 앞선 자료 검토에서 저장한 `late_observe` 화면을 근거로 잔류물 유무를 주석했다. 해당 요청 시각에 가장 가까운 2Hz 출력의 `candidate.alert`가 하나라도 참인지 비교한다. 이는 표면 단위 상태 이진 분류이며 물체별 위치 정확도·전체 영상의 사건 단위 F1·위생 종류 분류·실시간 시스템 전체 성능이 아니다.

정답 양성 10개: S44, S34, S45, S16, S21, S40, S49, S24, S18, S25.

정답 음성 11개: S31, S47, S27, S15, S08, S10, S12, S11, S03, S37, S06.

S21·S25는 종료에도 물건이 남아 있으나 양성 관찰 시점 평가에는 사용할 수 있다. S18은 일부 가림이 있는 컵이므로 현재 알림을 유지하는지도 포함한 검사다. 알림이 평가 시점에는 없지만 더 이른 시점에 있었다면 이번 체크포인트에서는 FN이지만 ‘영상 전체에서 한 번도 못 찾음’이라고 표현하지 않는다. 정상 시점 TN이어도 영상의 다른 시점에는 오탐이 있을 수 있다.

## 실제 실행 경로

- 원본 WebM → FFmpeg `fps=fps=2:start_time=0` → 1280×720 RGB → 별도 C 평가 실행 파일.
- 영상 PTS에 따라 0.5초 간격으로 샘플링한다. 중간 프레임은 버리고 필요한 경우 복제하며 광학적 보간은 하지 않는다. 표면 모듈의 `now`는 샘플 시간+1초로 설정해 0초 초기값 충돌을 피한다.
- `src/detector_ort.c`, `src/postprocess.c`, `src/surface_monitor.c`, `src/surface_config.c`의 실제 코드를 재사용한다. 합성 검출 결과나 AI 성공 스텁이 아니다.
- 사람: `yolo11n-pose-416x224.onnx`. 물체: `yolo11n_tier2_fp32.onnx`. CPU, ONNX 내부 스레드 1, confidence 0.25, IoU 0.45, fast preprocessing.
- 사람 추론은 샘플마다 실행하고, 원래 코드와 같은 골반 키포인트/박스 중심 비율을 이용 구역 anchor로 사용한다.
- 물체 모델은 표면 스케줄러의 실제 검사 요청이 있을 때 잘라낸 영상 영역에 실행한다. 결과는 동일 영상 시각에 동기적으로 제출한다.
- 설정은 평가 시작 시 운영 revision 5의 복사본에서 `table-1`만 남긴다. ROI·이용 구역·기본 임계값은 결과에 맞춰 조정하지 않는다. 기본 enter 3초, departure 45초, table confirm 15초, clear 10초, threshold 24, min_area 0.003이다.
- 기존 기준 파일은 읽지 않는다. 각 영상별 새 작업 폴더에 15초부터 5회 가림 없는 관측으로 기준을 생성한다. 실제 준비 완료 시각을 결과에 남긴다.
- 재사용 기능은 ON으로 한 번 평가한다. OFF 비교는 이번 결과에 포함하지 않는다.

## 운영 감지기와 다른 부분

운영 실행 파일을 그대로 실행한 것이 아니라 **동일 표면 모듈과 실제 모델을 사용하는 격리된 오프라인 어댑터**다. 트래커, 카메라 상태 진단, 실시간 비동기 지연은 재현하지 않는다. 사람은 매 샘플의 새 검출을 사용하고 카메라 입력은 유효하다고 가정한다. 영상 중 PTS 간격이 큰 구간도 2Hz 리샘플 과정에서 중복될 수 있다. 이 차이를 숨긴 채 배포 시스템 전체의 실시간 성능으로 보고하면 안 된다.

quality가 0이 아닌 체크포인트도 별도로 공개한다. 사용자에게 알림이 나왔는지 평가하는 혼동행렬에서는 알림이 없으면 음성으로 집계하지만, ‘유효한 청결 판정’으로 해석하지 않는다. 품질 불량에 따른 판단 보류와 탐지 실패 원인을 함께 보고한다.

## 재현과 산출물

`tests/evaluate_surface_video.c`와 CMake 대상 `evaluate_surface_video`가 어댑터다. 운영 EXE를 덮어쓰지 않도록 `build-windows/surface-validation/`에 빌드한다. ORT 헤더·라이브러리·DLL 버전은 일치해야 하며 이번에는 1.26.0을 사용한다. 최초 실행은 오래된 1.17 DLL 때문에 시작에 실패했고 해당 불완전 결과는 성능 집계에 쓰지 않는다.

실행 스크립트: `scripts/run_surface_video_evaluation.js`.

후처리: `scripts/summarize_surface_video_evaluation.js <결과 폴더>`.

최종 평가 폴더: `runs/video-evaluation-3yhvPj/`.

- `manifest.json`, `config.json`: 입력·모델 SHA-256·설정 복사본·평가 차이.
- `Sxx/predictions.jsonl`: 영상 시각별 실제 표면 출력·사람 검출 수.
- `Sxx/process.log`: 모델 실행 호출 수 및 호출 구간의 경과시간.
- `results.json`, `summary.json`: 체크포인트 결과와 혼동행렬.
- `analysis.json`, `results.csv`: 후보 증거 누적·품질 상태·모델 파일 변경 검증·표 형식 결과.

모델 호출 구간 경과시간은 디코딩·파이프 대기를 포함한 전체 속도나 CPU 사용률이 아니다. 사용자 작업과 함께 실행했으므로 하드웨어 처리량 벤치마크로 주장하지 않는다. 정확한 알림 지연·시간당 오탐·실제 행동 시점 라벨은 이번 평가에서 확정하지 않는다.
