## 1부. Tier 2 물체 룰 확정 필터 (`src/rules.c`)

### 문제

`external_drink` `external_food` `animal_on_*` `no_cup_seated` 는 Tier 2 를 **한 번 돌려 한 번 보이면 바로 발화**했습니다.
Tier 2 는 `detect_every_obj`(90프레임)마다 돌아서 한 번의 오검출이 곧 경고였고, 선풍기→food 같은 오탐이 그대로 나갔습니다.
또 래치 상태를 `track_id == -2` 슬롯의 `overstay_latched` `fall_latched` `fall_start` 에 룰마다 다른 뜻으로 돌려 쓰고 있었습니다.

### 변경

- 최근 `object_confirm_window`(기본 5)번 관측 중 `object_confirm_count`(기본 3)번 이상 보여야 확정, window 번 연속으로 안 보여야 해제.
  연속 K회가 아니라 K-of-N 으로 한 이유는 컵·병이 손에 가려 한두 번 빠지는 일이 흔해서입니다.
- 룰마다 전용 상태(`ObjRuleState`)를 둬서 재활용 필드를 없앴습니다. 로그에 `hits=3/5` 를 남겨 임계값 조정 근거로 씁니다.
- `object_confirm_count` 가 0 또는 1 이면 필터 없이 기존 동작(즉시 발화·즉시 해제).
  `RulesConfig` 끝에 필드를 추가했으므로 위치 초기화를 쓰는 기존 코드는 자동으로 이 모드가 됩니다.

## 2부. 인원 초과 `occupancy_exceeded`

활성 트랙 수 > `max_occupancy` 가 `max_occupancy_hold_seconds`(기본 10초) 유지되면 WARN. **기본은 꺼짐(0)** 입니다.
적정 인원은 매장마다 달라 일반적인 기본값이 없고, 트래커가 한 사람을 잠깐 둘로 쪼개는 경우를 hold 로 흡수합니다.

## 3부. 장시간 무동작 `person_motionless`

서 있거나 누운 사람이 기준 자세 대비 박스 큰 변의 10% 이내로 `still_seconds`(기본 300초) 움직이지 않으면 WARN.
쓰러짐 룰이 놓치는 "처음부터 누운 사람·주저앉은 사람"을 보완하려는 것입니다.

- 직전 프레임이 아니라 **시작 시점 기준 자세**와 비교합니다. 천천히 걷는 사람은 프레임 간 이동이 떨림 수준이라 매번 "정지"로 보입니다.
- 의자에 앉은 사람은 제외합니다. 상체 직립만으로는 앉은 사람과 구분되지 않아, 무릎이 엉덩이보다 박스 높이의 22% 이상 아래일 때만 "선 자세"로 봅니다. 애매하면 대상에서 빼서 미탐 쪽으로 틀립니다.
- 손 들기(도움 요청)는 기지개·손 뻗기와 구분되지 않고 무인 매장에서는 손님이 제스처를 알 방법도 없어 **제외**했습니다.

## 4부. 미주문 착석: `PROBABLY_ORDERED` 면 억제

### 발견

문서에는 "키오스크 ROI 에 들어오면 `ORDERED`"라고 적혀 있었지만 코드는 달랐습니다.

- `ORDERED` 는 `tracks_mark_ordered()` 로만 설정되는데 **호출하는 곳이 없습니다.**
- 키오스크 근접(30초 유지, bbox 크기·상체 직립)은 `PROBABLY_ORDERED` 까지만 올리고, 이는 의도된 설계였습니다("근접은 결제 증거가 아님").
- 그런데 발화 조건이 `order != ORDERED` 라서 `roi_kiosk` 설정 여부와 무관하게 **300초 이상 머문 모든 사람**에게 `unordered_seated` 가 나갔습니다.
- `roi_kiosk` 는 설정을 읽지만 보호 영역 계산에만 쓰이고 주문 판정에는 쓰이지 않습니다. 기동 로그 문구("ORDERED 비활성")도 현재 동작과 맞지 않습니다.

### 결정과 변경

`order == UNORDERED` 일 때만 발화하도록 바꿨습니다. 이미 발화한 뒤 `PROBABLY_ORDERED` 가 되면 래치를 풉니다.
결제 연동 전까지 오탐보다 미탐을 택한 것이라, 키오스크 앞에 서 있다가 결제 없이 앉은 사람은 놓칠 수 있습니다.
계획에 있던 "`roi_kiosk` 기반 주문 판정"은 이미 의도적으로 걷어낸 설계를 되돌리는 일이라 구현하지 않았습니다.

## 이 작업의 한계와 미해결

- **실제 영상·카메라로 검증하지 않았습니다.** 오탐이 줄었는지, CPU 점유율이 그대로인지 모릅니다. 룰만 추가했으므로 추론 비용은 늘지 않을 것으로 보지만 측정값은 없습니다.
- **i5-4200U 실측은 여전히 없습니다.** 문서의 수치는 i7-8700 측정값과 추정치입니다.
- 키오스크 근접 판정은 bbox 크기·자세 휴리스틱입니다. 카메라 배치 때문에 `probably_ordered` 가 안 찍히면 미주문 착석이 장기 체류자 전원에게 다시 나갑니다.
- `person_motionless` 는 현장 미검증입니다. 키오스크·픽업대 앞에 오래 서 있는 정상 손님이 걸릴 수 있어 `still_seconds` 조정이 필요할 수 있습니다.
- **쓰러짐 비율 기본값이 코드 안에서도 둘입니다.** `rules.c` 는 1.3/1.6, `main.c` 는 설정 키가 없을 때 1.8/2.2. 운영 `config.json` 이 1.3/1.6 이라 지금은 문제없지만 키가 빠진 매장은 더 엄격해집니다. 통일은 하지 않았습니다.
- `main.c:395` 의 `--stream-port` 도움말이 "on 127.0.0.1" 로 남아 있는데 실제로는 모든 인터페이스에 바인딩됩니다. 수정하지 않았습니다.
- `docs/i5-4200u-optimization.md:39` 는 `detect_every=3`(초당 약 5회 추론)을 전제로 계산되어 있어 현재 운영 값(5)과 다릅니다. 연쇄 수치가 있어 손대지 않았고 재계산이 필요합니다.
- 계획 중 이번에 하지 않은 것: 배회, 입장·퇴장 카운트·꼬리물기, 시럽 펌프 동작, 쓰레기통 ROI, 쓰러짐 바닥 ROI, 문 ZNCC, residue 블록 평균 판정, 성능 항목(surface 1초 강제 추론, 회전 재탐지 제한, `compute_appear_hist` 서브샘플링 등).
