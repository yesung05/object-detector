# unmanned_detector 0.1.0-alpha.1 — 실제 카메라 부하 시험

## 조건과 해석 범위

- 시험일: 2026-09-26 KST.
- CPU: **Intel Core i7-8700, 물리 6코어 / 논리 12스레드**. Ryzen 측정 결과가 아니다.
- Windows x64 Release/baseline, ONNX Runtime CPU EP 1.22.0, FP32 사람/포즈 및 Tier 2 모델.
- 실제 HD WEB CAMERA, 요청 1280×720/30fps. 실제 처리 FPS는 아래 수치를 사용한다.
- 기본 3스레드 / Tier 2 간격 증가 / 1스레드를 각 약 180초, 모션 게이트 해제 연속 추론을 약 120초 실행했다.
- 앞의 세 조건: 사람 감지 간격 5프레임, Tier 2 간격 90/45/90프레임. 추가 조건: 사람 간격 1프레임, 모션 게이트 OFF, 요청 추론 상한 10FPS, Tier 2 간격 15프레임.
- 사용자 설정의 시험용 사본에 `tier2_always=1`을 지정해 테이블 매핑 후에도 Tier 2를 계속 평가하게 했다. 원래 운영 설정은 덮어쓰지 않았다.
- 별도 데이터 폴더를 사용해 초기 10분 안정화와 테이블 자동 탐색이 포함된다.
- CPU/메모리는 감지기와 그 하위 프로세스(conhost)를 합산했다. 다른 앱이 함께 실행 중인 PC이며 시스템 전체 CPU도 수집했다.
- CPU 평균은 첫 10개 샘플을 제외한 1초 단위 표본이다. 원본 영상은 측정 도구에서 저장하지 않는다.
- 장면/사람 움직임을 고정한 영상 재생 비교가 아니므로 설정 차이만의 인과 효과나 최대 수용 인원으로 해석할 수 없다.
- 단기 기능/부하 시험이며 2주 연속 안정성 및 오탐/미탐률 검증을 대체하지 않는다.

## 프레임과 추론

FPS는 저장된 좌표 스냅샷 값의 평균, 처리 시간은 마지막 스냅샷의 세션 누적 평균이다. 프레임별 독립 표본 지연 평균과 구분한다.

| 조건 | 입력 FPS | 사람 추론 FPS | 마지막 Tier 1 평균(ms) | 마지막 Tier 2 평균(ms) | 측정 구간 Tier 2 호출 증가 |
|---|---:|---:|---:|---:|---:|
| baseline_threads3_obj90 | 14.94 | 5.30 | 15.19 | 13.89 | 117 |
| tier2_increased_threads3_obj45 | 15.04 | 3.75 | 14.81 | 13.59 | 147 |
| threads1_obj90 | 14.87 | 3.45 | 22.40 | 20.99 | 119 |
| continuous_inference_threads3_obj15 | 15.01 | 7.94 | 14.70 | 13.62 | 120 |

Tier 2 간격 90→45가 전체 호출의 정확한 2배를 의미하지는 않는다. 자동 테이블 탐색의 별도 주기, 실제 처리 프레임 수, 감속도 영향을 준다. 연속 추론 조건도 설정한 10FPS가 보장되는 것은 아니다.

- 평상시는 약 10초, 사건 전후에만 최대 5Hz로 저장한다. 매 프레임 저장이 아니다. 알림 없는 짧은 움직임의 전체 궤적은 보존되지 않을 수 있다.
- `last_write_ms`는 다음 갱신까지 같은 값이 유지된다. 위 통계는 1초 상태 조회 샘플의 평균/p95이며 개별 DB 쓰기의 독립 표본 통계는 아니다.
- 좌표 JSON 용량은 SQLite 본체/인덱스/WAL/성능 DB/실행 로그의 총 디스크 사용량과 다르다.
- 시작 이벤트가 포함된 짧은 시험을 그대로 2주로 외삽하면 오차가 크다. DB별 좌표 JSON 1GiB 한도와 디스크 여유를 운영 중 확인해야 한다.
- 4개 이벤트 DB의 PRAGMA quick_check: ok, ok, ok, ok.

## Ryzen 최적화

현재 Intel 전용 OpenVINO가 아니라 ONNX Runtime CPU EP를 사용한다. AMD라는 이유로 최적화가 빠졌다고 단정할 근거는 없다. 다만 기본 3스레드, FP32, baseline은 자원을 제한해 운영하기 위한 설정이며 특정 Ryzen 모델의 최고 처리량을 찾은 결과는 아니다.

대상 Ryzen에서 동일 모델과 입력으로 스레드 수·추론 빈도를 비교해야 한다. [ONNX Runtime 공식 스레드 설정 문서](https://onnxruntime.ai/docs/performance/tune-performance/threading.html) 참고.
