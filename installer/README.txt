unmanned_detector 0.1.0-alpha.8 설치 및 실행 안내 (Windows 10/11 x64)

지원 환경: Windows 10 1607(build 14393) 이상 또는 Windows 11, x64.
  1809/LTSC 2019에서도 추가 설치 없이 실행됩니다. 필요한 런타임은 모두 들어 있습니다.
  1507/1511은 설치 단계에서 차단됩니다.
대시보드 브라우저: Chrome 또는 최신 Microsoft Edge.
  구형 Edge나 Internet Explorer에서는 대시보드가 동작하지 않습니다. 이 경우 안내 문구가 표시됩니다.
  Edge/Chrome이 설치되어 있으면 기본 브라우저와 관계없이 그쪽으로 엽니다.

1. unmanned_detector-Setup 설치 파일을 실행합니다. 관리자 권한이나 Python 설치는 필요 없습니다.
2. 카메라를 연결하고 바탕 화면의 unmanned_detector을 실행합니다.
3. 카메라가 하나면 자동 선택하며, 여러 개면 선택 창에서 카메라를 선택합니다.
4. 브라우저에서 http://localhost:8080 대시보드가 열립니다.
   실행 창의 X/최소화는 트레이로 숨기며 감시를 계속합니다.
   시계 옆 숨겨진 아이콘(^)에서 실행 창/대시보드를 다시 열 수 있습니다.
   중지는 트레이 메뉴의 [완전 종료]를 사용합니다.
5. 새 장소는 설정 > 감시 장소에서 장소 초기화를 실행합니다.
   최초 안정화는 기본 10분이며 문/테이블 인식 결과는 설정에서 확인합니다.
6. 좌표 기록은 대시보드의 좌표 재생에서 확인합니다.

프로그램: %LOCALAPPDATA%\Programs\unmanned_detector
설정 및 기록: %LOCALAPPDATA%\unmanned_detector
설정, 문 위치/기준 이미지, 테이블, 안정화, 로그는 사용자별로 분리됩니다.
업데이트/프로그램 제거 시 사용자 데이터는 보존됩니다.
기존 개발 폴더의 학교/집 설정이나 촬영 자료는 설치 파일에 들어 있지 않습니다.

업데이트 전에 트레이 메뉴에서 [완전 종료]를 선택하세요. 같은 버전 또는 새 버전의
설치 파일을 실행하면 프로그램만 교체됩니다. 자동 시작은 현재 제공하지 않습니다.
8080/8081 포트를 기존 개발 서비스가 쓰고 있으면 먼저 그 서비스를 종료하세요.
카메라가 안 보이면 Windows의 카메라 권한 및 다른 앱의 카메라 사용 여부를 확인하세요.

AI 추론은 CPU에서 실행합니다. 실제 설치 기기의 성능은 현장 확인이 필요합니다.
런타임/DLL과 FP32 모델이 포함되어 실행 시 별도 모델 다운로드는 없습니다.
이 설치본에는 코드 서명이 없으므로 Windows에서 게시자 확인 경고가 나타날 수 있습니다.

좌표 수집량은 실행 로그 DB당 1 GiB로 제한됩니다. 한도 도달 시 좌표 수집이
중단됩니다. 2주 운영 중 기록 상태와 남은 디스크 공간을 확인하세요.
수동 내보내기 도구 tools\export-coordinate-trial.py 실행에만 Python이 필요합니다.
예: python tools\export-coordinate-trial.py --logs "%LOCALAPPDATA%\unmanned_detector\logs" --out trial-export
세부 설명: docs\coordinate-field-trial.md

이 빌드는 현장 검증 중인 Alpha입니다. 부팅/로그인 자동 시작은 포함하지 않습니다.
쓰러짐은 신뢰도 높은 새 관절, 이전 서 있는 자세(1초/3회), 수평 자세 유지
(기본 5초/3회 이상)를 함께 확인합니다. 머리 이동/넓은 박스만으로 즉시 발화하지
않습니다. 처음부터 누워 있거나 관절이 가려진 경우 확정이 어려울 수 있습니다.
침대 오분류 모델을 재학습한 것은 아니며 현장 오탐/미탐률은 별도 검증이 필요합니다.
기존 HUNIK 사용자 데이터 폴더는 삭제하지 않습니다. 필요하면 런처의
--data-dir 인수로 기존 폴더를 지정해 사용할 수 있습니다.

0.1.0-alpha.8 변경 요약 (0.1.0-alpha.7 이후)
- 로그가 분석하기 쉬워졌습니다. 이벤트 기록에 프레임 번호·시각·종류·트랙·JSON 값 열이 추가되고, 로그 파일마다
  실행 정보(run_info: 버전·빌드·실행 인수·모델 해시·설정, PIN 같은 비밀 값은 *** 로 가림)가 들어가며,
  시간별 요약(summary)이 파일 끝에 한 줄 남습니다. 성능 로그에는 추론·추적 시간과 카메라 이상 시간 열이 추가됩니다.
  늘어나는 용량은 시간당 약 15~20KB(현장 로그 기준 약 0.1%)입니다. 이전 로그 파일은 그대로 읽히고 새 열은 열 때 자동으로 붙습니다.
- 성능 로그와 화면의 cam_fps 는 "처리한 프레임 수 ÷ 시간"으로 바뀌었습니다. 이전 값은 프레임이 몰려 오면 실제보다
  크게(30fps 카메라에서 최대 100 이상) 나왔으므로, 이전 로그의 값과 직접 비교하지 마세요.
- 감지 판정은 바뀌지 않았습니다(같은 영상에서 검출·관절·룰 이벤트가 이전 버전과 동일함을 확인).

0.1.0-alpha.7 변경 요약 (0.1.0-alpha.5 이후)
- 보안: 파일 입력·출력은 로컬 파일만 허용합니다. rtmp://, http:// 같은 주소를 넣으면 거부되며 영상이 밖으로 나가지 않습니다.
- 카메라 실행 시 사람 추론을 별도 스레드에서 처리합니다(--async-infer, 카메라 기본 켜짐). 화면 끊김을 줄이는 기능이고
  CPU 사용량은 줄지 않으며, 판정이 추론 한 번 시간만큼 늦게 나올 수 있습니다. i5-4200U 에서 아직 측정하지 못했으니
  설치 후 CPU와 끊김을 확인하고, 문제가 있으면 실행 인수에 --async-infer 0 을 넣어 끌 수 있습니다.
- 쓰러짐: 설정 파일에 fall_aspect_ratio_kp/nokp 값이 없는 매장은 기본 비율이 1.8/2.2 에서 1.3/1.6 으로 바뀝니다
  (대시보드로 저장한 설정은 영향 없음). 이전보다 쓰러짐을 더 민감하게 판단합니다.
- 식탁 자동 탐색이 신뢰도 0.28~0.30 구간을 놓치던 문제와, 큰 의자 위의 작은 동물을 못 잡던 문제를 고쳤습니다.
- 대시보드: 설정 > 알림 관리에 "몸싸움 감지 사용" 스위치 추가(꺼져 있으면 알림 모드와 무관하게 알림이 오지 않음),
  문 "닫힘으로 리셋"이 PIN 이 필요한 기기에서 실패하고도 성공처럼 보이던 문제, 탭이 숨겨져도 계속 갱신하던 문제,
  카메라 화면이 끊기면 수동 재연결만 되던 문제를 고쳤습니다. 다시보기에 몸싸움·잔류물 이름표를 추가했습니다.

0.1.0-alpha.5 변경 요약
- 대시보드: 새 디자인(Pretendard 글꼴 내장), 시스템 상태 줄, 알림 줄의 오탐/맞아요 버튼과 묶음,
  설정 > 알림 관리(알림별 켜짐(알림 O)/켜짐(알림 X)/끔과 정밀도), 설정 전체 초기화(설정 파일을 먼저 백업).
- 가림 화면: 단색(기본) / 엣지 그레이 / 열화상 (설정 > 영상·개인정보). 엣지·열화상은 윤곽선이 남으므로
  비식별 수준은 매장 정책에 맞게 선택하세요.
- 폭행(몸싸움) 2단계 감지: 프로토타입이며 기본 꺼짐입니다(config.json 의 fight_enabled=1 로 켬).
  연출 데이터로만 평가했고 카페 오탐은 확인되지 않았으므로 처음에는 알림 관리에서 "켜짐 (알림 X)"로 두고 기록만 쌓으세요.
